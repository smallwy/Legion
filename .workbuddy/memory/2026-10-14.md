### 关键事实 / 决策

- 引擎版本 **3.8.0** 为准；以下 API 均**读引擎源码核实**，非凭记忆：
  - `Graphics` 组件内多次 `fill()/stroke()` **合并进同一 mesh → 1 个 Graphics = 1 DrawCall**（65535 顶点内）。
    这是整个 DrawCall 架构的基石：全场动态实体共用一个 `Graphics`（`EntityRenderer`）。
  - `screen.windowSize` 存在（screen.ts）；`Batcher2D.walk()` 按 children **遍历序**深度优先决定绘制优先级。
  - `KeyCode.KEY_E / ESC / SPACE`、`input.on(Input.EventType.KEY_DOWN)`。
- **绘制顺序坑（已修）**：运行时 `addChild` 的敌人节点会排在相机节点之后盖住 HUD。
  修法 = 世界拆**实体树 + 相机树**两棵，相机树整体挂在实体树之后（`GameBootstrap.onLoad`）。
- **静态检查**：`client/tools/`（cc-stub.d.ts + tsconfig.check.json）对全部脚本跑 `tsc --strict` → **0 error**。
  抓出真 bug：`new Node('Field')` 误用浏览器全局 `Node`（漏 import）→ 已修。
- 占位精灵：`assets/placeholder/sprite-*-v2.png`（256×256 无 alpha、近白底）经
  `client/tools/preprocess_sprites.py` 洪水填充抠透明 + 配色变体 → `client/assets/resources/art/`
  （pet.png / enemy-walker 绿 / enemy-flyer 红 / enemy-tank 灰蓝）。
