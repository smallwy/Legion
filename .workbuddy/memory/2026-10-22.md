### 踩过的坑（都写进代码注释了）

- **空气透视按距离累积，不按高度。** 树脚雾给 48px 高会把树干拦腰切两截，因为
  同一棵树上下半截离镜头一样远。只能 26px 高、alpha 0.14，作用是「地面与树根之间没有硬边界」。
- **树干 40×sc / 树冠 31×sc 是「绿篱」的配方。** 比例 1.2 读作棒棒糖，15 棵连起来就是一道墙。

- **深度只靠「往雾里混」不够**，两端的颜色都要动：`hexMix(treeFar, treeNear, depth)` 再混雾。
  只做单向混合时，最近那棵也只比最远那棵实一点，十五棵同一个淡橄榄色。
- **基线位移不能给 30px**。给 30 树干整根落到草脊以下、间距又均匀 → 读作「一排栅栏」。

- **受光方向必须统一**。太阳在 (700,74)，但两棵近景树的高光都固定偏左 ——
  左边那棵等于高光画在背光面，两个物件受光矛盾就被读成「两张贴纸」。

| 病 | 根因 | 数值 |

| 火坑像贴图 | 无描边 / 无断面 / 内部只有一种暗色 / 7 根 5px 细火苗 | CUT=8、INSET=14、BOT=y+32、三团 qflame 28/25/44 |

### 这轮踩的新坑

- **Python 脚本写回 LF 文件会变成 CRLF。** `io.open(..., "w")` 在 Windows 上默认
  按文本模式转换，整个 8783 行的 `grove.html` 全被改写，diff 一度 17025 行。
  修法：二进制读改写（`d.replace(b'\r\n', b'\n')`），或者 `newline=''`。
  **以后用脚本改源文件，先确认它的行尾，改完看 `git diff --stat`。**
- **前景丛会盖掉坑。** 第 1 关火坑 500~600 和 0.695 那丛（中心 667、半径 78）
  刚好重叠，整个坑下半截被草吃掉。改成按当前关卡 `PITS`/`CAMP` 实时避开。
- **canvas 里画「一堆东西」不能用多个圆各自描边**（内侧边交叉会读作几个球叠着）。
  唯一稳法是「粗描边一遍 + 填充一遍」，填充盖住内侧，留下并集外轮廓。土堆用的这个。
- **一团火只有外焰能描边**。内焰也描，火内部出现黑线，读作「火裂开了」。

### 剩余未达标（写进文档 §5）

配色偏橄榄灰、树形仍是「圆冠+直杆」、草地是三档纯渐变、平台全悬空、
天空无光源、前景体量偏小、上角垂叶未做。

**判断：其中「树形」和「草地」投入产出比最高**（占画面面积最大），

## 第三轮（11:30-11:55）：两端开口 / 出口朝向 / 背景明度骨架

用户三条反馈：①左下右下球要直接滚出去、上层才反弹 ②门要朝向我方单位不是朝向玩家
③场景还是不对，附了一张参考图（暖奶白天空、分层圆冠林、粗木平台、深色前景丛）。

**做法与结论**

- 两端按层分开：`onGroundLane(b) = b.y >= GROUND_Y - 24`。地面层开口（左滚出=判出场，
  装的人放回场上；右滚进=落袋），上层才是实心墙。预瞄线必须同步，否则"骗人"。
- 出口：正对镜头的拱门 → **横放空心圆木，近端断面画成竖椭圆**（rx27/ry42）。
  椭圆是"这个面斜着朝我"的唯一信号；正圆=正对着我的洞。洞内必须画内腔地面
  （往右上收的浅色楔形），那是"能走进去"的全部证据。
- 浮空台：一块板 → 两根圆木（每根各有受光弧+背光弧，中缝暗线贴亮线）+ 端头年轮。
- 背景：问题不是细节而是**明度骨架**。树冠改五瓣并集、树高 1.5→2.0、
  每棵 ±0.30 色相偏移、中景补 3 根粗树干 + 9 丛灌木、底部加舞台压暗 0→0.22。

**两个 canvas 坑（必须记住）**

1. `blobPath()` 内部有 `beginPath()`。做"多瓣并集"必须加 `cont` 参数跳过它，
   否则画 5 个圆**只有最后一个被填充** —— 画面上看起来完全像"颜色调淡了"，极难反推。
2. `stroke()` 描的是**每条子路径的整圈轮廓**，并集图形的内部弧线会露出来（读作线团）。
   所以并集图形一律不描边，靠明度分层次；要描边就得退回单瓣。

**行尾符雷区**：`prototype/grove.html` 是 LF，`tools/grove-smoke.js` 是 CRLF，
`GroveRuntime.ts` 是 LF。补丁脚本用 `newline=''` 读、锚点必须按各自的行尾写，
否则要么 0 命中，要么整个文件被改写行尾变成上万行假 diff。

回归：14 项结构检查 + 367 项冒烟（新增 8 项钉住"开口/反弹/预瞄一致"）。
提交 `971b634`，已推送。

**未解决（真实状态）**：缺的是**质感**不是分层。继续代码绘制是边际递减；

## 第四轮（11:55-12:15）：删掉两端装置 + 火焰动画

用户三条：①火坑能动起来吗，能像真的一样 ②右下角圆筒太突兀直接出掉 ③左侧那个也不需要。

**结论一：两端的"出口装置"是同一个错误犯了两遍。**
前几版做过四种形态（编筐→拱门→朝左空心圆木→通高树干）。每版都"往画面里加东西"，
而这屏已有平台/坡/坑/木桩/角色五种物件，新装置必须画大才读得出是什么，一大就成
画面体量最大的单体 → "突兀"的机制跟画得好不好无关。

真病根：**把逻辑墙（WALL_L=26/WALL_R=934）当地面边缘来画**。地面块画到 26/934 就收口，
露出"地面到此为止"的断头，于是必须再画封口物去遮。要遮的东西本来就不该存在。
改：地面块画 -20~980，逻辑墙只作碰撞范围；左端判出界改成 `b.x + b.r < -4`（真滚出屏幕）。

**结论二：火坑"像真的"= 四件事缺一不可。**
独立相位（不是等比缩放）/ 亮度闪烁 / 焰舌分离 / **火光溢出**。
第 4 条是分界线：不照亮周围任何东西的光源，眼睛必然判定是贴图。

**三个 canvas 数值坑（重要，下次直接抄）**
1. 光晕必须 `globalCompositeOperation = "lighter"` 加色。普通 alpha 0.26 时
   采样和周围只差 5 个色阶，人眼完全无感。
2. 径向渐变衰减曲线要"平"：0~55% 几乎不掉、85% 后收口。标准三段式在半径 110 处只剩 4%。
3. 光晕用**扁椭圆**（ry/rx≈0.58）：圆形半径 200 会照到 350 层浮空台**上面**去，
   平台不透明，穿过去就露馅。

**方法：验证动画必须连拍，不能看静帧。** 一张好看的静帧和一个好看的循环动画，
在单帧上完全一样。新增 `tools/_fire-seq.js` 连拍 8 帧（0.15s 间隔）→ `shots/fire-seq.png`。

回归 14 项结构 + 367 项冒烟全过。提交 `f6b587e`，已推送。

### 第一版不合格：管线少了两步，不是画得差

放进游戏立刻看出「四只敌人读不出来」。量出来是：AI 水彩边缘渐隐（没有剪影边界）、
彩度偏低（乌鸦 mean 149,128,123，R/G/B 差不到 26）、明度贴着草地
（bug lum 165 vs 草地 152，只差 13，色相又都是绿）。
**旧的三档色代码图形有亮色 c1（lum 178）+ 深墨线，在 34px 下反而更好读。**

> **可读性不是细节密度，是明度差 + 剪影边界。** 这条要记住 ——
> 「AI 出图细节更多」≠「更好读」，小尺寸下常常反过来。

修法（都在 `prep_foes.py`，不换图不重出）：

1. **`outline()` 补墨线** —— 按 alpha 外扩画 `#3A2B44`（= `COL.outline` 同色）。
   不用 `MaxFilter`：方形掩膜半径一大就出直角，虫子的圆肚子变圆角矩形。
   改成「高斯模糊 σ=0.62×ow → 阈值 110 → 再模糊 0.30×ow」= 圆形膨胀 + 1px 抗锯齿。
   线宽 `clamp(vh × 0.065, 1.5, 2.6)` 显示像素 —— **按体高定，不按贴图尺寸**，
   否则小虫子相对线宽粗一倍。
2. **`vivid()` 提彩度** —— 走 HSV 的 S 通道 `pow(S,0.80)×1.45`，**明度一律不碰**。
   `ImageEnhance.Color` 是乘法，S=0.12 的灰紫乘 1.45 还是 0.17，等于没动。
   这一条是踩出来的：先试了全局 Color(1.45) 没效果，才换成逐像素 HSV。
3. 亮度只微抬 1.06。**压暗是错的方向** —— 第一版试 bright=0.97，越压越融。

修正后明度差：+19 / −19 / −28 / +50（全部 ≥19）。

### 结构性错误：vw 从来没生效过

`prep_foes.py` 里写死 `vw/vh`，但 `drawFoe()` 用 `ih = f.h`（**碰撞高**）反算宽度 ——
**`vw` 完全无效**，`vh` 只在恰好等于碰撞高时才对得上。

定规：**`w/h` 是碰撞盒，`vw/vh` 是画多大**，两套值都放 `grove.html` 的 `FOES` 表，
与 `prep_foes.py` 的 `FOES` 表**逐字一致**（那边装框、这边绘制，不一致就变形）。

- 贴图底边必须贴 `f.y`：`yTop = bh/2 - ih`，**不是 `-ih/2`**。
  写成 `-ih/2` 会让视觉更高的敌人往地里陷 `(ih-bh)/2` —— 野猪陷 7px，脚看不见。
- **包裹层（游戏唯一的血条）也要按 `vw/vh` 算**，中心用 `f.y - vh/2`。
  原来用 `bw/bh`，贴图化后环会切进身体里（野猪的血条比它自己小一圈）。

| 敌人 | 碰撞 | 视觉 | 溢出 |

## 雪原：8 套主题里替换掉 swamp，不是加第 9 套（提交 c437dc1）

### 雪地必须开的三个口子（都不是审美，是可见性）

1. **`SNOW_DIM = 0.90`，不用 `GRASS_DIM = 0.80`。**
   `#D6E3F2 × 0.80 = #ABB6C2` —— 一块冷灰水泥，不是雪。
   压暗草地本来是为了让角色跳出来；雪地改由**描边 + 木平台的暖棕**承担分离。
   **只给雪地开这一个口子**，否则会变成"每关都能找到理由调参数"。

2. **树冠积雪**（`drawTree` 的 `!back` 分支，`TH.snow` 才画）。
   雪景最省事的识别特征**不是"地面白"，是树顶那道白边**。
   大块 `blobPath(·, cy−r·0.46, r·0.66)` + 偏心高光 `arc(·, cy−r·0.58, r·0.30)`，
   **不描边**（描边就变成"树冠上贴了块白补丁"，雪是堆上去的、边界是软的）。
   位置比受光面（`−r·0.34`）更高：雪盖的是上表面，不是正面的反光点。

3. **八处派生覆写，集中在 `makeTheme` 循环末尾。**
   `makeTheme` 所有派生都假设"草是绿的、土是褐的"，雪地一条不成立：
   - `hillFar`/`hillNear`/`horizon`：sky2 与 grass 都近白 → 混出白，**远山整片消失**
   - `grassDark = hexDim(grass, .74)` → `#9EA6B2`，**沥青路面**（雪的暗部是背光的雪，是蓝的）
   - `shrub` → **深绿灌木丛**，读作"没扫干净的落叶"（改成冷白 = 雪堆，形状现成）
   - `treeNear` → 淡绿白压成灰绿，"掉漆的树"（锁深绿 #2E5B4A）
   - `treeFar` 混 hillFar 拉到 **0.72**（0.28 出灰绿一片，读作雾霾）
   - 远景树**不往暖金偏**，改由 `hueShift` 决定"这棵树积了多少雪"

### 落雪：纯函数、零状态

不建粒子数组，位置由 `(序号, S.t)` + `hash` 直接算。不占存档、不动玩法断言、
切关不用清场。**绝不能用 `Math.random()`** —— 每帧随机会变成噪点闪烁。

## 机制纠正：是「雪球」不是「连锁」（提交 3bd25cd / 16b86f3）

  └─ 糊满：卷进球里 → 球变大 → 继续滚

**不会撞出第二颗球。** `MAX_BALLS = 2`，注释：「这不是性能限制，是注意力限制 ——
场上 4 颗球时玩家不是在决策，是在救火」。

## 一球能卷几只：数字定数量，不靠感觉（新工具 `_chain-test.js`）

直接跑原型：摆 N 只 + 造球 + updateBalls，统计 `holds`。

| 配置 | 卷几只 | 球径 r |
|---|---|---|
| 一行 3 只（原配置） | 3 | 28.4 |
| 一行 5 只 @ 间距 110 | **5** | 34 |
| 一行 6 只 @ 间距 92 | 6 | 36 |
| 一行 8 只 @ 间距 68 | 8 | **36（封顶）** |

## 出图发现的真 bug：连续卷人叠字

### 删能量门禁：不能只删"恢复"

原 `ENERGY_MAX 100 / COST 20 / REGEN 18s` —— 打 5 趟等 6 分钟，且按离线时间戳结算。

> **只删 `REGEN` 会变成"只出不进，5 趟后永久归零"，比原来更糟。**
> 所以要删就删整套：4 个常量 + `settleEnergy`/`spendEnergy` + 存档字段读写 + 出场 UI。

**连带的坑：三件任务的奖励原来是假的。**
`out/feed/send/pat` 都有"能量 +10"，门禁删了之后再发能量 = 发一个没人用的数字，
**奖励变成空的，比没有奖励更伤**。全换成实际资源（果子/材料/吧唧）。

节奏交给饱食度（每关 −16、饿了火力降、喂一顿花果子）—— 那是**经营**，不是**等待**。

### 雪做成机制：四件都挂 `S.snowDepth`

| 机制 | 数值 |
|---|---|
| 越下越厚 | 90 秒长满（par 是 60 秒，**故意比 par 长**） |
| 敌人冻僵 | −30%（`updateFoe` 七处 `def.spd` 乘 FK） |
| **猫打滑** | 地面摩擦 2600 → 最大 −55% |
| 脚印 | 间距 11px / 12 秒消失 / 上限 120 |

**「球打滑」改成了「猫打滑」。** 球在这套物理里**没有滚动摩擦**
（不撞东西就一直滚），"更滑"没有实现空间。有摩擦的是猫。
> **慢是惩罚，滑是手感变化** —— 后者才是雪该有的物理感。

**90 秒 > par 60 秒是有意的**：第一次打会在雪最厚前过关，重打刷 S 的人才撞上厚雪。
**雪是一趟比一趟更难的变量，不是固定皮肤。**

### 雪机制出图抓到的三个坑（代码看起来对、渲染出来不对）

1. **`arc(π, 0)` 默认顺时针** → 经过 +y（canvas 里 y 向下）= 齿朝下鼓，
   雪画到台面**下面**去了，和背景雪堆灌木混成白疙瘩。要 `anticlockwise = true`。
2. **雪线照草齿画成圆齿 = 花边。** 草皮本身就是一排向下鼓的弧，
   两层齿叠在同一位置谁也读不出是雪。改成**低频起伏（54px 一段）的实心带**，
   比草齿（26px）慢一倍才不会共振。
3. **脚印 `#7E96B8 @ 0.42` 在白雪上只暗 26 级 = 等于没画。**
   用纯红测一次才确认"不是没画，是太淡"。

> **方法：当"有没有画"和"画得太淡"分不清时，先把它画成不可能看错的样子。**

最终脚印 `#A8BED8 @ 0.55`（暗 40 级）。

### 评级落盘：两处存储，一个独立的合并函数

```
pawpack.best            ← grove.html 自存（JSON 数组 8 格）
pawpack.save.v1.best    ← GroveBattle._syncRanksToHome() 合并写回
```

**为什么必须独立于 `_syncProgressToHome`**：那个函数在 `next === prev` 时 early return，
而**"重打一关刷 S"恰好是进度不变、评级变了**的场景 —— 塞进去等于永远不触发。

合并**只升不降**：拿过 S 再打 A 不抹掉 S，否则玩家怕打坏纪录而不敢重打（和重玩动机相反）。
白名单只认 `S/A/B`：存档是外部输入，浏览器里能手改。

### 结算显示 S 线

`送走 10/10 只 · 用时 62.4s / S 线 60.0s（差 2.4s）`

> **62.4s 是个事实，差 2.4s 是个理由。** 原来只报用时，玩家不知道离 S 多远，
> "再来一次"这个念头根本不会出现。

差值只在**超 S 线 20% 以内**出现。阈值用比例不用绝对值 ——
各关 par 从 60 到 135 秒不等，写死 12 秒的话第 1 关很宽容、最后一关永远不显示。

评级旁加「新纪录 / 首次记录」：**S 是绝对标准（一辈子拿一次），新纪录是相对自己
（每关每次都可能）**，30 分钟的游戏里后者才能反复触发。
