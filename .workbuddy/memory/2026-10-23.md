## 主界面宠物：群聚 + 接地 + 原地动作（commit 2e093a8）

用户拍板 D（原地动作）+ A（两帧踏步），并加一条要求：**六只要聚在一起**。

### 查找过程中确认的两条硬事实

1. `HomeRuntime.ts` 的 `startWalk()` 原本**没有调用方**（死代码）。原因写在自己的
   注释里：单帧正面立绘试过横移/蹦跳/走近三种，都读成"滑/撒欢/跳"。
2. 主界面的房子/路标/锅/垫子/栅栏**全在 `bg.png` 里**，不是独立节点。
   所以"场景像贴图"改不了单张图，只能靠叠加层。

### 为什么以前判死、这次能成立

缺的不是缓动曲线，是**接地**。没有影子时任何位移都读成"贴图被拖着走"。
凑齐四件事才成立：影子（不跟 bob）、步频由位移推、梯形速度、原地姿势。

### 关键数值（都是量出来的，不是估的）

- 六张 pet-*.png 画布都 292 高，但 alpha 包围盒内容高：猫 242 / 狗 216 /
  狐 248 / 仓鼠 213 / 牛 225 / 兔 292。**聚在一起会暴露 40% 的身高差**，
  于是加了 `PET_FIT` 表做归一，矮胖角色封顶 1.12。
- 宠物高约 84（内容 70），所以**前后排 y 差必须 ≥ 44**，否则前排头顶压掉后排的头。
- 布局试过两种，3+3 对齐不行（中间那只必挡两侧，白兔只剩耳朵）。
  最终用**锯齿**：x 距 42、y 差 44，占 396~606 共 210px，邻只靠 y 分离。

### 工具坑（会骗人，已修）

`client/tools/_home-rt-shot.js` 的 `--t` 原来只是"把时钟拨到 t 再推 3 帧"，
**任何与时间有关的动效永远停在 48ms**。之前判断"宠物动没动"全是在看第 48ms → 必然静止。
现在真从 0 跑满 t。另加 `--cleared=8`（六只全解锁）和 ellipse 渲染（影子靠它）。

### 未验证

沙箱起不了 Cocos 预览，所有结论来自离屏渲染 + 数值探针（位置轨迹）。
真机手感（帧率、热区跟手）没测过。

## 待办 / 已给方案未做

- 场景"贴纸感"：给 bg.png 加一层 `contact layer`（接地暗部 + 前景草丛），
  再叠加零素材动态（烟囱烟、锅气、蝴蝶、光斑）。**动态比画细更有效**。

## 宠物搬进粉色垫子 + 零遮挡（commit c01af8b）

用户新要求：六只解锁后**在垫子上、派遣牌附近、互相不要遮挡**，可以坐着休息。

### 零遮挡的唯一解法（这条最重要）

垫子可用宽只有 **209px**（x 770~979），六只横排要 350px。
横向错开半只身宽也放不下 ⇒ **只能纵向错开超过整只身高**：
后排 y=532 / 前排 y=600，差 68 > PET_H 60。后排的脚落在前排头顶之上，
两张图**一个像素都不重叠**。这比"错开一点点"的要求硬得多，别再退回 44px。

右边界 979 是被派遣绿牌逼的（牌面 x 979..1107 / y 455..575，是可点热区）。

### PET_H=60 是推导值

前排三只（砂糖 0.864 + 团子 1.277 + 豆奶 1.053 = 3.194 身高单位）
必须装进 209−2×缝。H=66 → 210.6 就贴住了。想放大宠物只能换更大的垫子，
调参没用。

### 尺寸统一的坑（这次才暴露）

Home.scene 里六个 UITransform 是历次手调留下的：
53.7×84 / 108.9×148 / 110×138 / 55.8×128 / 120.5×138 / 73.3×112。
**既不等高也不等比**：雪团被横向压窄 40%，年糕是砂糖的 1.76 倍高。
以前散在 1300px 草地上看不出来，坐到一块立刻"大小不齐 + 变形"。
正确做法：按 alpha 包围盒的宽高比重设 contentSize（`PET_ART` 表），
六张图内容都贴底（bottom-gap=0），所以脚底自然落在锚点上。
旧的 `PET_FIT` 表（假设节点都是 84 高）已废弃删除。

### 走动关掉了

`PET_WALK=false`。位移和"不遮挡"直接冲突。生气交给原地姿势：
坐 0.84 / 趴 0.74（上一版 0.94 在截图里根本看不出在坐），
坐+趴权重 64%，坐的时长 2.6~5.2s，活动类 0.9~1.8s。
影子 alpha 92→110，宽度随 `sx` 变化 50%（跟满就成水渍）。

### 布局改成函数

`layoutPets(names)`：1~3 只单排居中、4~6 只两排（按原顺序奇偶分排）。
写死六个坐标的话，只解锁一只时它会站在最左边。

### 工具

- `_home-rt-shot.js --dbg`：打印每只的设计坐标/尺寸。调布局靠目测截图
  会一路调错（这次就是靠它发现群整体偏左 35px）。
- 渲染图是 **1280×720，1 像素 = 1 设计单位**，可以直接用 PIL 量垫子边界
  （粉色连通块 bbox），不用换算 bg.png 的像素坐标。
- `_rt-check.js` 修了 4 条过期断言：静止 scale 恒定（现在有姿势）、
  草地上只有一只（现在已解锁全在场）、出门文案（"能量 N"→"N 只 · 饱食 X"）、
  点遮罩关面板（closeSheet 走 queue，不推一帧永远读到没关）。
  现 58 项全过。

## 画面质感：把"贴纸感"当画面级问题处理

用户原话：「主界面和战斗内 美术感偏弱 都像贴图 比较假」。

### 诊断（这份拆法以后可以复用）

单物件都在及格线以上，问题在**没有被同一个镜头拍下来**，五条根因：
① 没有接触（硬边纯色影子）② 明暗没有全局方向 ③ 没有全局暗部
（每件都取合理中间调 → 没有一处是暗的）④ 没有空气（清晰度全一致）
⑤ 没有材质（零噪声 = 一眼矢量）

### 做了什么

- 战斗 `grove.html` 新增 `drawPost()`，在**所有内容之后**（含 HUD/结算卡）
  跑五道 pass：泛光 → 提对比 → 分离色调 → 颗粒 → 暗角。
- 影子统一朝左下（角色 `w*0.15`、平台 `-9px`），改径向渐变 / 三层柔边。
- 前景灌木画到离屏 canvas，叠回 `blur(2.4px)`（焦平面）。
- 主界面烤一张 640×360 `resources/ui/post-overlay.png`（暗角+颗粒），
  `HomeRuntime.attachPostOverlay()` 挂到最后。

### 踩到的坑（都会重犯）

- **泛光 alpha 是最难调的一个数**：0.46 整屏蒙奶油色；0.18 完全看不见
  （实测泛光层均值 27/255，screen 后草地只抬 0.007）。最后按主题分档
  0.38 / 雪原 0.28 / 夜关 0.20 —— 因为泛光强度实际取决于"画面里有多少
  接近白的东西"，雪地和月光会整片溢出。
- **冷调不能用 multiply**。蓝×绿=灰橄榄，下半屏草地直接脏。分离色调
  两层都用 `soft-light`（暗部推色、亮部几乎不动）。
- **canvas 的 `filter` 只能作用在 drawImage 的源上**，不能对已有像素施加。
  想给整帧提对比，只能整体 copy 一次再 drawImage 回来。
- **mock 的 resources.load 回调在第三个参数**。写成
  `typeof type === 'function' ? type : cb` 会把 SpriteFrame 类当回调调用，
  报 "Class constructor cannot be invoked without 'new'"。
- `tools/tsconfig.all.json` **从来不是全绿基线**（1573 个 error，都是
  HTML 抽取代码没类型标注）。别拿它当验收，用 `grove-runtime-check` +
  `grove-smoke`。

### 验收

grove-smoke 377 / grove-runtime-check 14 / _rt-check 58 / verify-scene 17，
全过。对比图 `shots/quality-0{1,2,3,4}-*.png`。
方案文档 `client/docs/PAWPACK-画面质感-分层方案.md`。

### 老实说：这一轮解决的是"色调/氛围"，不是"结构性的平"

剩下的按 ROI 排序（文档里有表）：
1. 背景本体纹理密度（草地 90 撮 alpha 0.1 太淡）—— 不用美术
2. 角色立绘与环境的色彩融合（立绘比背景饱和一档、对比高一档）
3. **UI 卡片**：白描边矢量和手绘水彩背景是两套语言。这条不做，
   前面五条的效果会被它吃掉一半。

### 遗留（未提交）

`assets/ui/home/bg.png` + `tools/bg-erase-sign.py` 是上一轮"擦掉背景里的牌"
的半成品实验，用户当时中断了，**故意没有提交**。

## 动感补课：尘土层 + 宠物嬉戏（提交 cfa8a98 / 435b80f）

用户追问："动感呢？特效呢？宠物嬉戏呢？敌方移动不自然你处理了吗？"

### 盘点结论（先盘再做，避免重复造）

敌方步态**早就重做过了**（伸→缩→顿三段、每只错相位、频率按物种分档），
命中碎片/飘字/压扁、撞墙木屑/震屏/方向字都有。真缺的是：
①球落地无尘 ②滚动无尘 ③敌人被卷走瞬间消失 ④PET_WALK=false 全程静坐。

### 战斗尘土（addDust/drawDust）

画在前景后、单位前（尘土属于地面）。落地按 _fallVy 给量、
滚动 0.07s 一粒出在球后脚跟、裹球/被卷走各一蓬。

**本会话最大的坑：视觉特效严禁消耗 rand()（固定种子 S.rng）。**
尘土挂在落地/滚动高频路径上，每粒吃一次随机数，整局 AI/掉落序列全变，
"150 秒清场"冒烟断言直接超时。addDust 一律 Math.random。
absorbIntoBall 里加 addFrag 同罪（那条路径原来不消耗随机数）。

探针法验证粒子：vm 载入 grove → 手工塞球 → 数 S.dust.length。
（探针里别写 `while(...) expr?0:0` 这种假循环体，死转 3 分钟。）

### 宠物嬉戏（HomeRuntime.ts）

PET_WALK=true、PET_ROAM_R 6→20。不遮挡靠：领地绝对（slot±20 不累积）+
剧本落点预计算（追逐停点=贴边外 10px）。三剧本：追逐（62/92px/s 快慢差）、
扑跳（蹲0.26/腾空0.38抛物线15px/落地0.30）、蝴蝶引导扑。
setWalkTarget() 抽出共用位移管线——剧本另写移动必打滑。

**过期断言要跟着需求改**：_rt-check 六条"站在原地/脚不离地"是
PET_WALK=false 时代的防抖回归，需求反了就得改写成新不变量
（会走、不越领地、影子钉地不跟跳）。改完 57 项全过。

### 实测事实

**--cleared=6 是"4 在家 2 派遣"**，六只全在家要 --cleared=8。
之前拿 6 当"六只全解锁"截图，豆奶/星屑一直没出现在画面里（还没发现过）。
未绑定的宠物保持场景原始位置和旧 contentSize（豆奶 120×138、星屑 73×112），
别把它们当布局 bug 查。

## 推球：野猪「原地抽动」+「开局卡木桩」（两个不同 bug，同一个观感）

用户报「敌方小猪一直往前面抽动，像抖动」「开局卡在木头那里半天」。
查下来是**两件不相干的事**，都定位到了具体行。

### 一、抽动 = 步态相位被累加器拖着跑

`drawFoe` 里 `cyc = (S.t + f.bob) / stepT`。`f.bob` 出生时是随机相位种子（0~6.28），
但 `updateFoe` 每秒给它 `+3.2`（乌鸦悬停 `sin(f.bob)`、BOSS 呼吸要用这个累加值）。
→ 相位实际以 `1+3.2 = 4.2` 倍速推进：野猪 `stepT=0.45` 本该 2.2 步/秒，**实测 9.83 步/秒**。

一个周期本来是「伸 34% → 缩 16% → **顿 50%**」，后半段完全静止才是「一步」能读出来的原因。
提速 4.4 倍后一帧静止都没有 → 只剩「在抖」。

修法：出生定死 `f.ph`（新字段），绘制用 `S.t + f.ph`。实测 9.83 → **2.21 步/秒**。

**通用教训**：视觉相位/偏移**不能借用任何会被每帧累加的字段**。同一个对象上
「累加器」和「种子」必须是两个字段，混用不会报错，只会让参数悄悄偏离设计值 4 倍。

### 二、卡木桩 = 出生点和木桩坐标完全重合

第 5 关「弹跳林」：`stumps: [{x:650, y:350}]`，而 `waves[1]` 也写 `{foe:"boar", x:650, y:350}`。

`stepBody` 的木桩判定是「重叠就把人顶到桩外侧」，而 charge 分支每帧
`f.face = sign(p.x - f.x)` 重写朝向 → 顶出去 → 下帧又朝玩家（即朝桩）走 → 又被顶回同一处。
结尾的 `if (f.hitWall) f.dir = -f.hitWall` 翻的是 `dir`，**charge 分支根本不读 dir**，救不了。

实测：8 秒 480 帧 `x` 恒为 700（= 672 + 半宽 28）、`hitWall` 帧帧 -1、**一步没动**。

修法：① 出生点挪 580；② `foeFromSpec` 末尾加 `nudgeOutOfStumps(f)` 通用脱困，
朝玩家那侧推（推到背后等于原地转圈）。
**BOSS 必须排除** —— 把 BOSS 从 700 挪到 623 后，它五发弹幕有 4 发直接撞进平台，
smoke 里「扇形张开」两条当场红（spread=0.00）。

### 三、贴身时朝向 30Hz 翻转

`f.face = sign(p.x - f.x)` 没死区。玩家站在它身上时 `sign` 逐帧翻号，
`g.scale(f.face,1)` 整体镜像跟着抽 —— 实测 x 在 `514.02 / 514.62` 之间每帧来回 0.6px。
加 8px 死区（贴到 8px 内不再重判朝向）。
