## 飞行怪「抖」的真凶：朝向逐帧翻转（2026-10-27，`f2fb5ef` + `afa027e`）

用户报：「上下跳动有些奇怪，**抖动很严重**」。截图里红框圈的是主线乌鸦（`crow`，`#A98CF0`）。

**先做量化工具，再改代码** —— 这一步救了我，否则会照着直觉改错地方。

### 工具（都已入库）
- `client/tools/_hover-trace.js`：逐帧采 y 画 y-t 曲线，三个指标
  （抖动强度 = 二阶差分 RMS / 包络起伏 = 逐秒峰峰值 max/min / **朝向翻转次数**）。
  两条对照曲线必须**固定 `f.bob`/`f.ph`**（出生是 `rand()`，不固定就错开半周期，
  看图的人会以为形状变了）。
- `client/tools/_face-shot.js`：把朝向翻转拍成两行 × 8 格连续帧（每格 0.1 秒）。
  行 A 每帧手动 `f.face = sign(dx)` 复原旧写法。

### 真凶
```js
f.face = sign(dx);              // updateFoe 的 fly 分支，无条件写
```
乌鸦 `|dx| < 40` 时速度降到 0.15 倍（13.8px/s，**一帧 0.23px**），
贴到玩家脸上后它在 `dx = 0` 两侧来回微穿越，`sign` 跟着翻 →
**约 60Hz 的极限环**。实测：0.8 秒翻 48 次（几乎每帧）、8 秒 83 次。
翅膀 1.9Hz 拍动 + 每秒 10 次镜像翻转 = 抽搐。

修法：`if (Math.abs(dx) > 26) f.face = sign(dx);`
26 远大于一帧位移 1.5px，只有真绕到另一侧才转身。

### 同时删掉的重复位移
`drawFoe` 里 `g.translate(cx, cy + Math.sin(f.bob) * 2.5)`。
飞行怪的 `f.y` 本来就每帧由 `homeY` 算正弦，绘制层再叠一个**频率不同**的 2.5px
→ 两个近频正弦打出拍频。**位置只该由物理层决定一次。**
（那个 2.5px 的本意是给"静态贴图"补动感，代码图形不该吃。）

### 巢蛾悬停重做（用户"你要针对怪物设计"）
慢气流浮沉 11px（0.26Hz）+ **单侧**扑翅上冲 1.4px。
第一版给 3.6px / 1.7Hz，实测抖动强度 **0.1386，是乌鸦的 6 倍** —— 那不是飞是抖。
且只取正半周：真蛾子拍翅只往上顶，对称正弦读起来就是抖。
蛾的光晕也从 `litOn` 布尔改成平滑量 `glowK`（150px 硬判边界会让光晕啪嗒闪）。

### 我自己被曲线否掉的一次改动（重要教训）
先凭直觉把乌鸦 `18·sin(φ)` 改成 `18·sign(sinφ)·|sinφ|^2.1`
（想把 80% 时间挤到 ±9px，读作"停在某高度、偶尔下沉"）。画成曲线一看：
**纯正弦是圆滑的波，平台版是方波** —— 平台段 + 陡峭过渡比匀速正弦更像"跳"，
指标 0.0229 → 0.0464。**当场回退。**
→ **改美术问题之前先画曲线，不要凭手感改公式。**
→ 乌鸦摆幅 18 是**玩法参数**（注释里记着收窄会毁掉第 8 关机器人），一像素没动。

### 两条通用的坑
1. **采样率低于信号频率时，统计出来的永远是 0。**
   `_face-shot` 第一版"翻转次数"数的是 8 个采样点之间有没有变脸，
   采样间隔 6 帧、信号约 60Hz → 混叠成 0，明明在抖却显示"两行都是 0 次"。
   必须在内层循环**逐帧**比。
2. **复现病态要摆到触发条件里**。第一版把乌鸦放相隔 80px，两行都 0 次 ——
   80 在死区外，旧写法也稳定，等于什么都没验证。必须放到 `dx ≈ 0.4`（贴脸）。

## 砍掉跳虫：同一种外观不许有两种行为（2026-10-27，`f4b81dc` 已推送）

玩家原话：「这种敌方我不需要可以跳，而且走到最左边还会抖动。」

**跳虫是什么**：`f3b0a83` 加的设计 —— 主线刺毛虫里约 1/3（`f.ph < 2.09`）
被就地升级成"会追人、会往上一层扑"，靠头顶一个橙色感叹号三角区分。
**外观完全一样**（截图里圈出来的那只恰好不是 jumper，头上没三角，
但玩家圈的是"这种虫"）。

### 砍的三条理由
1. **不可教**。玩家没法从长相推出会不会跳，只能把每只都当会跳
   → 每一只普通怪都变贵了。这不是难度，是把所有普通怪的成本一起抬高。
2. **左端来回蹭**（"走到最左边还会抖动"的根因）：
   8px 死区判朝向 + 速度 66px/s（一帧 1.1px）→ 贴脸后 face 卡旧值继续朝墙走
   → 撞墙 `wallT=0.45` 强制背离 → 走开 26px 又因死区没解除而转身撞回来。
   `_left-jitter.js` 量化（第 5 屏左端台面，6 秒）：
   | | x 范围 | 速度反向 | 撞墙帧 |
   |---|---|---|---|
   | 跳虫 | 43..117（73px） | 9 次 | 127/360 = 35% |
   | 刺毛虫 | 57..382（325px） | 1 次 | 0 |
3. 它想补的结构性缺失（"跳上台面就绝对安全"）该由关卡目标和武器回答，
   不该由一只伪装成普通怪的怪回答。

### 做法
`f.jumper = 0;` + 一大段注释（写明三条理由 + 保留状态机的原因）。
状态机全部保留（crouch→pounce→landT / `pounceLands` 预演 / 蹲身压扁 /
脚下脉冲环 / 抬头标记）—— 它是干净的"预告-可躲-可反击"实现，
将来做成独立剪影的怪种时把赋值换成按 `sp.foe` 判定即可。

### 守卫
`grove-smoke.js` 新增反向断言「跳虫不出场」：2000 次 `foeFromSpec` 计数必须 0。
**已做反向验证**：临时恢复旧表达式 → 当场报 `650/2000`（正好 1/3）。
→ 又一次印证：**断言必须做过"能红"的验证**，否则不知道它是不是在测空集。

### 副作用是好的
**ALL9 从 1486 项 / 失败 4 条 → 1491 项全绿。**
原来那 4 条红就是跳虫拖出来的（多处理一只会跳的怪，某几屏清场余量不够）。
→ **"玩家嫌它烦"和"机器人跑不动"往往是同一件事。** 机器人基线可以作为
"这条机制是否超出玩家操作预算"的代理信号。

### 教训
- **同一种外观不许有两种行为**。要加第二种行为，先给它第二个剪影。
- **靠头顶图标区分行为 = 承认外观没表达清楚**。图标是补丁，不是设计。
- 死区救不了极限环：死区只推迟穿越，不消除"贴脸时每帧都可能跨过 0"。
  真正要修的是"撞墙后不许立刻回头"（`wallT` 有做），但 `wallT` 结束后
  边缘规则又把它送回墙边 —— 规则的**出口**没设计好，加多少死区都会循环。
