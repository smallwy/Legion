### 评审中被修掉的四个洞（这几条别再让它们回来）

1. **子弹若能杀怪，球就没戏份**。玩家会算 DPS 然后用子弹（更远、更安全、更多）→
   已立为第 5 条硬规则：吐雪只加雪层、裹住的敌人无敌、击杀只有球一条路。
2. **「打箱掉弹」是自我循环**。木箱 12～15 发、只掉 0～2 发；**球砸碎的才掉 3～5 发**。
   价值差写在掉落上，不靠调概率。
3. **门随机藏在某口箱里会退化成扫图**（见箱就砸，砸完没找到就骂设计）。
   正解：**门可见、被箱墙挡住**；只有"子弹砸不动"的材质才可能是门位，「砸不动」本身是线索。
4. **系统刷补给箱是伪兜底**（玩家学会故意打空 + 掩盖数值问题）。
   用现成的**近身撞敌零耗造球**（`coatFoe` / 冲刺撞）当保底，代码几乎不用改。

## 六点对齐后的定稿值（同日，commit `7706d0f`）

用户逐条确认，最终落进 §2.7：

| 机制 | 定稿 |
|---|---|
| 木箱 | 子弹 **2～3 发** / 球 1 下。**砸碎不掉弹、只掉收成** |
| 石箱·铁箱 | 子弹**完全无效**（冒火花、不留痕），只认球 |
| 冰墙 | 子弹只掉冰渣；**只认特大球或高速球**，判据 = **球径 × 速度** |
| 球体积 | 四档按卷人数（0~1 / 2~3 / 4~5 / 6），**每档换外观** |
| 箱子 | **可堆**，当空间材料；**必须挡子弹** |
| 箱内容物 | 收成（必掉）/ 雪之碎片（球砸 40%、子弹砸 10%，补 3~5 发）/ 弱怪 10~15% / 炸弹 / 门 |
| 炸弹箱 | 可预判、不炸死（扣 1 血）、连锁两跳、**门免疫**、被炸箱不掉弹 |
| 门 | 位置**关卡设计定死**（裸露 / 墙挡 / 藏指定箱），不随机；未达成一律红锁 |

**最关键的一处修正**：用户原本让木箱「2～3 发碎 + 掉 3～5 发」，那是**净赚**，
弹药永不枯竭、稀缺感与保底同时失效。改成"砸碎只掉收成 + 雪之碎片按概率（球砸 40% / 子弹 10%）"，
价值差靠 4 倍概率拉开。

**连带结论：逼玩家用球的职责不能交给木箱**（2～3 发成本太低），只能交给石箱 / 铁箱 / 冰墙。
木箱只负责"教"（球更快、掉更多）。**关卡设计里控制箱子密度，才是"子弹拆箱够不够"的唯一调节阀。**

### 这一轮踩到的四个 bug（都是"看起来能跑、其实毁体验"的类型）

1. **`stepBody` 的顺序错了会让人瞬间传送到场地边缘。** 站在地面上的身体，包围盒和地面
   平台永远重叠（`y+h` 比平台顶低一丁点）。先做水平碰撞的话，水平轮把它当撞墙，
   按 `vx` 的符号推到 `s.x + s.w` 或 `s.x - o.w`——也就是**场地最左/最右**。
   所有怪第一帧瞬移到 x=902 挤成一堆。**正确顺序：先垂直分离，再水平分离，
   水平轮跳过 `o.y + o.h <= s.y + 2`（站在上面）的块。**
2. **子弹命中判定不能分两轮（先怪后箱）。** 那样怪站箱子后面照样被打中，箱子等于没挡子弹，
   「先清怪再推球」永远比「一箭双雕」省事。要**收集所有候选、取 x 方向最近的那个**。
3. **`g.strokeStyle = undefined` 不会报错，会沿用上一个颜色。** `drawBall` 里写的是
   `b.snowballEdge`（球对象上没这个字段），于是四颗球全戴上了门的锁红描边，
   看起来像"快散了"。**canvas 的无效赋值是静默的，这类错只能靠出图发现。**
4. **静止时被挤进实心块里会永久卡死。** 水平分离只写了 `vx>0` / `vx<0` 两条分支，
   `vx=0`（箱子塌下来砸在站住的玩家头上）两条都不进。要补"按最近的边顶出去"。

### 布局与数值上的硬约束（改关卡前先看）

- **地面散箱会同时挡路和挡枪。** 箱子必须挡子弹是设计，但箱子和怪挤在一起时，
  那只怪就变成"打不着"，只能贴脸换血换。**箱子挡枪必须是玩家能绕开的挡，不能是死结。**
  现在地面只在起点右侧留两口（96/144，当第一课），其余全放台面上。
- **箱子之间不能重叠。** 756 那只最右伸到 804、和箱墙的 792 叠了 12px，
  结果箱墙上面的箱子有一只角搭在散箱上，砸掉底箱也不塌（物理对、布局错）。
- **弹药 100 在 8 怪 + 12 木箱的密度下是"刚好卡住"**：8×6 + 12×3 = 84，剩 16。
  但玩家会用球砸箱（不耗弹），所以真实玩法里弹药是宽裕的——**真正的成本是"搓球的时间"，
  不是弹药数**。这条要靠手感验证，纸上定不了。
- **6/4 是倒挂的**（饱的时候反而更费子弹），代码里写成 `NUM.snowShots` 显式表，
  HUD 实时显示当前档位发数，跑完就能判断要不要改。
- 可达性断言必须"先砸光箱子 + 只留被测那只怪 + settle 前就清零速度"，
  否则会报出假失败（被挡枪 / 被邻怪撞飞 / 随机巡逻位置抖动）。

## 单屏 → 三层纵深（commit `923739f`，用户第 2 轮反馈）

用户原话：「箱子明显不够，空间设计感太简陋，达不到探索性的高度，只能体会到一颗球在砸一个箱子」

### 诊断比方案重要

**不是箱子少，是所有东西摊在一个平面上。** 960×600 里箱子、怪、门互相全可见，
没有"里面"就没有探索 —— 再加箱子也只能加出"更多一颗球砸一个箱子"。

### 现在的结构（世界 960×1560，屏高 600，镜头只跟纵向）

| 层 | y 范围 | 内容 |
|---|---|---|
| L3 地表 | 100–480 | 出生点。往右一段就撞箱墙，唯一出路是砸开脚边那排覆霜木箱 |
| L2 中层 | 520–1000 | 主战场。4 处高台错落 + 三层箱塔 + 第二个洞 |
| L1 底层 | 1060–1500 | 黑暗洞窟（越深越暗、光只跟玩家）。冰墙封门，门**藏在一层冰封圣箱里** |

**"霜"是唯一的视觉语言，三层各用一次、规则递进**：覆霜木箱=下面能挖穿 /
冰墙=子弹完全无效 / 冰封圣箱=里面有门。不看 UI 也能学会。

天空画在**世界坐标**里而不是固定屏幕上 —— 下到地下天就自然没了，这是"深"的一半。

### 门的新规则（推翻了上一轮"门可见被墙挡"）

位置仍由关卡定死（不随机），但**藏起来**：外面 2×2 冰墙 + 里面一层冰封圣箱，
砸掉最后一口才露出来，露出瞬间闪光 + 飘"找到门了"。
实现是 `doorBlocked()` **直接问"门这块地方还有没有活着的箱子"**，不维护 hiddenBy 引用
（箱子会塌落、会被连锁砸碎，引用很容易失效）。

### 球砸箱必须变大（用户要求，同时也是死局兜底）

`NUM.ball.absorbBox = 2.0`（吸一只怪是 1.0）。这条不只是手感：
L1 放 4 口普通木箱专门喂球，**玩家把怪清光也能把球喂到大档去破冰墙** —— 没有它，
清光怪 = 永远停在最小号球 = 破不了冰墙 = 卡死。

`killTarget` 8 → 3，且 **必须 <= 底层怪数**。单向关卡掉到底就上不来，
门槛高于底层存量 = 门永远开不了。底层放 3 只。

### 这一轮踩到的五个 bug（前两个机器断言全绿，只有出图能看出来）

1. **填洞的盖板箱"左右夹住"才算支撑。** 盖板是嵌在缺口里的，箱底 528 和平台顶 480
   根本不同高，`abs(b.y+b.h - s.y) < 2.5` 对它们全部失效 → 三口盖板一开局整排掉到中层，
   地表凭空多出一个大坑。
2. **支撑判定不能给水平容差。** 792 和 840 两列是肩并肩的（792+48 = 840），容差一开
   就互认"我在你上面"，砸掉底座上面那格赖着不掉，箱子塌落整个失效。
   **接触和重叠是两件事**：只有"夹住"那条可以认接触，其余必须严格重叠。
3. **球越大球顶越高，会被矮平台挡在门外。** r=46 时球顶 1408，L1 那些 1400 的平台
   正好把大球拦在冰墙前 —— 而破冰墙恰恰只要大球。平台抬到 1380（底面 1398，留 10px
   滚道），同时离地 120 玩家（跳高 123）照样跳得上。**平台高度是被"球要能滚过去"倒推的。**
4. **怪会顺着台边一层层走下来把上面走空。** crawler 从 (740,826) 走到 (801,826) 后掉层，
   最后全场怪聚在洞窟底，上面两层变成空台子。加台边折返（`groundAt` 探前方 40px）。
5. **大球从"地面-30"出生时球底比地面还低 16px**，第一帧被判成"侧面撞地面"原地反弹。

### snowlab 美术重做（岩室 / 雪坡 / 洞光 / 箱阶）—— 提交 dc5dcbd

用户："斜坡在实际中肯定是不合理的，需要自然，你甚至都可以用木箱子作为路况，
背景设计肯定你要设计商业化的效果"。四条落地：

1. **斜坡的硬约束**：上沿那条直线就是碰撞面，**弧度一改人就浮空/陷进去**。
   所以"自然"只能从别处来——雪层厚度起伏、坡面雪堆、坡脚积雪、岩体层理。
2. **`rise > 0` 是"右端更高"**，低端在左（x0）。这条判反过一次，
   两段雪包的积雪全堆到顶点，山坡正中一道白弧像张嘴。
3. **canvas 没有 blur，软边靠叠**：体积光用 7 层由窄到宽的梯形叠加；
   一整个梯形填上去边是硬的，像贴了张半透明色纸。
4. **标准 ellipse 读作"污渍"**，远景岩块必须用抖过顶点的不规则多边形。
   等距等大的雪堆连起来像"一串珠子"，比不加还假。

**判据要按"此刻的状态"算，不能按"初始配置"算**：洞口的光原本查
`h.cover`，那是生成时的封法，砸开之后不变 → 挖穿了却一点光都不漏。
改成渲染时查洞口上还有没有活着箱子。

**先算后放，又一次**：箱阶（用箱子砌的路，高封顶 2 格 96 < 跳高 123）
必须排在随机平铺之前，否则四连格同时空只剩 3%，永远落不下来。

**出生点 x 要提前算**：原来放在最后一步，⑥ 放怪时不知道它在哪，
开局有怪站在玩家 30px 旁，一进关就掉血——只有放大出图才看得见。

### 「箱子很少」的根因是结构约束，不是概率

三代方案依次失败，每一代都以为是概率给少了：

1. **孤岛摆坨 + 强制间隔 2 列** → 20 列只放得下三四坨。
2. **随机游走** → 遇到地形列被重置成 0，夹一个平台要好几列才爬回来。
3. **对称分布 ±2 独立随机** → 在 0 下界反复反射，箱数均值 41.7。

最终解：**先建列模型，再每列独立随机，再统一削坡**。
关键三处：

- 每列高度取 `pickOne([0,1,2,2,3,3,3])` —— **多给正项**，专门抵消 0 下界的反射。
  少数负项只会把均值压回去，不会让分布更自然。
- 独立随机必然出现 `[3,0]` 断崖，所以最后跑 10 轮"高差 ≤2"修正，
  **优先抬高低的一边**（抬不损失箱子，削会）。
- 洞口盖板列用 `LOCK` 保底，削坡不许把它削没。

结果：一关平均 114 口，每层 min 12 / p25 25 / 中位 28 / max 43，200 种子全过。

### 「箱子能当路」是三条算术，不是手感

峰值 ≤3 格 = 144px（站上去头顶 186 < 净空 200）；相邻列高差 ≤2 格 = 96px（< 跳高 123）；
站在箱堆上回不了上层（恒差 82px）→ 关卡天然单向下行。
这三条现在是校验器里的不变量（9~12 条），不是注释。

### 这轮踩的八个坑（全部只有出图能发现，断言全绿）

1. **石箱的"石纹"画成 `^` 折线 = 向上箭头。** 48px 的箱子里，
   `moveTo → lineTo 上 → lineTo 下` 就是一个正正经经的箭头，一整排石箱像一排路标。
   石纹只能用**低透明度斑块**。
2. **HUD 两串字叠在一起，是因为我改了一处忘了另一处。** 饱食度档位文字画在
   `bx+162=322`，体力挪到 344、圆点从 396 起 —— 完全覆盖。缩略图上是"满泡体每只"+红点。
   顶栏 8 个字段的可用宽度是固定预算，改任何一格都要重算全场。
3. **地表层的天花板是天空，却还挂着旗子/吊灯/绳子。** 半空飘一面红旗，
   像删不掉的 UI。池子必须按层切：`k===0` 只从地面件抽。
4. **出生点清箱在最后一步跑，把整整一列的箱子删掉**，而怪和装饰早按过期的
   `colTop` 摆好了 → 地表两个路牌悬空 140px。
   **凡是"后面还会改数据"的生成，前面算出来的派生量都会过期。**
   修法不是补丁式重贴，而是把改动整体前移到消费方之前。
5. **雪球是"白→浅蓝"渐变，地表是暖白** —— 最小那颗在草地上等于隐身，
   四档对照图只能看见三颗。**浅色实体放在浅色背景上，描边是唯一的存在感。**
6. **同心圆当档位标记读作雷达波。** 换成黄金角撒的雪团颗粒（位置由 i 决定，
   不会每帧跳，外层 `g.rotate` 已经让它跟着球滚）。
7. **孤坡土包 96×64（34°）成对拼成一个尖顶 = 三角屋顶。** 摊到 120×44（20°）。
   试过 132：地形按"列与包围盒相交"吃列，多吃一列就让两个种子的箱子掉到 11 口判红。
8. **出图工具自己会把图画错。** clear 场景只破 `mat === 'ice'`，
   而门厅的喂球箱有概率正好压在门的格子上 → `doorBlocked()` 为真 →
   HUD 显示"门·未找到"、结算面板压根不出图。
   **验收图不对时先怀疑工具，别改产品代码去迁就它。**

### 顺手的几条

- 土体加三条水平层理线（只 `h > 40` 时画），坡才有厚度感；薄楼板里塞三条线像划痕。
- 土包/平台/石箱色都压暗一档，让"80% 是木箱"这件事读得出来 ——
  占比低的材质不该比主材质更抢眼。
- 地表装饰避开出生点 70px（路牌左右各伸 26px，贴着人放像角色举着牌子）。
- 出图工具新增 `S.showMeter` 开关：量具面板压在右上角浮台上，
  跑原型要留、给人看设计图要关。图名从 `f1..f8` 改 `floor1..5`（层数 3~5 随机）。

## 能上能下 + 球撞箱不变大（提交 9f91487，已推送）

用户两条：「玩家没办法跳到上一层 设计上需要考虑」「球撞击箱子 应该不会变大吧」。

### 球撞箱变大是捷径，不是机制

`absorbBox: 2.0` 意味着一关一百多口箱子里砸三口就从小球到特大球。
冰墙（要求 tier 2）直接形同虚设，「裹住敌人」这个核心操作被完全绕过。
改成 0，体积唯一来源是**吞掉敌人**（裹住算，被球碾死也算）。

`absorbFoe` 同时 1.0 → 2.0：档位阈值 2/4/6，门厅只有 3 只怪，
1.0 的时候门厅根本攒不出能破冰墙的球 —— 那是数值上过不去，不是操作问题。

**"杀光怪会不会卡死"这个问题不需要箱子来兜底**：杀怪本身就在喂球。

### 上行：数字够 ≠ 走得通

层高 240、净空 200、玩家 42、跳高 123。3 格箱顶 144 + 123 = 267 > 240，
账面上跳得上去。但**上一层地板在洞口处是镂空的**，玩家跳上去落点正好
在洞里，原样掉回来。实测"跳 + 空中横移"81 次成功 7 次。

结论：这不是难度，是动作没做出来。要靠三件事同时成立：
1. 生成侧在每个洞口正下方留一列 3 格（井梯）——原来是 `MAX0[i] = 1`
2. 一列做梯、其余只垫 1 格（全垫 3 格会让"挖穿"变成"挖穿还挂在半空"）
3. 物理侧按 W「爬」上去（`wellClimb`），不是跳

**"跳不上去就加跳高"是错的方向** —— 那会推翻层高/坠落/镜头一整套参数。
正确的做法是承认"洞口是竖井，该爬不该跳"，然后把它做成梯子。

### 这一轮的坑，全是"看起来对、跑起来不对"

1. **`floor(h.x/48)` 取到的列可能有一半在地板下面。** 洞口从 360 起、
   列从 336 起时，玩家站上去头顶正好顶着上层地板，一跳只升 14px 就被打回。
   要用 `ceil` 往洞里收。
2. **硬性 3 格列 + 0 格邻居 = 削坡永远削不平**（144 > 跳高 123），
   200 种子里 149 次红。修法是让削坡能把"敞开的洞口列"抬到 1 格
   —— 敞口洞上多一口能砸的木箱，卖点没变。
3. **门厅不能做井梯。** 门壳和 5 口喂球箱占掉八九列，那些必须是 0 格。
   最后一层是终点，不需要回去。
4. **`upper - feet` 写成负的，整段永远跳过。** 玩家在下一层，feet 比 upper
   大，应该是 `feet - upper`。改完发现"怎么还是没生效"时先查符号。
5. **扒边的 vy 判据写成 `≤ 60`**，于是玩家刚踏进洞口往下掉的第一帧
   （vy 只有 35）被判成"上升中"，被扶回地板 —— 永远掉不下去。
   必须 `≤ 0`。
6. **断言按住 W 六十帧**，玩家爬上去之后接着跳，跳完落回洞里，
   看起来像"爬梯失败"，其实是测试自己按着不放。

### 可发现性也算功能

玩家看到的只是"一列顶到天花板的箱子"，光看图不知道按 W 能爬。
所以加了一个**只在真能爬时出现**的「W ↑ 爬上去」提示气泡 ——
常驻提示会变成噪音，按需出现才是教学。

### 补一刀：气泡画在头顶会越界（42d5cbe）

「梯顶离天花板只有 14px」不是形容词，是算术：净空 200 − 梯 144 − 身高 42 = 14。
气泡高 23 还要留边距，所以"画在头顶"在爬梯这条路上**必然**跑进上一层房间，
看上去像楼上有人喊话。改成先量净空（量到**楼板底面** `floorY + GEN.thick`，
不是楼板线），够 38px 才画头顶，不够就翻到身侧。
没选画在脚下：脚下就是梯子那口箱子，气泡贴上去像箱面的标签，语义指反了。

**顺带踩到的坑**：想临时裁图放大核对，直接 `cat > client/tools/_crop.js`
把它**覆盖**了 —— 那个工具早就在，接口是 `<图> <x,y,w,h> <倍数> <输出>`
（质量也更好：high 平滑 + 自动建目录）。已 `git checkout --` 还原。
**写"临时小工具"之前先 `ls client/tools/` 看一眼**，这些 `_` 开头的脚本
全是长期资产，不是一次性脚本地。

## 弹药算术 + 走立绘（e459fb6 / 46c2aa8）

### 「怪少了会不会没球可推」—— 算出来是真的紧

链：裹敌 → 那只怪变球（本金 absorbed=1，tier0）→ 球撞死另一只 +2 → 冰墙要 minTier。
所以"一颗能破冰的球吃几只怪"完全由 minTier 决定：
minTier 2（≥4）= 1裹+2撞 = **3 只怪/颗**；minTier 1（≥2）= **2 只怪/颗**。
一关平均 6.8 只、门厅固定 3 只 → 要 3 只就是"刚好够、容错为零"，
先用雪弹打死一只、或一只怪掉洞里，就是死局且门上没有补救。
**minTier 2 → 1**。门槛意义没丢：本金 1 < 2，仍然必须吞一只。
新增 `tools/_snowlab-econ.js`（扫种子统计怪数/木石铁冰），断言加第二十二节
（真造球，不走 spawnBall 捷径），128 项绿。

**教训**：改了一处数值（absorbBox 2.0 → 0）必须回头重算它下游的每一笔账。
上一轮砍掉"砸箱涨体积"时没算冰墙门槛，留下了这个零容错的口子。

### 立绘路线（程序化到顶了）

分工按商业项目惯例拆：**背景 = 厚涂位图，玩法元素 = 矢量程序化**。
玩法元素要严格对齐 48px、要随状态变色、要锐利 —— 位图做这些更差。

关键发现：**世界宽正好 960 = 一屏**，所以每层正好一个 960×240 房间 →
每层一张全景立绘就够，**不用平铺、不用透明通道**，AI 生图最容易废的
两件事（接缝、抠图毛边）直接绕开。这条决定了这条路可行。

管线：`_snowlab-bg-build.js`（裁+缩+JPEG）→ `_snowlab-embed-bg.js`（base64
内嵌 `<script id="art-bg">`）→ HTML 里 `BG_IMG` 优先、程序化回退。
内嵌不外链：preview 静态服务只给一个文件，兄弟图 404 静默回退最难查。
**注意**：内嵌块用带属性的 `<script id=...>`，因为断言/出图工具用
`/<script>([\s\S]*?)<\/script>/` 抓**字面** `<script>`，带属性才不会被误抓。

**坑**：`@napi-rs/canvas` 的 `new Image(); im.src = buffer` 能读出
width/height、`complete` 也 true，但 drawImage 全是黑的、不抛错。
必须 `await loadImage()`，所以出图工具整段包进 async 了。

## 贴墙跳穿箱 / 走坡抖 / 推球 / 地形自然化（7ff5da2）

### 「往上跳反而掉进箱子」是扒边的瞬移没验落点

不是手感，是真 bug。扒边为了把人从洞口扶上台面会横向瞬移 ~26px，
冰墙上摞着箱子时那 26px 正好把人推进上一格箱体内部（最深 30px = 整个身体），
然后水平碰撞再把人推出洞口 → 看起来就是"跳上去又掉下来"。
修：新增 `blockedAt()`，**瞬移类修正必须先验落点**；顶天花板补 prevTop 判断
（原来"这帧重叠 + vy<0"就当顶头，斜着往上跳从侧面啃进箱子会被按到块底面）。
`tools/_snowlab-feel.js` 量的：46/48 → 0/96。

### 走坡抖的正解是"下坡贴地"

坡面一帧掉 4px，人只靠重力掉 0.6px → 腾空、砸下、再腾空，60 帧 onGround 翻转 4 次。
加：上一帧站在地上 + 这一帧在落 + 脚下 16px 内有坡面 → 贴上去。
**符号踩坑**：写成 `脚底−坡面`，恒为负，全部被跳过，数字一动不动还以为是公差不够。
y 向下增大：`坡面−脚底 > 0` 才是"坡在脚下"。

### 「球怎么推」= 没摸到，不是没提示

推法一直有（朝球走过去撞，助跑更猛）。补齐两样：脚边有静止球时浮
「走过去顶它」+ 方向箭头；life 4.6s → **16s 且推一次回满**（4.6 秒里根本
来不及绕到球后面）。融化保留，只清理被丢下的球。

### 地形：几何体 → 有机轮廓

- 台子 18→34 厚，底面瘤状起伏 + 根须 + 石子，顶面换石材（原来走木色渐变，
  所以读成"钉在墙上的木板"）；
- **描边只描上沿**：闭合描边会在两段土丘共用的竖边上画两道线，
  人字中间一道黑缝 —— 这才是"三角屋顶"观感的主因；
- **对称人字一定像屋顶**。土丘改成两边坡度不同（96+144），顶点扣雪帽/压石头；
- 坡面铺装按坡度选（陡→木阶/乱石，缓→素土），地表那层整块是雪；
- 半埋石头 + 磨秃顶边，救"一大块纯土色三角"；
- 地板缝 64 等距 → 46~82 抖动 + 换色板 + 节疤。

**试过又退回的**：坡长 168、土丘宽 108~132、平台宽 4 格 —— 都会多占一列箱子，
200 种子里有 3~5 个掉到 11 口（门槛 12）。地形宽度是硬预算，不是美术选择。

## 五条意见的收口：宠物、箱子堆、场景丰富度（这一轮的主战场）

用户原话（第 5 轮）：「1 左右移动晃来晃去 / 2 宠物能跳一个箱子高、走动待机、
太少、没有远程 / 3 箱子不规矩、太密、可以有桶 / 4 子弹符合宠物特点、射程远、
平行丢出有下落 / 5 上下层能跳、场景丰富度、美术风格」。

### 晃 = 箱子地形，不是镜头

镜头早就按层吸附（`S.cam.k` 只在"落地 + 脚离地板 <60"时换层）。剩下的晃是
箱子铺成连续高地后每两格上下 48px。解法不是动镜头，是**动箱子**。
第二十六节断言把它钉住：清箱后走平路，镜头 0.00px / 脚底 0.00px / 0 帧倒退。

### 箱子从"地形"变"堆"

切游程 → 摆 1~4 列宽的堆 → 堆间留 1~2 列平地 → 预算封顶 `COLS*0.7`。
中位数仍是 22 口，但"0 高列" p50 8→9、p10 4→5，视觉上从连续地形变成一堆一堆。
连带代价：地表层箱子掉到 7~9 口 → 出生点改成**对齐列边界**
（原来骑在两列缝上，一次清掉两整列），门槛 12/10 → 10/8。

### 宠物三种外观 = 三种子弹

`pet`（外观/子弹）和 `kind`（行为 crawler/runner）**必须分开**——
旧的 `spawnFoe(x,y,'crawler')` 断言全靠 kind 指"一只会巡逻的怪"，混在一起会全红。
行为优先级「瞄准 > 待机 > 走路」。抛物线靠运气试不出来：
`g=760/vy=-70` 胡萝卜 0.4s 砸地，三轮试算后才定 `g=210 / vy=-60 / spd 360~420`
（实测下垂 45px、水平 330px）。

### 两个真 bug（都是"断言全绿、图不对"逼出来的）

1. **`FR` 在造怪之后才重置。** `S.foes = L.spawns.map(makeFoe)` 在 `reset()` 中间，
   `FR = rngFrom(...)` 在函数末尾 → 每张新关卡的第一批怪吃上一张关的随机流。
   同种子两跑，宠物种类和朝向都不一样。`_snowlab-feel2.js` 的⑤抓到的。
2. **崖边停住 = 悬空。** 落地判据是"包围盒有重叠"，身体 99% 悬空只压 0.6px
   也算站着；一待机就定格成浮空的兔子。加 `solidFoot`（身体中段单独探一次）
   给"待机"和"开枪"两个会停住的动作当闸门。

### 光要看得见，必须先有暗

亮米色墙上用 `source-over` 叠暖黄，亮度只涨 3%~5%，等于没打光。
改用 **`lighter` 加色混合**，墙从 (232,211,174) 推到 (250,242,205)；
同时把楼板下的暗压 `.26/0.24` → `.34/0.30`。顺序是"先压暗、再打光"。

### 出图工具的坑：地面件不能画在箱子之前

"画在地形之前 = 木桶在箱子后面"这个免费的前后关系是**错的**：
箱子 48×48、木桶只有 26 宽，相邻列高一格就把木桶整块盖掉，地表层装饰
在图上等于不存在（看了一小时才发现"装饰加了但看不见"）。
现在拆两批：挂件在地形之前，落地件在地形之后。

### 装饰的三件新东西与"不许骗人"

`chandelier`（每层主灯，k>0 保底）/ `lantern`（暖色空中点）/ `ladder`（靠墙断梯）。
梯子做成"10° 倾斜 + 左轨短 20px + 缺一根横档 + 断口木刺"，
并在 `k===0` 时禁掉（地表上面是天空，没地方靠）。**直上直下的梯子会被玩家
当成能爬的路** —— 装饰不许给出假的可交互暗示。

## 第二轮五条：敌方换皮、侧视、容器实体化、黑洞地穴、打击感

用户原话（第 6 轮）：「1 敌方为什么用我方的宠物呢 / 2 战斗背景是立体的吗
一些和战斗无关的凸显出来 UI不合理 又不形成阻挡 就是个图贴上去 打箱子破碎感
球的击碎感 有物理打击的感觉 / 3 黑洞太突兀 可以地下做个玄关 / 4 敌方和我方
宠物不应该朝向玩家 应该是个侧视的」。

### 敌方不能是"我方的宠物"

上一轮我把敌方做成了兔/狗/刺猬（`NUM.pet`）。**概念错了**：那是"我方"的形象。
改成 `NUM.breed` = `moss` 苔泥团 / `fang` 尖牙兽 / `grub` 霜甲虫，
投掷物变泥球 / 牙 / 冰锥。

**区分靠体块关系，不靠颜色或小配饰**：一团 / 横着拉长 / 拱起的硬壳。
"耳朵竖/垂/一圈刺"那种是萌宠的做法，敌人这么分等于还是在做宠物。

### 侧视 = 单眼 + 前突的嘴 + 前后腿

`drawFoe` 整块翻进"永远朝右"的坐标系（`g.scale(face, 1)`），朝左只是镜像。
正面画法（两只对称眼 + 正面肚皮）只说明"这是谁"，不说明"它在往哪走"；
朝向是这款唯一要紧的信息，必须写进剪影。

### "看着能撞的，就真能撞"

罐子 / 小箱从 deco 搬进 `boxes`（22×30 / 30×30，hp 1）。
**规则要只有一条**，不能有的能穿有的不能穿 —— 玩家会记不住，然后不信这个场景。
货架太大直接不做（会堵路），地表补树桩 + 碎石堆把密度补回来。

### 黑洞：换列，不要删箱子

生成侧原来取 `colTop[col]`，那一列有箱子它就悬在箱山上。
**修法是"只挑本来空着的列"，不是"把那列箱子删掉"** —— 删箱子会拆掉井梯的
踏脚，实测"每层都能跳回上一层"从 26/26 掉到 21/26。

绘制侧三个毛病：椭圆太规整（像铁盆）、紫光把内壁一起照亮（像紫色垫子）、
顶部那条 2.4px 高光弧（像眼白）。三个叠起来 = 地上趴着一只紫色眼睛。
改成：不规则破口 + 漏斗挖穿楼板 + 三级石阶 + 被顶开的断板 + 碎石；
**光先打、洞壁再压上去**；高光弧只留 1.4px 半圈。

### 打击感的三件套

① 碎片要有材质形状（木 = 会转的板条，石 = 棱角块）；
② 顿帧 + 冲击环（**环必须双色**：深棕打底，浅色压上。只用浅色在雪地上看不见）；
③ 顿帧和震屏跟着 `ballPow` 走，不要一律 0.05s / 10px。
环同时最多 4 个：特大球连碾 5 个箱子会有十来个环叠成一团泡泡。

### 这一轮最贵的教训：`s.index` 会命中注释

用 python 的 `s.index("/* 黑洞（吐怪巢）。")` 当锚点替换 `drawNest`，
它先命中了 **`S` 对象定义里那条同名的注释**，把 S 到 drawBox 之间的全部代码
（NUM、genLevel、物理、step……）一次性删掉。整个文件报废，只能 git checkout
重做一遍所有改动。

规矩：**批量替换的锚点必须带行首（`"\n/* ..."`）并断言 `s.count(anchor) == 1`。**
光断言 `end > start` 不够 —— 那次 end 确实在 start 后面，只是 start 在文件前段。

### 出图工具的三次白跑

1. 冲击环 `t` 设成负数（第二圈延迟 50ms），半径算成负的，canvas 抛
   `IndexSizeError`，整批出图挂掉 → 进度必须 `clamp(t/life, 0, 1)`。
2. 撞箱那一帧碎片全叠在箱子中心（hitStop 期间 `step` 提前 return，碎片不更新）
   → 要等顿帧走完（约 7 帧）再截。
3. 球随手写 `y = gy − 26`，下半截埋进地板 → 第一帧判成水平撞墙、
   `vx *= −0.35` 原地反弹，图上是"球停在箱子前面"。
   必须 `y = gy − r`（球底正好贴地）且贴着箱子放。

`_snowlab-feel2.js` ①②③ 全 0.00px、⑤ 一致；新增 `impact` 出图；

## 第四轮（同日）：战斗背景从"贴纸"改成"盒子"

用户第 2 条剩的半边：**「你这战斗背景是立体的吗 有一些和战斗无关的凸显出来
UI设计是不是不合理」**。上一轮只做掉了"又不形成阻挡"（容器实体化）。

### 做法

`drawRoomWall` 整个重写。原来是 `WALL_L..WALL_R` 铺满一整块，
纹理画到边上为止 —— 出图上就是"一张壁纸贴在屏幕后面"。
现在按盒子画：后墙左右内收 54（`DI`）、上下内收 11（`DY`），
两侧补上侧墙 + AO，内角一条亮缝，后墙再压一层极淡的暖灰（空气透视）。

`DI = 54` 的来历：小于 40 读不出透视，大于 70 会吃掉一整列箱子（列宽 48）。

### 三个坑

1. **侧墙的板缝透视方向反了。** 第一版用 `t^1.55` 分布，越靠内角越**疏** ——
   看起来像"墙越往里越宽"，比等距更像画错。正解 `1-(1-t)^1.55`。
2. **侧墙材质没跟房间主题走。** 所有房间都画竖板缝，砖房的墙角变成
   "一截木板接在砖墙上"。现在 wood 画压缩竖缝、brick 画朝消失点收的横缝、
   rock 画两道顺墙裂缝、niche 只留 AO。
3. **消失点用房间中点，不读 `S.cam.y`。** `camViewOffset()` 已经保证
   镜头停稳时房间居中在屏幕 300，用房间中点几何关系不会跟着镜头抖。

### 顺带：墙面装饰退后

挂件和箱子原来共用同一套 `COL.ink` 2.5px 描边 + 同样饱和度，
读起来就是"能撞的东西"。现在：柔影 + 降透明度（按"像不像能站的东西"分档：
横梁 0.54 / 蛛网 0.56 / 其余 0.66），自发光三件不降。

### 顺带：怪物原地抽搐（`_snowlab-feel2.js` ④ 挂了很久的 6 次）

根因**不是地形**，是 runner 的朝向每帧由"玩家在哪边"重算：
撞边后 turnLock 锁 0.3s 反弹（148×0.3 = 44px），锁一解又朝玩家撞回去。
探针前 40 帧的 x 在 44px 里来回，那个 44 就是这个乘法。
改成撞边/撞崖/贴身（30px 死区）一律**钉住站定**，窄台面走速按走廊长度
衰减到 0.35 倍。6 次 → 3 次（crawler 的正常巡逻节奏）。
已补断言「二十九、怪物不会原地抽搐」，阈值 3。

## 第五轮（同日）：回答「上 Cocos 是不是立体 + 重新立绘」

用户问「如果是做到 cocos 上 是一个立体的 重新立绘的界面吗」。这一轮**没改代码**，
全是方向验证，两条试错都撤回了。

### 先查清 Cocos 侧的真实形态

- `Battle.scene` 里 **0 个 Camera、0 个 Canvas、0 个 Sprite**，只有 Scene + BattleRoot。
  战斗画面是 `GroveBattle.ts` 往 Cocos 画布上盖的一层 DOM canvas。
- 全工程 **0 个 3D 模型 / 0 套骨骼**，88 张 PNG。
- 所以现在的「Cocos 版」= 一个壳 + 一张 web 画布，只能跑 Web。

### 结论：不是 3D，是 2.5D 分层

`client/art/02-concept/03-battle-target/target-look-2.5D-分层纵切面.png` 是目标图。
四层叠出来（远景墙 / 中景挂件 / 玩法层 / 前景遮挡），一个多边形都没有。
玩法判定永远在同一个 XY 平面 —— 上 3D 只让推球和落袋变复杂，换不来收益。

### 实测：立绘值不值

`_lit-vs-proc.png`（脚本在 `/tmp/_littest.js`，未入库）把 AI 立绘缩到 30/44/64px 和程序化并排。
30px 下立绘确实更好（有明暗、口鼻、轮廓），但草叶牙齿冰棱全糊。
**玩家 42px、屏高 600 = 占 7%**，90% 细节被像素吃掉。要上立绘得先提尺寸。

### 试错一：前景遮挡层（撤回）

想从画面顶部垂下根须造纵深。`depth=0.226` 时镜头在第 2 层，**地表 y=340 还在画面里**，
根须画在雪原上成了左上角黑块。

根子：贴层吸附镜头 + 单屏房间，画面顶部永远是「地表或上一层的墙」，
没有「从上面垂下来的东西」该待的位置。**2.5D 前景遮挡依赖镜头自由移动，snowlab 不是。**

### 试错二：道具换手绘贴图（撤回）

木箱/木桶/陶罐出图 → 抠白底 → 按碰撞盒（48×48/48×48/22×30）内嵌，
接口照抄背景那套（`setPropArt` + 程序化回退）。三个问题：

1. 贴图带**顶面透视**，和侧视冲突；
2. 木桶原图比 48px 高，等比缩放成了「一截横纹木桩」；
3. **风格割裂** —— 手绘木箱挨着程序化石箱（平灰块）和金箱（平黄块），一眼两套。

第 3 条是原则问题：贴图自带深棕描边，为了不双描边跳过了统一描边，
而**那圈统一的 `COL.ink` 描边正是整个游戏的视觉语言**。跳过它 = 让木箱脱离体系，
比不换更难看。

素材留在 `client/assets/snowlab/props/`（@4x，质量够用），规范定了可直接接。

### 教训

**换贴图必须全套统一换**（同描边、同视角、同光源）。这不是「加几张图」，
是先定美术规范。半套换 = 净负收益，比不动更糟。
