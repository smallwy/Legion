### 两条「断言自己写错」的教训（比代码改动更值钱）

1. **判"被挡住"要看整段过程的最高点，不能看最终位置。**
   头撞箱底之后人会落回本层，最终脚底 == 起跳高度 —— 和"根本没跳"
   长得一模一样。第一版因此 7 个样本里 4 个被记成"没挡住"。
2. **试验场要铺满人的宽度。** 玩家 45 宽、箱子 48 宽，人放窗口左边 7px 处
   右边溢出箱沿 4px，就顺着箱侧擦上去站到了楼上地板 —— 图上读成
   "楼板还能穿"，其实是试验场没铺满（改成两口箱子 96px 才封住）。

## git push 在本机要显式指定代理

`~/.gitconfig` 里有 `http.https://github.com.proxy = http://127.0.0.1:7897`，
**这个端口早就不在监听了**（Clash 现在只有 7993/TUN，而此刻 mihomo 核心
根本没起，只剩 clash-verge-service）。直接 `git push` 报
`Failed to connect ... over proxy 127.0.0.1`，把 env 里的 proxy 全清掉
则是 21 秒超时（公司网直连 GitHub 不通）。

**可用的做法**：走沙箱自己的代理 38190（`example.com` / `api.github.com` /
`github.com` 都能过，git 端点实测 401 = 可达）：

```
git -c "http.https://github.com.proxy=http://127.0.0.1:38190" push origin main
```

`curl -x http://127.0.0.1:38190 https://github.com/` 偶尔返 000、隔一条命令
又好了 —— **单次 000 不足以判死，用 `/info/refs` 端点复测**。
