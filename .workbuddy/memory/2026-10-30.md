### 换手必须等一帧
`Component.destroy()` 在 Cocos 3.x 是**延迟销毁**。同帧"销毁旧的 + 挂新的"
会让两个组件同时活着：两台 ClearCamera（都吃 SOLID_COLOR 清屏，后画的盖先画的）
+ 两块 `z-index:10` 的 DOM 层（谁压谁不确定）。症状不是崩溃，是"画面定住"。
所以 `battleSwitch` 先 destroy、再用宏任务轮询 `isValid`，死透才挂新的。
两个组件的 onDestroy 也都补了拆自己那台相机 —— 以前不会切换，这条一直没暴露。

### `setSnowlabEntry(null)` 原来不还原
`if (typeof fn === "function") snowEntry = fn;` —— 传 null 是静默不改。
组件销毁时想还原就会留一个指向死组件的闭包，下次进出征页点门，
调的是上一个场景里那个对象。改成传 null 回落到 `snowEntryDefault`。

## 为什么会这样

`GroveRuntime.ts` 是 `extract_grove_runtime.py` 从 `grove.html` 抽出来的。
原型里 `setSnowlabEntry` 只是同文件内部用的普通函数（出征页改一个变量就够了），
抽取脚本尾部那批 `export function groveBoot/groveTick/...` 是**手写的模板**，
新函数不在模板里 → 生成物里它就是 `function setSnowlabEntry(...)`。

于是 `GroveBattle` 的 import 指向一个不存在的命名导出。
ESM 的行为：**链接阶段**直接抛 `does not provide an export named ...` ——
整个模块不执行，`addComponent(GroveBattle)` 拿到 undefined，
`Battle.scene` 里一台相机都没建 → **纯黑屏，一行日志都没有**
（连 onLoad 里那句「推球已接管战斗场景」都没机会打）。这就是"零信息的黑屏"。

为什么所有检查都是绿的：
- `ts-syntax-check.js` 用 `transpileModule`，**只查语法、不解析模块**；
- `grove-smoke` / `grove-runtime-check` 跑的是 `grove.html` 的代码（函数在那儿是存在的）；
- `tsc -p tools/tsconfig.all.json` 能抓到（TS2459），但它同时吐 2460 条生成物里的
  implicit any，没人会翻。

## 修法

1. `extract_grove_runtime.py` 加一条 must：`function setSnowlabEntry(fn) {` →

   （原型仍是唯一真源）。重抽后 diff 只有 1 行。
2. 新增 `tools/import-export-check.js`（门禁，39 文件 / 0.2 秒）：
   扫每个相对 import 的命名符号，确认目标文件真的有 export。
   自检过 —— 临时去掉 export，它精确报出
   `GroveBattle.ts:47 import { setSnowlabEntry } ← GroveRuntime.ts 没有导出这个`；
   还原后全绿。**第一次跑行号报错（报 6 行）**，因为剥注释时把 `/* */` 整段删了、
   行号全前移；改成「块注释换成等量空格」后准确。
3. 新增 `tools/_battle-mount-smoke.js`（cc 桩 + `@napi-rs/canvas` 真画布）：

## ② 球与球会撞会合（c823bad）

根因：球是唯一攻击手段，却是**孤立**物理体 —— 球与球能重叠穿过。
所以"推球"只有一种用法，关与关只差地形。这是"σ=0.0"的物理层原因。

- **撞**：动量按半径三次方分配，e=0.86
- **合**：两边都慢（<70）+ 贴住 0.28s → absorbed 相加。快球撞上去只弹不合

五个坑：
1. **合体判定挂"重叠"上 → 永远合不上**。位置分离把两球推到正好相切，
   下一帧 `d < minD` 不成立 → 计时逐帧清零。改：碰撞按重叠、合体按挨着（minD+3）
2. ⑤⑥ 断言**假通过**：只验"合出那颗的 absorbed"，两颗都是上限时"没合"也通过
3. `fuseT` 每帧衰减 0.34 → 0.28s 实际变 0.42s，和常量对不上
4. `d < 0.001` 直接 continue → 同心两球永远分不开（"双色球"）
5. `drawBall` 没过滤 dead + `fuseBalls` 没移出数组 → 合完还站着原来的

`_pairs-shot.js` 四个坑：boot 返回结构 / 只跑碰撞不跑积分（球冻住）/
`groundAt` 从 0 扫（球跑到天上）/ 走完整 stepBalls 会掉洞。
