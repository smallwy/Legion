## 一、5 分钟组装步骤

### 1. 建空项目
Cocos Dashboard → **新建项目** → 选 **Empty (2D)** 模板，命名如 `MunchLegion`，**引擎版本 3.8.x**。
（必须 3.8+：本项目用到的 `screen` 属性、`Graphics` 合批语义均以 3.8.0 引擎源码核实。）

### 2. 拷贝资源与脚本
把本目录的两块内容拷进新项目：

```
本目录 assets/resources/art/        →  新项目 assets/resources/art/
本目录 assets/scripts/              →  新项目 assets/scripts/
```

拷完回编辑器等它自动导入（右下角进度条走完）。**不要**把 `tools/` 拷进去——那是沙箱侧的
预处理与静态检查脚本，不属于游戏工程。

### 3. 建场景 + 挂唯一组件
1. `assets/` 里新建场景 → 命名 `Battle` → 双击打开。
2. 层级面板右键 → **创建空节点**，命名 `Game`。
3. 选中 `Game`，属性检查器 → **添加组件** → **自定义脚本** → `GameBootstrap`。
4. 保存场景（Ctrl+S）。

> 整个 demo **只挂 `GameBootstrap` 一个组件**。相机、主角、英雄小队、敌人、BOSS、渲染器、
> HUD、结算面板全部由代码运行时搭建，编辑器里不需要摆任何东西——方便整包迁移与参数复现。

### 4. 运行
点预览（浏览器 / 模拟器均可）。控制台应打印：
```
[GameBootstrap] 世界构建完成 · 占位精灵 已加载 · 3 英雄列队 · 20 波怪潮 + BOSS · 操作：WASD 移动 / F 喂食 / E 撤离
```
如果是 `占位精灵 全部缺失（程序化兜底层）`，说明第 2 步的 `resources/art/` 没拷到位——
也没关系，程序会用几何图形兜底画出来（见 §4 容错策略）。

### 5. 可选项：把场景设为启动场景
`项目设置 → 项目数据 → 起始场景` 选 `Battle`，这样预览直接进战斗。

## 二、操作说明

| 操作 | 按键 | 说明 |
|---|---|---|
| 移动主角 | `WASD` / 方向键 | 八向，斜向已归一化（不会斜着更快）；**整支队伍跟着你走** |
| **喂食** | `F` | +35 饱食，消耗 1 块肉，**喂的瞬间主角减速 0.4 秒**（怪群里喂要付学费） |
| **选强化** | `1` / `2` / `3` | 升级时弹出三选一；面板打开期间世界冻结，只认数字键 |
| 提前撤离 | `E` 或 `Esc` | 立即结束、进结算（红线②：无失败惩罚） |
| 再来一局 | 结算时按 `空格` 或**点鼠标** | 全部实体 + 等级 + 饱食度重置 |
| 自动行为 | — | 英雄**自动索敌施法**；敌人按攻击/施法半径自动逼近与读条 |

### 一局在玩什么（CR-015）

- 你控**主角**（金环+金点），**3 名英雄列成纵列跟在你身后**（左后 / 右后 / 正后）。
  你往哪走、队形就转到哪，英雄**自动索敌施法**（前摇 .25 + 施法 .1 + 后摇 .3）。
- **20 波怪潮**：每波从你 **600px 外**环形涌来并主动追击，单波 6 → 26 只。
  打完一波有 **3 秒喘息**（捡珠、喂食、拉距离的窗口）。
- **捡经验 → 升级 → 三选一**：一局约升到 **Lv 9**（约 41 秒弹一次卡）。
  10 项全是被动强化（伤害/出招间隔/移速/索敌/喂食量/慢饿/多发/暴击/耐饿/击杀回血）。
- **饱食度（全队共享一条）**：0.5/秒衰减，`100 → 70` 用 60 秒、`→ 30` 用 140 秒。

  | 档位 | 区间 | 火力 | 英雄前摇环颜色 |
  |---|---|---|---|
  | 满饱 | ≥70 | ×1.0 | 淡金 |
  | **半饿（最强）** | **30~70** | **×1.5** | **亮金** |
  | 全饿 | <30 | ×0.6 | **红**（= 该喂了） |

  **这是本作的唯一创新点**：宠物不是子弹，是有状态的活物。喂早了浪费（掉回 ×1.0），
  不喂会变弱（×0.6），**最强的时候是"有点饿"**。
- **肉块**：击杀 12% 掉落（红方块，与绿菱形的经验珠形状+颜色双重区分）。一局 302 杀约 36 块，
  实际只需 5 块左右 —— **喂食的代价是时机和 0.4 秒减速，不是资源焦虑**（刻意的）。
- **第 19 波清完 → BOSS「腐甲巨虫」登场（即第 20 波）**：620 HP，AOE 半径 155px、
  读条 **1.2s**，红圈填满即伤害 —— 靠走位离开圈心；贴身还有推挤伤害。
- 结束条件三种：**击杀 BOSS（通关）** / HP 归零（**撤退，不算失败**，红线②）/ 主动 `E` 撤离。

## 四、DrawCall 预算（验收线 < 20）

**关键设计**：全场**所有动态实体共用一个 `Graphics` 组件**。

已用 **3.8.0 引擎源码核实**：`Graphics` 组件内多次 `fill()/stroke()` 会合并进**同一个 mesh**，
一个 `Graphics` 组件 = **1 个 DrawCall**（65535 顶点以内）。（读 `graphics-assembler.ts` 的
`stroke()/fill()` 与 `batcher-2d.ts` 的 `walk()` 得出。）

对比：如果每个敌人一个 `Graphics`，同屏 28 只敌人 = 28+ DrawCall，直接爆验收线。

静态估算：

| 来源 | DrawCall | 备注 |
|---|---|---|
| 背景 `BackgroundRenderer` | 1 | 静态，只画一次 |
| 动态场 `EntityRenderer` | 1 | 敌人兜底体 + 前摇圈 + 子弹 + 经验珠/肉块 + **BOSS 本体与 AOE 圈** |
| 特效层 `FxSystem`（CR-016） | **1** | 碎屑 + 飘字 + 扩散圈**全部**装在这一个 Graphics 里 |
| 玩家金环 | 1 | 独立 Graphics |
| 英雄精灵（3 只） | 1 | 三只共用 `pet.png` 同一贴图 → 合批 |
| 步行虫精灵 | 1 | `enemy-walker.png` |
| 飞虫精灵 | 1 | `enemy-flyer.png` |
| 甲虫精灵 | 1 | `enemy-tank.png` |
| HUD | **3~5** | 3 个 `Graphics`（血量心形 + 饱食度/经验条 + BOSS 血条，各 1 DC）+ 2 个 `Label`（统计、BOSS 名）；两个 Label 相邻且同字体图集时可合批 → 2 |
| 三选一面板 | ~2 | 仅在升级时激活 |
| 结算面板 | ~2 | 仅在结算时激活 |
| **合计** | **≈13~15** | 结算/选卡未弹出时 ≈11~13 |

> BOSS 不占额外 DrawCall —— 它和杂兵一样画在 `EntityRenderer` 那一个 `Graphics` 里（无专属贴图，
> 用几何兜底 + AOE 圈）。
> 若实测比上表高，优先怀疑 HUD 的 2 个 Label 没合批（字体图集不同 / 中间夹了 Graphics）。

> ⚠️ **验证方式**（我无法在沙箱实测，必须你本机确认）：
> 预览时打开左下角 **Profiler** → 看 `Draw Call` 与 `FPS`。
> 预期 FPS 稳定 60、DrawCall 在 10 上下。若明显偏高，最可能是 4 张占位精灵各占 1 次
> （不同贴图不合批）——把 `art/` 下 4 张图做成一个 **Auto Atlas**（编辑器：右键图片 →
> 属性检查器改导入为 `sprite-frame` → 建 Auto Atlas 资源把 4 张拖进去）即可再降。
> 这属于 **Day 2 优化项**，Day 1 不阻塞。

### 4.1 像素风的两个硬性设置（不做就必糊）

占位精灵由 `tools/pixelart_gen.py` **在 32px 网格上按几何图元直接绘制**（椭圆/线段/三角拼装
+ 自动三阶明暗 + 1px 描边），不是从大图缩下来的。显示尺寸 = 工作分辨率 **×2 = 64px**。

但引擎侧还有两件事必须做：

| # | 设置 | 位置 | 不做的后果 |
|---|---|---|---|
| 1 | **Filter Mode = Point** | 选中 `resources/art/` 里 4 张图 → 属性检查器 → `Filter Mode` 改 **Point** | 默认 Bilinear 会把像素插值成糊块，32px 变成"毛玻璃" |
| 2 | **关闭 Mipmap**（如开启） | 同上，`Generate Mip Maps` 取消勾选 | 远景自动降采样，像素颗粒随机跳变 |

> 为什么不用代码调：Cocos 3.8 的 `Filter` 枚举公共导出路径在不同小版本上不一致
> （3.8.0 源码里 `asset-enum.ts` 未被 `cc` 重导出，但 `Texture2D.setFilters()` 本身存在），
> 编辑器设置最稳、不挑版本。若你确认本版本有 `Texture2D.Filter`，也可在 `SpriteAssets` 里补：
> `tex.setFilters(Texture2D.Filter.NEAREST, Texture2D.Filter.NEAREST)`。

**方法论修正记录（重要）**：

第一版是「256px 厚涂稿 → 降采样到 24px → 量化 16 色」。结果放大后是**一团认不出是什么的色块** ——
降采样会把剪影细节连同噪点一起抹平，色块是"压"出来的，不是"画"出来的。**像素风的核心是
在目标网格上手绘剪影，不是压低分辨率。**

当前方案改为程序化绘制：每只怪用椭圆/线段/三角形按解剖结构摆放（甲壳、头、触角、6 条腿、
复眼、独角），明暗由列内垂直位置自动生成三阶（顶光），最后统一 1px 墨色描边。剪影由设计决定。

| 维度 | 旧：256px 厚涂稿 | 中间版：24px 自动降采样 | **当前：32px 程序化绘制** |
|---|---|---|---|
| 单张颜色数 | 15,915 ~ 24,817 | 14 ~ 16 | **9 ~ 11** |
| 4 张体积 | 290.3 KB | 3.4 KB | **1.9 KB** |
| 纹理显存（未压缩 RGBA） | 933 KB | 9 KB | **16 KB** |
| 缩放比 | 0.19（非整数，必糊） | ×2 | **×2** |
| 放大 8 倍后能否认出 | 能（但不像像素风） | **不能，糊成色块** | **能，剪影清晰** |

> 32px 版显存比 24px 版高（16 KB vs 9 KB），这是**为可读性付的必要代价**——4 张共 16 KB
> 在任何平台上都可以忽略，认不出来的贴图才是真浪费。
>
> 原始 256px 厚涂稿与 24px 中间版都已归档（`client/art-source/`，**归档≠删除**，可回滚）。

## 五、表现层（CR-016 · 零美术打击感）

像素风下"手感"的绝大部分不是画质，而是**信息反馈的密度与时机**。这一层没有新增任何图片资源，
全部是程序化绘制，四个手段：

| 手段 | 触发 | 时长/强度 | 作用 |
|---|---|---|---|
| **顿帧** `hitStop` | 击杀杂兵 / 玩家受伤 / BOSS 死亡 | 45ms / 75ms / 420ms | 让"打到了"被身体感知；逻辑时间压到 ×0.06 |
| **碎屑** `burst` | 击杀（步兵飞虫 10 颗、甲虫 14 颗）/ 玩家受伤 | 0.3~0.6s 带重力 | 让"打碎了"有物质感 |
| **火花** `hit` | 每次有效命中 | 0.11~0.2s 沿弹道扇形 | 让"打中了"有方向 |
| **飘字** `text` | 击杀 / 暴击 / 对 BOSS 的每次伤害 / 喂食 / 升级 | 0.72s 上浮 | 让"打掉了多少"可读 |
| **扩散圈** `ring` | 喂食 / 升级 / BOSS 死亡 / 玩家受伤 | 0.35~0.9s | 地面脉冲，把事件钉在位置上 |
| **震屏** `addShake` | 玩家受伤（7px）/ BOSS 暴击（2.2）/ BOSS 死亡（12） | 指数衰减 | 唯一的"体感重伤"信号 |

### 5.1 三个刻意的取舍（都可以改，但要知道代价）

**① 伤害数字默认 `'kill'` 而不是 `'all'`。**
同屏 3 英雄齐射 + 32 只怪时，全量伤害数字会变成"数字墙"，把真正要读的信息（红色前摇圈、
BOSS 的 AOE 圈）糊掉。默认只在**击杀那一击、暴击、以及对 BOSS 的每次伤害**时显示。
想要全量：`BattleConfig.FX.damageText` 改 `'all'`（帧数不掉，但可读性会掉）。

**② 顿帧只在击杀时触发，不在每次命中时触发。**
3 英雄齐射时 BOSS 每秒挨 3~5 下，如果每下都顿 1 帧，玩家读到的是"**掉帧**"而不是"**打得重**"。
BOSS 只有暴击才顿帧。这是 hitStop 最常见的误用，写在这里免得后人加回来。

**③ 震屏不会带着 UI 一起抖。**
HUD 挂在**相机节点**下，屏幕坐标恒定，所以移动相机只晃世界。震屏加在视野钳制**之后** ——
否则贴到场地边缘时，钳制会把抖动吃掉，边缘受伤就完全没有反馈。

### 5.2 性能边界（这是 `FxSystem` 存在的理由）

- 全部特效画在**同一个 `Graphics`** 里 → 整层 **1 个 DrawCall**。
  反面做法"每个粒子一个 Graphics 节点"：200 颗粒子 = 200 DC，直接爆验收线。
- 同屏上限写死在 `FX.maxParticles(200) / maxTexts(12) / maxRings(8)`，**满了就丢弃新特效**，
  不排队。宁可少一颗碎屑，也不能让帧率抖。
- 颜色按 (色号 × 4 档透明度) 预建 32 个 `Color`，热路径零分配；`tick` 里不 `new` 任何对象。
- 失效项回收**每 0.5 秒**做一次，不是每帧 `filter`（每帧 filter = 每秒重建 180 个数组）。

**本层最坏情况**（200 粒子 + 12 条飘字 + 8 个圈）：约 400 个矩形 + ~20 次 `fill/stroke`，
顶点数远低于 `Graphics` 单 mesh 的 65535 上限。

### 5.3 像素字模（`FxSystem` 里为什么有个自己的数字字体）

飘字用 `Label` 会额外占 DrawCall 且中文/英文位数不定。这里内置一套 **3×5 像素字模**
（0-9 与 `+ x ! L V .`），画时做**横向 run 合并**——一个数字 5~7 个矩形，而不是逐像素 15 个。

> 尺寸：字模 3×5 格 × `scale 3` = 9×15px；暴击用 `scale 4` = 12×20px。
> 这套字模只服务"短数字"，**不要**拿它排中文（中文请用 `Label` + 字体图集）。
> 重跑：`python client/tools/pixelart_gen.py`，同时输出对比图与游戏内尺寸预览图。

⚠️ **局限**：这是**程序化占位**，不是手工像素画。造型是"球+腿"的基本拼装，够验证玩法、
能在战场上一眼分清三种敌人；但称不上有角色设计感。正式美术仍需人工按美术指引 §7/§8
重画（30–60 分钟/只），届时只要保持 **32px 网格 + ≤24 色 + ×2 显示** 这三条，直接替换 PNG 即可。

## 七、已知简化 & 与计划书的差异（诚实清单）

1. **施法节奏已定案（CR-011）**：计划书 §2.7 原写「总攻速 **2.2 次/秒**（≈0.65s/轮）」，
   但 0.65s/轮实际只有 **1.54 次/秒**。CR-011 采 CR-009 的三段时长（后出决策优先），
   本实现按 **前摇 0.25 + 施法 0.1 + 后摇 0.3 = 0.65s/轮 = 1.54 次/秒**。
   若要精确到 2.2 次/秒，把 `HERO.recovery` 从 `0.3` 改 `0.1`（0.45s/轮 = 2.22 次/秒）。

2. **队伍是「3 英雄列队跟随」**（CR-014），**刷怪已从"清窝推进"改回 20 波怪潮**（CR-015）。
   队形槽位写死在 `HERO_SLOTS`（左后 / 右后 / 正后），改人数要**同时**改 `HERO.count` 和槽位数组。
   ⚠️ **本版仍不做职业定位**（坦克仇恨 / 治疗回血）。列队**只是阵型**，没有站位策略；
   真要做出"前排扛、后排输出"，还需要一层仇恨系统 + 治疗系统，那是独立的一块工作量。
   顺带说明：队形纵深 52px **小于**敌人攻击半径 60px，所以在数学上前后排**无法区分**——
   要做职业定位必须先队形摊开到 120px 以上，而那会和"紧致列队"的观感冲突。这两件事是互斥的。

3. **资源映射是暂定值**：结算面板「食物 = 经验珠数、材料 = floor(击杀/2)」是临时约定，
   等 Day 3 家园资源池接线后回写。

4. **占位美术是"程序化占位"，不是成品**：`resources/art/` 的 4 张精灵由
   `tools/pixelart_gen.py` 在 **32px 网格上用几何图元直接绘制**（不是从大图缩下来的，
   见 §4.1 方法论修正记录）。**仅内部试玩**，发布前必须人工重画或外包替换
   （美术指引 §11 已声明）。程序化绘制能保证「剪影可读 + 色数可控 + 整数倍缩放」，
   但造型是基本拼装，**没有角色设计感**，别拿它当验收美术。

5. **BOSS 无专属贴图**：`BossController` 的体型（128px）走的是 `EntityRenderer` 的几何兜底，
   颜色复用甲虫的钢蓝。它靠 **AOE 圈读条**建立威胁感，不靠造型。要出"BOSS 感"得住美术加一张
   32px 基础图 ×4 的大图，或在 64×64 网格上单独画一只。

6. **坐标系说明**：所有玩法节点在 `z = 0~100`，相机的 `z = camZ(1000)`、`near/far = 1/3000`，
   即「相机架高处朝 -z 看」。这是为了避开 3.x 里 `Canvas` 适配体系的耦合——本 demo **不用
   `Canvas` 组件**，直接用 `Camera(ORTHO)` + `UITransform`，`Widget` 适配由 `ViewUtil` 手算。

7. **2D 绘制顺序**：已核对 3.8 `Batcher2D.walk()` —— 按 children **遍历序**深度优先决定绘制优先级。
   因此代码把世界拆成**实体树**与**相机树**两棵：相机树整体挂在实体树之后，保证 HUD/结算永远在最上层。
   敌人节点是对象池**运行时才 addChild**，所以 `EntityRenderer` 的节点必须在建世界时就位，
   否则特效层会被后生成的贴图盖住。

## 八、离线静态校验（沙箱侧已做）

沙箱跑不了编辑器，但用 TypeScript 编译器 + `cc` 类型桩对**全部脚本**做了 `--strict` 检查：

```bash
cd client
"C:/……/node.exe" "……/typescript/bin/tsc" -p tools/tsconfig.check.json

```

它抓出并修掉的**真 bug**（都是"粘贴才暴露"的类型/作用域坑）：
- `new Node('Field')` 误用浏览器全局 `Node`（GameBootstrap 漏从 `cc` 导入）→ 已修。
- `EnemyManager` 同模块重复 import / 未使用符号 → 已修。
- `config` 里用了 `as const`，导致 `WaveManager._timer = WAVE.firstDelay` 被推断成字面量类型 `1.6`
  （赋 `3` 就报错）→ 所有从配置初始化的字段显式标 `: number`。
- 删 `EncounterManager` 后 `EntityRenderer` 仍 import `Nest` 类型 / `NEST` 常量 → 已一并清理。

**数值侧另有一道验算**：`python tools/sim_wave_balance.py` 会输出一局时长、饱食度窗口、
肉块供需、升级节奏，并对不合理项报警。CR-015 就是靠它抓出"清窝只有 57 秒"这个致命问题
（57 秒里饱食度只掉 28 点，整个喂食系统等于不存在）。

**运行时另有一道冒烟**（针对类型检查抓不到的东西 —— 字模位、绘制次数、池上限）：

```bash
cd client
node tools/fx-smoke/run.js       # 编译 FxSystem → 跑 14 条断言
# 通过 14 / 14
```

`run.js` 做两件事：把 `FxSystem`（连同它依赖的配置与颜色工具）单独编译成 commonjs，
再用一个**记录型 `cc` 桩**（`cc-runtime-stub.js`，会记下每次 `fill/rect/circle` 调用）
真正 `new FxSystem()` 跑起来断言。不装 TypeScript 时用 `TSC=<path/to/tsc>` 指定。

它验证的是"编译能过但一跑就错"的几类：3×5 字模有没有翻错列、横向 run 合并有没有生效
（`+35` 应是 13 个矩形而不是 45 个）、粒子/飘字上限有没有拦住、失效项未回收时能不能复用空槽、
狂刷 600 帧会不会抛异常。

**局限**：类型桩与 `cc` 运行时桩都是我写的，只能验证**脚本之间的自洽**，无法替代真机运行。
运行时行为（数值手感、渲染批次是否真合批、平台差异）仍需你本机预览确认。
