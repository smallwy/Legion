# 战斗场景往「商业化 2.5D + 手绘立绘」走：目标图与两条试错记录

这批图不是成品资产，是**方向证据**。2026-10-28 用户问的是：

> 「如果是做到 cocos 上 是一个立体的 重新立绘的界面吗」

回答分两半，两半都需要图才说得清。

---

## 一、不是 3D，是 2.5D 分层

`target-look-2.5D-分层纵切面.png` 是「做到位之后应该长什么样」。

它一个多边形都没有，全靠四层叠出来：

| 层 | 内容 | 作用 |
|---|---|---|
| 远景 | 暖棕木墙，低对比、降饱和 | 交代「这是个房间」 |
| 中景 | 吊灯、红灯笼、货架、坛子 | 生活的痕迹，但压暗 |
| 玩法层 | 箱山、雪球、角色 | 唯一参与判定的一层 |
| 前景 | 左右树干 / 藤蔓，虚化、压暗 | 造出「镜头在空间里」 |

**立体感来自层次和遮挡，不来自多边形。** 玩法判定永远只在同一个 XY 平面上，
上 3D 不会让推球更好玩，只会让落袋和碰撞变复杂。

这张图钉在 `client/art/02-concept/03-battle-target/`，改美术时对着它看。

## 二、立绘在游戏内尺寸下到底值不值

`client/shots/_lit-vs-proc.png`（工具产物，重跑 `_littest.js` 可复现）
把 AI 立绘缩到 30 / 44 / 64px，和现在的程序化绘制并排。

结论：**好，但好的幅度受尺寸限制。**

- 30px 时立绘仍有辨识度（轮廓、明暗、口鼻），程序化那版是扁平色块；
- 但草叶、牙齿、冰棱这些细节在 30px 全部糊掉；
- 玩家 42px、敌人 30px、屏高 600 —— **角色只占 7% 屏高**，90% 的立绘细节被像素吃掉。

所以「上立绘」之前先要决定：要不要把角色渲染尺寸提上去（32→48~56）。
只换图不提尺寸，提升有明显的天花板。

## 三、两条试错，都撤回了

### ① 前景遮挡层（撤回）

想靠「从画面顶部垂下来的根须」造纵深。**不成立。**

`depth=0.226` 时镜头在第 2 层，但地表 `y=340` 还在画面里 —— 根须会画在雪原上，
变成一个没来由的左上角黑块。

根子：**贴层吸附镜头 + 单屏房间**的结构下，画面顶部永远是「地表或上一层的墙」，
不存在「从上面垂下来的东西」该待的位置。2.5D 前景遮挡依赖镜头在场景里自由移动，
snowlab 不是这种镜头。

### ② 道具换手绘贴图（撤回）

木箱 / 木桶 / 陶罐出图、抠底、按碰撞盒（48×48 / 48×48 / 22×30）内嵌，
接口和背景那张 `bg-surface.jpg` 一样（`setPropArt` + 程序化回退）。三条实测问题：

1. 贴图自带**顶面透视**（木箱画成 3/4 立方体），和侧视画面冲突；
2. 木桶原图比 48px 高，等比缩到 48×48 成了「一截横纹木桩」；
3. **最致命：风格割裂。** 手绘木箱挨着程序化的石箱（平灰块）、金箱（平黄块），
   一眼看出是两套东西。

第 3 条是原则问题。手绘贴图自带深棕描边，为了不双描边走的是「跳过统一描边」，
而整个游戏的视觉语言正是那圈统一的 `COL.ink` 描边 —— 跳过它等于让木箱脱离体系，
比不换更难看。

**结论：换贴图必须全套统一换**（同一套描边、同一视角、同一光源方向），
否则割裂的代价大于质感的收益。这不是「加几张图」的事，是先定美术规范的事。

素材留在 `client/art/03-candidate/01-props/`（crate / barrel / jar，均为 @4x），
质量够用，等规范定了可以直接接。

**为什么在 `art/` 而不是 `assets/`**：它们现在 0 引用。放进 `assets/` 会被
asset-db 导入、算进包体，等于白背包体 —— 项目以前为这个把 `assets/bg/raw/`
的四张图搬出来过。等真的接进渲染管线再挪回 `assets/snowlab/props/`。

## 四、要往下走，先定这三条规范

不先定这三条，做什么都会割裂：

1. **描边**：所有游戏内元素共用一圈 `COL.ink`？如果是，贴图必须**不带描边**，
   或者带和 `COL.ink` 同色同宽的描边；
2. **视角**：纯正交侧视（看不到任何顶面）还是允许一点顶面？
   现在程序化是纯侧视，AI 出图默认带俯视 —— 两者混用必冲突；
3. **光源**：统一左上打光？立绘的阴影方向必须和场景一致。

定完之后一件事一件事换，每换一类就出图对比，不要一次铺开。
