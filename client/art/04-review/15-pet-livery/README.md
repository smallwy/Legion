# 15 · 战斗里的主角不再"另画一只"，改回立绘那只

用户这一轮的原话：

> 你现在完全脱离了 最开始设计的萌宠吗　之前也有立绘　完全不要了吗

## 先回答"是不是不要了"

**没有一像素被删。** 六只立绘全在，而且一直是在用的：

| 位置 | 内容 |
|---|---|
| `assets/ui/home/pets/` | 六只全身立绘，进包、主界面在渲染 |
| `assets/ui/home/heads-circle/` | 六只圆形头像 |
| `assets/scripts/config/Roster.ts` | 六只的 id / 名字 / 技能 / 稀有度 |
| `art/03-candidate/01-pets/` | 出图源 + `_anchor.json`（裁切基准） |

断掉的只有**战斗**这一个环节：`snowlab.html` 的战斗角色是纯 canvas 代码画的，
一张贴图都没引（`grep drawImage` 只有背景）。原因写在
`art/02-concept/03-battle-target/README.md` 里 —— 立绘是**正面站姿大图**，
战斗是**侧视 + 跑 / 跳 / 爬三种动法**，正面图放进去朝向不对、也动不了。
所以战斗单位一直是"按立绘重新画的侧身简化版"。

**但用户的感觉是对的**：简化的时候把识别特征丢了，简化成了另一只猫。

## 那条黑弧不是描边太粗

上一轮把它记成「耳朵描边放大后显杂」，判断错了。

真因：`foeCel()` 内部有两次 `beginPath()`，退出时留在上下文里的是它最后画的
**偏移椭圆** `(x - rx*0.20, y - ry*0.45, rx*0.93, ry*0.93)` —— 偏移到左上、还小一圈。
调用方写的是

```js
g.beginPath(); g.ellipse(...); g.fill();
foeCel(g, ...);              // ← 这里把路径冲掉了
g.stroke();                  // ← 描的是 foeCel 留下的那个偏移椭圆
```

头和身体各描一次这种错位椭圆，两条粗弧落在角色身上，从左边绕到头顶 ——
904px 的出图上比眼睛还显眼，像给猫扣了个铁丝头罩。

**粗只是让它更容易被看见，错才是它难看的原因。**

修法：`stroke()` 之前重建路径。三行。

## 改了什么

- 四档色阶照立绘抄（`cat/catDark/catLight/catShade`），深橙 → 奶油米黄；
- 加绿松领巾 `#7FB896`。**必须画在头之后** —— Q 版没有脖子，
  按真实遮挡顺序画（身体之后、头之前）会被头的圆吃干净，一格绿都不剩；
- 眼睛：眼白 4.9×5.7、瞳 3.8，白边收到 1.1px，双高光加大；
- 脚掌 `#FFF4E4`（白手套）；
- 内耳 `#E8A08A`（橘粉），顺带删掉耳朵上最后一条 `createLinearGradient`
  —— 那只耳朵还是厚涂，和身上别的 cel 不是一套；
- 尾巴：原来「10px 黑描边 + 6.6px 橙描边」是**给线条的笔法**，
  每边只剩 1.7px 彩边，中段又被身体和头遮住，露出的两截是纯黑。
  改成闭合路径 `fill + stroke`，形状是外拱的月牙，末端圆；
- 补一笔尾根暗面（`rgba(120,80,40,.22)`）：尾巴和身体同色时，
  没有这一笔从剪影上读是"身体侧面长出来的一只手"。
