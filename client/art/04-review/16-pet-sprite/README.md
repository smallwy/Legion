# 16 · 战斗主角改成贴图：直接用 `grove/pet/cat.png`

用户这一轮的原话：

> 之前是雪人关卡那个　单位也是侧着施法的　额
> D:\Legion\client\assets\resources\grove\pet　资源以前在这额

## 我上一轮走错了

上一轮（第 15 组）我把"主角不像立绘"当成"需要重画"，于是按立绘的识别特征
（奶油色、绿领巾、黑瞳双高光、白爪）**手写了一套代码图形**。技术上讲没错 ——
颜色和特征都对上了，`foeCel` 那个描错路径的 bug 也顺手修了。

**但那是在重造一个已经存在的东西。**

`assets/resources/grove/pet/` 里躺着六只游戏内版本的立绘（统一高 292），
是美术管道从 `ui/home/` 收缩出来的副本，`GroveBattle.ts` 的 `ART_MANIFEST`
里一直挂着 `pet-<id>`，雪人关卡（`prototype/grove.html`）就在贴。

**侧视、能施法、和主界面是同一只** —— 这三件事它本来就满足。我一次都没去看。

## 现在怎么接的

照抄 grove 的结构，一行判断：

```js
const petArt = artOf('pet-cat');
if (petArt) { drawPetSprite(...); return; }   // 有图贴图
// 没有才走下面那整套代码图形
```

- 注入键 `pet-<id>`，和 `GroveBattle.ts` 的 `ART_MANIFEST` **同一套名字**；
- 代码那套**不退场**，它是回退路径（jsdom 出图、加载失败、以后换角色没出图时）；
- `drawPetSprite` 连同它踩过的三个坑一起从 grove 搬过来（见下）。

## 搬过来的三个坑（都不是调出来的，是量出来的）

1. **按体高缩，不按图高。** 图高 292 里，脚底到头顶只占 0.656，
   顶上 34% 是耳朵和留白。按图高缩，身体只有该有的 65.6%。
2. **原图朝左。** 翻转判据是 `face > 0` 不是 `face < 0` —— 写反的那版
   是"向右跑、脸朝左"。
3. **出手闪白用 `filter: brightness()`，不是盖白矩形。** 盖矩形会在角色周围
   留一圈白框；系数 0.8 不是 1.8，1.8 会把橙猫提成白猫。

走路也不用整只上下蹦（那是跳），是**同一张站立图切三块**、绕髋关节前后对摆，
身体反方向轻前倾。

## 一个必须改的数字：`PET_VIS_K` 不能照抄 0.78

它定义的是「画出来的**体高** / 碰撞高」，不是图高。

- grove 用 0.78，是让猫的体高只有碰撞盒的 78%；
- snowlab 的 `PLAYER_H = 63` 是照**代码画的那只**量的，那只的体高就是 63。

直接搬 0.78 的后果：贴图猫体高 49，比木箱（48）高一格都不到。
而断言第三十节写着「玩家比箱子高 1.31」—— **那条断言还是绿的**，
因为它按 `PLAYER_H` 算、根本不看贴图。机器绿、画面错。

这里取 1.0（体高 = 碰撞高）。代价是耳朵溢出碰撞盒顶约 33px
（cat.png 的耳朵占图高 34%，代码那只只占 14%），耳朵大是素材本身的特征，认了。
05 图（浅井）看过：站在箱子上时耳朵没有穿进楼板。

## 验收

- `tools/_snowlab-check.js`：183 项全绿；
- `tools/_pet-shot.js` 新增 `POSE=run`：**切腿动画只有动起来那一帧才看得见**，
  静止特写永远是站立图，切歪了也看不出来。03 图是跑动帧。
- 出图工具都加了贴图注入，且**加载失败会吭声** —— 不注入就静默走代码图形，
  一张"看着也行"的代码猫最容易把"没加载上"当成"就长这样"。
