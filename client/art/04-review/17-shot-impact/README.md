## 1 · 「为啥代码要单独写」——答案是：能不重复，而且本来是重复了

`snowlab.html` 是 2026-10-28 建的单屏试验台，当时的理由写在文件头里：
`grove.html` 21599 行 / 27 屏 / 1463 项冒烟断言，而那一版要动的是**输入通道**
（近身糊 → 远程吐）和**资源模型**（球额度 → 弹药），两处都在最底层，
所以先在试验台把数值跑顺。

**这个理由只对"做量具"那一段成立，往后就不成立了。** 试验台后来长成了
第二个游戏（Q 版地牢房间、程序化箱堆、贴图主角、震屏、破碎），
而主线一直没跟上。判据很直接 —— 用户这一轮的第 2、3、4 条，
**有两条在主线里本来就是对的**：

| 用户说 | grove.html（10-20 就有） | snowlab.html（10-28 重写） |
|---|---|---|
| 子弹要有特色、符合宠物、有下落 | `HEROES` 六只六把武器：溜溜球去而复返 / 音波越飞越宽 / 坚果贴地滚 / **萝卜横射 806px** / 飞刀穿透 / 影子双发 | 一个统一的雪球，**直线 149px** |
| 宠物别比箱子大 | 玩家 38×44，木箱 48 —— **本来就小** | 贴图视觉宽 **68.7**，箱宽 1.43 倍 |
| 震屏效果不好 | 20+ 处分级触发（3~15） | 一处随机平移 |

图 01 是这一轮的六种投掷物，**参数全是从 grove 的六把武器继承的**
（刀最快最直、萝卜最远、坚果最重）。所以不是"重新设计一套"，
是把已经有的搬回来。

**什么时候必须单开文件**：只做数值量具、且不打算让玩家看到的时候。
一旦开始改玩家能看见的东西（美术、手感、镜头），就必须在主线里改 ——
否则两个版本会各自演化，谁也不是最终形态。

## 2 · 投掷物：射程 149 → 382，而且会掉

### 数值

| | 改前 | 改后（cat） |
|---|---|---|
| 弹道 | 水平直线 | 抛物线 |
| 射程 | 149px | **382px** |
| 下坠 | 0 | **52px** |
| 顶点 | — | 出手点上方 5.5px |
| 六只 | 共用一套 | **六套**（`NUM.shot.pets`） |

`vy0 = -80 / grav = 520` 是从"同高度还能打中多远"倒推的：
子弹掉到敌人胸口（≈30px）时 x 已经走了 327px，是原来的 2.2 倍。
再远就砸地 —— **射程有上限，但不再需要贴脸**。

**没有直接搬 grove 的六把武器**，因为 grove 的武器是"直接伤害"，
而 snowlab 的子弹只干一件事：给敌人加雪点，满 6 发裹成球。
搬伤害会绕开裹球，整条玩法断掉。所以只搬两样：**抛物线的飞行方式**
和**每只长得不一样**。

### 形状（图 01）

8~10px 的子弹上，配色没有意义 —— 能读出来的只有**外轮廓**。
所以六种靠轮廓分：圆盘带缝线（溜溜球）/ 两头大中间细（骨头）/
椭圆带缝（坚果）/ 锥形带绿叶（萝卜）/ 细长菱形（飞刀）/ 暗紫圆（影子）。
统一 `COL.ink` 描边，和场景里所有实体一个语言。

### 一个踩到的坑

第一版加了"砸到地面就碎掉"，用 `groundAt()` 判断 —— 结果子弹飞 134px
就消失了。因为 `groundAt` 把**箱顶也当地面**，而箱堆就是地形，
子弹一头撞进前方箱子就被判"落地"。平台挡子弹本来就有单独一段循环，
这条判据是多余的，删掉。

## 3 · 打击感：从"画面在抖"改成"被撞了一下"

### 震屏

改前：`translate(rnd(-sh, sh), rnd(-sh, sh))` —— 每帧独立随机。
帧与帧之间**毫无关系**，肉眼读作"画面在抖"，而不是"被什么东西撞了"。

改后三件事：

1. **平滑**：两条**非整数倍频**（1.0 / 2.31）的正弦叠加。非整数比意味着
   不会周期性回到同一点，看起来不像机械摆动。
2. **方向**：`shakeDX/DY` 是冲击的单位向量。大震才吃得进方向（`sh/14`），
   小震保持纯震颤 —— 否则子弹打箱子都让画面横移，会晕。
3. **指数衰减**（原来是线性 60/s）。线性的毛病在尾段：从 14 掉到 1 和
   从 1 掉到 0 用的时间一样长，最后那一下是"匀速停下"，读起来是机械。

### 碎片（图 02）

两个改动：

- **扇形而不是全向**。原来 `rnd(0, 2π)` 均匀撒开 —— 那是一次爆炸，
  不是被撞碎。有冲击方向时，角度收进 **±66°**，木片才会朝球飞去的方向扑出去。
  （只加"整体漂移偏置"不够：它只改变重心，不改变扩散形状，出图上看还是爆炸。）
- **多了两层尺寸**。加 4 片大残骸（16~26 宽，飞得慢、活 0.85~1.25 秒）——
  没有大块的时候，箱子碎完读作"箱子消失了"；大块是它的尸体，玩家看得见
  它被撞到哪去了。再加 10 片木屑（慢、久），负责撞击的"尾巴"。

木箱从 21 片到 **42 片**，石箱另加一层火星。

## 4 · 主角比箱子大：这是几何问题，不是审美问题

用户问「比箱子大 没办法独立站一个箱子的空格？」

**能站。** 碰撞宽 45 < 箱宽 48，玩法上一直站得住。
**但看着站不进去** —— 贴图实际画出来 **68.7 宽**，是箱宽的 1.43 倍。

### 根因

上一轮把 `PET_VIS_K` 从 0.78 提到 1.0，只对齐了**高度**（体高 = 碰撞高 63），
**宽度没人管**。cat.png 宽高比 0.716，体高一撑到 63，视觉宽就跟着到 68.7。

### 不能靠降碰撞高来解决

试过 63 → 55：视觉 46.3 宽 / 53.1 高，两个条件都成立，碰撞和视觉只差 2px。
但一跑断言就掉三条：比箱高 1.15、高度 ≥ 56 承载立绘细节、占屏 10.5% ——
**那三条是"角色别缩回去变小"的红线，缩宽度不能拿高度去换**。

### 最终

高度守住 63，只压视觉宽度：`PET_VIS_K = 1.0 → 0.70`。

- 视觉 **48.1 宽**（= 一箱宽）/ **55.2 高**（1.15 箱高）
- 碰撞 45×63 不动

代价：碰撞顶比耳朵尖高 7.8px，跳起来会"没碰到就弹下来"。
这 7.8px 只能认 —— **0.716 的宽高比决定了"宽进一格"和"碰撞=视觉"不可兼得**，
而宁可空一点碰撞，也不要角色缩成一小团。

图 04 是结果：猫的宽度现在和一个木箱基本相等。
