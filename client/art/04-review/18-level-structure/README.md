> 2026-10-29

## 02 · 地表实拍

浅层箱子少（预算 12 格 / 20 列），第一眼能看清"哪边能走、哪边是箱山"。
这一层是教学层：箱子疏、洞是宽的（144）或敞开的、没有会追人的 fang。

## 03 · 门厅实拍（种子 7）

门在画面右侧，外面包着两列两格冰。主角站在中间偏右，脚下一路是通的。
门厅的箱子是 3 格为主（深层堆峰最高档），横向移动得先拆出一条路。

## 04 · 门厅未破冰

同一位置，冰墙还没砸开。门完全看不见 —— "砸开最后一口箱、门在那里"
这个瞬间是设计要卖的，所以第 03 张才是"找到了"。

## 这一轮改了什么

### ① 难度递进：所有参数从 `tierOf(k)` 来

`tier = k / (层数 − 1)`，0 = 地表，1 = 门厅。**只管这一个数**，
所以 3 层的关和 5 层的关走的是同一条曲线（不是"层数多就一路难"）。

| 参数 | 浅 → 深 | 为什么要递进 |
|---|---|---|
| 洞宽 | 144 → 96/144 | 浅层宽口是"这里能下去"的教学，深层窄口要贴着边找 |
| 封口概率 | 34% → 86% | 越深越少敞开的口，玩家要为"盖板"付更多弹药 |
| 箱子预算 | 12 → 16 格 | 浅层看得清路，深层铺满，横向移动先拆路 |
| 堆峰 | 1~2 → 2~3 格 | 3 格差 144 跳不上去，只能绕 —— 难度不需要新机制 |
| 堆间空地 | 42% → 12% | "越往下越挤"最直接的表达 |
| 每层怪数 | 2 → 3 → 4 | 门厅固定 3（killTarget 的死局线） |
| fang 比例 | 0% → 约 57% | 追击型逼换位，巡逻型只是"多" |

断言守着「tier 严格递增」「怪数逐层不降」「洞越深越窄」「预算越深越多」，
所以下一轮谁再手滑加个 `chance()`，这四条会立刻红。

### ② 主通道：先划走廊，再摆箱子

原来"堆之间至少留 1 列平地"是**副产品**（堆宽随机、空地 30% 才给 2 列），
于是有的段连着五六列全是堆，玩家钻进去前后都被 144 挡住。

现在反过来：**先按 4~6 列的节奏把走廊钉死**（走廊列恒 0 格、不摆堆、
补箱也不碰），相邻列限高 2 格。`wells`（井梯）和它左右一列不许当走廊 ——
井梯是硬的 3 格，贴上去走廊就成了沟底（第一版没排除，200 个种子里
204 次撞"相邻列高差 3"）。

### ③ 死胡同用 BFS 量，不靠眼看

`unreachableCols(L, k)`：20 列，按**真实移动能力**走一遍。

- 相邻列高差 ≤ 2 格（96）可以走上去；**下坡不限**（走下去是掉，不是跳）
- 中间隔着洞、洞宽 ≤ 144 可以跳过去（水平 300 × 滞空 0.686 = 205px，留余量）
- 地形（台 96/114）不算阻挡：净空 214 − 114 = 100 > 身高 45，人从台底下走

`validateLevel` 第 13 条直接查它。这一条刚加上去的时候，200 个种子只有
**44 个**首掷通过 —— 也就是说"死胡同"不是偶发，是原来每关都有。
修法三条：

1. **单洞最宽 144**。192 的洞切出来的段跳不过去，实测在 200 个种子里
   制造了几百个走不到的孤段。"大豁口"的视觉改由"两个洞"承担。
2. **任何一段不少于 96（两列）**。一列宽的碎段是真空岛：两侧都是 144 的墙、
   上面是楼板，掉进去只能砸箱子，而砸出来还是只有一列。
3. **洞口右邻列限高 2 格**。左邻是井口缘（0 格），右边 3 格的话跨洞只有
   "从右往左"能用 —— 单向通行就是半个死胡同。

修完 197/200 首掷通过，剩 3 个由 `buildLevel` 重掷。

### ④ 门：3~17 列全宽随机

原来 `48 * ri(12, 17)` = 576~816，永远在右半边。玩三关就形成习惯"门在右边"，
整层前半段退化成赶路。现在只躲一条：上一层的落点带（避免"掉在门上"）。

## 遗留

- 主通道是**几何保证**（走廊 0 格 + 邻列 ≤2 格），但玩家看不出"这是主路" ——
  没有任何视觉提示。要不要在地面铺一条浅色石板，是个设计问题。
- 层数仍 3~5 随机。tier 把难度曲线拉平了，但"3 层关"总内容量还是比
  "5 层关"少三分之一。要不要按层数补箱子预算，没做。
- 结构图里能看出有的层（如种子 2 的 L1）洞贴着左墙，那一段只有 2 列，
  虽然连通但很窄。属于"能走，但不好看"。
