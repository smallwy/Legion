# 22 · 爬井的过程：从"一帧到位"到"竖直爬 + 横移跨"

用户这一轮的原话（2026-10-29），配了一张截图：

> 这里跳上去 会很不自然的 瞬间移动

截图圈的是地表层地板上的一个断口（洞口），下面是下一层，洞口正下方压着一口箱子。

## 1 · 到底是什么在瞬移

`wellClimb` 命中之后，`stepPlayer` 里是这样一行：

```js
p.x = cw.x; p.y = cw.y; p.vx = 0; p.vy = 0;
```

水平（横移到洞口外）和垂直（上升一层）**同一帧到位**。
144px 的井，一帧走完 —— 那不是"爬上去"，是闪现。
玩家看不到过程，也就学不会"这里能上去"。

## 2 · 为什么不能干脆删掉这条路

试过了，删不得。站在 2 格箱顶（离上层地面 144）时：

```
净空 = 214（层高 240 − 板厚 26）
头顶空间 = 214 − 144 = 70
人高 = 63            → 一跳只能再升 7px
```

**跳不上去。** 而井梯是"不卡关"的保底 —— 洞口被箱子堵、起跳点挤在斜角里
跳不满高度时，还有一条确定的路。删掉它，井梯就彻底走不通。

结论：**留机制、补过程。**

## 3 · 两段，不是一条斜线

| 段 | 做什么 | 速度 |
|---|---|---|
| ① 竖直 | x 锁死，人贴着洞口内侧往上爬 | 430 px/s |
| ② 水平 | y 锁死在落点高度，人从洞口跨出来 | 240 px/s |

**合成一条斜线（x/y 一起插值）看着像"飘"** —— 现实中没人能斜着穿过地板。
两段只多 0.1 秒，但读法完全不同：先"顺着井上去"，再"从井口跨出来"。

`smoothstep` 给首尾加减速。匀速移动会被读成"被机器搬运"。

三个实现细节，都不显眼但缺了就出问题：

- **接管点必须在 `stepPlayer` 最前面**（时间戳计时器之后、按键之前）。
  放后面的话，同一帧重力已经把 `vy` 加到 34、人往下沉半像素，下帧插值
  又拉回来 —— 144px 的井会看出"一段一段地顿"。
- **爬的这段时间给无敌。** 人贴在洞口里，这时被雪弹打中，位置会被击退
  逻辑改写，表现是"爬到一半掉回去"。
- **摆动只给绘制，不改 `p.x`。** 改真值会让落点判定和洞口碰撞跟着晃。

## 4 · 姿态：位置平滑还不够

位置平滑之后人确实是逐帧上升的，但**站着不动**匀速上升，读起来还是"电梯"。
补两笔：

- 身体左右 ±2.2px 摆动，0.35 秒一个来回 —— 手脚交替的节奏；
- `moveK` 固定 0.5，让腿蹬起来。

## 5 · 量到了什么

`tools/_climb-probe.js`（扫 40 个种子，找到 40 处可触发的井口）：

| | 改前 | 改后 |
|---|---|---|
| 单帧最大位移 | **144px**（一帧到位） | **10.7px** |
| 整段耗时 | 1 帧 | 34 帧（0.57 秒） |

轨迹（`x,y`，圆括号是本帧位移）：

```
192,421(0.0)  192,417(3.0)  192,406(6.2)  192,390(8.5)  192,371(10.1)
192,349(10.7) 192,328(10.5) 192,309(9.5)  192,292(7.6)  192,281(4.8)
192,277(1.2)  ← 到这里为止 x 一直是 192（竖直段）
189,277(2.5)  180,277(4.9)  169,277(5.9)  157,277(5.7)  148,277(4.1)
144,277(1.1)  ← 到这里为止 y 一直是 277（水平段）
```

两段是**分开的**，不是斜线。这是这张 README 里最要紧的一条数字。

`_snowlab-check.js` 第二十一节新增一条断言：

```
✓ 爬井没有单帧瞬移（最差 10.7px/帧，s1k1）
```

阈值 24：正常走 5px/帧、插值峰值 11px、自由落体终端速度约 14px。
一帧到位是 144px，一眼能分辨。

## 6 · 没验证到的

**"手感和观感"机器判不了。** 上面的数字只能证明"位移是连续的"，
证明不了"看起来像在爬"。人眼觉得别扭的可能是别的：摆动幅度、速度、
或者根本不该有这条路径（希望玩家自己跳）。
