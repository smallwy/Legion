# 第六轮反馈：往上会往左跑 / 最底层往下去了第一层 / 这个坡推不上去

用户原话（附三张截图）：

1. 「这个位置往上 会自动向左移动」
2. 「最下层往下 既然去了第一层　现在跳层的摄像头是不是有问题 一闪一下」
3. 「这个坡始终推不上去」

三条是三个不同的根因，但第 1 和第 2 条都跟"一帧之内人换了位置"有关。

---

## 01 井口往上爬：L 形 → 沿井壁的曲线

`client/tools/_round6-shot.js MODE=climb`（种子 1，第 2 层，洞口 192+144）

红线是改前，绿线是改后。两条线叠在同一张底图上。

| | 帧数 | 形状 |
|---|---|---|
| 改前 | 47 | **垂直爬到楼板面 → 在地板高度水平拐 96px** |
| 改后 | 23 | 前 32% 纯竖直，中段边升边靠，最后 8% 纯竖直爬出洞口 |

**根因**：`startClimb` 是两段插值 —— `tv` 秒内 x 锁死往上爬，然后 `th` 秒内 y 锁死、
在地板面高度**横着滑 96px**。物理上没毛病，读起来是"人升到顶之后悬空平移"。

改成一整条曲线之后，横移发生在**楼板底面以下**（人还在井里），
所以既不会"在地面上方滑行"，也不会"升到顶再拐弯"。

同一条问题还有第二处：**洞口翻越**（二段跳把脚送过楼板面之后的那次横移）
原来是一行 `p.x = nx; p.y = gh - p.h` —— **一帧**横移 48~112px，
断言量出来的单帧峰值就是 112。现在走 `startMantle`：0.10~0.26 秒的
smoothstep 跨步 + 6px 弧顶，单帧峰值 15.8px。

顺带修了方向：没按方向键时按"人在洞口的哪半边"决定往哪边翻。
原来写死 `dirs = [-1, 1]` —— 站在洞右半边也先试左边，横移距离直接翻倍。
**"自动向左"有一半是它。**

## 02 门厅按 ↓：改前被送到地表

`MODE=lobby`（种子 3，4 层）

改前：脚底 y=340，**人在第 1 层（地表）**。
改后：脚底 y=1060，人在第 4 层（门厅）。

两处一起坏的：

1. `segsOf` 给**每一层**地板都打 `floor: true`（半透楼板）。门厅是最底层，
   下面什么都没有 —— 打上这个标记等于"按 ↓ 可以穿出世界"。
   现在只有"下面还有一层"的才打。
2. 掉落兜底是 `groundAt(x, 0)`。它的语义是"从 y=0 往下扫，第一个能站的面"
   = **最上面那一层**。于是任何掉出世界的东西都被送到地表。
   现在改成"该 x 处最低的那块可站面"。

镜头那半条：`updateCamera` 固定 7/s 对新层一样用。跨一层是 240px（正常跟拍），
跨两层以上就是"镜头在整关里从上滑到下"—— 用户说的"一闪一下"。
现在按差距分档：≤1.5 层 7/s，超过 16/s（0.25 秒走完大半，读作快速下摇）。

## 03 最大的球推不上坡

`MODE=bigramp`（种子 1，第 1 层，坡 x=624 w=144 rise=96）

| | 最远 x | 结果 |
|---|---|---|
| 改前 | 711 | 卡在坡面上，离坡顶 57px |
| 改后 | 890 | 越过坡顶（768），落到台面上 |

**根因是"门槛写死 24"。** 球的贴面用**球心**那一列的高度（这是为了让球在坡上不抖），
所以滚到坡顶时球底比台面低 `半径 × 坡度`：

- r=25（开局球）：25 × 0.79 = 20px < 24 ✓ 上得去
- r=46（吸满 24 点）：46 × 0.79 = **36px** > 24 ✗ 永远卡住

换句话说，**同一个坡，小球上得去、大球上不去**。
用户推的是一颗吸过怪的大球，所以"始终推不上去"。

现在门槛 = `24 + 半径 × 斜率`。球不在坡附近时斜率是 0，门槛还是 24，
不会把球抬上别的台子（平台离地 96/114，平地上的球够不着）。

## 断言

新增「四十一」组，5 条，全部对着上面四个数：

```
✓ 翻越没有单帧瞬移（最差 15.8px/帧）
✓ 翻越之后真的站在上层地板上（50/50）
✓ 门厅地板不是半透楼板（按 ↓ 穿不下去）
✓ 掉出世界落在最底层（不是被传送到第一层）
✓ 最大的球（r=46）推得上坡（8/8）
```

全套：249 / 16 / 4 / 14 全绿。
