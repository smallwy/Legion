# client/art —— 不进引擎的美术资料

这个目录里的东西**不会被 Cocos 打进包**，只给人和工具看。
真正会被引擎引用、会被打包的图只有 `client/assets/` 下面那些。

分家理由：以前 `shots/` 里躺着 345 个文件（工具每跑一次就丢一张进去），
和"资产"混在一起，既查不到哪张是当前版本，也没法判断哪些能删。
现在两边职责分开 ——

| 目录 | 是什么 | 能不能删 |
|---|---|---|
| `client/assets/` | 引擎资产，场景按 uuid 引用、代码按路径加载 | **删了会坏** |
| `client/art/` | 素材源、概念图、候选图、评审图、归档 | 按本文件的说明删 |
| `client/shots/` | 工具的**落点**，已整个 gitignore | 随便删，随时能重跑 |

## 目录

### `01-source/` 素材源

能重新生成资产的原料。改尺寸、改压缩、换导出规格都要回到这里。

- `01-pets/` —— 六只伙伴的 256px 立绘源，`24px-autotrace` 是描边粗细试验的产物
- `03-bg/` —— 主界面背景的四张 AI 分层原图（天空 / 中景树干 / 地面 / 前景遮挡）。
  合成后的成品是 `assets/ui/home/bg.png`。
  **以前这四张躺在 `assets/bg/raw/` 里**，会被 asset-db 导入、被算进包体，但场景一张都没引用，
  等于白背 7.8MB —— 所以搬出来了。
- `05-style/` —— 四张风格选型图（chunky / pixel / q-vector / 对比图），定风格时的证据

### `02-concept/` 概念图

- `01-pets/` `02-foes/` —— AI 出的 Q 版角色概念图，最终立绘的参考
- `04-battle/` —— 战斗界面概念（`concept2-*` 六张：立绘谱 / 家园 / 三关 / 结算）

> 生成这些图的**脚本**在 `client/concept/`，和产物不在一起是有意的：
> 脚本里写死了 `../shots/` 相对路径，搬走就断。
> 那个目录自带 README，自己说明自己，不用动。

### `03-candidate/` 候选稿

AI 出图里通过初筛、但没进最终资产的。改立绘时先来这里翻，别重新出图花钱。

- `01-pets/` —— 六只的 `@v1` 候选图 + `raw/` 原始输出
- `02-heads/` —— 圆头像候选

### `04-review/` 评审截图

改完一遍、看一眼对不对的那种图。按主题分：

- `00-早期截图` —— 最开始按轮次编号的 01-…21-（第一版界面和战斗）
- `01-battle` —— 推球战斗的场地 / 敌人 / BOSS / 结算
- `02-home` —— 主界面（含宠物走动 `rt-*`、派遣卡、任务牌）
- `03-ui` —— UI 细节与九宫格，`质感基准/` 是 UI 质感定档时的对照
- `04-bg` —— 背景合成与镜头层对比
- `05-quality` —— 后期合成层（泛光 / 分离色调 / 颗粒 / 暗角）的改前改后
- `06-dispatch` —— 派遣卡的三版

### `05-archive/` 归档

明确被取代、但留着能说明"为什么不用它"的东西。**不参与任何流程。**

- `v1-糖果纸/` —— v1 糖果纸概念图
- `v1-背景/` —— home-bg v1（被 v2 与最终版取代）
- `v1-行走序列/` —— 行走序列帧。玩法最后选了**代码步态**（梯形速度 + 步频锁位移），
  序列帧没用上；保留是为了哪天要换回逐帧时不用重新出图。
- `v1-被否立绘/` —— 两张明确被否的初版（年糕姿态重复、星屑侧身头小）

## 这次清掉了什么

删之前都逐条查过引用，不是凭感觉：

- `assets/ui/home/heads/` 六张 v1 方形头像 —— 场景 0 处引用，已被 `heads-circle/` 圆头像取代，
  也没有任何生成脚本读它
- 门动画的 47 张中间帧 —— 成品 `grove-门口.gif` 已保留，重跑 `DOOR_GIF=1` 就能再出
- AI 风格选型基准 6 张、被否立绘 2 张、`home-bg@v1`、行走帧裁切 6 张
- `_` 开头的工具一次性产物 150+ 张（`_ab-*` `_chk-*` `_p-*` `_cmp-*`）——
  它们本来就该被 gitignore 挡住，是规则之前就提交进去的历史残留

## 命名约定

- 目录带数字前缀：`01-` `02-` … 保证在资源管理器里顺序就是阅读顺序
- 归档/被否的目录带 `v1-` 前缀，一眼看出不是当前版本
- `_` 开头的文件一律是**工具产物**，不进这个目录（`client/shots/` 才是它的家）

## 附：`client/assets/` 是什么结构（引擎真的会打包的部分）

```
assets/
  scenes/            Home.scene（当前场景）、Battle.scene（只有一个 BattleRoot 节点，脚本自己接管）
  scripts/           运行时逻辑，不在这里展开
  ui/
    home/            主界面贴图，**故意保持平铺**
      pets/          六只立绘（场景直连 spriteFrame）
      heads-circle/  六张圆头像（同上）
      panel-*        各面板底图
      badge-*        徽标圆环与顶盖
    icons/           11 张小图标（场景里被复用到 5 处以上）
  resources/         按**路径字符串**加载的图（resources.load）
    grove/
      pet/  head/  foe/  ui/     ← 这次拆的
    art/             老战斗原型的占位精灵，4 张共 1.9KB
    ui/post-overlay  主界面镜头叠加层（暗角 + 颗粒）
```

`ui/home/` 为什么不拆子目录：它是**场景资产 + 生成器源图**混在一起的位置 ——
`gen_grove_art.py`、`build-nine-slice.js`、`make-scene.js`、`_measure-planks.py` 等
六七个工具都按 `ui/home/xxx.png` 这个具体路径读它，拆一次要连着改六处，
而它本身已经是"一块屏幕的 UI"这一个完整概念。拆的收益不如风险大，所以留着。

`resources/grove/` 才是真的该拆：28 张平铺，找图只能靠 `pet-` `foe-` `ui-` 前缀眼扫，
而且前缀和目录语义重复。现在按用途四个目录，路径表在 `GroveBattle.ts` 的 `ART_MANIFEST`，
改完用 `node tools/check-resources.js` 断言每一条都真的落盘 ——
**resources.load 路径写错不会报错**，只会静默退回代码图形，这件事必须机器查。
