# 画面质感：为什么「像贴纸」，以及按什么顺序修

> 针对反馈：「主界面和战斗内美术感偏弱，都像贴图，比较假」。
> 这份文档只讲**画面怎么变真**，不涉及玩法。
> 每条结论都对应一次实际渲染对比（`client/shots/_ab*.png`），没验证过的会标注。

---

## 一、先把「像贴纸」拆成五条能测量的病

「假」不是一个问题，是五个。分开看才知道哪个便宜、哪个贵。

### ① 没有接触（Contact / AO）

物体和地面之间只有「一个灰椭圆」，没有「从接触点往外渐隐的暗」。

- 战斗：角色影子是**纯色硬边椭圆**（`rgba(22,38,28,.18)`），平台影子是**正下方一块圆角矩形**。
- 主界面：宠物有影子，但同样是硬边、正下方、纯色。

> 硬边影子贴在任何背景上都读作「贴纸下面垫了个灰椭圆」。
> 这一条是五条里最便宜、收益最高的。

### ② 没有统一的光照方向

太阳固定在右上 `(700, 74)`，但：

- 角色影子在**正下方**；
- 平台影子在**正下方**；
- 角色的高光在**左上**（立绘画的时候就是这么画的）；
- 树冠的高光在**顶部**。

> 每个物件的光都对，但它们不来自同一个光。
> 观众读不出「光从哪来」，就会把每个物件读成一张独立的图 —— 这是「贴纸感」最直接的成因。

### ③ 没有全局的明暗跨度

程序化画出来的东西有个共同病：**每一件都合理地取了一个中间调**。

| 元素 | 亮度（0~1） |
|---|---|
| 云 | 0.92 |
| 草地 | 0.65 |
| 木头 | 0.58 |
| 树冠暗部 | 0.55 |
| 远山 | 0.80 |

单看每个都「对」，摆在一起就**没有一处是暗的**。真实照片里一定有被压到 0.15 以下的暗部（背光的树根、平台底面、石头缝），正是这些暗部把亮部衬出来。

> 没有暗部 = 没有对比 = 平 = 假。这一条只能靠**整帧**处理，补单件没用。

### ④ 没有空气（大气 / 景深 / 散景）

- 天空、远山、中景树、平台、角色、前景灌木 —— **清晰度完全一样**。
- 没有任何东西在「镜头前面虚掉」，也没有任何光在「糊出边界」。

> 真实镜头只有一个焦平面，且一定有一层最近的、虚掉的东西挡着画面边缘。
> 全部一样锐利 = 眼睛收到「这里没有镜头」的信号 = 这是一堆图叠在一起。

### ⑤ 没有材质（纹理 / 颗粒）

草地是 90 撮极淡的小草（alpha 0.10~0.23），木头是三条短横纹，一个像素的噪声都没有。

> 程序化图形的边缘是数学精确的。真实镜头一定带感光噪声。
> 干净到零噪声，本身就是「这是画出来的」的证据。

## 二、修复顺序（按投入产出排）

| # | 手段 | 治哪条 | 成本 | 需要美术吗 |
|---|---|---|---|---|
| 1 | 后期合成：泛光 + 提对比 + 分离色调 | ③ | 一次实现，全局生效 | 否 |
| 2 | 影子统一朝左下 + 改径向渐变 | ①② | 改 3 处绘制代码 | 否 |
| 3 | 前景层模糊（景深） | ④ | 一个离屏 canvas | 否 |
| 4 | 镜头光斑 + 胶片颗粒 | ④⑤ | 一个循环 + 一张噪声图 | 否 |
| 5 | 椭圆暗角 | ③④ | 十行 | 否 |
| 6 | 背景本体的纹理密度（草地/木头/石头） | ⑤ | 大 | 否，但要逐层调 |
| 7 | 角色立绘与环境的色彩融合（降对比、加环境光） | ①② | 中 | **是**（改立绘或写 shader） |
| 8 | UI 卡片从「白描边矢量」改成「手绘纸质/木牌」 | 全部 | 大 | **是** |

**1~5 已经做完**（见第三节）。6 是下一步性价比最高的，7~8 必须排美术产能。

## 三、已经落地的东西

### 战斗（`client/prototype/grove.html` → 抽成 `GroveRuntime.ts`）

新增 `drawPost()`，在所有内容（含 HUD、结算卡）之后跑一遍，五道 pass：

| pass | 做法 | 关键参数（都是实测调出来的） |
|---|---|---|
| 泛光 | 1/4 分辨率下 `brightness(0.55) contrast(4.6) blur(5px)` 抽亮部，`screen` 叠回 | 强度 普通关 0.38 / 雪原 0.28 / 夜关 0.20 |
| 提对比 | 整帧 `contrast(1.14) saturate(1.10)` 再画回 | 提对比必掉饱和，两个必须同动 |
| 分离色调 | 亮部暖（跟太阳同坐标）+ 暗部冷，都用 `soft-light` | 冷调**不能**用 `multiply`——蓝×绿=灰橄榄，草地会脏 |
| 颗粒 | 三张噪声图轮换，`overlay` 0.075 | 三角分布，不是均匀白噪 |
| 暗角 | 椭圆径向渐变 | 按宽高比压扁，四角才均匀 |

另有两处结构改动：

- **影子统一朝左下**：角色影子 `x - w*0.15`、平台影子 `-9px`，且都改成径向渐变 / 三层外扩柔边。
  偏移量刻意压到 `w*0.15` —— 再大玩家会读不准「脚在哪」，那直接影响推球站位。
- **前景景深**：`drawForeground` 先画到离屏 canvas，叠回时 `blur(2.4px)`。
  2.4px 是「我知道我在看一个很近的东西」；5px 会读成「背景虚化」，前景跑到远处去了。

开关：`S.post`（泛光/调色/颗粒）、`S.dof`（前景景深）、`S.vignette`（暗角），可独立关。

### 主界面（Cocos）

- 新增 `tools/build-post-overlay.js`，烤一张 640×360 的 `assets/resources/ui/post-overlay.png`（225 KB）：
  椭圆暗角 + 胶片颗粒，两样都是**静态**的，不必逐帧算。
- `HomeRuntime.ts` 新增 `attachPostOverlay()`：`resources.load` 后挂一个全屏 Sprite 到 Canvas 最上层。
  加载失败**静默跳过**（少一层暗角不会有人觉得不对，主界面白屏会）。

> 为什么两边用两套做法：战斗是 canvas 2D，后期能逐帧算；主界面是 Sprite 场景，
> 没有后处理管线，为了一层暗角挂自定义 pipeline 不值。而暗角/颗粒恰好不随内容变化。

## 五、还没做，但按顺序建议做

1. **背景本体加纹理密度**（第 6 条）。现在草地是「90 撮 alpha 0.1 的小草」，
   密度再翻一倍、对比再提一点，画面会立刻「厚」起来。这是不用美术产能的最大一块。
2. **角色立绘的色彩融合**（第 7 条）。立绘比背景饱和一档、对比高一档，
   硬边贴上去就有「抠图」感。两条路：批量预处理立绘（降对比 + 边缘羽化，一次搞定 6 张），
   或者写一个 Sprite effect 做「环境光渗透」。
3. **UI 卡片风格统一**（第 8 条）。这是主界面最刺眼的一条 ——
   背景是手绘水彩，卡片是纯白描边 + 标准圆角，两套语言。
   要么把卡片改成纸质/木牌质感，要么全场景改成一个更「扁」的风格。
   **这一条不做，前面五条的效果会被它吃掉一半。**
