# CR-020 · 森林觅食 + ATB 即时回合制

> **触发**：用户「不行 你没理解我的意思 那就主线玩法 是野外觅食吧 一次可以安排多个宠物上阵
> 去森林 觅食 主要是即时回合制的吧 战斗场景是在森林中」
>
> **一句话**：战斗不是目的，觅食才是。森林是场景，ATB 是节奏，食物既是续航也是分数。

---

## 1. 我上一版错在哪

CR-019 把玩法改成「守家」：三只宠物守着窝，怪从三个门涌进来，你排指令把它们挡住。

机制本身没问题，但**方向是反的**。用户要的是**出门**，我做的是**看家**。差别不只是场景：

| | CR-019（守家） | CR-020（觅食） |
|---|---|---|
| 主动性 | 被动等怪上门 | 主动往深处走 |
| 目标 | 撑过 15 回合 | 能带多少回家 |
| 风险来源 | 格子被突破 | 贪不贪 |
| 结束方式 | 回合耗尽 | 撤退 / 团灭 / 走穿 |

守家是个**负数游戏**（不输就是赢），觅食是个**正数游戏**（赢多赢少）。后者才有"再走一层"的冲动。

## 2. 整体循环

```
营地（编队 1~5 只 + 喂食）
   ↓
森林第 1 层 ── 战斗 ──→ 选：继续深入 / 就地开饭 / 撤退回家
   ↓                          ↓
第 2 层 …… 第 5 层（野猪王）   带食物回家
```

- **5 层**，每层一波：`乌鸦×2+浣熊` → `浣熊×2+乌鸦` → `野猪+浣熊+乌鸦×2` → `野猪×2+浣熊×2` → `野猪王+乌鸦×2`
- 敌人血量/攻击随层数 +10% / +9%，数量也递增
- 战利品：2 / 3 / 4 / 6 / 14 份，另加每击杀 1 份

## 3. ATB：这套"即时回合制"具体是什么

```
每帧：atb += spd × dt × timeScale
atb ≥ 100 → 进入待选队列
待选队列非空 → timeScale = 0.16（全场减速）
玩家选招 → 结算 → atb 归零
```

三个参数决定手感：

| 参数 | 值 | 作用 |
|---|---|---|
| `ATB.full` | 100 | 条长 |
| 宠物 `spd` | 20~30 | 猫 3.3 秒一次，狗 5 秒一次 —— **编队 = 行动节奏** |
| `ATB.slow` | 0.16 | 待选时世界减速到 16% |

**为什么要减速而不是暂停**：暂停就是纯回合制（FF 的 WAIT 模式），不减速就是纯实时（你根本来不及选）。
16% 的妙处是**你能从容选招，但敌人的条还在涨** —— "慢慢想"有代价，这是即时回合制比回合制紧张的唯一来源。

**兜底**：慢放超过 6 秒没选，自动放第一招。没有它会因为玩家发呆而僵死。

## 4. 食物：一个资源干两件事

这是整套设计的支点。

| 用途 | 何时 | 代价 |
|---|---|---|
| **喂食** | 出征前 | 1 份 / 只，+25% 攻 +15% 速 +4 血 |
| **战斗中** | — | 乌鸦会偷走背上的或干粮 |
| **就地开饭** | 森林每层之间 | 3 份，全队回 50% 最大血，**一层只能一次** |
| **结算** | 回家 | 全部计入家底 |

于是"深入"变成一个真实的取舍：**想走到底就得在路上吃，但吃掉的不是分数**。
不带脑子一路冲，五层后到家是 0 份；保守打三层就撤，能带回 10 份。

### 为什么不做自动回血

第一版我给的是"每场胜利自动回 35%"。实测结果：**前 3 层满血通过，第 4 层断崖式全灭**。

自动回血的问题在于它把资源决策从玩家手里拿走了：血量永远够用，直到不够用为止。
改成手动开饭之后，玩家每一层都在做同一个决定 —— 这正好是觅食题材该有的决定。

## 5. 五个可出战宠物

| 宠物 | 血 / 速 | 技能 1 | 技能 2 | 定位 |
|---|---|---|---|---|
| 橘子（猫） | 26 / 30 | 挠 14 伤 | 弓背：2.2 秒内减伤 60%，被咬反挠 7 | 最快的输出 |
| 豆豆（狗） | 40 / 20 | 撞 11 伤 + 打空对方行动条 | 汪汪：全体敌人改打你 + 14 护盾 | 坦克 / 打断 |
| 团子（仓鼠） | 20 / 25 | 塞嘴 8 伤，击杀额外 +1 食物 | 钻地：1.1 秒不可选中，行动条 +40 | 采集 |
| 布丁（兔） | 24 / 26 | 踢 9 伤 + 定住 2 秒 | 蹭蹭：全队回 12 血 + 解定身 | 治疗 |
| 麻薯（鸭） | 28 / 22 | 扑翅：全体 6 伤 | 嘎嘎：全队行动条 +35 | 群伤 / 提速 |

**编队上限 5，池子也是 5** —— 也就是说"选谁上阵"实际是"放弃谁"。
三只队的实测通关率是 0%，五只是 35%，差距这么大是为了让编队这一步有意义。

三种敌人各有必须应对的理由：

- **乌鸦（thief）**：不打你，偷食物。不打它，这趟白跑。
- **浣熊（bruiser，护阵）**：在场时**其他敌人减伤 30%**。不先处理它，你打谁都像在戳海绵。
- **野猪（brute）**：只打最靠前的那只，伤害最高。

护阵这条是后加的。原版所有敌人都只是"掉血"，那最优解永远是打最脆的，目标选择等于没有选择。

## 6. CR-019 的抗命机制没丢，只是没放进这一版

CR-019 的"宠物不服从指令"（猫 70% / 狗 95% / 仓鼠 80%）是个好点子，但它的前提是
**玩家在排指令**。ATB 里没有指令可排，只剩"出手时选什么"，抗命无处落脚。

如果后续想加回来，最小改动是：**低血量的宠物有概率不按你选的技能出手**（慌乱）。
但这会让"血量管理"同时变成"控制力管理"，属于加深度不加宽度的改法，等这版手感确认后再说。

## 8. 踩到的坑（都是不报错的）

### 8.1 伤害被平方 —— 最严重的一个

```js
// 写的时候
let dmg = rawDmg * (actor.atk || 1);
// 敌人调用时
hitOne(e, t, e.atk);          // rawDmg 就是 e.atk
```

乌鸦 `atk=6`，实际打出 **36**。整队 14 秒团灭，而代码和日志都看不出任何异常。

根因是 `atk` 这个字段承担了两种语义（宠物的倍率 0.9~1.0 / 敌人的基础伤害 6~13）。
修法是把语义拆开：`hitOne` 只乘 `dmgMul`（倍率），敌人 `dmgMul = 1`、`atk` 只当基础值。

**教训**：一个字段承担两种语义，迟早会在某个调用点乘两次。

### 8.2 治疗是负收益

兔子回 7 血，放弃一次 9 点伤害。而战斗被拖长一轮 = 敌人多打你一次。
实测：**"聪明"策略（会治疗）通关率 20%，"无脑"（只输出）90%**——完全反了。

修：回血 7 → 12，顺手解定身。改完"聪明"才重新比"无脑"强。

**教训**：治疗类技能的水平必须和"这一回合的伤害"对齐，不能凭感觉给一个"看起来合理"的值。
判断标准是 **1 次治疗 ≈ 1.5 次普攻的等价血量**。

### 8.3 护盾漏 1 点血

```js
dmg = Math.max(1, Math.round(dmg));   // 在护盾结算之前
```

`Math.max(1, ...)` 的保底放在了护盾吸收前面，999 点护盾也每次都漏 1 血，
「汪汪」给的 14 护盾等于不存在。修法是把顺序排成 **会心 → 减伤 → 护盾 → 保底**。

### 8.4 资源就绪判定靠计数器

```js
if (--assetsLeft === 0) { /* 全部到齐，开始合成 */ }
```

只有 onload 保证异步时才成立。任何一张图同步就绪（缓存、data URI、测试桩），
第一张加载完就误判"全部到齐"，随后 `bake(undefined)` 直接崩。
改成按「实际到齐数量」判定，同步异步都对。

### 8.5 空目标读属性

`say(text, u)` 里直接读 `u.x`，而目标是 null 时会崩 —— 只在"刚好打死最后一只"时触发。
守卫要放在**单一入口**（`petAct`）而不是每个技能里各写一遍。
