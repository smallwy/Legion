# CR-021 · 格子阵型 + 全自动战斗

> 触发反馈：**「不太行啊 首先界面布局 横版都重叠了 界面也太low 你可以搞个格子 占位格子里面 战斗时全自动施法的」**

三条问题，我按"是不是同一个根因"拆开看：

| 反馈 | 根因 | 处理 |
|---|---|---|
| 横版都重叠了 | 单位坐标按数组索引硬算，4 只以上必然互相压住 | 改成**固定格子锚定** |
| 界面太 low | HUD/卡片没有信息层级，全靠大色块堆 | 重做战斗 UI + 编队界面 |
| 要格子 + 全自动 | 手动点技能与"上阵多只宠物"的定位冲突 | 战斗改为**全自动施法** |

第三条是**设计层的**，不只是界面：一只一只手动点技能，5 只宠物就是 5 倍的点击量，
而"摆阵型"这件事本身已经提供足够的决策量。全自动之后，玩家从"操作员"变成"教练"。

---

## 1. 格子：为什么重叠，怎么修

改之前：

```js
p.hx = 250 + col * 62 - row * 8;   // 按数组索引算
p.hy = 320 + row * 66;
```

两个问题叠在一起：

- **索引取模**：`row = i % 3`，第 4 只回到第 0 行，只靠 `col` 的 62px 错开——不够一个身位
- **没有边界**：`col` 到 2 就是 x=374，而敌人在 x=700 起，中间没有隔离

改成格子：

```js
const GRID = {
  rows: 3,
  rowY: [178, 284, 390],      // 后 → 前，行距 106
  rowSc: [0.84, 0.94, 1.04],  // 透视：前排画大一点
  petX: [162, 274],           // 我方两列
  enemyX: [666, 780],         // 敌方两列
};
```

单位**只认格心**（`hx/hy`），出手动画只动 `x/y` 的临时值并在结束时归位，
所以无论几只都不会重叠。索引统一为 `row * 2 + col`，**编队界面和战斗共用同一套编号**。

单位尺寸也改成由格子决定，不再用 `unitScale(y)` 的连续缩放：

```js
p.dispSize = p.def.size * p.sc * 0.82;   // 0.82 保证最宽的野猪也塞得进 104px 的格子
```

### 站位必须真的有影响

只画格子而不让它影响战斗，等于给玩家一个假的选择。三处接线：

| 单位 | 行为 |
|---|---|
| 野猪（brute） | 固定撞**最靠前**（x 最大）的那只 |
| 普通敌人 | 75% 优先咬前排两只 |
| 熊/浣熊（ward） | 在场时其他敌人减伤 30%，强迫你换目标 |

> ⚠️ **踩到的坑**：野猪原本写的是 `sort((a,b) => a.x - b.x)[0]`，x 最小的取第一个。
> 我方 x 越小越**靠后**，所以它一直在撞最后排——站位的意义刚好反了。
> 修方向之后，"前排谁站"立刻从装饰变成全局最重的决策。

## 2. 全自动施法

### 攒满就出手，但要错开

```js
if (p.atb >= ATB.full) {
  if (S.castGap > 0) continue;      // 同帧五只一起放，屏幕会糊成一团
  autoCast(p);
  S.castGap = 0.24;
}
```

`castGap = 0.24s`：不是冷却，是**视觉上的可读性**。没有它，五只宠物的技能特效
会在同一帧砸下来，谁也看不清谁打了谁。

### 自动选技的三条判据

```js
if (sk.target === 'allAllies' && alive.length >= 2 && teamK < 0.62) return sid;
if (sk.target === 'allEnemies' && foeN >= 2) return sid;
if (sk.target === 'self' && hpK < 0.55) return sid;
```

不这么写的话，`skills[0]` 就是永远的第一招，功能位（兔子/鸭）等于不存在。

`alive.length >= 2` 这一条是踩出来的，见 §4 治疗死锁。

### 顿帧替代慢放

手动模式那套「有人待选 → 全场 16% 慢放」在自动模式下没有意义（没人需要想）。
改成出手瞬间的顿帧：`S.hitPause = 0.055`，期间 `timeScale = 0.32`。

节奏比匀速清楚得多，而且不打断观战。

## 3. 界面重做

不是"换个颜色"，是把信息层级重新排一遍。

### 战斗界面

| 区块 | 之前 | 现在 |
|---|---|---|
| 顶部 HUD | 一行文字挤在一起 | 左侧粮袋胶囊 / 中间 5 节点深度路线（带连线）/ 右侧自动战斗标识 |
| 底部队列 | 138×96 卡，只够放名字和血条 | 172×100 卡：头像 + 名字 + **当前会放什么技能** + 血条（带数值）+ 20px 高行动条（带百分比） |
| 技能面板 | 右下角 3 个按钮 | **删掉**，换成一行说明 |
| 战斗日志 | 无 | 两侧阵型之间的空档，最近 3 条，越旧越淡 |
| 战场 | 只有森林 | 森林 + **格子**（前排暖 / 后排冷）+ 四边压暗 |

「当前会放什么技能」是这次最有用的一处信息：全自动之后玩家看不到操作，
但能通过这张卡知道"兔子现在会放踢还是蹭蹭"，自动施法就不再是黑箱。

### 编队界面

左边**站位格子**（2 列 × 3 行，只出 5 格），右边宠物池（5 张竖卡）。
点卡片上阵/下阵，点格子里的一只再点另一格可以换位。

> 为什么只画 5 格：池子就 5 只宠物，画 6 格会让玩家以为"还能再带一只"，
> 然后把最后一格空着反复琢磨。少画一格比多画一格干净。

**坐标只算一次**：`rosterPool()` / `rosterCells()` / `trailButtons()` 都返回带 `x,y,w,h`
的对象，绘制和点击**共用同一份**。之前的写法是绘制写一套坐标、点击再写一套，
只要改了一处，就会出现"点不准"这种最难查的毛病。

## 4. 三个 bug，都不报错

### ① 函数重名 → 自动战斗静默失效

`chooseSkill` 定义了两次：新的自动选技 `chooseSkill(p)` 和旧的手动选招
`chooseSkill(skillId)`。后者把前者整个覆盖，返回值是 `undefined`。

后果一路传到渲染层才炸：

```
SKILLS[undefined].name  → Cannot read properties of undefined
```

离根因已经很远了。修法是给手动那个改名为 `manualPickSkill`，并加一条回归锁住它：

```js
ok(typeof P._chooseSkill(p) === "string", "自动选技不能返回 undefined");
```

**教训**：JS 的函数重名不报错，只静默取后定义的那个。改名后应当全项目搜一遍。

### ② 治疗死锁 → 一局打到 3200 秒

只剩一只 12 血宠物打一只 13 血敌人，打了 **1281 次出手**还没结束。

真因：`chooseSkill` 里 `teamK < 0.62` 就选群疗 —— 只剩一只时它是在给自己回血，
用一次出手换一次不挨打，敌人也在攒条，双方血量纹丝不动。

修了两处：

1. 群疗必须有"群"：`alive.length >= 2`
2. 战斗超时兜底：`BATTLE_TIMEOUT = 75s`，到点按剩余血量比例判

第二道是真的必要 —— 全自动战斗里玩家没法"换个打法"，一旦僵住就永远出不来。
手动战斗可以靠玩家操作脱困，自动战斗不能。

### ③ boss 全体横扫 → 人越多越吃亏

原来 `e.atk * 0.72` 打每个宠物，5 只队伍挨的总伤害比 4 只高 25%，
结果"多带一只"反而更容易团灭。

改成总伤害恒定、按存活人数平分：

```js
const share = 3.0 / Math.max(1, cands.length);
```

## 5. 实测

`node tools/forest-smoke.js` → **123 / 123**

`node tools/forest-balance.js`（每格 40 局）：

| 配置 | 通关 | 团灭 | 到第 5 层 | 出手 | 带回食物 |
|---|---|---|---|---|---|
| 5 只 · 顺序站位 | 100% | 0% | 100% | 79 | 43 |
| **5 只 · 坦克在前** | **100%** | 0% | 100% | 47 | 46 |
| **5 只 · 脆皮在前** | **0%** | 100% | 100% | 14 | 13 |
| 5 只 · 坦克在前 + 喂 | 100% | 0% | 100% | 41 | **49** |
| 4 只 · 坦克在前 | 100% | 0% | 100% | 35 | 43 |
| 3 只 | 0% | 100% | 0% | 32 | 7 |
| 单猫单刷 | 0% | 100% | 0% | 6 | 0 |
| 4 只 · 无治疗位 | 0% | 100% | 100% | 11 | 7 |

单场战斗（深度 1，3 只队）中位 **15.3 秒 / 9 次出手**。

### 关于"100% 通关"

这不是难度失控，是**容错型难度**的必然形态。

全自动意味着玩家没法临场救场，所以胜负几乎是阶跃的：站位对了就稳过，
把仓鼠放前排就雪崩，中间地带很薄。

对休闲宠物题材来说这个形态是可接受的 —— 它不惩罚手速，只惩罚错误决策。
真正必须保证的是**错误配置必须输**，否则这些决策全是装饰。所以判据写成了：

- 站位是真决策（坦克 100% vs 脆皮 0%）✓
- 人数有影响（5 只 100% vs 3 只 0% vs 单刷 0%）✓
- 治疗位是刚需（100% vs 0%）✓
- 好配置能稳过（100%）✓
- 喂食有收益（带回 46 → 49 份）✓

顺带看出一件事：**顺序站位出手 79 次才赢，坦克在前只要 47 次**。
站位不影响"能不能赢"，但影响"赢得有多难看"——这个差异比通关率更有意思，
后面可以拿它做评分（剩余血量、出手数）。

## 7. 同步到 Cocos 要动什么

| 模块 | 改动 |
|---|---|
| `BattleConfig.ts` | 新增 `GRID`（行/列坐标、缩放）、`BATTLE_TIMEOUT` |
| `HeroSquad.ts` | 站位改成格子索引；删掉"选招"相关的 `await`/`aiming` |
| `AbilitySystem.ts` | 新增 `chooseSkill()` 自动选技 + `autoCast()` |
| `BattleDirector.ts` | `castGap` 出手间隔、`hitPause` 顿帧、`battleRealT` 超时 |
| `EntityRenderer.ts` | 单位锚点改格心；格子底板（1 Graphics 画全部格子） |
| `BattleHud.ts` | 重做：顶部 HUD + 底部队列（含"当前会放的技能"）+ 战斗日志 |
| 新增 `RosterPanel` | 编队格子 + 宠物池 |

**DrawCall 估算**：格子底板 1 个 Graphics、单位每个 1 Sprite、HUD 若干。
静态约 **13~16**（验收线 20）。压暗边用 4 个 Graphics（也可烘成一张图，更省）。

**关键约束不变**：Cocos 侧没有 Canvas 的 `source-in`，描边要么让美术出带描边的图，
要么写 `ImageAsset` 像素级 alpha 膨胀。原型里那套离线描边不能直接搬。
