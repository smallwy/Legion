# CR-022 · 向《雪人兄弟》借机制：调研、诊断与融合方案

> 提出日期：2026-10-20
> 用户原话：**「可以融合雪人兄弟这个游戏做一定的玩法微创新吗，或者结合当前的立项做个深度调研，我想做雪人英雄这类的关卡元素」**
> 本文性质：机制调研 + 设计提案，**未改任何代码**。拍板后才进原型。

---

## 0. 结论先行

1. **能融合，而且比想象的更贴合。**《雪人兄弟》的核心不是「雪」，是**把敌人变成可推的物体**这一条。这条正好接住立项里 `系统 A：老实牛——完全不能移动，靠玩家走位带它` 那个一直没落地的设想。
2. **但必须换掉它的骨架。** 原版是「50 关线性 + 命数 + 超时即死」，直接违反立项三条红线中的第 1、2 条。我们拿它的**动词和关卡元素**，不拿它的**推进结构和惩罚结构**。
3. **诊断出一个更要紧的问题**：`forest.html` 第 3051 行写着「全自动战斗里没有按键操作」，而立项 §1.3 玩法公式写的是「玩家只走位」。**CR-021 把玩家从战斗里踢出去了。** 你想加入雪人兄弟，我判断真正的原因是想让手上有活干，而不是想要雪。
4. **推荐先做一件事**：一个单屏空地原型（约 1 天量），只验证「喷→裹→推→卷→收」五拍手感成不成立。手感不成立，后面所有关卡元素都不用谈。
5. **六个角色任选、一局只带一只**（18:20 定稿）。没有「主战单位」、没有「主人」、也没有战斗中换人 —— 出门前挑一只，这一局就是它。**单角色反而把差异化从可选项变成硬指标**：既然整局只能用一个，六种「喷」必须长得完全不一样（六条弹道形状各不相同，不是换数值）。详见 §3.3。

## 1. 调研：《雪人兄弟》到底好玩在哪

### 1.1 事实层（多来源交叉，已确认）

| 项 | 内容 |
|---|---|
| 出处 | Toaplan（东亚企划），1990 街机 / 1991 FC |
| 结构 | 50 层，5 场景 × 10 层，每 10 层 BOSS |
| 场景 | 冰雪 → 火焰 → 机械 → 暗黑森林 → 炙热城堡 |
| 操作 | 左右移动 + 跳跃 + 射击，**只能向上跳，不能穿过平台向下** |
| 视野 | **单屏固定**，无滚动 |
| 核心 | 持续喷雪 → 敌人逐层被裹 → 成雪球（无敌，打不死）→ 推动 → 滚撞其他敌人 → 连锁 |
| 雪球 | **滚动中撞到敌人会变大，越大越强**；撞墙反弹 |
| 敌人差异 | 有的要吃多下才裹住、有的裹成球后特别沉难推、**有的会主动破坏你的雪球** |
| 限时 | 约 90 秒，超时出无敌南瓜怪 + 幽灵追杀 |
| 道具 | 红=移速 / 蓝=积雪速度+球体积 / 黄=射程 / 绿=短暂无敌+变大碾压 / 气球=浮空 / 1UP |
| 陷阱 | 冰面（滑，易失控）、弹簧台、熔岩、尖刺 |
| 地形交互 | **砖块能被雪球击碎，砸开新路** |
| 全清奖励 | 一球清全屏 → 掉大量加分道具 + 1UP |

> 一个待你确认的点：你说的「雪人英雄」如果不是 Snow Bros 系列（比如指 2024 年的 *Snow Bros. Wonderland* 重制，或者另一款同名手游），跟我说一声，我重做对标。下文一律按 Snow Bros 原版机制为准。

### 1.2 它真正的设计内核（这一节是重点）

大多数人对它的记忆是「喷雪变球推出去」，但**让它 30 年后还能出重制版的原因，是它把「输出」和「决策」拆给了两个不同的按键**：

```
喷（B 键，连续）      →  纯输出，不需要判断，可以无脑按住
推（方向键，一次）    →  纯决策，一下定生死，推错就亏
```

这个拆分带来三个结果：

- **门槛极低**：喷不需要瞄准精度，只要方向大致对。
- **上限极高**：推的方向、时机、位置决定这一球能带走 1 只还是 5 只。
- **失败很便宜**：喷错了没关系，推错只是球滚走，重来一次。所以新手敢乱按，高手才需要算。

**这是它比同期「纯射击清版」（如魂斗罗）更适合休闲定位的根本原因** —— 它给了玩家一个「不用瞄准的高频动作」和一个「必须思考的低频动作」。

### 1.3 一条容易被忽略的设计：球是「限时资产」

被裹住的敌人**不能被普通攻击打死**，只能推。而球放着不管会化开，敌人复活。

这就制造了一个持续的小压力：**你每裹住一个敌人，就欠了一笔必须在几秒内处理完的债**。你不能只喷不推，也不能攒一堆球慢慢来。屏幕上的球越多，压力越大。

> 这条是「节奏」的来源。没有它，玩家会退化成站桩喷雪。

### 1.4 关卡元素的真实作用（不是装饰）

把这些元素按「它改变了玩家的什么决策」分类，才能判断哪些值得抄：

| 元素 | 它改变的决策 | 价值 |
|---|---|---|
| 单向平台 | 上去就下不来 → 落点选择变重 | ★★★ 结构性的 |
| 冰面 | 刹车失灵 → 推球要提前量 | ★★★ 手感层，最省钱 |
| 砖块可击碎 | 球能开新路 → 路线不是固定的 | ★★★ 让球有了第二个用途 |
| 火焰（融球） | 球有死亡区 → 推之前要看地形 | ★★☆ |
| 弹簧台 | 跨层，能救「上不去」 | ★★☆ |
| 尖刺/熔岩 | 踩到就掉血 → 走位有成本 | ★★☆ |
| 传送门 | 球也能进去 → 涌现 | ★★☆ 双刃剑，难调 |
| 移动平台 | 时机 | ★☆☆ 开发贵，收益低 |
| 限时南瓜怪 | 强制推进节奏 | ☆☆☆ **不动，违反红线 2** |

**结论**：优先抄「单向平台、冰面、可击碎砖块」这三样，它们成本最低、改变决策最多。限时惩罚坚决不要。

## 2. 诊断：现在的问题不在「战斗不够花」，在「玩家没事干」

### 2.1 事实

| 来源 | 说的是什么 |
|---|---|
| 立项 §1.3 玩法公式 | 「玩家只走位，多宠自动施法捕杀」 |
| 立项 §2.1 流程图 | 「玩家：WASD 走位 + **F 喂食**」 |
| 立项 系统 A（老实牛） | 「完全不能移动，**靠玩家走位带它**」 |
| 立项 系统 C（护主） | 「**玩家被击中** → 最近的宠物冲锋过去」 |
| `forest.html` 3051 行 | 「**全自动战斗里没有按键操作**」 |

**立项假设玩家在场上；CR-021 把玩家移出了场。**

### 2.2 后果

玩家在战斗里能做的事只剩「看」，决策全部前移到开打前的编队格子。这带来两个连锁问题：

- **战斗时长被浪费**：一场 15 秒，玩家 0 次输入。这 15 秒对留存没有贡献。
- **「半饿最强」这类系统失去载体**：它要的是「你在战斗中要不要保持半饿」的临场纠结。玩家不在场，就只剩下开打前调一个滑块。

### 2.3 所以雪人兄弟给的不是「新玩法」，是「一个动词」

玩家需要的是**一个高频、低门槛、但每次都要判断方向的动作**。雪人兄弟的答案是「推」。

而「推」在觅食题材里有一个天然的第二用途 —— **推回家**。这一条是原版没有的，也是我们微创新的入口。

## 3. 融合方案：从「喷雪裹球」到「打包搬运」

### 3.1 一句话

> **宠物负责把猎物「打包」成球，玩家负责把球「推」向敌人（清场）或推向营地（收货）。球是这一趟唯一的产出，也是唯一的武器。**

### 3.2 核心循环：原版四拍 → 我们五拍

```
【原版 Snow Bros】
  喷 ──→ 裹 ──→ 推 ──→ 滚撞连锁
  (持续)  (无敌物)  (一次决策)  (变大变强)

【PAWPACK】多出第五拍
  喷 ──→ 裹 ──→ 推 ──┬──→ 滚撞连锁 ──→ 球变大
  (宠物自动)  (自动)   │
                     └──→ 滚进营地 ──→ 变收成
                          ↑
                    每一推都在两件事之间选边
```

**第五拍「收」就是微创新所在。** 原版的球只有一种去向（撞），我们的球有两种去向，而且两者互斥：

| 推向 | 得到 | 失去 | 什么时候该选 |
|---|---|---|---|
| **推向敌人** | 连锁，球变大，一次清场 | 球会滚远，可能滚出场外或卡进泥里 | 场上还有 3 只以上敌人 |
| **推向营地** | 立即落袋为安，结算成食物 | 放弃了这次连锁，剩下的敌人还要再打 | 时间快到了 / 血不多了 / 场上只剩 1 只 |

这个取舍**每一推都要做一次，一次只要 0.5 秒**。它比「开打前调一次站位」高频得多，而且是纯手感的，不需要读数字。

### 3.3 一只出战：为什么砍掉接棒制

> **本节是 2026-10-20 18:20 用户第二次拍板后的定稿。之前两版都作废。**
>
> | 版本 | 方案 | 为什么死 |
> |---|---|---|
> | v1 | 玩家 = 「牧羊人」，宠物退成炮台 | 用户：「这个是主线玩法哦 应该不行吧」—— 主线主角必须是宠物，不能凭空多出一个世界里没有的角色 |
> | v2 | 接棒制：六只全在场，1–6 随时换 | 用户：「还是只用一个作为战斗角色吧 不同的角色 都可以选上战斗 只能选一个」 |
> | **v3（当前）** | **一局只带一只，六只任选，六种「喷」手感完全不同** | ← 定稿 |

规则压到一条：

> **出门前挑一只，这一局就是它。没有换人，没有跟随。**

这不是把 v2 砍小了，是**把复杂度从「同时管理」挪到「选择之前」**：

| 维度 | v2 接棒制 | **v3 单角色** |
|---|---|---|
| 战斗中要管几个东西 | 六只的状态 + 换人时机 | **一只** |
| 「选谁=选玩法」落在哪 | 战斗中按 1–6 试 | **出门前那一次选人** |
| 换手感的成本 | 按个键 | 重开一局 |
| 六个角色的差异要求 | 可以相似（反正随时换） | **必须一眼能看出来**（换角色就是换游戏） |
| 和《雪人兄弟》的距离 | 远（原版只有一个雪人） | **近**（原版就是一个角色一套手感） |

**关键结论：单角色反而把「差异化」从可选变成了硬指标。** 既然玩家整局只能用一个，这六种「喷」要是长得像，选人就退化成选颜色。

所以六个角色的**弹道形状本身不同**，不是同一颗子弹换数值：

| 角色 | 标签 | 弹道 | 手感一句话 |
|---|---|---|---|
| 尖耳猫 | 三连毛球 | 扇形三发（vy −105 / 0 / +105） | 覆盖宽，射程短 |
| 短尾犬 | 声波撞击 | `kind: wave` 宽波 + pierce | 最贴身的距离，一下糊两格宽 |
| 胖仓鼠 | 坚果弹 | vx 940 高速穿透 | 射得最远，能一路穿后排 |
| 长耳兔 | 萝卜炮 | `kind: lob` 抛物线（grav 1400，aoe 74） | 抛射落点炸一片，能越过木桩 |
| 老实牛 | 牛角顶 | r 34 超宽贴身判定 | 站着就是墙，靠身体糊 |
| 影狐 | 影刃 | vx 780 `kind: blade` | 最快，贴身切 |

#### 3.3.1 单角色带来的硬问题：死了怎么办

v2 的答案是「自动切下一只」。v3 没有下一只，所以回到**血量 + 短暂无敌**：

- 3 点血，被咬 / 被火坑烫各扣 1，扣完这一局结束（带回一半收成）
- 受击后 0.9 秒无敌闪烁，防止连击秒杀
- 火坑对玩家也是伤害源 —— 它同时是「收成加倍点」和「危险区」，这一层是免费的

原型实测（`grove-smoke.js` 10b）：机器人用默认 3 血也能清场，说明**开局不会被秒**，难度下限是安全的。

#### 3.3.2 差异化的第二阶段：六种「推」

弹道只是第一层。真正拉开差距的是**它们怎么处理一颗已经在滚的球**（原型只做了第一层，这层是设计预留）：

| 角色 | 推球表现 |
|---|---|
| 尖耳猫 | 推出去带角度偏转，能拐弯撞侧面的人 |
| 短尾犬 | 推得慢但撞得狠，一次多糊一层 |
| 胖仓鼠 | 能把球**吞进颊囊**，走到营地再吐出来（远距离搬运） |
| 长耳兔 | 推得最远，但自己一碰就飞 |
| 老实牛 | **推不动球**；但能撞碎枯木桩，靠球自己滚过来撞它 |
| 影狐 | 推完闪回推之前的位置（无伤接力） |

> **原型当前只做了弹道差异，第二层没做。** 先看弹道够不够撑起「换个角色就是换个游戏」这句话 —— 不够再上第二层。

#### 3.3.3 顺带解决的事：寻路需求归零

v2 的跟随方案是「直接朝目标 lerp，忽略碰撞」，现在不需要了，但它留下一条结论：**这类玩法最容易失控的是平台寻路**。

单角色把场上需要寻路的单位压到 1 个。敌人只需巡逻 / 直冲 / 飞行三种，都不需要 A*。这是单角色在技术侧最大的隐性收益。

### 3.4 「推」的四条规则（原版保留，逐条对上）

| 原版规则 | 我们保留 | 理由 |
|---|---|---|
| 球会滚，撞墙反弹 | ✅ 保留 | 反弹制造意外，是乐趣不是 bug |
| 滚撞敌人 → 敌人被卷进去，球变大 | ✅ 保留 | 「滚雪球」在字面上就成立了 |
| 球放着不管会化开，敌人跑掉 | ✅ 改成「松开」 | 制造「欠债必须还」的节奏压力 |
| 被裹住的敌人打不死 | ✅ 保留 | 否则玩家会用输出硬解，绕过整条链 |

### 3.5 和「半饿最强」怎么咬合（这是白送的）

立项 §2.3 系统 B 现在有了一个**动作级**的载体，不再只是数值面板：

| 饱食度 | 打包速度 | 球的初始体积 | 风险 |
|---|---|---|---|
| 满饱 | 慢（稳） | 小 | 安全，但一球撞不死两只 |
| **半饿** | **快（×1.5）** | **大** | **球更容易中途松开** —— 这是代价 |
| 全饿 | 极慢 | 小 | 宠物会中途跑去啃球，把战利品吃掉 |

这条设计让「喂不喂」变成一个**战斗中随时要做的决定**，而且它的后果直接体现在手感上（不是数字上）。这正是立项要的「两线的张力由这一条建立」。

### 3.6 三条红线的校验

| 红线 | 本方案是否违反 | 说明 |
|---|---|---|
| ① 不做线性关卡线 | **不违反** | 单屏空地是「地点里的一个区」，不是「第 N 关」。清完 = 这片林子今天搜刮过了，明天可再来 |
| ② 不做失败惩罚 | **不违反** | ①被撞 = 手里的球掉了，不是死；②时间到 = 「收工钟声」，没推进营地的球丢在原地，人安全回家；③宠物倒地 = 「饿晕」，喂食即回 |
| ③ 不做大地图 | **完全符合** | 单屏固定场景正是原版的结构，也正好是红线要的「一屏」 |

> 提示：如果保留原版的「超时出无敌南瓜怪追杀」，红线 ② 立刻破。**这一条必须砍。**

## 4. 关卡元素清单（PAWPACK 化）

原版的元素是冰雪主题的。逐个翻译成森林/觅食，**同时给每一个绑定一条决策**，不做纯装饰：

| # | 原版 | PAWPACK 版 | 视觉 | 它逼玩家做什么决定 | 优先级 |
|---|---|---|---|---|---|
| 1 | 单向平台 | **树枝 / 树根** | 横枝 + 苔藓 | 上去就下不来，落点要想 | P0 |
| 2 | 冰面 | **落叶堆** | 一堆橙黄落叶 | 刹车失灵，推球要提前半格松手 | P0 |
| 3 | 可击碎砖块 | **枯木桩** | 裂开的短桩 | 球撞碎它 = 开新路 + 掉野果 | P0 |
| 4 | 火焰融球 | **沼泽泥坑** | 冒泡的深色泥 | 球滚进去就卡住，路线有禁区 | P0 |
| 5 | 尖刺 | **荆棘丛** | 深紫带刺 | 撞上去掉手里的球 | P1 |
| 6 | 弹簧台 | **弹菇** | 大蘑菇 | 上高台救场 | P1 |
| 7 | 药水 | **野果**（红/蓝/黄/绿） | 四色小果 | 红=移速 蓝=打包快 黄=推得更远 绿=短暂无敌 | P1 |
| 8 | 传送门 | **兔子洞** | 洞口 + 草 | 球也能滚进去 → 路线涌现 | P2 |
| 9 | 移动平台 | **漂木 / 藤蔓** | — | 时机 | P3（贵，先不做） |
| 10 | 限时南瓜怪 | **收工钟声** | 天变橘色 | **砍掉惩罚，只改结算** | — |

### 4.1 一条建议：前三天只做 1、2、3

理由是：这三个加起来只需要「平台 + 摩擦 + 可破坏体」三套最基础的东西，但已经能造出「这球该不该推、往哪推」的全部纠结。做了 1-3 之后再判断要不要 4-8。

## 5. 三种接入方式（需要你拍板）

| | A. 替换主战斗 | B. 并存为辐条 | C. 只在现有战斗里加球 |
|---|---|---|---|
| 做法 | 远征 = 一连串单屏空地 | 保留 ATB 战斗，另开「搜刮」玩法 | 格子战斗里加入「可推的球」 |
| 玩家手上 | 全程走位 + 推 | 两种玩法切换 | 战斗中多一个推的动作 |
| 与立项契合 | 高（就是 §1.3 的「走位」） | 最高（Hub-and-Spoke 本来就要多辐条） | 中 |
| 开发量 | **最大**，等于重写战斗层 | 中（新玩法独立，不动旧代码） | 小 |
| 风险 | 现有 4 版原型全部作废 | 两个玩法都要维护，内容量翻倍 | 可能两头不讨好：ATB 的节奏容不下推球的实时感 |
| 我的建议 | 手感验证通过后走这条 | 想稳就走这条 | **不推荐**，ATB 是回合推进，推球是实时物理，硬塞会打架 |

> 我的倾向：**先做手感验证（A 的第一步），再决定落在 A 还是 B**。因为 A 和 B 的第一天工作量是一样的 —— 都是做一个单屏空地。

## 6. 风险与代价（说实话的部分）

### 6.1 设计风险

| 风险 | 严重度 | 缓解 |
|---|---|---|
| **cozy 定位被操作难度破坏** | 高 | 不做命数、不做超时惩罚、球松开是「敌人跑掉」不是「你死」。所有失败都是「收获变少」 |
| **「推」变成唯一最优解**（比如永远推回家最稳） | 高 | 数值上让「一次撞 3 只」的收益明显高于「推回家 3 次」。需要平衡采样验证 |
| **两个玩法都不够深**（如果选 B） | 中 | 选 B 的话，搜刮玩法要能独当一面，不能是附属小游戏 |
| **单屏关卡的设计成本高** | 中 | 原版 50 关是 8 个人做的。我们做 3 个地点 × 2 个空地 = 6 张，靠元素组合出变化 |
| **宠物在平台关卡里怎么跟随** | 中 | 这是个真问题，见 6.3 |

### 6.2 Cocos 技术侧（我的本行，说清楚取舍）

| 需求 | 推荐做法 | 不推荐 | 理由 |
|---|---|---|---|
| 平台碰撞 | **自己写 AABB + 单向平台判定** | 2D 物理刚体 | 雪人兄弟的手感（跳跃高度、落地、单向穿越）是手工调出来的，刚体会带来不可控的弹性与摩擦 |
| 球滚动 | **自己写速度积分 + 边缘检测** | `RigidBody2D` 圆形刚体 | 刚体滚球会出现「原地打转」「贴墙抖」，而且连锁时机不可控 |
| 落叶堆打滑 | 摩擦系数插值，`vx *= 0.995` vs `0.82` | 物理材质 | 同上，参数要能手调 |
| 可击碎砖块 | 碰撞时置 `broken=true` + 播放碎块粒子 | 真正的刚体碎裂 | 视觉足够，成本低一个数量级 |
| 渲染 | **1 个 Graphics 画所有地形**，单位用 Sprite | 每个砖块一个节点 | 沿用 CR-018 的 DrawCall 纪律：目标 < 20 |
| 点击/按键 | 键盘（Web）+ 虚拟摇杆（小游戏） | — | 立项要出 Steam + 小游戏，两套都要 |

**代价评估**：这套东西比现在的「格子 + Graphics」重。现在的 forest.html 是 3000 行且没有物理；加平台跳跃 + 推球物理，预计 +1200~1600 行。**这是个真实的成本，不是一句「改一下」能带过的。**

### 6.3 一个还没想通的问题（我承认没底）

**宠物在平台关卡里怎么表现？**

- 如果宠物跟着玩家跳 → 6 只宠物在平台上挤成一团，碰撞和寻路都很难看
- 如果宠物固定在平台上当炮台 → 玩家的走位就变成了「去哪个炮台旁边」，还成立，但少了跟随感
- 如果宠物在地上走、只在自己的平台范围内活动 → 最像原版的「敌人」，画面最干净

我倾向第三种（宠物是「布阵的炮台」，玩家在平台间跑动串联它们），但**这条我没验证过，需要在原型里试**。这也是为什么我建议先做手感验证而不是直接写完整玩法。

## 7. 验证计划（怎么证明它对）

分三步，每步都有明确的「不通过就停」条件：

| 步骤 | 做什么 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| **V1 手感**（1 天） | 单屏空地，2 只宠物、3 只敌人、无花活 | ① 能在 30 秒内自己发现「应该推球」；② 推中连锁时有明显爽感；③ 玩家平均每 3 秒做一次「推」的决定 | 说明这条链不成立，回来重想 |
| **V2 取舍**（2 天） | 加「推回家」和第二拍结算 | 让 5 个人玩，至少 3 人出现过「犹豫推向哪」的停顿 | 说明第五拍是多余的，退回纯原版机制 |
| **V3 平衡**（2 天） | 加落叶堆、枯木桩、沼泽 | 采样 40 局/配置，验证「只推回家」胜率显著低于「先连锁再收」 | 调数值或增加推回家的成本 |

V1 我可以直接做——沙箱里有 `@napi-rs/canvas`，能离屏渲染截图，不用等你在浏览器里看。
