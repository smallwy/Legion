# CR-029 路线 B 落地 · 宠物层的成本、顺序与第一个切片

> **状态**：2026-10-21 用户拍板「走 B」，本文是执行方案，不再论证值不值得。
> **前置**：`CR-028` §6 路线 B（宠物 + 家园 + 推球，咩咩式小体量）。
> **已落地**：`client/prototype/grove.html` 的「家门口」场景与出门演出（§6）。

---

## 1. 把 B 路线压成一句话

> **养六只会饿会闹的小动物，今天带谁出门。**

这句话有三个动作，对应三个系统：

| 词 | 系统 | 现在的状态 |
|---|---|---|
| **养** | 家园：喂饭、做道具、看它们闹 | **0%** |
| **带谁** | 六只宠物的性格与解法差异 | 解法有（弹道不同），**性格 0%** |
| **出门** | 推球清野 | **做得最完整的一环** |

**B 路线不是"在推球上加一个家园"，而是把重心从"出门"挪到"带谁"。**

这是它和路线 A（$9.99 复古街机）唯一的分野：A 卖"一球清一屏"的爽感，B 卖"这只猫今天特别想出门"。

## 2. 成本核算：20 周这个数字从哪来

一人团队、全部自己写。按**可交付**估，不按"能跑起来"估。

| 阶段 | 内容 | 周 |
|---|---|---|
| **P0 性格层** | 门口 + 出门演出（**已做**）、关卡内台词、饿/饱表情与动作 | 2 |
| **P1 家园** | 一屏、六个窝、灶台喂食、收成入池 | 2 |
| **P2 半饿** | 三档火力（满饱 3 发 / 半饿 2 发 / 全饿 5 发）+ 喂多少的决策 | 1 |
| **P3 道具** | 工作台 + 6 件规则修改器（不加数值，只改规则） | 2 |
| **P4 内容** | 8 屏 → 24 屏（+16 屏），每屏 3 个目标 | 7 |
| **P5 商店与打磨** | 胶囊图、GIF、Demo、Next Fest 准备、手柄、设置页 | 3 |
| | **小计** | **17** |
| | 缓冲（一人项目的必然损耗） | +3 |
| | **合计** | **20 周** |

**和 CR-028 的估计一致。** 这不是我加码了，是 P1/P3 这两块立项书写得很细，真要实现就是这个量。

### 2.1 为什么不能"先做一半再说"

B 路线有两个循环，缺一个就不成立：

```
出门（推球）→ 收成 → 家园（喂饭 / 做道具）→ 更强的出门
```

- **只有出门**：就是路线 A 的雏形，20 周砍成 8 周也能发，但天花板回到 6,900 份。
- **只有家园**：变成纯放置养成，六只的差异没地方体现。

**中间没有"半个 B 路线"这种东西。** 所以要么接受 20 周，要么退回 A。这一点必须在开工前说清楚。

## 3. 顺序：**先做性格，最后做家园**（这一节是核心判断）

直觉上应该先搭家园（容器），再往里放宠物（内容）。**反了。**

| 直觉顺序 | 为什么错 | 本文顺序 | 为什么对 |
|---|---|---|---|
| 1. 家园 | 做出来是一个空屋子，六只站在里面没有行为，**看不出任何价值** | 1. 性格 | 直接产出可传播素材，第二天就能验证假设 |
| 2. 喂食 | 喂了没反应，等于给数值，玩家不会记得 | 2. 半饿 | 喂食有了战术含义，"喂多少"变成打法选择 |
| 3. 道具 | 道具改的是规则，但玩家还没觉得这些家伙可爱，不会为了它们做道具 | 3. 家园 | 此时性格已经成立，家园是**放大器**：给六只一个"家" |
| 4. 性格 | 到这一步才发现"性格不好笑"，前面三块全白做 | 4. 道具 → 5. 内容 | 顺序不倒，风险后置 |

> **一句话：家园是容器，性格是内容。空容器不产生价值，内容自己就能传播。**

这条判断的代价是：P3 道具和 P4 内容都排在性格验证之后，如果性格验证失败（§7），前面只亏 2 周而不是 20 周。

## 4. 内容量的杠杆：不靠堆屏数

CR-028 §7.2 算过：3 小时需要 **60-80 屏**（按现在每屏 38 秒的机器人数据）。24 屏只有 1 小时出头。

**但 B 路线不需要 60 屏。** 它可以靠"同一屏值得再打一遍"拿到时长：

| 杠杆 | 怎么产生重玩 | 成本 |
|---|---|---|
| **六角色 × 地形克制** | 枯木桩挡住所有直射 → 只有长耳兔的抛物线能越过去；窄口荆棘 → 只有老实牛贴着糊。**同一屏换一只就是另一种解法** | 已有（六角色已做） |
| **三个目标 × 同一屏** | 已有 goal 系统：限球数 / 连锁 3 / 营地过 3 只 / 收成达标 / 零崩球 / 无伤。**每屏给 1 个主目标 + 2 个挑战目标** | 数据配置，几乎零成本 |
| **道具 × 地形** | 火种让火坑不断连锁、厚泥靴防打滑 —— 同一屏带不同道具是不同打法 | P3 的 6 件道具已经覆盖 |
| **半饿** | 同一屏，喂饱了稳但造球慢，半饿造球快但脆 | P2 的三档数值 |

**24 屏 × 平均 2.5 趟 ≈ 60 屏次 × 2 分钟 ≈ 2 小时**，加家园与重试正好 3 小时。

> **这条是 B 路线相对 A 路线唯一的结构性优势**：A 加内容只能加屏（成本线性），B 加角色让旧屏重新有用（成本有杠杆）。
>
> 反过来说：**如果六只在同一屏里的表现只是"打得快慢不同"，这个杠杆就不存在**，B 路线会退化成贵一倍的 A。所以 P4 的每一屏都要明确"这张图谁最吃亏、谁最合适"。

## 5. 砍掉什么

### 5.1 砍掉「派遣板 + 系统 C 关系网」—— **2026-10-21 用户已拍板**

立项 §2.3 把它写成"唯一差异点 / 护城河"。**已砍。**

理由不是它不好，是**它护的不是 B 路线的城**：

| | 咩咩启示录真正的护城河 | 系统 C 六条关系 |
|---|---|---|
| 是什么 | 教徒**有名字、会老、会死、会叛教** | 同类相邻 +20%、异类 −15%、抢食、嫉妒 |
| 玩家感受 | "我给它起了名字，它昨天死了" | "这样摆效率高 15%" |
| 层 | **情感层** | 策略层 |

B 路线的卖点是"六只会饿会闹的小动物"。**"它们会闹"是情感层，"搭班 +20%"是策略层。** 前者才是要护的城。

而且它是立项里**成本最高、玩家最看不见**的一环（要界面、要心情图标、要计算、要图鉴）。同样两周，投在"六只在门口的反应"上，市场回报高一个数量级。

> 保留其中一条最便宜的：**「连续 3 趟只带同一只 → 其余心情↓」**。它只需要一个计数器 + 一个心情图标，却直接支撑"轮换出门"这个行为，也是性格的一部分。其余五条砍。

### 5.2 产地从 4 个减到 3 个

萤火洞留作免费更新（立项 §2.4 阶段 5 原本也是这么写的）。3 产地 × 8 屏 = 24 屏，和 §2 的排期对齐。

### 5.3 后端仍然不做

Go + Nakama 云存档/排行榜，推到"Demo 有反馈之后"。单机 3 小时的产品不需要它。

## 6. 第一个切片已落地：门口

**代码**：`client/prototype/grove.html`，`drawSelect()` + `drawHut()` + `pickHero()`。

原来这里是一张「六张武器卡」的网格 —— 那是**选武器**的界面，不是选宠物。

现在换成**家门口的夏夜**：

| 元素 | 作用 |
|---|---|
| 一间小屋、窗里有灯、门帘会摆 | 证明"它们住在这"，不是从菜单里蹦出来的 |
| 六只散在门前，各有呼吸相位 | 不同步浮动，才像活物不像摆件 |
| 悬停 → 头顶冒出**第一人称自荐** | 「我先去探路。」「路上有吃的吗？」「天黑才好办事。」 |
| 选中 → **1.62 秒出门演出** | 门为它掀开，被选中的跑进去，**其余五只各自反应** |
| 底部文案 | 「六只都在等 · 一只出门，五只看家」 |

### 6.1 五只的反应表（这才是"性格"）

| 宠物 | 没被选中时做什么 | 说什么 |
|---|---|---|
| 尖耳猫 | **扭头背对**你 | 「哼。」 |
| 短尾犬 | **追到门口**，被门挡住 | 「我也想去……」 |
| 胖仓鼠 | 头都不抬，继续吃 | 「（低头吃着）」 |
| 长耳兔 | 缩下去，整体变暗 | 「……好吧。」 |
| 老实牛 | **趴下**（横向摊开、纵向塌掉） | 「（趴下了）」 |
| 影狐 | **往后退半步**，淡进暗处 | 「（往后退了半步）」 |

**用行为，不用文字。** 文字玩家会跳着读，行为会被记住。这六条里没有一句需要读台词才能看懂。

> 这就是 CR-028 §7.3 说的「我们一个都没有」的那个东西：
> **六只挤在门口，一只被拎走，剩下五只各有反应** —— 这就是商店页 GIF 的第二帧。

### 6.2 实现上踩到的三个坑

1. **`drawPet` 内部反复改 `globalAlpha`**（影子 0.18、受击闪白、眼睛高光）。外面设一次 `globalAlpha = 0.28` 想画半透明影狐，画出来还是全不透明。改成 `o.alpha` 传进函数、内部每处 `globalAlpha` 都乘它。
2. **"趴下"不能用 `squash`**。squash 只压 14%，读起来是"蹲了一下"。真趴下要横向摊开 + 纵向塌掉，用 w/h 比值（`wMul 1.2 / hMul 0.54`）。
3. **气泡会叠**。狗追到门口会挤在猫旁边，两条气泡同高就是一团糊字。按索引奇偶分两条高度道。

另外一个几何约束：**出门那只最后停在门洞正中，全不透明会把门糊死。** 跑动末段（62%）就要开始淡出，跑到门口时已经半只身子在门里。

## 7. 验收：什么情况下说明 B 不成立

性格层做完（P0，2 周）**立刻做一件事，不要等 20 周**：

> **出两张胶囊图 + 两段 8 秒 GIF，跑商店页 A/B。**

| 版本 | 第一眼 |
|---|---|
| A | 一只猫在喷毛球，球在滚 |
| B | 六只挤在门口，一只被拎走，剩下五只各有反应 |

判据：

| 结果 | 结论 | 动作 |
|---|---|---|
| B 明显高于 A（愿望单转化 ≥ 1.5 倍） | 性格层成立 | 按 §2 排期全速做 |
| A ≈ B | **"宠物"这层没做出来** | 停止扩家园，回去做性格，或退回路线 A |
| B 明显低于 A | 玩家要的是"爽"不是"萌" | 直接转路线 A（现有代码 3-4 周可收尾） |

**这个测试成本是 2 天，收益是省掉 18 周的错误投入。** 现在所有判断（包括本文）都是模型推算，只有点击率是硬数据。

## 10. 第二个切片已落地：把性格带进关卡，把"趟"变成选择

**代码**：`client/prototype/grove.html`。**冒烟 358 项**（`ALL9=1` 时 368 项）全绿。

第一个切片解决了"门口那 1.6 秒"，但**一进关，六只就退化回六个弹道不同的发射器**。
玩家推完 8 关，记不住任何一句它说过的话 —— 那 B 路线就只剩一个壳。

这个切片补三件事，全部围绕同一个问题：**出门那段时间里，它们还是不是活的？**

### 10.1 关卡内台词：三个触发点，一处不刷屏

| 触发点 | 时机 | 为什么选它 |
|---|---|---|
| `first` | 这一关第一次推出一颗球 | 核心动词，玩家刚做完一件新事 |
| `big` | 一球卷走 ≥3 只 | 爽点，说完正好看清飘字 |
| `hurt` | 只剩 1 滴血时挨打 | 玩家注意力最集中的一刻，那句被记住 |

**每关每句只响一次。** 结算面板那句单独写（`finishSay`），并且**跟饿不饿绑**：
满饱是邀功（"这一片我先看过了。"），半饿是嘴硬（"还走得动。"），全饿是求饶（"先……先回家吧。"）。
同一只猫，饿和饱说话不是一个调 —— 这是这次最便宜、最有效的一处。

六句不同的话，不是一张通用文案表：

```
cat  我先去探路。 / 一起带走。   / 嘶——
dog  推！推！推！ / 全抓住了！   / 呜……
ham  这个能吃吗？ / 够吃三天！   / 我的粮——
rab  我跳得过去。 / 都不用落地。 / 耳朵疼……
ox   慢慢来。     / 都在这儿了。 / ……不疼。
fox  别出声。     / 一个都跑不掉。/ ……被看见了。
```

### 10.2 越往里走越饿：饿必须有后果

出门 **100**，每过一关 **−16**。第 3 关起半饿，第 6 关起全饿，8 关推满正好见底。

| 档 | 看得见的 | 看不见的 |
|---|---|---|
| 满饱 ≥70 | 肚子圆、嘴角上扬 | — |
| 半饿 30~70 | 肚子小一圈 | — |
| **全饿 <30** | 肚子瘪 + 两道瘪纹、眼睛下垂、头顶挂「饿」牌、每 4 秒肚子叫一圈波纹 | **冲刺（K）无法使用** |

**只收走冲刺，不碰火力。** 火力（×1.5 / ×0.6）是 P2 的数值，现在提前接进来会把
"表现"和"数值"搅在一起，改一个得同时验另一个。但**饿必须有后果** ——
不然它只是贴在图标上的一个字，玩家永远不回家，"再贪一关"就不成立。

冲刺是"两段式造球"和保命的关键，收走它玩家会立刻感觉到"它真的跑不动了"，
而且这个惩罚是**可逆的、看得见的、不碰数值的**。

### 10.3 收工 or 继续：让"趟"成立

结算面板从"一个按钮 + 3 秒自动走"改成 **两个按钮 + 5.5 秒**，鼠标停在按钮上还会暂停倒计时。

```
这一趟走了 1 关 · 攒下 43 果 × 1.15 = 49
肚子 · 满饱 ████████████░░

[ 继续深入 倍率变 1.30 ]   [ 收工回家 +49 果 · 吃饱 ]
```

- **继续**：倍率 +0.15（上限 ×2.0），肚子 −16
- **收工**：`攒下的 × 倍率` 落袋，肚子回满，**进度不退回**

**倍率是"贪"唯一的收益**，而且只有收工才结算 ——
每关都回家的人永远拿 ×1.0，贪到底的人拿 ×2.0。实测同一份 3 关：
**贪到底 187 vs 每关收工 49**。这个差距足够让"再推一关"变成一个真的决定。

反过来：没有倍率，"继续 / 收工"就退化成"点哪个都一样"，那条设计等于没做。

### 10.4 家门口现在有东西了

门口屋前多了一个**果筐**，数量按 `home.loot` 分四档。这是"出门有产出"的
唯一视觉证据 —— 家园（P1）还没做，但这堆果子先让"回家"有了意义。

> 一个会变多的东西，比一个数字更能让人想"再来一趟"。

### 10.5 实现上踩到的三个坑

1. **台词气泡和饿牌都挂头顶 → 叠成一坨。** 饿牌改挂**腰侧**（语义也更对：它表达的是肚子饿），气泡独占头顶。
2. **只把肚皮改小，在 40px 的角色上根本读不出来。** 补两道瘪纹（alpha 0.62）+ 眼睛压扁 + 嘴撇下去，三处一起改才读得出来。
3. **测试桩缺 `ctx.rect`。** `drawTree` 的树干一直在用它，但**此前没有任何一条测试调 `render()`** —— 一调就炸。现在结算面板有一条"能渲染"的断言守着。
