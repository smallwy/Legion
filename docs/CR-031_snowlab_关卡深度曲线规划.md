# CR-031 · snowlab 关卡深度曲线规划（原型侧落地）

> 提出日期：2026-10-29
> 用户原话：**「没必要都是多层 可以循序渐进 你现在能把关卡设计深度规划出来吗」**
> 本文性质：规划提案。**未改动 `snowlab.html` 一行代码**，拍板后才实现。
> 前置：`CR-023`（雪人式长主线 · 四层深度模型）、`CR-022`（雪人机制调研）
> 现状依据：`client/tools/_diff-audit.js` 跑 200 个种子的审计结果（见 §1）

---

## 0. 结论先行

**能做，但第一步不是调层数，是先把"关卡序号"这个概念造出来。**

现在 `reset()` 拿到的种子是 `Math.random()`，`genLevel(seed)` 里层数是
`3 + chance(.55) + chance(.45)` —— 这两行合起来的意思是：**第 1 关和第 30 关用的是
同一张牌洗出来的概率分布**。"循序渐进"没有挂载点。

审计数据（200 个种子）：

| 指标 | 分布 | 问题 |
|---|---|---|
| 层数 | 3 层 21% / 4 层 55% / 5 层 25% | 与"第几关"无关 |
| 箱子格数 | 41 ~ 105（极差 64） | 最少的关只有最多的 39% |
| 怪数 | 9 ~ 15 | 极差 6 |
| 出铁箱的关 | **187 / 200** | 铁箱本该是"后期机制"，第 1 关就可能撞上 |
| 出追人怪的关 | **199 / 200** | 追人怪等于没有教学期 |
| 出冰墙的关 | 64 / 200（32%） | 第 1 关有三分之一的概率要求"吞一只怪才破得动" |
| 难度粗分 | 29.2 ~ 108.1（**3.7 倍**），标准差 16.6 | 随机在冒充曲线 |

**所以规划的核心不是"加层数"，是"把 15 个已有零件按教学顺序排一遍"。**
30 关之内一个新机制都不用做 —— 全用现有的。

---

## 1. 三种深度必须分开算

现在只有一个 `tierOf(k) = k / (nF - 1)`，它只管**单关内**从浅到深。
跨关卡是常数。而玩家感觉到的"变深了"其实是三件事叠在一起：

| 深度轴 | 承载什么 | 现在 | 规划 |
|---|---|---|---|
| **空间深度** | 要下几层 | 每关随机 3~5 | 随进度 2→5（关 1-4 只有 2 层） |
| **机制深度** | 同时要用的动作有几种 | 全靠 tier，与进度无关 | 按章解锁，一次一个 |
| **资源深度** | 球/弹药的规划链有多长 | 每关一样 | 随章变长（球要养得更大、拆箱更多） |

单关内的 tier 递进（地表→门厅）本身是对的，**不动它**。要动的是把 tier 的
起点和斜率挂到关卡序号上。

---

## 2. 关卡曲线（30 关 = 4 章）

用户说的"没必要都是多层"落在关 1–4：**两层的关只有 1 个内容层 + 门厅**，
一分钟能走完，正好用来教推球和拆箱。

| 章 | 关 | 层数 | 内容层 | 每层箱格 | 整关箱格 | 怪/层 | 整关怪 |
|---|---|---|---|---|---|---|---|
| 一（木屋） | 1–4 | **2** | 1 | 24 | 24 | 2 | 2 |
| 二（砖房） | 5–10 | 3 | 2 | 15 | 30 | 2 | 4 |
| 三（石洞） | 11–18 | 4 | 3 | 14 | 42 | 2~3 | 8 |
| 四（地窖） | 19–30 | 5 | 4 | 13 | 52 | 3 | 12 |

读法：**总量单调涨（24→52，2.2 倍），每层密度反而略降（24→13）。**
这不是矛盾 —— 层多之后单层要留呼吸，否则 4 层箱山叠起来满屏是箱子。
现有生成器其实已经是这个关系（3 层关每层约 19 格、5 层关每层约 16 格），
这一栏只是把它写死。

**2 层关的内容上限是物理的**：层高固定 240、宽 960 → 一层最多 20 列 × 3 格，
而"看得清路"的可用密度是 10~24 格。所以 2 层关天生是"半关"，
它只该出现在开头，不该靠 `chance()` 在后段冒出来。

层数上限锁 5：6 层要 1440 的世界高度，镜头要么拉远（角色变小）要么
可视层数变少（上下都看不见），而且每层能摊到的箱子只剩 10 列左右。

## 3. 机制解锁表（15 条，全部是现有零件）

规则：**一关只引入一个新机制**，且首现关不再叠加其他变化。

| 关 | 新机制 | 零件 | 它逼出的决策 | 物理效果 |
|---|---|---|---|---|
| 1 | 糊 → 成球 → 推 | ✓ 有 | 往哪推 | — |
| 2 | 下行口（掉下去） | ✓ 有 | 从哪个口下 | 洞宽 192~240 |
| 3 | 井梯上行（W） | ✓ 有 | 要不要回去补 | 洞口左列 3 格 |
| 4 | 石箱（要球够动量） | ✓ 有 | 先养球还是绕 | minPow 560 |
| 5 | 斜坡 / 雪包 | ✓ 有 | 上坡要助跑 | `ramp` |
| 7 | 追人怪 runner | ✓ 有 | 先清谁 | `kind:'runner'` |
| 9 | 霜箱封洞 | ✓ 有 | 拆几步才下得去 | `cover:'frost'` |
| 11 | 投掷怪 fang | ✓ 有 | 别站桩 | `breed:'fang'` |
| 13 | 冰墙（要吞怪才破） | ✓ 有 | 弹药规划 | `minTier 1` |
| 15 | 铁箱（绝对推不动） | ✓ 有 | 只能绕 | minPow 1150 |
| 17 | 半透楼板 ↓ 下穿 | ✓ 有 | 抄近路还是掉层 | `walkThrough` |
| 19 | 窄洞 96 | ✓ 有 | 落点精度 | 洞宽 96 |
| 22 | 门压两层箱 | ✓ 有 | 拆箱预算 | 门厅门 |
| 25 | 跨两层竖井 | ✓ 有 | 一次下两层 | 层间洞对齐 |
| 28 | 全混合 + 4 层箱山 | ✓ 有 | 综合 | — |

**这张表是规划里最值钱的部分**：30 关不需要新内容，只需要新顺序。
第 31 关往后（新产地深窟）才需要新零件 —— 那部分见 CR-023 §4.3 的
火坑/弹菇/兔子洞，属于 P1，不在本文范围。

> 与 CR-023 的对应关系：CR-023 的"浅层 3 屏 / 中层 4 屏 / 深层 5 屏"
> 在原型里就是"3 层 / 4 层 / 5 层"。原型是竖井式（往下掉），不是单屏横推，
> 所以"屏"直接等于"层"，不需要额外换算。

## 4. 三条编排原则

| # | 原则 | 为什么 | 落地方式 |
|---|---|---|---|
| 1 | **一关只变一件事** | 同时引入两个新东西，玩家分不清输给了哪个 | 首现关的 `boxes` / `foes` 不涨 |
| 2 | **新机制首现关要比前一关简单** | 注意力在学新东西上，这时候加量是纯挫败 | 首现关的内容量回退到上一段水平 |
| 3 | **换章才换材质/天花板/光色** | 视觉上的"新地方"是章节的锚点，不是每关的 | 沿用第七轮的 ROOM 主题（木屋/砖房/石洞/地窖） |

第四条是反向的：**同章内参数几乎不涨**，靠地形随机给新鲜感。
"每关涨一点"是最容易写、也最累人的曲线 —— 玩家感觉不到进步，只觉得越来越挤。

## 5. 两个技术陷阱（不修的话曲线白做）

### 5.1 `tierOf` 按层内比例算 → 短关更早撞硬墙

```js
const tierOf = k => (nF <= 1 ? 0 : k / (nF - 1));
```

3 层关的 tier 是 `0 / 0.5 / 1`，5 层关是 `0 / 0.25 / 0.5 / 0.75 / 1`。
铁箱门限是 `tierL >= 0.45`，于是：

| 关长 | 铁箱首次出现的层 | 相对深度 |
|---|---|---|
| 3 层 | 第 2 层 | 1/3 处 |
| 5 层 | 第 3 层 | 1/2 处 |

**短关在第 2 层就出铁墙，长关要到第 3 层。** 3 层关比 5 层关更早遇到硬墙 ——
这跟"层数多 = 更深 = 更难"的直觉正好相反。

修法：tier 改成按**绝对楼层**算，与关长无关：

```js
const tierOf = k => clamp((k + stageOffset) / 4, 0, 1);
```

`stageOffset` 由关卡序号给（关 1 时 0，关 30 时 1）。这样"铁箱出现在第几层"
在任何关长下都是同一个答案。

### 5.2 `szK` 层数补偿 → 2 层关会被铺满

```js
const szK = Math.sqrt(4 / Math.max(1, nF - 1));
```

2 层关 `szK = 2`，预算 = `20 × 0.58 × 2 = 23` 格，超过一层的可用列数。
教学关会变成"满屏箱子"，玩家既看不清路也学不会。

曲线本身已经规定了总量（§2 的整关箱格），`szK` 就多余了 ——
**删掉它**，改成预算直接读曲线表。

### 5.3 生成不可复现（已在第七轮前修掉，记一笔）

`reset()` 不带 stage 的话，`stage` 必须参与种子的派生，否则同一个种子在
不同 stage 下生成的图一样，"关卡"就退化成"换个随机数"。

## 6. 实现落点

```js
/* 曲线表。**这是唯一的难度真源** —— 层数、箱子、怪都从这里查，
   不许再有 chance() 决定层数。 */
const STAGE = [
  { to: 4,  floors: 2, boxes: 24, foes: [2, 2], chapter: 1, mech: [] },
  { to: 10, floors: 3, boxes: 30, foes: [2, 2], chapter: 2, mech: ['ramp', 'runner', 'frost'] },
  { to: 18, floors: 4, boxes: 42, foes: [2, 3], chapter: 3, mech: ['fang', 'ice', 'iron', 'through'] },
  { to: 30, floors: 5, boxes: 52, foes: [3, 3], chapter: 4, mech: ['narrow', 'door', 'shaft'] },
];
const stageOf = n => STAGE.find(s => n <= s.to) || STAGE[STAGE.length - 1];

function genLevel(seed, stage = 1) {
  const cfg = stageOf(stage);
  const nF = cfg.floors;           // 不再掷骰子
  ...
}
```

调用侧：`reset(seed, stage)`；`LEVEL_SEED = (seed ^ stage * 0x9E37) >>> 0`，
保证同一关重开是同一张图、换关一定换图。

引擎（Cocos）侧需要一份 `progress.stage`，存在本地；原型侧只用 URL 参数
或 console 手动切，验收用。

## 7. 验收

1. **`_diff-audit.js` 加 `--stages` 模式**：逐关 1..30 跑 20 个种子，验
   - 层数阶梯：`floors(n+1) >= floors(n)`，且恰好 4 段
   - 机制集合单调包含：`M(n) ⊆ M(n+1)`
   - 整关箱格/怪数单调不降
   - **同段内离散度 < 20%**（现在跨关是 3.7 倍）
2. **新断言**（`_snowlab-check.js` 第四十二组）：
   - 关 1 的箱子 **100% 是 wood**，场上无 runner、无 iron/ice
   - 关 30 的层数恒为 5
   - 同一 stage 下重开两次，`FLOORS/boxes.length` 完全一致
3. **人工验收**：关 1 / 关 6 / 关 14 / 关 22 各出一张 `_floors-shot.js`，
   看"四张图能不能读成四个阶段"。
