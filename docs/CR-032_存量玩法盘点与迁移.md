## 1. 三套玩法的家底（`node tools/_legacy-audit.js`）

### 1a. grove 的 7 种目标（这是 snowlab 最缺的东西）

`clear` 5 屏 · `chain` 7 屏 · `collect` 5 屏 · `limit` 4 屏 · `bank` 2 屏 · `nohit` 2 屏 · `intact` 2 屏

每一屏都在问一个不同的问题：

| 目标 | 玩家要解决的问题 |
|---|---|
| `clear` 清场 | 把 N 只全送走 |
| `chain` 连锁 | 一颗球里装够 N 只 |
| `limit` 限球 | 只有 N 颗球，怎么规划 |
| `collect` 收集 | 收够 N 口粮（火坑双份 → 权衡） |
| `bank` 加注 | 存球换更大的 |
| `nohit` 无伤 | 一次都不挨打 |
| `intact` 不破 | 壳不能破（逼你走坡不砸） |

### 1b. snowlab 48 关的真实形状

```
骨架：直井 → 之字 → 中枢 → 靠壁 → 螺旋 → 双井 →（重复 8 轮）
目标：进门 · 进门 · 进门 · ……（48 次）
怪数：6 → 6 → … → 10 → … → 15 → 15 → 15（第 37 关封顶）
```

**玩家第 7 关就见过全部 6 种骨架。剩下 41 关是同一批走法配更多箱子和怪。**
这正是用户最早那句「感觉层与层之间没有差异化」的根 —— 我修的是**层与层**，没修**关与关**。

## 2. 三处重复（按证据强度）

### 2a. 「深潜无尽」和「深巢无尽」是同一个东西 —— 连种子公式都同源

```js
// grove.html:3100  nestBuildRaw(深度 d)
const R = nestRand((seed ^ (depth * 7919)) >>> 0);

// snowlab.html  diveNext()
reset((d.base + d.depth * 7919) >>> 0, -d.depth);
```

`7919` 是从深巢抄来的。做深潜时我以为是"新造一个模式"。

### 2b. snowlab「四层主题」和 grove「3 产地」是两套并行的地方身份

grove：苔原 / 枯木坡 / 泥沼（有叙事、有章末 Boss）。
snowlab：木屋 / 砖房 / 石洞 / 地窖（纯材质）。
玩家在一个游戏里会见到两套地区命名。

### 2c. CR-031 的 48 关曲线 vs grove 的 27 屏

CR-031 全文 5 次提到 grove，全是「第三扇门 / 跳转出口 / 断言脚本」，
**一次都没把 27 屏和深巢当基线对齐**。

## 3. 迁移清单（决定 snowlab 是下一代之后）

### 3a. 能迁、且必须先迁（按性价比排序）

| # | 迁什么 | grove 现成实现 | snowlab 缺什么 | 成本 |
|---|---|---|---|---|
| 1 | **评级 + 星级** | `STAR_JUDGE`（8 种判定）/ `STAR_OF_STAGE` / `judgeStar` / `recordStar` + 碎片奖励 | 通关只有「进门了」，没有重打理由 | 小。纯增量，判定量从 snowlab 现有状态里都能取到 |
| 2 | **目标类型** | `GOALS` 7 种 + `checkGoal` | 只有"进门" | 中。要逐种映射到多层竖井；`intact` 与"砸箱子"冲突，需重定义 |
| 3 | **Boss** | 每屏末波 | 无 | 中。snowlab 有 fang/crawler/grub/moss 四种，缺一个体型 ≥2 箱的 |
| 4 | **产地叙事** | 3 产地 + 章末 | 只有材质主题 | 小。把 snowlab 四层主题挂到 grove 三产地名下 |
| 5 | **球额 / 饱食条资源化** | `ballLimit` / `collect` | 饱食条只当血条 | 中。牵动推球手感 |

### 3b. 不能迁（要认）

- **27 屏的几何**：绝对坐标 960×600 单屏横版，snowlab 是 48 网格多层竖井。
  一屏一屏重画不现实，也不必要 —— 那 27 张图的价值在**参数意图**（第 1 节那张表），不在像素位置。
- **深巢**：和深潜重复，两者合并成一份（保留 grove 的词条系统 + snowlab 的 6 种骨架）。

### 3c. 退役的确切含义

grove **冻结，不删、不加内容**：

- 代码留着，出征页前两扇门留着（用户还能玩到 27 屏的完整体验）
- 不再往里加关卡、机制、美术
- **唯一例外**：`STAR_JUDGE` / `GOALS` / `NEST_MODS` 作为「设计参考实现」，迁完之前不许改

## 4. 迁移顺序

```
第 1 步  评级 + 星级       ✅ 已落地（见 §6）
第 2 步  目标类型 3 种      ← collect / limit / nohit（clear 等价于现状）
第 3 步  Boss              ← 每 8 关一个，和骨架轮次对齐
第 4 步  深潜 × 深巢 合并    ← 删掉一套，留词条 + 骨架
```

第 1 步成本最低、收益最直接：48 关现在通关零反馈，加评级等于给 48 屏各加 3 个可选目标
（`81 颗星` 的对照物），**不动任何玩法代码**。

## 6. 第 1 步落地：三星（`2026-10-30`）

| 星 | id | 名字 | 判定 | 维度 |
|---|---|---|---|---|
| ★1 | `nohit` | 一毛不拔 | 本关受伤 0 次 | 防守 |
| ★2 | `bigchain` | 大打卷 | 一颗球连碎 ≥ 4 口 | 效率 |
| ★3 | `clearout` | 一只不留 | 本关的怪全部清掉 | 彻底 |

**没做「限时」那颗星。** grove 的 `par.time` 是每屏手调的（60→100），
snowlab 是生成器关卡，一关时长从 20 秒到 3 分钟不等（3 层 30 口箱 vs 5 层 104 口），
拍一个统一秒数要么全白送、要么全卡死。等跑出真实通关时长分布再补。

### 6a. 存档格式

`localStorage['pawpack.snow'] = { stage: 25, stars: { "24": 7 } }`，`7 = 0b111`。

**存位不存数组。** `writeSnowProgress` 是 `Object.assign` 浅合并，
数组每次整体替换 —— 重打第 24 关只拿到 1 颗，会把之前拿的 3 颗冲成 1 颗。
位是标量，配 `Math.max` 天然只增不减。

### 6b. 两个容易白送的口子（都被断言挡住了）

1. **0 只怪的关卡**：`killed >= killedTarget` 是 `0>=0`，天然成立。
   `clearout` 里必须加 `killedTarget > 0`，否则教学关白给一颗。
2. **`hp` 反推受伤次数**：`hurtPlayer` 里有"缓一缓"把 hp 补满，
   挨了三次打和一次没挨，结束时的 hp 可能一模一样。必须单独记 `stat.hits`。

### 6c. 验收

`_snowlab-check.js` 第四十六组 20 条，按阈值两侧各测一次
（`bigchain` 连碎 3 口不给 / 4 口给）；全套 320/0、floor 16/0、jump 4/0、
runtime 14/0（重抽 9796→9879 行）。评审图 `client/art/04-review/27-stars/`。
