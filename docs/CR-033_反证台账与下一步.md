## 1. 先认一个错：我把机制说错了

上一轮（CR-032）我写：

> 「被撞到的敌人当场变成新球，以 70% 速度继续滚，滚出一场风暴。」

**这是 BALL x PIT 的机制，不是 PAWPACK 的。** 查 `absorbIntoBall`（grove.html:2580）后确认：

```
球滚过敌人 → 给敌人 +1 层苔
  ├─ 没糊满：只是加层，球继续滚
  └─ 糊满：  卷进球里（absorbIntoBall）→ 球变大 → 继续滚
```

**不会**撞出第二颗球。`MAX_BALLS = 2` 是硬上限，而且注释写得很清楚：

> 「这不是性能限制，是**注意力限制**：场上有 4 颗球的时候，玩家不是在决策，是在救火。」

所以真实画面是**雪球**（一颗球越滚越大），不是**连锁爆炸**（一串球依次弹开）。
这两个画面在 GIF 里完全不同，卖点文案、分镜、capsule 构图全部要按"越滚越大"写。

⚠️ 这条错得很危险：如果没查，整套物料会照着错误机制做，做到最后才发现对不上游戏。

## 3. 已经做掉的（本轮）

```
第 1 关 P1：3 只 @462（间距 150）→ 5 只 @462（间距 110）
P2         ：4 只 → 3 只（高层教学整体挪下来，第 1 关只教一件事）
```

**为什么是 5 只不是 6 只**：6 只时球径 r=36 正好封顶，但总敌人数变 11，
`grove-smoke` 的「150 秒内清场」实测 180 秒还差 2 只 —— 机器人把时间全花在糊人上。
5 只时 r=34，视觉增长已用掉 87%，而总数回到 9。**用数字取舍，不用感觉。**

已经有三份 CR 文档了（031 / 032 / 033 都是判断，不是产品）。
