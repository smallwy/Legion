# CR-034 · 三项拍板的落地记录

> 2026-10-22 · 三条指令：① 删掉时间门 ② 雪做成机制 ③ P0 三件（评级落盘 / 结算显示 S 线 / 图鉴显示最佳）

---

## 1. 删掉时间门：不能只删"恢复"

原设计：`ENERGY_MAX 100 / COST 20 / REGEN 18s`，打 5 趟后要等 6 分钟，**且按离线时间戳结算**——
关掉游戏也在计时。

这是手游留存模型（靠内购/广告变现，用等待制造回访）。用在买断制上只有一种结果：
"我花 88 块买的游戏，它凭什么不让我玩。"

### 1.1 为什么没做成"只删恢复、保留消耗"

删掉 `ENERGY_REGEN_SEC` 之后能量只出不进，打 5 趟永久归零 —— 比原来更糟。
所以**整套删**：`ENERGY_MAX / COST / REGEN_SEC / FEED` 四个常量、`settleEnergy()`、
`spendEnergy()` 两个函数、`SaveState.energy / energyAt` 的读写路径、出场 UI。
`launchBattle()` 里那个 `if (!paid.ok) { toast; return; }` 分支也一并消失。

### 1.2 连带的：三件任务的奖励原来是假的

`out / feed / send / pat` 四件任务的奖励里有"能量 +10"。
门禁删了之后再发能量，就是发一个没人用的数字 —— **奖励变成空的，比没有奖励更伤**。

换成能立刻花出去的东西：

| 任务 | 原本 | 现在 |
|---|---|---|
| 出门一趟 | 果子 +12 · 能量 +10 | 果子 +12 · 材料 +2 |
| 喂一顿 | 材料 +4 · 能量 +8 | 材料 +4 · 果子 +6 |
| 派人去采 | 吧唧 +2 · 能量 +10 | 吧唧 +2 · 果子 +10 |
| 跟它熟一点 | 能量 +15 | 果子 +15 |

### 1.3 节奏由饱食度接管

饱食度每关 −16，饿了火力下降（`SATIETY.mulFull/Hungry/Starving`），喂一顿要花果子。
这条链是**经营**，不是**等待** —— 玩家随时能出门，但出门前会想一下"这只还撑不撑得住"。

### 1.4 UI 换了三个地方

- 出门按钮副标题：`能量 60` → `3 只 · 饱食 82`
- 出发卡副标题：`能量 60/100 · 出发消耗 20…` → `第 3 关 · 最好成绩 A · 再打一次看能不能刷到 S`
- 失败提示：`苔原没打开，能量还在` → `苔原没打开，再点一次`

第二条不只是填空：**出门前是告诉玩家"S 线在哪"最合适的位置** —— 他还没进去，正好带着一个目标。

## 2. 雪做成机制

完整规格见 `client/docs/PAWPACK-雪原主题-规格.md` §6，这里只记判断。

四件事都挂在 `S.snowDepth`（0..1）上：

| 机制 | 数值 | 落点 |
|---|---|---|
| 越下越厚 | 90 秒长满（par 是 60 秒） | `tick()` |
| 敌人冻僵 | −30% | `updateFoe` 的 7 处 `def.spd` 乘 FK |
| **猫打滑** | 地面摩擦 2600 → 最大 −55% | `updatePlayer` |
| 脚印 | 间距 11px / 12 秒消失 / 上限 120 | `leavePrints` + `drawPrints` |

外加平台顶面雪厚（`snowLine`）与落雪密度（35%→100%）跟着同一个变量长。

### 2.1 三条要记住的判断

**① "球打滑"改成"猫打滑"。** 球在这套物理里没有滚动摩擦（不撞东西就一直滚），
"更滑"没有实现空间。有摩擦的是猫。**慢是惩罚，滑是手感变化** —— 后者才是雪该有的物理感。

**② 90 秒长满而 par 是 60 秒，是有意的。** 第一次打会在雪最厚之前过关，
重打刷 S 的人才会撞上"整片白 + 敌人冻僵"。**雪是一趟比一趟更难的变量，不是固定皮肤。**

**③ 一个数都不碰。** 只改猫和敌人的速度，不改碰撞、球径、波次。
`grove-smoke` 367 → **377**，多出来的 10 项全是新增的雪断言，原有 367 项一个没变。

### 2.2 出图抓到的三个坑

| 现象 | 真因 | 修法 |
|---|---|---|
| 雪画到台面**下面**，和背景雪堆混成白疙瘩 | `arc(π, 0)` 默认顺时针，经过 +y（canvas 里向下） | `anticlockwise = true` |
| 雪线读作**花边** | 草皮本身是一排向下鼓的圆弧，两层齿叠在同一位置共振 | 改低频起伏（54px 一段）的实心带 |
| 脚印完全看不见 | 不是没画，是 `#7E96B8 @ 0.42` 在白雪上只暗 26 级 | 纯红测一次确认位置 → 定 `#A8BED8 @ 0.55`（暗 40 级） |

第三条的方法值得复用：**当"有没有画"和"画得太淡"分不清时，先把它画成不可能看错的样子。**

## 3. P0 三件：把已经算出来的东西接上

### 3.1 评级落盘

改造前 `S.best` 只活在推球的 `S.best` 里：**算出来、写内存、从不读取、重启归零**。
一个 30 分钟的游戏，"刷 S"是仅有的重玩动机，而这个动机连凭证都不留。

现在：

```
pawpack.best          ← grove.html 自己写（JSON 数组，8 格）
pawpack.save.v1.best  ← GroveBattle._syncRanksToHome() 合并写回
```

**为什么是两处**：推球原型要能在浏览器里单独跑（没有家园存档），家园要能在图鉴里读。
合并规则只升不降 —— 拿过 S 再打 A 不会抹掉 S，否则玩家会怕打坏纪录而不敢重打。

**为什么不塞进 `_syncProgressToHome`**：那个函数在 `next === prev` 时 early return，
而"重打一关刷 S"恰恰是**进度不变、评级变了**的场景 —— 塞进去等于永远不触发。

白名单校验：只认 `S/A/B`。存档是外部输入（浏览器里能手改），一个 `"SSS"` 不该变成图鉴上的一行怪字。

### 3.2 结算显示 S 线

原来结算只写 `用时 62.4s`。玩家知道自己花了多久，但不知道离 S 差多远 ——
**62.4s 是个事实，差 2.4s 是个理由。**

现在：`送走 10 / 10 只 · 用时 62.4s / S 线 60.0s（差 2.4s）`

差值只在**够得着**的时候出现（超 S 线 20% 以内）。阈值用比例不用绝对值：
各关 par 从 60 到 135 秒不等，写死 12 秒的话第 1 关很宽容、最后一关永远不显示。
差 5 倍的局说"差 18 秒"不是激励，是提醒他这局打得很烂。

### 3.3 "新纪录"

评级旁边加三个字：`新纪录` / `首次记录`。

**这三个字比 S 更值钱** —— S 是绝对标准（一辈子拿一次），新纪录是相对自己（每关每次都可能拿到）。
30 分钟的游戏里，后者才是能反复触发的那个反馈。

### 3.4 图鉴战绩条

图鉴副标题下加一条：`S ×2  A ×1  B ×0  已通 3 / 8 关`。
全空时不显示一排 0（那看着像坏了），改成一句说明告诉玩家这里会有什么。

**位置是量出来的**：副标题底在 140、第一行宠物圆顶在 116，中间只有 24px。
条高 22、y=129 是唯一不压两边的值。

## 4. 顺手修掉的一个结构性脆性

`extract_grove_runtime.py` 用 `body.index('loadProgress();\nresetRun();')` 定位启动段。
我在中间插了一行 `loadBest();`，**抽取直接失败**。

危险的不是失败，是**失败之后 `grove-runtime-check` 仍然 14/14 全绿**——
因为它读的是上一次的编译产物。这正是记忆里那条坑（"离屏工具读的是编译产物"）的另一个入口。

锚点改成只认 `loadProgress();` 一句（函数定义是 `function loadProgress() {`，不含分号，不会误命中）。

> **规则：任何用"多行文本"做锚的抽取/替换脚本，锚点必须小到不会因为加一行就失效。**
