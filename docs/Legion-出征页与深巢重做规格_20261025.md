# Legion · 出征页版式 + 深巢重做规格

> 版本 v1 · 2026-10-25
> 画布基准 960×600（现有 `W/H`），全部数值为逻辑像素。
> 本文只定规格，不含实现。

---

## 一、出征页：卡横排 + 悬停放

### 1.1 结论

右侧独立预览卡**删除**。玩法卡横排、宽度由玩法数算出；鼠标悬停时卡自己放大 1.2 倍，中心不动。

### 1.2 为什么删得掉

预览卡存在的唯一理由是"这条路长什么样"，可卡本身就是立绘 —— 用 40%~87% 的画面去重复卡里已有的信息，是纯损耗。删掉后卡从 358 宽涨到 410，立绘可用面积接近翻倍。

### 1.3 为什么不能再竖排

左列可用高度只有 420（y 52..472）。358×201 竖排的第 3 张从 490 落到 691 —— 直接出屏。**纵向列表天生不可扩展，横向条天生可扩展**，这是排列方向的问题，不是"缩多少"的问题。

### 1.4 栅格公式

```
w = floor((960 - 60×2 - (n-1)×20) / n)
h = min(420, max(120, round(w × 9/16)))
y = 52 + round((420 - h) / 2)
```

| 玩法数 | 卡尺寸 | y | 卡底 | 右缘 |
|---|---|---|---|---|
| 2 | 410×231 | 147 | 378 | 900 |
| 3 | 266×150 | 187 | 337 | 898 |
| 4 | 195×120 | 202 | 322 | 900 |
| 5 | 152×120 | 202 | 322 | 900 |
| 6 | 123×120 | 202 | 322 | 898 |

**依据**：

- **边距 60**：960 宽下"留得够"的下限。再小（40）边缘卡贴屏幕没有呼吸；再大（88）则 4 张卡只剩 195 宽。
- **gap 20**：必须大于卡内边距 16，否则两卡会被读成"一整块被竖线切开"而不是"两扇独立的门"。
- **`floor` 不用 `round`**：3 个玩法时 round 算出 267，`267×3+40 = 841`，右缘 901 比边距多 1px。半像素错位就是这么来的。
- **高夹在 120~420**：
  - 上限 420 —— 只有 1 个玩法时 840 宽按 16:9 是 473，会顶穿 472 撞到底部提示条。
  - 下限 120 —— 5 个玩法时纯 16:9 只有 86 高，扣掉文字块 56 + 过渡 16，立绘只剩 30px，那张图等于没画。
- **垂直居中**：上下留白对称。4 个以上时下方会空出约 150（那是夜色草地，不是纯空白），可以接受。

### 1.5 悬停放大

**不改变栅格，中心不变。**

| 项 | 值 |
|---|---|
| 缩放 | 1.2 |
| 锚点 | 卡中心（改了中心，鼠标会在放大瞬间掉出卡外 → 复原 → 再放大，闪成一片） |
| 描边 | 1.4px `rgba(160,200,180,.30)` → 2.4px `#F0A81E` |
| 邻居 | 不变暗（深巢立绘本就暗，再压会看不出内容） |
| 绘制顺序 | 先所有非焦点，再焦点 — 一遍画完再补焦点，会被后画的邻居切掉一条边 |
| 命中判定 | **永远用常态矩形**。常态区是放大区的子集且同心，鼠标放上去不会抖；放大后盖住的邻居也仍然点得到 |

放大后不出画布：2 张时左卡中心 265、半宽 246 → 左缘 19，是这一版最紧的一处。

### 1.6 卡内布局（三行，自下而上排）

压暗带**不是固定高度的渐变**，而是"先把字从底往上排好，再按排出来的实际高度反推带到哪儿为止"，实心 0.88 + 上过渡 16px。

| 行 | 字号（常规 / 小卡 / 矮卡） | 内容 |
|---|---|---|
| 名字 | 20 / 16 / 15 | 玩法名 |
| 副行 | 13.5 / 11.5 / 11 | `第 N 屏 · 产地` 或 `最深 N 层` / `没下潜过` |
| 第三行 | 11.5 | 主线：三颗星条件原文（`✓` 已拿 / `○` 未拿）；深巢：两条规则 |

**为什么从底往上排**：第一版是"先画固定 96 高的渐变，再把字放在 h-58 / h-34 / h-14"。h-58 落在渐变 alpha 只有 0.5 的地方，第三行直接压在苔原那张的亮草地和小熊身上，`○不碰火坑` 根本读不出来。自下而上排 + 实心带，任何背景都是 0.88，不靠蒙。

**第三行只在卡高 ≥ 170 时画**：它要 22px，加上名字 20 + 副行 18 + 上下留白 14，硬塞进 150 高的卡会把字压到亮图上。所以 2 个玩法有、3 个以上没有 —— 那时卡本来就退化成"入口"，细节靠悬停放大看。

### 1.7 触屏没有 hover —— 必须补

`hover` 在触屏上不存在。当前实现是**触屏点一下直接进关**，等于真机上完全没有"放大预览"这一步。

| 设备 | 选中 | 进入 |
|---|---|---|
| 鼠标 | pointermove 进卡区，自动放大 | 点击卡（直接进） |
| 触屏 | 第一次点击 → 放大 | 点第二次 / 点卡内「出发」 |
| 键盘 | ← → | Enter |

**待确认**：触屏要不要补两跳。不补的话，手机玩家永远是"没看清就被丢进关卡"。

### 1.8 待定

- 玩法数 ≥ 6 时的翻页（可视 5 张 + ← → 按钮，不做拖拽：拖拽要新增手势层，运行时抽取有风险）
- 4 个以上时下方约 150 的留白要不要放东西

## 二、深巢：换世界观，不是换排布

### 2.1 认账

当前深巢 = 从主线 8 套主题里挑一套 + 重排台子。配色、台子画法、敌人行为全是主线的。它解决了"第 20 层不等同第 3 层"，但没有解决"深巢不等同主线"。这一节全部推翻，另起一套。

### 2.2 一句话定位

| | 主线苔原古道 | 深巢 |
|---|---|---|
| 空间 | 地表，开阔（活动区 934 宽） | 地底，被岩壁夹住（活动区 640 宽） |
| 方向 | 横着往右推 | 竖着往下沉 |
| 送走 | 推进营地 = 送回地面（**往上**） | 逼进裂缝 = 掉到下层（**往下**） |
| 光 | 右上斜阳 | 下方菌光/岩浆（**方向相反**） |
| 情绪 | 送它们回家 | 把它们丢下去，自己也往下 |

**这五行里，任何一行不成立，玩家就会觉得"还是同一款游戏"。**

### 2.3 空间：窄井 + 密集堆叠 + 裂缝

| 项 | 主线 | 深巢 | 依据 |
|---|---|---|---|
| 活动区宽 | 0..934 | **160..800（640）** | 640 能放 3 道裂缝 + 2 段坡；再窄摆不开，再宽失去压迫感 |
| 平台层数 | 3（462 / 350 / 248） | **4–5，层距 110** | 层距 110 与球直径 46 的比例是 2.4，球在层间通过时留得出余量 |
| 营地 | 1 个，贴端点，宽 82 | **0 个** | 深巢没有"回家"这个概念 |
| 裂缝 | 无 | **3–5 道，初始宽 90–130** | 90 宽 = 球直径 ×2，玩家有空间判断但不至于一脚踩空 |
| 出口 | 关卡通关 | **井底，走进去即下一层** | 无尽模式的"下一层"必须在画面里有个实体 |

**裂缝会变大**：每丢进去一只兽，裂缝 +8 宽，单道最多 +40（5 只封顶）。

- 这是深巢唯一的"进度可视化"：玩家能看见自己在改造地形
- 上限约束：**所有裂缝总宽 ≤ 场地宽 40%（640×0.4 = 256）**。超了场地就成筛子，走不动
- 副作用是正向的：裂缝变宽后球更容易掉进去——玩家自己造的便利，也是自己的陷阱

### 2.4 玩法差异（三个动词上的不同）

**① 目标从"一个端点"变成"多个任意位置"**

主线只有一个营地，兽必须一路推回右端。深巢有 3–5 道裂缝，任意一道都算。同样一只兽，主线要推 600px，深巢可能推 80px。

→ 节奏快一档。主线的乐趣在"长途搬运的规划"，深巢的乐趣在"就地解决的取舍"。

**② 裂缝会吞掉球**

主线的球掉坑是纯损失。深巢里球滚进裂缝 = 那颗球（和装在里面没送走的兽）一起掉到下层，**下一层开局会在地上捡到它们**。

→ 损失变成"库存转移"，不是"操作失误的惩罚"。符合无失败惩罚红线。

**③ 玩家掉进裂缝 = 直接下一层**

打不过就跑。跳过这层剩余目标，代价是没有这层的收成。

→ 反卡死出口。无尽模式最怕的就是"这层我怎么都过不去"，必须有一个体面的退路。

### 2.5 怪物：4 种全新，剪影语汇整套换掉

主线 4 种的共同点：**都站在地上、都被推着走**。深巢 4 种必须每只都打破其中一条。

| 名字 | 剪影特征（涂黑也能认） | 行为 | 送走方式 | 出场深度 |
|---|---|---|---|---|
| **盲蛛** | 细长 8 腿 + 极小身体，占地宽 76 | 不追光，追**震动**——玩家推球跑动会把它吸过来 | 推进裂缝，或引它自己走到裂缝边 | 1+ |
| **石壳** | 圆钝无腿，像滚石，直径 52 | 只会往低处滚，撞墙反弹，砸到玩家算挨打 | 它自己滚进裂缝（但你得先把它推上坡） | 5+ |
| **巢蛾** | 有翼，剪影上下不对称，飞在半空 | 球碰不到，只在空中飘 | **只能用光**：球火 / 岩浆照亮满 3 秒，它自己掉下来 | 9+ |
| **地脉虫** | 只露一个头从岩壁伸出，长条 | 每 4 秒探头 2 秒，缩回时无敌 | 探头窗口内推进裂缝 | 14+ |

**为什么这四只撑得住**：它们分别对应深巢的四个物理事实——暗（巢蛾靠光）、窄（盲蛛靠震动定位）、往下（石壳靠重力）、岩壁（地脉虫住在墙里）。主线四种怪没有一只需要这些条件，所以两边永远长得不一样。

**剪影规格（同源五要素）**：

| 项 | 规格 |
|---|---|
| 视觉尺寸 | 盲蛛 76 宽 / 石壳 52 / 巢蛾 44 / 地脉虫 56 |
| 线宽 | 3px（主线是 2.5px，深巢整体加粗一档，因为暗底需要更实） |
| 圆角 | 全为 0（岩质生物，没有一处柔角）—— 与主线虫子的圆润形成对立 |
| 留白率 | 图形占画布 68%~74% |
| 光源 | 一律从**下方**受光，底部一道 2px 亮边 |

### 2.6 场景：地下语汇，不是地表换色

主线 8 套主题共享同一套语汇：天空 / 云 / 远山 / 草 / 土 / 木。深巢必须整套换掉，**不是调色**。

| 层 | 位置 | 内容 |
|---|---|---|
| 天花板 | y 0..90 | 岩层，从 90 往上逐渐压黑到纯黑；嵌倒挂钟乳石（下缘参差） |
| 岩壁 | x 0..160 / 800..960 | 岩层剖面，水平层理纹，嵌矿脉与化石 |
| 活动区 | x 160..800 | 岩架 / 木梁 / 铁架（人工井下结构），表面覆菌苔 |
| 地面积水 | y 510..600 | 菌光水洼 / 岩浆（按深度带） |

**光源方向反向**：主线是右上斜阳（`tundra` 主题的 `sky1 #F7B44C` 从顶部淡到地平线）。深巢的光从**画面下方**打上来，所有平台的下沿有亮边、上沿是暗的。

这一条是"一眼认出换地方了"的最低成本手段——同一批几何，光一反过来，观感完全不同。

**色值（4 个深度带）**：

| 深度 | 岩体 | 暗部 | 光源 | 强调 |
|---|---|---|---|---|
| 1–8 | `#4A4038` | `#2B2521` | `#C98A50`（菌光） | `#7FB069` |
| 9–18 | `#3D3A44` | `#221F28` | `#8FA8C8`（矿光） | `#C4553D` |
| 19–30 | `#33283A` | `#1A1420` | `#C4553D`（岩浆） | `#E8B44A` |
| 31+ | `#241C2E` | `#100C16` | `#E8B44A` | `#6B4E8C` |

四带之间不是渐变过渡，是**整层切换**——换带那一层玩家应该立刻感觉到"更深了"。

### 2.7 暗：深巢的基底规则

径向遮罩，以玩家为圆心：

| 深度 | 照明半径 | 玩家状态 |
|---|---|---|
| 1–5 | 460 | 与主线相当，先熟悉 |
| 6–15 | 340 | 要靠记忆走 |
| 16+ | 260 | 看不见的地方不敢推球 |

**咬合已有系统**：球本身就是火（主线已有），深巢让它成为光源，+80 半径；火坑 / 岩浆也是光源。

于是球从"得分工具"变成"探照灯"——先扔一颗照亮，再决定从哪推。这和"一球卷多只"的最优解天然同向，不需要额外教学。

**这一条是整套设计里性价比最高的**：零新素材，只加一层遮罩 + 三个光源点，但它是唯一让玩家在**第一帧**就确认"这不是同一条路"的东西。

## 三、成本与顺序

| 项 | 工作量 | 依赖 | 备注 |
|---|---|---|---|
| 出征页改版（删预览 / 横排 / 上浮展开 / 触屏两跳） | 0.5 天 | 无 | 纯版式，风险低 |
| 暗（遮罩 + 三光源） | 1 天 | 无 | 效果最大 |
| 裂缝替营地（判定 + 长大 + 球/人掉落） | 2 天 | 无 | 生成器要重写 |
| 窄井空间（活动区 640 + 4–5 层堆叠） | 2 天 | 裂缝 | 场地参数化 |
| 场景语汇（天花板 / 岩壁 / 井下结构 / 反向光） | 3 天 | 窄井 | 程序绘制，量大 |
| 4 种新怪（剪影 + 行为） | 5 天 | 场景语汇 | 每只 1–1.5 天 |

**建议顺序**：出征页 → 暗 → 裂缝 → 窄井 → 场景 → 怪。

理由：暗和裂缝改的是**感知与动词**，这两条一落地，"深巢不是主线换皮"这件事就成立了。先换怪、后换场景是最差顺序——怪换了场景还是主线的，玩家照样觉得一样。

## 四、待确认

1. **出兵宽度 640 会不会太窄**：现在活动的空间 934，砍到 640 是砍 31%。这直接影响"一球卷多只"的空间余量，要在机器人上先跑一遍再定。
2. **裂缝长大上限**取舍：单道 +40 / 总宽 40%，两个上限取更严的那个。
3. **主线 4 种怪要不要也享受深巢的加减**：不同步，两边怪表完全独立。
4. **深巢要不要保留"收成"**：现在有 `collect` 目标，但如果裂缝玩法强调的是"往下丢"，收成该怎么算需要重定。
