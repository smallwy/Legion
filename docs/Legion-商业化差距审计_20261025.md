# Legion · 商业化差距审计

> 审计日期：2026-10-25
> 触发问题：「你有自己独立思考的能力吗 / 如果现在商业化，差距还有多大 / 经济系统、玩法形成闭环了吗」
> 本文所有结论都有代码位置或实测数据支撑，标注了置信度。**没有一句"我觉得很不错"。**

---

## 0. 结论先行（三句）

1. **玩法内核是好的，产品是不存在的。** 推球 + 连锁 + 收工倍率 + 饥饿压力，这套内核值得做。但它是**一个 30 分钟的原型**。
2. **经济闭环形状存在，但收支失衡到 5 趟后失效。** 不是"没做"，是"做了但没压力"。
3. **最缺的不是内容量，是"成长"。** 赚到的东西只能换成"继续赚的燃料"，赚不到"更强"。这是循环，不是螺旋。

## 2. 经济系统审计：闭环有形状，三处断裂

### 2.1 现存的链（这部分做得比想象中好）

```
战斗（27 屏）→ 收成 S.food → 收工 ×倍率 → S.home.loot（果子）
                                ↓
                    工坊 RECIPES：果子10 + 材料2 → 干粮1
                                ↓
                    灶台 MEALS：干粮(0果) / 野果(8果+22饱) / 热汤(16果1材+48饱)
                                ↓
                              饱食度
                                ↓
                    满饱 1.00 / 半饿 0.95 / 全饿 0.86（全饿不能冲刺）
                                ↓
                        下一趟能走多远
```

派遣是第二条产线（干粮 / 果子 / 材料），补的是"省下造干粮的开销"。
**这条链是真的，而且有设计意图**：`HomeBiz.ts` L80-88 把「派遣 → 干粮 → 肚子 → 战力」写成了"别的系统补不上的一条链"。

**结论：闭环的形状是对的。这是全项目最被低估的部分。**

### 2.2 断裂一：没有出口（最致命）

`RECIPES` 全表只有两条：

| id | 产物 | 性质 |
|---|---|---|
| `ration` | 干粮 | **消耗品**（吃了就没了） |
| `basket` | 收集篮 | 一次性 |

`MEALS` 三条全是消耗品。

**没有任何一条"永久变强"的产出。** 加上已确认的红线「不做宠物等级/加点，成长只走道具改规则」，结果是：

> **玩家第 1 小时和第 10 小时的能力完全相同。**

所有产出只能换成"再来一趟的燃料"。这是**循环（loop）**，商业游戏需要的是**螺旋（spiral）**。
循环能撑 30 分钟，螺旋才能撑 30 天。

**置信度：高。** 这是 `RECIPES` 表配置的事实，不是推断。

### 2.3 断裂二：收支 3.75 倍通胀 → 5 趟后压力消失

估算依据（都是实测/配置值，非拍脑袋）：

| 项 | 数值 | 来源 |
|---|---|---|
| 一屏收入 | ≈30 果 | 第 2 屏 `STAGE=2` 实测收成 33 |
| 一屏掉饱 | 20 | `grove.html:3420` `BELLY_PER_CLEAR = 20` |
| 喂一顿成本 | 8 果 / +22 饱 | `HomeBiz.ts` MEALS.野果 |
| 每屏净收益 | **+22 果** | 30 − 8 |

**收入的 3.75 倍于维持成本。** 跑 5 趟之后果子就过剩，"饿了火力下降"这条压力线**自动失效**，整个「贪不贪」的张力（`goHome()` 注释里明确说这是"全篇唯一不做失败惩罚的张力来源"）也就一起消失了。

**这是"玩不明白"的第二层原因**：不是规则看不懂，是**看懂了也没有成本**。

**置信度：中高。** 基于单屏实测 + 配置表推算，需要真机跑 10 趟验证才敢说死。

### 2.4 断裂三：注释漂移（会害后面的人算错）

`HomeBiz.ts` L30 / L86 两处都写「饱食度每关 −16」，实际常量是 **20**。

按 16 算："野果 22 饱能走 1.4 屏"；按 20 算："只够 1.1 屏"。**喂饭频率差 27%。**

这正是 MEMORY 里第 2 条教训的又一个案例：**同一件事存两份，必然漂移。** 只不过这次飘的是注释，而注释会被下一个改数值的人当依据。

**修法**：注释里不写数字，写 `见 BELLY_PER_CLEAR`。

## 3. 商业化差距表

### 3.1 硬差距（有 0 到 1 的空白）

| 维度 | 现状 | 商业化门槛 | 差距 |
|---|---|---|---|
| **变现** | **0**。无广告、无内购、无体力、无抽卡 | 2~4 个变现点（激励视频 + 首充/礼包） | **从零开始** |
| **音频** | **0**。全项目无一行音频代码（grep `audio/sfx/music` 只命中 CSS） | BGM 4~6 首 + SFX 30~50 个 | **从零开始** |
| **美术** | 代码 canvas 手绘（`gen_grove_art.py` 只把 `ui/home/` 收缩到 `resources/grove/`，立绘 192 / 头像 96） | 全套位图资产 + 动效 | **从零开始**（这是我这行，后面单列） |
| **平台适配** | Web 单文件 `grove.html` 12000+ 行，依赖 `document` | 微信/抖音小游戏包，需过审 | 需移植 + 合规审查 |
| **留存钩子** | 0。无每日、无排行、无社交、无随机挑战 | 至少 1 个（7 日留存 >15%） | **从零开始** |

### 3.2 软差距（有基础但不够）

| 维度 | 现状 | 门槛 | 差距 |
|---|---|---|---|
| **内容量** | 27 屏 × 机器人 20~60s ≈ 人手 40~120s ≈ **20~50 分钟主线** | 60~150 分钟 + 长线 | **3~5×** |
| **养成深度** | 6 宠物 / 6 武器 / **零成长** | 至少 2 条成长线 | **差一个量级** |
| **经济闭环** | 有循环，无出口，3.75× 通胀 | 产出 → 沉淀 → 成长 → 新内容 | 缺最关键的第三层 |
| **BOSS 差异化** | 三流派已做（cliffs 断台 / marsh 泥潮 / hills 基准） | 每章独立 BOSS 行为 | 已过半 |
| **空间设计** | 地面骨架 27/27 全平地；额度解耦仅覆盖 **1/27 屏** | 至少 1/3 屏强制读地形 | **差 8 倍** |

### 3.3 总评

> **能玩的 30 分钟原型：完成了。**
> **能上架的小游戏：还差"一套完整的外壳 + 一条成长线"。**
>
> 这不是"打磨"的距离，是"再做一个产品层"的距离。粗估：美术 + 音频 + 变现 + 移植 + 养成 = **等于把已经做对的内核，再包一层同样体量的工程**。

## 4. 我的独立建议（和你之前所有方向都不同）

**建议：砍到 9 屏，做一版能上架的最小闭环。不要继续加 27 屏。**

理由，按重要性：

1. **验证顺序错了。** 现在还没验证过"有陌生人在第 3 分钟愿意继续玩"。在这个前提没验证前，加内容 = 给未验证的东西加成本。
2. **9 屏 + 完整外壳 > 27 屏 + 空外壳。** 前者能上架、能拿到真实数据；后者只能内部演示。
3. **成长线必须在 9 屏上就能立起来。** 9 屏装不下成长线，说明成长线设计有问题，27 屏也装不下。
4. **美术成本是超线性的。** 27 屏全套资产 → 9 屏全套资产，成本差 3 倍，但验证价值相同。

**具体做法（按顺序）：**

| # | 动作 | 为什么先做这个 |
|---|---|---|
| 1 | 加**一条**永久成长线（例如「道具改规则」：花 30 果永久解锁"火坑给 ×3"） | 没有出口，所有经济设计都是空的。这是唯一的 0→1 |
| 2 | 把果子通胀压掉（提高喂饭成本 或 降低收成） | 不压掉，成长线会被过剩资源秒解锁，还是没压力 |
| 3 | 球额度从 1/27 扩到 9/27 | 已验证有效（4 球 vs 5 球），成本纯数据 |
| 4 | 换美术 + 补音频 | 我负责的部分，见下 |
| 5 | 变现层 + 平台移植 | 最后做，因为它最贵且不改变玩法价值 |
