# Legion · 场景三族与 BOSS 三流派

> 版本 v1.0 · 2026-10-24 · 触发：用户「你的重心怎么老是在球上 为什么不是在空间设计上多去思考 比如场景上的 很多地方啊 boss机制也单调」
>
> 本文只回答两件事：**27 屏为什么看起来是同一张画**，以及**BOSS 为什么打得一模一样**。球的东西本文一律不谈。

---

## 0. 结论先行

1. **前两批改错了方向。** P1（地面材质 / 反射板）、P2（赛道 TOUR）改的都是"球怎么滚、球走哪条路"——那是**通关条件**，不是**空间**。空间是「这一屏是哪个地方」「这块地形在跟我做什么」。
2. **27 屏共用同一套远景**，客观审计结果：4 朵云 + 3 层圆顶山 + 30 棵树 + 6 丛灌木，**坐标全部写死**，27 屏只换配色。所以玩家走过三章，感觉是"同一个地方换了色温"。
3. **27 屏的 BOSS 也共用同一套动作**：砸地 / 散射 / 产卵，19 屏连等级都相同。第二章遇到的"新 BOSS"，长得一样、打得也一样。
4. 本批实装：**场景三族**（密林 / 断崖 / 沼泽，远景 + 植被 + 前景三处同时分族）+ **BOSS 三流派**（cliffs 会砸断台面、marsh 会渗泥）。
5. **最贵的一条教训**：三族差异化**不许靠减动作**。减掉的不是"多余的一招"，是敌人的来源和玩家的走位时机 —— 反证四轮，见 §3。

## 1. 审计：同质化的三个来源

不是感觉，是数出来的。

| 层 | 审计结果 | 结论 |
|---|---|---|
| 地面骨架 | 27/27 屏都是**一整条平地 26..934**，零断裂、零高低差 | 一切"地形感"都只能靠浮空台补 |
| 浮空台 | 高度只有 4 档（156×6 / 248×22 / 350×45 / 462×52） | 竖向节奏在三章里是同一个 |
| 远景 | 云 4 朵 + 山 3 层 + 树 15+15 棵 + 灌木 6 丛，**坐标写死** | 换主题只换配色，形状语言完全一致 |
| BOSS | 27/27 屏都刷，19 屏 lv5，**三动作全部共用** | 三章遇到的是同一只 BOSS |

**"空间设计"不是只有机关。** 机关回答"怎么过"，场景回答"这是哪里"。后者缺失时，前作再多样也是"在同一个房间里换装置"。

## 2. 场景三族：一次改三处，只改远景没用

只换远景的话，走进画面 1 秒后玩家视线就落在地面附近了。三族必须**远景 / 植被 / 前景**同时分族。

| | 密林 `hills`（1-9 屏） | 断崖 `cliffs`（10-18 屏） | 沼泽 `marsh`（19-27 屏） |
|---|---|---|---|
| 远景 | 圆顶山 3 层 + 云 4 朵 | **尖峰岩柱** 3 层 + 卷云 2 条 | 积水亮带 + **芦苇** 2 层 + 低雾 7 团 |
| 植被 | 阔叶树 15 棵 | **枯树** 5 棵（15 → 5） | 阔叶树 12 棵（15 → 12） |
| 前景 | 灌木 6 丛 | 石堆 + 碎石 | 高杆芦苇 |
| 大树干 | 3 根 | 无 | 无 |

### 2.1 分派点只有一个

```js
const SCAPE_OF_THEME = { tundra/snow/slope/bouncy/well/stairs/tower: "hills",
                         cliff/wither1..3: "cliffs",
                         marsh1..3: "marsh" };
let SCAPE = "hills";   // loadLevel 里重置：SCAPE = SCAPE_OF_THEME[L.theme] || "hills"
```

`drawBgTree` / `bgTreeRow` / `drawScape` / `drawClouds` / 前景扫描 / BOSS 流派——全部读同一个 `SCAPE`。
**一处真值，六个消费者**，所以不存在"换了远景忘了植被"。

### 2.2 踩过的三个坑

1. **岩柱直接用 `hillFar/hillNear` → 和天空同色，缩到 30% 直接消失。**
   那两个色是为"圆山往天空退"算的比例，不是给"立起来的石头"用的。
   改：混 `trunkNear` 0.30/0.26 并压明度，另加右缘受光棱 `rim = hexMix(color, "#FFFFFF", 0.34)`。
2. **前景用固定点位表 → 被避让排除后归零**（第 20 屏 0 根芦苇、第 12 屏 0 块石头）。
   改：**扫描式布局**（间距 26~46），被避让的点改画矮碎屑 `drawFgPebble`。
   边距也得收：40/60/70 会让 8/27 屏点位全灭，收到 22/30/46。
3. **"中段矮前景"是伪需求。** 球底 556、球顶 534，只剩 22px —— 画什么都会被地面吃掉。
   中段直接交给碎屑，阈值抽成常量 `FG_EDGE_MIN = 0.30`。

## 3. BOSS 三流派：只加不减（这条是买来的）

### 3.1 实装

```js
const BOSS_STYLE = {
  hills:  { slam: true, fan: true, spawn: true, crack: false, mud: false },
  cliffs: { slam: true, fan: true, spawn: true, crack: true,  mud: false },
  marsh:  { slam: true, fan: true, spawn: true, crack: false, mud: true  },
};
```

- **断台（cliffs）**：把离 BOSS 最近的一块**浮空台**整块打掉。改的是"能站的地方"——台面没了，玩家要么换位、要么掉到下一层。
- **泥潮（marsh）**：在朝玩家那一侧铺一段泥。复用已有 `GROUNDS/MAT` 机制（球 ×0.72 + 每帧拖拽、人摩擦 ×2.10），不新增物理。

两条都**不打断移动**：抬手只开一个计时器，BOSS 照常走，时间到了地形再变。

### 3.2 三条护栏（踩出来的，不是想出来的）

| 护栏 | 为什么 |
|---|---|
| 断台**不打 ground** | 地面没了，营地、出生点、球的物理全塌——那不是难度，是坏档 |
| 断台**不打 462 那层** | 462 是球最常走的线。抽掉一块，第 12 屏单球只装到 2 只（目标 3）、第 15 屏落袋 3（目标 4） |
| 断台**不打有活敌人的台面** | 敌人脚下的板抽掉它会直落地面，机器人算好的路线全废 |
| 断台**每屏最多 2 块** | 碎光了这屏就变成一块光板，地形设计全废 |
| 泥潮**营地左 280px 不铺** | 那一段是"滚进门的最后一截"。铺上去球停在门口，玩家读作"门坏了"（第 15 屏落袋 3 vs 目标 4 就是这么来的） |
| 泥潮**最多 2 段** | 3 段 × 150px 之后第 27 屏清不完（6/7）：泥是"让路变难"，不是"把路堵死" |

### 3.3 ★ 减动作 = 减敌人（本轮最贵的教训）

第一版为了"看起来更不一样"，给 cliffs 关了 `fan`、给 marsh 关了 `slam`。
ALL9 当场三条红：

```
12. 树桩林：单球能装够目标只数  [最大 2 vs 目标 3]
15. 弹菇田：营地真的能送到      [落袋 3 vs 目标 4]
27. 沼气王：机制闭合，机器人能清场 [清 6/7 · 240s]
```

排查走了四轮反证（这是唯一一次把根因**测**出来而不是猜出来的）：

| 实验 | 结果 |
|---|---|
| crack/mud 全关、fan/slam 也关 | **857 / 3 红**（仍然红） |
| 只开 cliffs.crack（fan 保留） | 860 全绿 |
| 只开 marsh.mud（slam 保留） | 860 全绿 |
| crack/mud 全关、只留 fan/slam 关闭 | **857 / 3 红** |
| fan/slam 恢复 + crack/mud 全开 | **860 全绿** |

**元凶不是新动作，是"少一个动作"。** 那三个动作不只是"攻击方式"：
产卵是**敌人的来源**，砸地逼玩家跳、扇形逼玩家换位 —— 是**走位时机**。
少一个，整条节奏就变了，机器人算好的那一套全错。

> 结论：三族用**加法**差异化（cliffs +断台、marsh +泥潮），基础三件谁都不许关。
> 冒烟 §33 ② 已把这条钉死：三个流派的 slam/fan/spawn **必须全为 true**。

## 4. ★ 机制做了 ≠ 玩家看得见

`crack/mud` 的计时器先落地时，`f.cracking` / `f.mucking` 在**绘制代码里一次都没被读过**：
BOSS 举手、台面塌掉，中间什么都没有。**冒烟当时还是全绿的。**

「系统是通的」和「玩家看得见」是两件事。补了预告层，并且守住一条等式：

> **画的就是砸的。** 抬手那一刻锁定目标（`f._crackTgt` / `f._mudSpot`），
> 落手只执行锁定的那一块。**一份数据两处读**，所以不可能出现"画一块砸另一块"。

### 4.1 预告画的三个规矩

1. **画在目标上，不画在屏幕中央。** 弹一行字是 UI；在那块板子上画裂纹才是"这块板要塌了"。
2. **进度要看得出来。** 三个信号同时随 k 长大：裂缝变深、箭头压下来、角括号收紧。
3. **颜色必须和背景错开。** 第一版用 `#FF6B3D` 橙色 —— 暖橙天空 + 暖橙木头，**撞成一片**，
   出图上我自己都要盯半天才找到。改成 `sigLine()`：先画 3.4px 深底、再画 1px 亮面，
   浅背景有暗边、深背景有亮芯。裂缝反过来用**深色做芯**——木头裂开的地方是暗缝，
   浅色线在浅木头上只读作"在发光"。

### 4.2 泥潮的二次修正

沼泽关本身 **24/27 屏遍地是泥**。BOSS 再铺一段、长得和地形泥一样，玩家看不出它做了什么——
机制在跑、反馈为零，等于没做。所以 BOSS 泥带 `boss: true` 走另一套画法
`drawMudMound()`：顶边四个缓包 + 一直冒泡 + 顶面反光。
**物理仍然只认 `MAT.mud`**，`boss` 只是画法标记，不是第二份真相。

高度 12px 是量出来的：球底 556、球心 545。高过 545 会把球整个盖住（读作"球被埋了"，物理上并没有），
压在 548 以下球就只是"陷在泥里"。

## 6. 还没做（诚实清单）

| # | 缺口 | 影响 | 成本 |
|---|---|---|---|
| 1 | **地面骨架 27/27 全平地** | 一切竖向节奏都靠浮空台，三章骨架仍是同一个 | 高（`GROUND_Y` 有 20+ 处硬编码） |
| 2 | 浮空台只有 4 档高度 | 台面语言在三章里是一致的 | 中（纯数据 + 审计三条不变量） |
| 3 | 三章各 9 屏内部仍是同一套 | 玩家在同章内仍会觉得"又是这里" | 中（每章 3 个变体就够） |
| 4 | hills（第一章）没有招牌动作 | 第一章是基准，暂时可接受 | 低—中 |
| 5 | 泥潮的视觉效果偏弱（深绿草地上的暗褐） | 需要在 1x 下再看一轮 | 低 |
| 6 | 机器人巡回 17/27（倒木阵 / 烂木桥 / 泥沼深 寻路死循环） | 与本文无关，仍是待人工试玩项 | — |

**顺序建议**：先补 #2（成本最低、见效最快），再动 #1。
#1 的唯一低成本做法是把 `GROUND_Y` 收敛成一个"地面高度表"，让每屏可以声明断裂与落差——
这是**唯一一处必须改常量的工程**，做之前要先跑一遍 `grove-level-audit.js` 存基线。
