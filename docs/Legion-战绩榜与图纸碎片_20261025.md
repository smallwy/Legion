## 0. 先修了一个真 bug —— 用户说的「宠物 ICON 没显示」找到了

`HomeRuntime.petFrame()` 拿**显示名**去比**节点名**：

| 变量 | 实际值 |
|---|---|
| `this.pets[].name` | `slot.name` = 节点名 → **砂糖 / 年糕 / 团子** |
| 调用方传进来的 `name` | `who.name` = 显示名 → **尖耳猫 / 短尾犬** |

`p.name !== name` 永远成立 → 每一只都被跳过 → 返回 `null` → 工坊左边走 `else`
分支画一个灰圆圈。截图对比：`shots/_t-perk.png`（改前，空圆）vs 同一张（改后，尖耳猫立绘）。

修法不是"再补一份名字表"，是**统一走 `petByNode`**（节点名 → `PetDef` → 显示名）。
全项目只有这一处映射，和 `refreshSlots` 用的是同一个函数。另加 `heads` 兜底：
宁可给一张 96 的头像，也不给空圆（空圆读作"加载失败"）。

## 1. 评级给奖励：先有分，才有榜

### 病根

`S.best` 从有评级那天起就在落盘，**但没有任何界面消费它**。
审计原话：「评级 S/A/B 只落盘，不给任何东西 → 玩家没有理由为『打得更好』付出」。

### 规则

| 情况 | 给不给 | 材料 |
|---|---|---|
| 首次达成 | 给 | S=3 / A=2 / B=1 |
| 评级提升 | 给 | 同上 |
| **打平** | **不给** | 0 |
| **降级** | **不给，且不覆盖旧纪录** | 0 |

**打平不给是关键**：无条件给的话，重打第 1 屏（难度最低）能无限刷材料，
整条经济线当场作废。

### 为什么给材料而不是果子

果子实测通胀 **6.5×**（单屏收 47.3、喂饭只花 7.3），再加只会更废。
材料是真稀缺：改造件要 180 果 + 4 材 + 2 碎片，一趟最多 5 材。

### 落点

`S.trip.rankLogs` → `_bankRun` → `payoutFromRun({ rankLogs })` → `logs = 屏数 + 评级奖励`。

**和果子走同一个出口**：这一趟的账只有一个出口，中途退出也只按已攒下的算。
评级奖励自己写一份存档的话，两条口径必然漂移（MEMORY 教训 2）。

抽成纯函数 `rankAward(prevBest, rk)` 是为了冒烟能直接测四条边界 ——
塞在清屏流程里的话，测试只能靠机器人打到通关，而"这一趟正好拿 S"不可控。

### 玩家看得见

结算卡评级徽章下方加了「材料 +N」一行。
**机制做了 ≠ 玩家看得见**（本项目第 5、6 条教训）—— 材料加了但结算卡不提，等于没给。

## 2. 战绩落盘：`pawpack.stats`

| 项 | 内容 |
|---|---|
| 键 | `pawpack.stats`（和 `pawpack.best` 分开） |
| 结构 | `{ t: number[], c: number[] }`，下标 = 全局屏号，长度恒为 27 |
| 规则 | 用时只快不慢、连锁只高不低 |
| 坏档 | 一律清 0，不清空下标 |

**为什么不 filter**：过滤会把下标压缩，`t[3]` 变成 `t[2]`，
于是第 3 屏的战绩挂到第 4 屏头上 —— 而且看起来完全正常。

**为什么必须战斗侧写**：主界面没有 `playT`，用时只在战斗里存在。

## 3. 战绩榜（本地）

点 HUD 那排进度点打开 —— **没有新增入口节点**：这条路本来就有，只是原来通向一句废话 toast。

| 块 | 内容 |
|---|---|
| ① | 总星数（大号）+ 一句人话（`starsTitle`） |
| ② | 四档分布 S / A / B / 未通 |
| ③ | 三项纪录：全 S 屏数 / 最快一屏 / 最高连锁 |
| ④ | 27 格明细 3×9，颜色 = 评级 |

**总星数 = 27 × 3 = 81**，是这游戏唯一一个单调可比的数。
不用"最快用时"当主指标：单屏可以靠"不打死怪直接跑"刷 1 秒通关，
而总星数要求**用时达 par 且 用球达 par** 两条同时满足，刷不出来。

### 明确没做云端榜

客户端上报的分数**永远不可信**（改个内存就第一）。真榜要么做好友榜
（靠社交压力代替反作弊），要么接受作弊。

**顺序必须是**：① 评级给奖励（本轮）→ ② 总星数（本轮）→ ③ 本地榜（本轮）→ ④ 有发布渠道再接云端。

## 4. 图纸碎片：给派遣一个独占产出

### 病根

| 渠道 | 效率 |
|---|---|
| 派遣（最赚的仓鼠，满 10 趟） | **10 果/分** |
| 战斗（一趟 5 屏） | **72 果/分** |

**1/7**。而且果 / 材 / 币 / 干粮四样战斗全给更多 ——
问题不是效率，是**没有独占**。

### 设计

| 项 | 值 | 依据 |
|---|---|---|
| 满一趟派遣（10 趟 × 60 秒）给 | **2 个** | `DISPATCH_SHARD = 2` |
| 一件改造件要 | **2 个** | 也就是"想装下一件，先去等一趟" |
| 收集篮倍率 | **不作用** | 吃了会 `floor(2×1.5)=3`，一件一趟就够，独占价值当场消失 |
| 旧档缺字段 | 0 | **不继承 `DEFAULT_SAVE.shards`** —— 以后改初始赠送，老玩家不该凭空多一份 |

改造件代价变成 `180 果 · 4 材 · 2 图`。三条约束各管一件事：

| 约束 | 数值 | 管什么 |
|---|---|---|
| 180 × 2 > 290 | 360 > 290 | 一趟买不到第二个 |
| 180 + 40 < 290 | 220 < 290 | 买完还够喂饭 |
| 4 ≤ 5 | — | 走满一趟才够材料 |
| **2 ≤ 2** | — | 碎片要等一次派遣 |

缺货时按「**碎片 > 材料 > 果子**」顺序报：碎片最难拿，先说它最有信息量。
三种都不够时只说果子，玩家修好果子再来还是买不到，会骂人。

### 本轮钉住的关键断言

- 打平不给 / 降级不给 / 降级不覆盖旧纪录（否则第 1 屏能无限刷）
- 更慢的用时、更低的连锁不许覆盖纪录
- 坏档 → 全 0，不崩；越界屏号不抛
- 脏评级（`"SSS"` / `"S "` / `null` / `3`）一律不计分
- 四档之和 = 屏数
- 负 / NaN 的 `rankLogs` 被夹到 0
- **战斗侧不产碎片**（`!/S\.shards|\.shards =/`）—— 战斗能拿到的话独占性就没了
