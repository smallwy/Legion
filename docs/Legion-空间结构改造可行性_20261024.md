# Legion · 关卡空间结构改造可行性评估

> 版本 v1.0 · 2026-10-24 · 触发：用户「关卡肯定不是这样平铺的吧 感觉没啥意思 这样下去 可不可以做成那种围起来的 做创意性的 靠球去推塔 过关是规则设计的 有的是推完 有的是数量满足 反正这个是数值控制」
>
> 本文只做**空间结构与表现层**的可行性判断，不涉及数值配平与引擎代码。标注「需程序侧确认」的条目，必须由程序角色复核后才能排期。

---

## 0. 结论先行

1. **规则多样化你已经做完了。** `GOALS` 里已有 7 种过关条件（清场 / 限球 / 连锁 / 落袋 / 收成 / 零崩 / 无伤），27 屏的实际分布是 `chain 7 / clear 5 / collect 5 / limit 4 / bank 2 / intact 2 / nohit 2`。**玩家感觉"没意思"，不是规则少，是空间记不住。**
2. **"平铺感"是可以量化的，不是主观感受。** 27 屏里 **24 屏的出口固定在 x=852**，131 块台面**全部是水平横条**（4.85 块/屏）。玩家的空间语法只有一句话：「从左推到右」。规则换了 7 次，空间只换了 1 次 —— 而玩家是用眼睛读关卡的，不是用 HUD 文字。
3. **"围起来"能做，成本比想象低；"推塔"能做，但有一个物理硬限制会让新手做法直接失败**（见 §3）。**"换成俯视"不能做** —— 等于重写物理与全部绘制，27 屏几何作废。
4. **推荐路线：不推翻现有 27 屏，新增两种"结构型"关卡语法（围合庭 + 推塔）作为增量**。先做 4~6 屏验证爽感，通过再铺开。

---

## 1. 诊断：为什么"平铺"读不出变化

| 维度 | 现状 | 问题 |
|---|---|---|
| 出口位置 | x=852 占 24/27 屏，其余 848×2、830×1 | 出口从来没有换过地方，玩家不需要看就知道去哪 |
| 台面形态 | 131 块全部水平横条，无纵向结构 | 每一屏的"轮廓"长得一样，缩略图并排看不出区别 |
| 层数 | 地面 556 + 248/350/462 三层固定 | 层高是常数，玩家第一次见就学会了全部 |
| 行进方向 | 单一：左 → 右 | 没有任何需要"回头"或"绕路"的屏 |
| 判定轴 | 全部是"把敌人送进洞/坑" | 只有一条胜负轴，规则再多也是同一种动作 |

**核心结论**：7 种规则被一条永远不变的空间通道压平了。玩家的经验是「我在这条路上换着花样推」，而不是「我在一块场地上做决策」。

**对比说明**：同样只有"推"这一种动作的游戏（雪人兄弟、Peggle、推箱子），靠的不是增加动作，是**改变空间的拓扑**——回环、封闭、垂直、可破坏。这三件事本作一件都没用上。

---

## 2. 三方案可行性

### 方案 A · 围合庭（场地经营）

**做法**：保留侧视与全部现有物理，把"出口固定在右"改成**多个出口分散在场地上**；上方加横梁或悬台形成封闭感；用错位台面造出回环。

| 项 | 判断 |
|---|---|
| 可行性 | **高**。左右墙已存在（`WALL_L=26` / `WALL_R=934`），球撞墙反弹系数 `0.62` 已实现，`vy`/`GRAV` 已有 —— **技术上几乎零新增** |
| 改动面 | 关卡数据（`camp` 从单点改数组）+ 结算判定 + 一点绘制。**不动物理，不动 27 屏已调的几何** |
| 不可行点 ① | **高弹 + 卷人 = 失控**。球在墙间来回弹 3~5 次，玩家从「我在推」变成「我在看」。必须加限制：**一次推动只能改变一次方向**，或反弹系数在围合场内降到 0.45 以下 |
| 不可行点 ② | **侧视的"围起来"其实一直是围着的**——左墙右墙本来就有，上方是敞开的天空。所以单纯加墙玩家感受不到，必须有「出口不止一个」配合，否则只是"多画了几道栏杆" |
| 美术代价 | **天空消失**。6 套产地色板里天空是最大色块，围合后背景占比掉 40%，色板要重调（中心比边缘亮 2 个明度级，否则读作"洞"） |

**判定**：值得做，但**必须和"多出口"捆绑**，否则是纯装饰。

---

### 方案 B · 推塔（纵向结构）

**做法**：画面中立一座纵向结构（塔/堆叠台面），敌人站在上面；球撞上去让结构塌，塔上敌人失去立足点掉进坑或营地。

**这里有一个物理硬限制，决定成败**：

> 球**只能贴地面或台面表面滚动**。它的 `vy` 只来自重力下落，**没有任何向上主动速度**。也就是说 —— **球永远打不到塔的高层。**

所以"推塔"必须拆成三种做法，只有第一种是新手能直接做的：

| 做法 | 球怎么打到 | 技术成本 | 判断 |
|---|---|---|---|
| **① 撞塔基 → 整塔垮** | 贴地滚过去撞最下层 | **低**（塔的每层是一个 `plat`，撞中触发整组移除 + 碎块粒子） | **推荐**。一撞全塌，是天然的 GIF 瞬间 |
| **② 逐层拆** | 需要球能向上飞 | **中**（要给球加"上抛"，等于新增一个武器/道具维度） | 可选，做完 ① 再评估 |
| **③ 真刚体积木塔** | 需要刚体物理 | **高**（现为手写 AABB，无旋转、无堆叠求解） | **不做** |

| 项 | 判断 |
|---|---|
| 可行性 | **中**。核心新增概念只有一个：**可破坏台面**（`plats` 加 `hp` / `breakable`，`removePlat()`） |
| 视觉收益 | **最高**。纵向剪影 + 崩塌瞬间，是 27 屏里唯一能做出"重量感"的结构。缩略图测试天然过（塔是高瘦剪影，一眼可辨） |
| 不可行点 ① | **平台消失会打破几何不变量**。27 屏的落点、可上性、营地可达性全是按**静态**台面算的。塔一塌，敌人掉哪、球卡不卡，全部重新算 —— 刚清完的 43 项几何失败就是"台面错 20px"引发的，拆台面的影响面更大 |
| 不可行点 ② | **推塔和"推进营地"是两条胜负轴，不能同屏共存**。现在核心是"把敌人送进洞"，推塔是"把结构拆掉"。混一起玩家会问「我到底该干什么」。**必须整屏只留一条轴** |
| 不可行点 ③ | **塔的层数必须能被一眼数出**。侧视剪影里 4 层塔和 5 层塔在 960 宽画面里只差 14px，玩家不知道还剩几层 —— 需要在塔侧加层数刻度（美术侧解决） |
| 美术代价 | 塔需要独立一套材质（木栈/石堆/冰柱），且**崩溃碎块必须有 2~3 帧残骸状态**，否则"塌了"读作"图没了" |

**判定**：**最值得做，但只做 ① 号做法**，且必须整屏独占一条胜负轴。

---

### 方案 C · 俯视围栏（真·围起来）

**做法**：换视角，四壁围合，球像台球一样弹。

| 项 | 判断 |
|---|---|
| 可行性 | **不可行（本作周期内）** |
| 原因 | ① 俯视 = **没有重力**，`GRAV` / 坡 / 台面 / 坑 / 跳 五套系统全部失效；② 27 屏几何**全部作废**；③ 全部绘制（敌人走路、宠物立绘、球滚动）的视角都要重画 |
| 唯一例外 | 作为**独立的支线小关卡**（不接主线、不复用 27 屏几何、单独一套 `mode`）可以试。但那等于做第二个游戏 |

**判定**：**不做**。你的直觉"围起来"是对的，但侧视 2D 里已经有墙了，换俯视买到的东西不值这个价。

## 3. 推荐路线：增量替换，不推翻 27 屏

**原则：新语法只做「插入」，不改已有 27 屏。** 27 屏刚做完几何校验，全部重调是纯浪费。

| 阶段 | 内容 | 屏数 | 验证点 |
|---|---|---|---|
| **P1 验证** | 推塔屏 ×2（做法 ①）+ 围合庭 ×2（三出口） | 4 | 爽感能不能被读出来：连续打 4 屏，问他"这 4 屏和前 3 屏感觉一样吗" |
| **P2 铺开** | 每产地末关前插 1 屏结构屏 | +3 | 结构屏放在产地收尾前，作为"这产地的高潮" |
| **P3 混排** | 结构屏占总量 1/3，其余保持平铺 | 27 → 36 屏 | 平铺屏不再是"全部"，而是"调剂" |

**关键设计约束（三条，缺一不可）**：

1. **结构屏必须整屏独占一条胜负轴**。推塔屏只判"塔状态"，围合屏只判"多出口分配"，不混"清场"。
2. **结构屏的入口必须在屏开局 3 秒内被看懂**。做法：屏开局先给一次"自动演示"（塔自己塌一层 / 球自己弹一次），不写文字。这一条是玩家理解成本的唯一解法。
3. **围合屏的出口数量与位置必须承担数值意义**。三个出口 = 三种价值（近的给少、远的给多），否则玩家还是会往最近的那个推。**这里需要数值角色接手**。

## 4. 美术层面的连带影响（我的本职判断）

| 项 | 影响 | 处理 |
|---|---|---|
| 产地色板 | 围合/塔屏的天空占比从 ~55% 掉到 ~15%，6 套色板的最亮色块失去用武之地 | 每产地补一套「结构屏变体」（压暗天空、抬高地面材质占比） |
| 明度层级 | 围合屏四壁会吃掉边界明度 | 中心主体比墙面**至少高 2 个明度级**，否则读作"从洞里往外看" |
| 塔的剪影 | 层数在 960 宽里只差 14px/层 | 塔侧加**逐层凹槽 + 层数刻度点**，靠形状不靠尺寸区分 |
| 崩塌表现 | 单个 sprite 消失读作"图没了" | 每层需要 **2~3 帧残骸**（完整 → 开裂 → 碎块），并保留 0.4 秒再淡出 |
| 围合边界 | 墙画太厚会压缩可玩区 | 墙面视觉厚度 ≤ 12px，物理厚度 ≤ 6px（**需程序侧确认**当前 `WALL_L/WALL_R` 是否已是纯边界） |

## 5. 需要拍板的四件事

1. **"推塔"你要的是哪种？** ①撞塔基整塔垮（便宜、爽、可做）／②逐层拆（要给球加上抛，改动更大）／③真物理（不做）。**我推荐 ①**。
2. **结构屏占多少？** 全换（27 屏重做）／1/3 混排（推荐）／只做 4 屏试点。
3. **围合庭要不要和推塔分开做？** 我建议先做推塔（视觉收益高、机制独立），围合庭放 P2。
4. **能不能先让我出 2 屏的静态概念图？** 拿图给你看，比拿描述给你看快。看完再决定要不要动代码。
