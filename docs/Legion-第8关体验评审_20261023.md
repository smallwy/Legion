## 1. 通关条件不清晰 —— 可读性缺陷，必修

### 证据

**① 目标卡只画了名字，没画规则。**

`GOALS.clear` 定义了三层文案（1307 行）：

```js
clear: {
  id: "clear", name: "清场", verb: "送走全部",
  brief: (st, n) => "把 " + n + " 只全送走，怎么推都行",   // ← 这句从来没被画出来
}
```

HUD 上只出现 `name`（"清场"两个字）。玩家看到"清场"无法推出"把 10 只全送走"。

**② 「球 6」是错误读数。**

7509 行：

```js
text: "剩余 " + (S.total - S.killed) + " 只 · 球 " + S.stat.made
```

`S.stat.made` 是**已经造了多少颗球**（累加器，`makeBallFrom` 里 `S.stat.made++`），不是剩余球数。玩家读到"球 6"会理解成"我还有 6 颗球"，实际含义是"你已经造了 6 颗"。

而同关 `par: { time: 75, made: 10 }` —— 10 才是评级标准，这个数字玩家全程看不到。

**③ 真正的过关条件比 UI 显示的多一条。**

```
checkGoal():  if (S.killed < S.total) return false;
主循环:        allSpawned && S.foes.length === 0 && S.balls.length === 0
```

第三条 `S.balls.length === 0` 意味着：**敌人被卷进球里但球还在场上滚，不算过关**。玩家把最后一只卷进一颗球、球慢慢磨到崩开，这期间屏幕显示"剩余 0 只"却不出结算 —— 玩家 100% 会以为卡死。

**④ 进度条没有文字。**

`frac: S.killed / Math.max(1, S.total)` 只有视觉，没有 `0 / 10`。

### 玩家实际看到

> "清场" + 一条空进度条 + "剩余 10 只 · 球 6" + 金币 4。

信息全在，但没有一条告诉玩家"目标是送走 10 只""球 6 是什么意思""为什么清了 0 只还不赢"。

### 改法

| 优先级 | 改什么 | 怎么改 |
|---|---|---|
| P0 | 目标卡第二行 | 渲染 `GOALS[x].brief(...)`（函数已存在，直接调），字号比 name 小一档 |
| P0 | 「球 6」读数 | 改成 `造球 6 / 10`（带球图标），`10` 取自 `par.made`。语义从"剩余"变成"用量" |
| P1 | 进度条叠字 | 条中央叠 `已送 4 / 10`，白字 + 深色描边保证在橙条上可读 |
| P1 | 收尾卡死提示 | 主循环里若 `S.killed >= S.total && S.balls.length > 0`，HUD 闪一句「把球里剩下的送走」 |

> 这四条全是 UI 层，不动任何数值与判定，不影响 `grove-smoke.js` / `grove-runtime-check.js`。

## 2. 乌鸦半天打不着 —— 设计如此，但判定窗口有缺陷，必修

### 定性

**它不智能，行为极其简单**，问题出在「摆动幅度把判定窗口吃掉了一半」。

### 证据

**① 行为（2310–2323 行）** —— 全速贴向玩家，垂直正弦摆动：

```js
if (f.fly) {
  const dx = p.x - f.x;
  f.vx = sign(dx) * f.def.spd * FK * (Math.abs(dx) > 40 ? 1 : 0.15);
  f.x += f.vx * dt;
  f.y = f.homeY + Math.sin(f.bob * 0.8) * 18;   // ← 固定 homeY，±18px 摆动
  return;
}
```

`crow: { w: 36, h: 32, spd: 92, kind: "fly" }`，第 8 关第 2 波出生点 `{ x: 500, y: 300, fly: 1 }` → `homeY = 300`，y 在 **282 ~ 318** 之间摆。

**② 碰撞判定（2951 行）** —— 中心点距离，阈值 `b.r + f.h/2`：

```js
const dx = Math.abs(b.x - f.x), dy = Math.abs((b.y - b.r) - (f.y - f.h / 2));
if (dx > b.r + f.w / 2 || dy > b.r + f.h / 2) continue;
```

普通球 `r = 22`（`makeBallFrom`：`const r = isBoss ? 44 : 22`），乌鸦 `h = 32` → 阈值 **38px**。

**③ 算一下三种情况（球底 `b.y` 贴台面）**：

| 玩家在哪推球 | 球心 y | 鸦心 y（266~302 摆动） | dy | 能否撞到 |
|---|---|---|---|---|
| 350 层台面 | 328 | 266 ~ 302 | **26 ~ 62** | **只看鸦心 ≥ 290 才行** |
| 248 层台面 | 226 | 266 ~ 302 | 40 ~ 76 | ❌ 全部打不到 |
| 地面滚球 | 534 | 266 ~ 302 | 232 ~ 268 | ❌ 全部打不到 |

**④ 关键结论**：在唯一有效的 350 层推球时，判定窗口只在 `sin(bob*0.8) ≥ 0.333` 时开放 ——
**约 39% 的周期能打中，61% 的时间球会从它身上穿过去。**

这就是"半天打不着"的真实原因：不是它聪明，是**判定窗口每 2.5 秒只有 1 秒开着**，而球滚过去的时机玩家无法控制。视觉上球明明贴着脸过，判定说没碰上 —— 这是玩家最难接受的一类失败。

**⑤ 更糟的一条**：第 8 关中间 `340 ~ 600` 是真空（无台面），乌鸦出生点 `x = 500` 正在真空正中。它飘在真空区上方时，**球没有任何物理路径能经过那里**，等于短暂无敌。

### 改法

| 优先级 | 改什么 | 怎么改 |
|---|---|---|
| P0 | **悬停高度下沉 18** | `f.y = f.homeY + FLY_DROP + sin(...) * 18`（`FLY_DROP = 18`）。把基准从 300 压到 318，可打窗口从 39% → **83%** |
| — | ~~摆动幅度收窄~~ | **实测反了，不要动。** 摆幅 18→7 让窗口从"偶尔低下来"变成"一直高着"，第 8 关机器人从 79s 达标直接变 240s 超时 |
| — | ~~飞行单位判定容差 +10~~ | **试过，撤回。** 变成"球还没碰到鸟它就变球了"，比打不着更糟 |

> 关键教训：**摆动幅度不是"判定空窗率"的旋钮**。它让鸟偶尔飞进判定区，
> 收窄摆幅等于把这个机会一起砍掉。真正错的是**基准高度**（关卡表里填的 300
> 比球心 328 高出 28px，超出判定阈值 38 能覆盖的范围）。改基准，别改摆幅。

## 3. 野猪走路像平移 —— 贴图化副作用，必修

### 定性

**贴图是静态的，行走信息在贴图化那一刻就丢了，现有的补偿量小到不可见。**

### 证据

6883–6891 行，敌人立绘的绘制分支：

```js
const walkBob = f.kind === "walk" || f.kind === "charge"
  ? Math.abs(Math.sin(t * 8 + (f.bob || 0))) * 1.2 : 0;    // ← 只有 1.2px
g.drawImage(foeImg, -iw / 2, bh / 2 - ih - walkBob, iw, ih);
```

- 野猪 `vh = 54` → **1.2 / 54 = 2.2%**，屏幕上是 1 个像素的抖动，肉眼读不出来。
- `Math.abs(Math.sin(...))` 是**单频上下跳**，读作"蹦"，不是四足动物"左右换重心"的走。
- 没有水平重心偏移、没有前倾、没有步频差、`g.scale(f.face, 1)` 只做镜像，贴图没有第二帧。
- 代码自己承认了这件事（注释原文）："贴图是静态的，原来画法里'腿在动'的信息会丢"。

对比：代码图形的版本里有真正的腿摆动（`const swing = Math.sin(o.gait || 0) * 0.95`，6330 行），贴图化之后这套全废。

### 改法（按成本递增，1+2 能解决 80%）

| 优先级 | 改什么 | 怎么改 |
|---|---|---|
| P0 | **换维度的摇摆** | 把上下 1.2px 弹跳换成**左右旋转**：`g.rotate(Math.sin(t*9 + f.bob) * 0.045 * f.face)`。四足走动是重心左右交替，旋转比上下弹跳好读一个数量级。零美术成本，1 行 |
| P0 | **冲锋前倾** | `charge` 类（野猪）单独处理：常驻前倾 `0.10 rad`，冲锋瞬间 `0.18 rad`；配合 `scaleX(1.03)` 的呼吸。野猪本来就是「唯一会冲锋的小怪」，姿态必须和毛毛虫区分 |
| P1 | **步频跟速度挂钩** | 现在 `t*8` 是固定频率，和实际速度无关。改成 `t * (6 + |f.vx| / 26)`，跑得快腿扇得快，静止时几乎不动 |
| P2 | **3 帧序列帧** | `prep_foes.py` 出「左腿前 / 中立 / 右腿前」三帧，按 `gait` 切。唯一能真正解决"走路"的方案，但要重出美术资源 |

> P2 只在 P0 做完了还觉得不够时再上。美术侧我可以出三帧，但需要同步改 `prep_foes.py` 的装框逻辑和 `ART` 键名（`foe-boar-0/1/2`），属于跨文件改动，要单独排。

## 4. 球到处弹飞 —— 不是弹簧，是四条机制叠加，建议

### 定性

**第 8 关没有弹簧菇**。你看到的"弹飞"是四条既有机制的合成，被第 8 关的窄球道放大。

### 证据

**① 先排掉弹簧**：第 8 关配置（1245–1253 行）只有 `plats / pits / stumps / camp / waves`，`ramps: []`，**没有 `bouncers` 字段** → `BOUNCERS = L.bouncers || []` 为空。弹簧菇（`vy = -980`）只在第 5 关。

**② 四条真实来源**：

| 机制 | 代码位置 | 表现 |
|---|---|---|
| 撞墙反弹 | 2814–2833 | `vx = -vx * 0.62`，最低 120，带木屑 + 震屏 |
| 球撞球连带 | — | 相撞把速度交给对方，远处那颗突然飞走 |
| 撞 BOSS 弹回 | 2968–2976 | `vx = dr * max(380, |vx|*0.85)`，`vy = -140` |
| 塔沿自由落体 | 地形 | 中间 320px 真空，球滚过塔沿直接掉 |

**③ 为什么第 8 关最明显**：两座塔各 **314px** 宽（`26..340` / `600..860`），球道是八关里最短的之一。球滚半秒就撞墙，反弹频率自然最高。

### 改法

| 优先级 | 改什么 | 怎么改 |
|---|---|---|
| P1 | 反弹的可读性 | 现在有木屑 + 震屏，缺"方向"。撞击点加一个 1 帧的朝内箭头或「弹!」浮字（弹簧菇已经有「弹!」，撞墙复用同一套即可） |
| P2 | 反弹次数 | 现在"第二次撞墙就散掉"，可以考虑改成「衰减到某个速度以下就停下来滚」，而不是消散 —— 消散会被读作"球没了" |
| — | 不改 | 如果手感上你接受，这条可以只做 P1 的可读性，不动物理 |

> 我的判断：**这条不是 bug，不需要改物理**。球的"弹"是这个游戏的核心手感之一（撞墙有反馈、球撞球能连锁）。真正缺的只是"这声弹是从哪来的"的指向性。

## 5. 打完敌人变多 —— 设计如此，但感知为零，必修（加提示）

### 定性

**两个机制叠加，都是有意的设计，但玩家完全没有线索，所以读作 bug。**

### 证据

**① 波次补位（8552–8567 行）—— 这是主因**

```js
const trigger = nextBoss ? alive === 0 : alive <= 1;      // ← 剩 1 只就补
if (trigger && S.waveT > 3.5) S.waveGap = nextBoss ? 1.6 : 1.1;
```

**场上剩 ≤1 只 → 1.1 秒后刷下一波（6~7 只）**。也就是：**你清得越快，下一波来得越快**。

设计意图代码里写清了（原文注释）："最后一只常常站在高台上，玩家得爬两层、糊三下、再推一趟 —— 那 20 秒里没有任何决策，只有赶路。"

这个判断本身是对的，但代价是：玩家卷掉一片、场上剩 1 只 → 6 秒内又冒出 7 只 → **"我打完反而变多了"**。

**② BOSS 产卵（2447–2470 行）—— 次要，但更迷惑**

第 3 波是 `{ foe: "boss", lv: 5 }`，`spawnT = 7.5s` 周期：
- 两侧各钻出 1 只幼虫
- 幼虫不打人，爬回 BOSS 身边被吃掉 → **BOSS 补 1 层壳**（上限 3）
- 幼虫没有名字、没有图例、和毛毛虫长得像 → 玩家读作"又冒出两只虫"

**③ 为什么感知为零**

| 机制 | 现有提示 | 玩家能读到吗 |
|---|---|---|
| 波次补位 | `S.waveGap = 1.1` 秒的地面三圈扩散 + 「下一波」三个字 | ❌ 1.1 秒，且玩家这时在盯场上 |
| 「剩 1 只就补」的规则 | 无 | ❌ |
| BOSS 产卵 | 「钻出两只幼虫」浮字（`addText`） | ⚠️ 有，但没说"它会回巢补壳" |
| 幼虫的作用 | 无 | ❌ |

### 改法

| 优先级 | 改什么 | 怎么改 |
|---|---|---|
| P0 | **波次预告延长 + 常驻** | `waveGap` 1.1 → 2.0 秒；并且从「场上剩 2 只」开始，HUD 角落就挂一个闪烁的「下一波」小标 —— 让"要来了"是持续的，不是 1 秒的 |
| P0 | **把总数显式化** | 目标卡改成 `已送 4 / 10`（同第 1 条）。**总数固定这个事实一旦可见，"变多"的错觉就消失**——这是最省力、最有效的一改 |
| P1 | 幼虫的身份 | 幼虫头顶挂一个小图标（壳碎片），或浮字改成「幼虫 · 爬回 BOSS 补壳」；颜色从 `#CDE888` 往冷调偏，与毛毛虫 `#8FD45E` 拉开 |
| P1 | BOSS 产卵的可读性 | 产卵前 0.5 秒给 BOSS 一个"鼓肚子"的 `scale` 脉冲 + 屏幕边缘红色脉动，让"它要下蛋了"提前一秒可见 |
| P2 | 波次节奏 | 如果实测还是觉得被推着走，把 `S.waveT > 3.5` 的呼吸期提到 5 秒（现在 3.5） |

> **不要取消补位机制**。"清完才刷"会把最后一只的赶路时间变成纯空转，那是更大的体验问题。缺的是**预告**，不是机制。

### 踩到并修掉的坑

**换错旋钮，把机制改坏了。** 一开始按"摆幅决定判定空窗率"的思路把 18 收到 7，
结果第 8 关机器人从 **79s 达标** 变成 **240s 超时**、造球数 38→156。
原因是摆幅是乌鸦"偶尔飞低进判定区"的唯一机会，收窄等于把机会砍掉；
而基准高度 300 本身就比球心 328 高 28px。**该改的是基准，不是摆幅。**
补一条：摆幅收到 7 即使配上正确下沉量，也因"鸟几乎钉在判定线上不动"
把机器人拖进 MAX_BALLS 死锁。**抖动节奏不能压成常数。**

**加长浮字会出屏。** 「钻出两只幼虫」(6 字) → 「幼虫钻出 · 回巢给 BOSS 补壳」(13 字)，
BOSS 靠左时字头直接压到屏边。在浮字绘制循环里加 `measureText` 夹取解决 —— 这一条
对所有靠边敌人的浮字都生效，不是只对幼虫。

## 第五轮（2026-10-23 晚）：目标卡改版 / 解锁可见性 / 敌人步态

这一轮的三条全部来自同一张第 8 关截图上的红框标注，**都是"读不出来"类问题**，
不是机制问题 —— 所以改动全部落在表现层，判定与数值一行未动。

### 1. 目标卡：从"系统词 + 一根条"改成"玩家话 + 豆子阵列"

| 项 | 改前 | 改后 |
|---|---|---|
| 目标名 | `清场` | `全部送回家` |
| 说明 | 把 12 只全送走，怎么推都行 | 12 只一只不留，推进营地或火坑都算 |
| 进度 | 14px 胶囊 + 条内 10px 字「0 / 12」 | **12 颗豆子，一颗 = 一只**，已送的实心带高光、未送的是空圈 |
| 数字行 | 造球 0 / 10 | 左「还差 12 只」· 右「造球 0 / 10」 |

**为什么拆成两张表。** `GOALS[x].name` 是系统词（冒烟脚本拿它打印战绩表格、`padEnd(5)`
排得整整齐齐），不能动；新增的 `title` 才是给玩家看的话，HUD / 关卡标题 /
结算卡标题三处读 `title || name`。这样文案能随便改，守门脚本一行不用碰。

**为什么进度要拆豆子。** 「已送 4 / 12」是这一局**唯一的目标读数**，却被压进
14px 高的胶囊里，字号只能给到 10px。拆成 12 颗豆子之后，"还剩几个空圈"是
扫一眼就有的答案，根本不用读字；底下的中文只是兜底。

豆子**固定豆径、整体居中**（`dr = 5.8`、间距上限 21）：按 N 均分宽度会让
8 只的关散成省略号、14 只的关挤成一串珠子。收成关（70 份）继续走连续条 ——
70 颗粒子是噪点不是信息。

### 2. 解锁的伙伴：三处都看不见，三处都补上

**根因不是展示缺失，是"解锁这件事从来没有主动说过"。**
`recordClear` 会返回"这一关刚好跨过阈值的伙伴"，但这个返回值**被直接丢掉了**；
唯一的提示是一条 3.6 秒的 DOM 提示，而且只在 `?from=home` 时才弹。
而推关模式（`nextLevel` 直接进下一关）根本不回主界面 —— 玩家通了第 8 关、
星屑到家，屏幕上什么都没发生，回主界面才发现多了一只。

| 位置 | 做了什么 |
|---|---|
| **关内（目标卡下方）** | 「通这关 · 星屑 到家」+ 头像圆片。**不闪不动** —— 奖励是事实不是事件 |
| **结算卡（卡片上方）** | 金底贴纸横幅「新伙伴到家 · 星屑」+ 头像，斜 -0.055 rad |
| **主界面槽位** | 锁着的标签 `第7关` → `差2关`，`title` 也改成「再通关 2 关解锁 · 豆奶」 |

**`第7关` 是这次最典型的坏文案**：一个没有动词的名词短语。玩家看到槽位下面
三个字"第7关"，第一反应是"这是第 7 关的宠"或者"我要去打第 7 关"，
而不是"我还差 2 关"。"差 N 关"把距离写在脸上，是唯一的可执行读法。

关内预告条的判定口径必须和 `recordClear` **逐字一致**（都用
`new Set(cleared).size + 1`，不是 `S.progress + 1`）。用后者的话重打老关
也会挂"通这关 · 年糕到家"，打完什么也没有 —— **挂着不兑现比不挂更伤**。

结算横幅挂在卡片**外面**：卡里 570×412 已经排满（角标/关卡名/评级/三星/
它说/数据/按钮），硬挤一行只能压缩评级区，而评级是这一页的主角。

### 3. 敌人步态：毛毛虫和野猪是两种完全不同的走法

前两版都失败，踩的是同一个坑：**把两种步态套了同一套动作。**

- **毛毛虫（`walk`）是蠕动** —— 一伸一缩、贴地爬、**没有左右重心交替**。
  给它画摇摆，读作"一只虫子在摇头"，比不动还怪。
- **野猪（`charge`）是四足** —— 左右换重心 + 每一步落地顿一下 + 冲锋前倾。

上一版还有三处硬伤：`lean` 常驻 0.08~0.18 rad 且**不随速度变**（一张站着画的
图被恒定掰斜 10°，读作"要摔倒"不是"在冲"）、`sway` 只有 2.9°（54px 高上是
1.4px 位移）、`walkBob` 1.6px —— 后两个都低于人眼在动图里的分辨阈值。

**这一版的核心是挤压拉伸（squash & stretch），不是位移。**

| 类型 | 形变 | 频率 | 其它 |
|---|---|---|---|
| 毛毛虫 | ±10.5% 横向 / ∓14.5% 竖向，`sin` 带正负 | 2.6 ~ 6.8 Hz·速度 | 无摇摆、无前倾 |
| 野猪 | +12.5% 横向 / −16.5% 竖向，`|sin|` | 6.5 ~ 14.5 Hz·速度 | 摇摆 6°、前倾 6.3°×速度 |

### 踩到并修掉的坑

**整体上下位移会让脚离地。** 第一版给野猪加了 `walkBob = (1-step) * 4.5`，
连拍两帧一对比就露馅：整只猪被抬起 4px、四只脚全部离地，读作"它在飘"。
**起伏必须来自形变，不能来自位移** —— 压扁拉伸的锚点是脚底
（`translate(0, bh/2)` 已经把原点挪过去），身体怎么伸缩脚都钉在原地。
位移只能做出"跳"。

**幅度要给够。** 0.075 的竖向形变在 54px 高的猪上是 4px，90ms 间隔的连拍里
几乎看不出差别。调到 0.165（≈9px）才"一眼能看出在颠，但还不像橡皮"。
Q 版走路的挤压量通常就在 15~20% 这一档。

```
ALL9=1 grove-smoke.js    387 项全绿（八关机器人巡回，第 8 关仍达标）

ts-syntax-check.js       4 个文件语法通过
```

画面验收：第 8 关 HUD（豆子阵列 + 关内奖励条）、结算卡（解锁横幅）、

## 第六轮（2026-10-23 深夜）：主界面解锁 bug / 步态第五版 / HUD 布局

这一轮三条里，**第 2 条（主界面看不到宠物）是真 bug，而且是两条独立断点叠出来的**，
不是"表现没做够"。先给结论和证据。

### 1. 「解锁了但主界面没有」——两条断点，都在 Cocos 侧

`grove.html` 和 `game.html` 那套存档/解锁是对的（`clearCount() >= p.at`）。
玩家看到的是 **Cocos 主界面**（`HomeRuntime.ts`），那里有两条独立的错。

#### 断点一：`bindPets` 的判据写成「只留最新那一只」

```ts
// 改前
const lead = PETS.find((p) => this.save.cleared >= p.at);   // 已解锁里 at 最大的
const on = !!def && !!lead && def.id === lead.id;           // ← 只有它 true
```

后果不是"新解锁的不出现"，而是**更糟的一种**：解锁雪团的那一刻 `lead` 换成雪团，
砂糖 / 年糕 / 团子同时 `active = false` —— 院子里立刻只剩一只，而且以后每解锁一只，
上一只就消失。

用真实数据跑了一遍（源是 `Roster.ts` + `Home.scene`，不是手算）：

| cleared | 修复前草地上有 | 修复后有 |
|---|---|---|
| 0 | 砂糖 | 砂糖 |
| 1 | **年糕** | 砂糖、年糕 |
| 3 | **团子** | 砂糖、年糕、团子 |
| 5 | **雪团** | 砂糖、年糕、团子、雪团 |
| 8 | **星屑** | 六只全在 |

`cleared = 3` 时屏幕上只有团子 —— 玩家说"我解锁了几个，主界面没有"，读数完全对得上。

同一份判据在 `syncLawn()` 里还有一份（派遣回来会重算 active），**两处必须一起改**，
否则派一次遣草地又回到一只。

#### 断点二：底部宠物槽位永远 55% 透明，且标签写死「第N关」

`bindDock()` 里对所有 `Slot-` 一律 `opacity = 140`（55%），已到家的也是灰的；
而 `tag` 那个 Label 的文字是**场景里写死的「第1关 / 第3关……」**，
`HomeRuntime` 从来没改过它。

所以已经解锁的槽位看起来和没解锁的一模一样。改法：

- 未到家 `opacity 140` + `差{need}关`；已到家 `opacity 255` + 宠物名。
- 「差N关」和 `game.html` 的 `.tag` 口径一致，两边读起来是同一句话。

#### 顺带修掉的两个连带问题

- **`PET_ROAM['砂糖'] = [120, 392]`** 是"草地只站一只"时期的写法（给它宽敞的走动范围）。
  六只同时显示后，这 272px 直接盖住年糕的 `[288, 358]` → 两只走成一坨。
  改回原型的原始值 `[136, 192]`。
- **落脚点共用 `LAWN_SPOT` 一个点**，六只会叠在一起。改成 `PET_FOOT` 表，
  直接搬 `game.html` 的 `cx / footY`：六档 `footY`（548/568/574/596/602/610）
  本身就是景深，排成一条 y 会读成"一排贴纸贴在草地上"。

### 2. 步态第五版：伸缩的轴错了

前四版全部失败，前四版里有三次在调参数。**第五版找到的是方法错**：

1. **用 `sin` 做连续形变** → 没有一帧静止 → 读作"抖"。改成相位切三段，最后一段形变完全回 1。
2. **缩放的是 `sqY`（竖直）** → 那是"变高变瘦"，读作长个儿 / 呼吸，和爬行无关。
   毛毛虫蠕动、四足跑动，身体都是**沿前进方向（水平）**一伸一缩。

| 类型 | 周期 | 水平伸缩 | 竖直补偿 | 前探 | 其它 |
|---|---|---|---|---|---|
| 毛毛虫 `walk` | 0.62s/步 | ±13% | ∓5% | 2.6px | 贴地，无竖直位移 |
| 野猪 `charge` | 0.45s/步 | ±10% | ∓3.8% | 3.0px | 蹬地抬 2.6px + 前倾 4.9° |

频率从 3~7 步/秒降到 1.6~2.2 步/秒。**一半时间是完全静止的**（相位 0.50~1.00），
那段静止才是"一步"能被看见的原因 —— 连续变化只会被读成抖。

验证方式：停掉 rAF，手动设 `S.t` + 敌人坐标，逐相位调 `render()` 截帧，
八帧对齐后对比。伸（ph=0.30）和挤（ph=0.46）的体长差肉眼可辨，静止段三帧完全一致。

### 3. HUD：目标卡与被挤出去的奖励条

截图红框标了两处，问题都是**"这块东西不属于它所在的那一层"**：

| 问题 | 为什么是问题 | 改法 |
|---|---|---|
| 「通这关 · 星屑 到家」是**卡片外面的独立白胶囊**（y=140） | 那个位置正好压第 3 层台面（156）边缘，玩家把它读成"场地里的一个物件"。悬在 HUD 和场地之间的东西，默认归类为场地 | 收回卡内做最后一行，卡片 118 → 130 |
| 开场大字「第 8 关 双塔 · 全部送回家」 | 目标名和右上卡片第一行完全重复。同一句话两遍不会更清楚，只会让"全部送回家"看起来像关卡名的一部分 —— 玩家读成「这关叫'双塔·全部送回家'」 | 只留「第 8 关 双塔」 |
| 卡片底边贴住台面 | 卡片 138 高时底边 152，台面 156，只差 4px，读作"长在台面上" | 压到 130，留 12px 间隙 |
