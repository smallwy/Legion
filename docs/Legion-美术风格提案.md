## 1. 风格锚点（每批提示词逐字复用，不改写）

> **Q 版手绘水彩卡通风**。2D 侧视。光源来自右上，暖色轮廓光。所有物体统一 **3–4px 深棕实色描边**（`#1D2628` ~ `#754E2D`）。材质靠**手绘笔触与堆叠结构**表达，不靠渐变：木头是**分块的板**（每块独立圆角 + 顶面高光 + 暗部），不是一根圆角条。背景三层纵深：前景灌木（最暗、最饱和）→ 中景树与平台（中调）→ 远景山与天空（最亮、降饱和 30%）。比例约 **3.5 头身**的动物，手脚短、头大。色彩走**暖秋**：奶白、暖黄、焦糖棕、鼠尾草绿。**禁忌**：纯色平涂无描边、锐利直角、冷色（蓝紫）主光源、写实材质贴图、镜面高光、背景与主体同明度。

## 7. 第二轮落地记录（2026-10-22）

### 7.1 已改并验证

| 项 | 做法 | 关键判据 |
|---|---|---|
| 平台 = 堆叠木板 | `LAYERS = 3`，`LAYER_SHIFT = [0, 16, 32]` 错缝；旧版是"一块渐变 + 等距竖缝" | 要有**三条证据**才读得出"叠着"：① 层缝是上亮下暗**两条**（只画暗线读作裂纹）② 拼缝错开（对齐读作栅栏）③ 端头**一层一个**年轮（一个占满 33px 的椭圆又读回"一根整木"） |
| 坡的层缝 | 用已有的 `band()` 按垂直厚度采样，缝**沿曲线**走 | `fillRect` 画水平线在 40° 坡上会直接穿出路面 —— 这是"坡"和"台阶"最容易被写混的一处 |
| 草地压暗 | `GRASS_DIM = 0.86`，只压 `grass`/`grass2` | **不动** `sky`/`hill`/`wood`：hill 是"远"，压暗它把纵深反着压平；wood 靠描边和投影分离，压暗成一条黑杠 |
| 地面三档明度 | 派生 `grassLight` / `grassDark` 做 `createLinearGradient` | 从 300 到 H：亮 → 中 → 暗，主体才落在 L3 |
| 远山 | 三层 `drawHills` + 地平线雾带 `rgbaOf(TH.horizon, .94→0)` | **0.48 / 0.72 不是 0.24 / 0.50**：混得太少在暖色主题（第 4 关橙黄天空）上山整片消失，只剩"天+地"两块。雾带渐变必须用 `rgbaOf`，从 `#RRGGBB` 渐变到 `rgba(0,0,0,0)` 中间会插出灰黑 |
| 中景树线 | 站在地平线上（底边 306~320），`drawTree(..., true)` 用 `treeFar`（混 0.28 而非 0.52） | 远景树退后靠**换色**，不靠变透明：0.34 的绿压在一片绿上读作"没画清"，不是"远" |
| 近景树描边 | 统一 `COL.ink`，3.4 / 2.8px 按远近分档 | 原来是树 `rgba(30,64,44,.55)` 偏绿 2.4px、平台 `COL.outline` 偏紫 2.6px —— 一张画面两套描边系统，读作"拼的图" |
| 树冠形状 | `blobPath()`：48 点密集采样 + 直线段，半径按 3/5 两个频率起伏 | **原来 3 个圆 fill + 3 个圆 stroke**：fill 是并集、stroke 是三条整圈，内部弧线全露在外面，读作线框气泡。canvas 没有"只描并集外轮廓"的 API，改成单条闭合路径 |
| 树叶颜色 | 从草派生后**再往叶绿锚 0.30**（`LEAF = #6FB33F`） | 第 4 关是纯暖橙（草 `#D9764A`），树完全从草派生就变成橙褐色，读作"一块鼓包"。混 0.30 后在暖色关是橄榄绿：仍在关内色域里，但有"活的东西"这个读法 |
| 前景灌木 | 9 丛，半径 16~36、横向抖动 ±29、顶端 552~568 | 死线 `GROUND_Y - 4`（552）：盖住草皮鼓包、只淹球底 4px。570 时只露底边一条，读作花纹。**三个量必须同时松开**：只抖半径，顶缘连成平滑波浪，读作"花边" |
| 木桩 | 用 `TH.wood2` / `TH.wood3` + `COL.ink` 描边 | 原来写死 `#6B4A2E`：第 8 关紫草地上插一根棕色柱子，是全场最刺眼的"外来物" |
| 结算卡 | 代码画 `creamCard()`，620×520，圆角 26 | `ui-res.png` 圆角半径实测 **≈150px（图高 420 的 36%）**，是张泡泡卡。九宫格要求 `ds ≥ 圆角半径`，`ds=56` 时边条把圆弧沿边拉长，铺到 620×520 就摊成一颗蛋 |
| 结算压暗 | 两段：`rgba(0,0,0,.35)` → `rgba(20,40,60,.45)` | 单段半透明压不掉色相：`rgba(9,12,11,.52)` 压在橙黄天空上是 (86,76,61) 一片暖棕，奶油卡浮成"棕色相框" |
| 六只立绘 | ImageGen 各 1 张 + `client/tools/prep_pets.py` 后处理 | 见 §7.2 |

### 7.2 立绘管道（`client/tools/prep_pets.py`）

```
采背景色 → 涂水印 → 抠底 → 连通性过滤 → 去紫边 → 裁透明边
  → 按**体高**缩放 → 脚底贴底补齐 → 出头像（圆底 + 裁切）→ 棋盘格接触表
```

| 参数 | 值 | 为什么 |
|---|---|---|
| `PET_H` | 640 | 输出图高 |
| `BODY_H` | 420 | **统一体高**（脚底到头顶，不含耳朵） |
| `TOL` | 58 | 与背景色的色差容忍（三通道差的最大值） |
| `HEAD_S` | 480 | 头像边长 |
| `PET_BODY_K` | **0.656** | = 420/640。`drawPetSprite` 里 `dh = h * 1.35 / PET_BODY_K`。**按图高算的话画出来身体只有 65.6%**，换图那天六只集体缩水三分之一，站在小怪旁边像幼崽 |

**统一的是"体高"不是"bbox 高"**：bbox 含耳朵，长耳兔 bbox 比仓鼠高 30%，统一 bbox 会把兔身体缩得极小。每只给一个 `EAR_K`（耳朵占 bbox 高比例），按 `BODY_H / (bbox_h * (1 - EAR_K))` 反算缩放比。

**抠图两个必踩的坑**：
1. 写死 `#FF00FF` 不行 —— 六张图实际出的是六种不同玫红/浅粉，有的还带矩形接缝。改成四角自适应采样 + 最小色差。
2. 纯阈值会把橙色虎斑猫身上的条纹一起挖掉（橘色和玫红只差 50 出头）。加 `outer_only()`：垫 1px 白边 flood fill，只有与画面四边连通的才算背景。

**头像从立绘裁，不另外生成** —— 同源才不会有"头像和立绘不是同一只"。但裁切框一只一套（兔要更大、仓鼠要往里收），且角色缩到圆内 **0.90**，否则耳朵/角/尾巴从圆的四角长出去。圆底必须图自带（游戏里直接 drawImage，没有额外遮罩），且 `putalpha` 用 `ImageChops.multiply` —— 直接 `putalpha` 是**覆盖**不是相乘，圆内透明区 RGB 是 (0,0,0)，头像会变成"圆里一圈黑"。

**接触表必须画在棋盘格上**：纯色底会把"没抠干净"藏起来（品红残边压在品红底上根本看不出来）。

### 7.4 这一轮发现的、**没修完**的

1. **机器人从来不会开枪。** 喷在游戏里是"按住连发"（`if (S.keys.atk && p.atkT <= 0) ...`），而 `grove-bot.js` 只置 `S.press.atk` —— 那是边沿表，喷不读。也就是说这套冒烟从上线起，机器人只验证过"撞"和"推球"两条路径。已修（改 `keys.atk`）并顺带补了三条几何 bug（坡只能下不能上 / `layerExits` 把被坡接住的位置当落口 / 限球关不知道有额度）。修完之后第 4、5 关从"240 秒超时"变成 28s / 66s 达标；但第 3、7 关（都是 `limit 7`）反而**超额度判失败** —— 机器人还没有"省着造球"的策略。八关巡回的断言不受影响（`limit` 关只断言额度数字），仍全绿。
2. **素材一致性**：`ui-tip` / `ui-cream` 两张面板图仍是老口径（尺寸小、圆角不大），暂时没问题；但只要有人把它们铺到 400px 以上，会重复 `ui-res` 的蛋形事故。
3. **立绘画风变了**：从原来的厚涂赛璐璐变成更简洁的矢量卡通（统一 chibi 比例、头占 45%、厚棕描边、双色 cel shading、左上光）。如果更想要原来的质感，需要回厚涂方向重出。
4. **`.meta` 没动**：Cocos 侧 spriteFrame 的 rect 口径（640 图高、480 头像）保持不变，不需要重导。
