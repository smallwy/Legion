# 跳虫 —— 主线第一种会往上层扑的敌人（2026-10-27）

> **一句话**：把「249 只敌人里没有一只会往上走」这个结构性缺失补上第一块。
> 每块产地的**第 4 屏起**，约 **1/3** 的刺毛虫会追人、会扑向玩家所在的上一层。

---

## 1. 病根（先量，再改）

这一轮之前，全部 27 屏的"平"可以落到五行代码上：

| 事实 | 位置 / 依据 |
|---|---|
| `f.vy` 在全文**只被赋过一次值，而且是 0** | `foeFromSpec` / `stepBody` —— 249 只敌人没有一个主动向上移动过一个像素 |
| 普通刺毛虫**连追人的意图都没有** | `else { f.vx = f.dir * spd }`，`f.dir` 是出生时 `S.rng() < 0.5` 定死的，撞墙/到边缘才翻 |
| 只有 `charge` 一族会朝玩家 | 野猪 / 盲蛛走 `f.face = sign(p.x - f.x)` 那条分支 |
| 伤害源只有三类 | 身体碰撞（要求同层）、BOSS 砸地 / 喷吐、火坑 |
| 玩家 4 血、1.2 秒无敌、能跳能冲刺 | `hurtPlayer` / `p.invT` |

**推论**：玩家跳上任何一块浮空台就**绝对安全**。空间对敌人无效，所以对玩家也无效 ——
这就是「空间设计感很平」的物理成因，不是美术问题，也不是台面摆得不够花。

### 1.1 顺带查出来的既有死角

六把武器的弹道 vy 全是 `0` 或 `-40`（`spawnShot` 的六条分支），**没有一支能往下打**。
而 `updateShots` 也不判台面遮挡。

所以在跳虫出现之前就存在一个死角：**玩家站在台面上，打不到正下方的怪。**
以前没人踩到，因为怪不会往你脚下凑。跳虫一进来，这个死角立刻变成"清场卡死"。

## 2. 设计：三段状态机（不是一条 AI）

```
crouch 0.30s   →   pounce（滞空 0.69s）   →   landT 0.28s   →   追人
   "要来了"            "能躲"                   "该你打了"
```

三段里**每一段都是一个可读窗口**，少任何一段它就退化成暗算：

| 段 | 规则 | 玩家能做什么 |
|---|---|---|
| crouch | 原地不动、身体压扁（高 ×0.72、宽 ×1.18）、头顶感叹号闪烁（20Hz 硬切）、脚下橙色脉冲环 | 跑开 / 提前糊它 |
| pounce | 固定初速 `vy=-720`、横移 `±210`，**纯抛物线，不追踪** | 走位躲（落点是可算的） |
| landT | 落地 0.28 秒完全不动、不打人 | 糊它 / 推球撞它 |

**起跳条件**（四个同时成立）：玩家在它上方 >40px、水平距离 <240、自己站在地上、冷却结束。
**玩家在下方时**：走向最近的台面边缘让重力带下去 —— 这一条是为了不制造死角，不是为了好看。

## 3. 参数与依据（全部由已有重力反推，不新造物理）

`GRAV = 2100`（既有）。

| 参数 | 值 | 依据 |
|---|---|---|
| `JUMPER_VY` | 720 | 跳高 = 720²/(2×2100) ≈ **123px**。27 屏台面只落在 156/248/350/462 四个高度，相邻层差 92~112px —— 123 是"越过最高那档（462→350=112）+ 11px 余量"。再高就跳出画面，读作"它飞起来了" |
| `JUMPER_PUSH` | 210 | 滞空 2×720/2100 ≈ 0.69s，横移 ≈ **145px**，正好是一道台面到斜上方那道台面的水平偏移量级。少了它虫子只会原地上下，一次都上不了台 |
| `JUMPER_CD` | 2.2s | 两次扑击间隔。1.6 以下场上会变成"蛙群"，玩家没有能站稳的窗口 |
| `JUMPER_LAND` | 0.28s | **公平性，不是手感**：没有它，虫子落在你身边的同一帧就能撞掉一滴血 |
| 密度 | 1/3 | 从 `f.ph`（`[0,2π)` 均匀分布）派生：`f.ph < 2.09`。**绝不能在这里调 `rand()`** —— 每只敌人多消耗一个随机数会让 27 屏的 `S.rng` 流整体位移，机器人行为全变（`boreT` 那次已经踩过） |
| 出现位置 | `S.stage >= 3` | 每块产地的前 3 屏是教学段（糊 → 推 → 躲），那里放一只主动追人的怪等于教走路时先泼一盆水 |

**深巢不开**（`!S.nest`）：那边已有四怪各一套入口条件，再叠一层会直接毁掉 `nest-play` 的基线。

## 4. 三个坑（都实际踩到了）

### 4.1 木桩死锁，移动版

跳虫每帧把朝向重写成"朝玩家"。玩家站在木桩另一侧时：
桩把它顶到外侧 → 下一帧又朝桩走 → 又被顶回原地，**一步不动**。

`nudgeOutOfStumps` 的注释里记的是**出生那一刻**的同一个坑。
出生能一次推出去，移动中只能靠时间逃：撞墙后 `wallT = 0.45`，期间强制背离。

### 4.2 幼虫被误标成跳虫

`f.kind === "walk"` 这个条件同时命中 BOSS 产下的幼虫（`def.kind` 也是 walk）。
它们被打上"会跳"的标记，头顶多一个橙色感叹号，而行为其实是"爬向 BOSS"。
加 `!f.larva` 修掉。

### 4.3 射击死角 → 清场卡死

接 §1.1。修法是给跳虫加"玩家在下方就走向最近边缘"，
**而不是**给武器加向下弹道 —— 后者会改掉六把武器的全部手感，代价远大于收益。

## 7. 第二轮修正（同日）：白跳与穿模

用户一句话点了两个问题：**"有点地方不能跳、有的可以，要做合理的设计"** +
**"我看你的 UI 图，敌方和横木都叠加了"**。两条都是第一版留下的真问题。

### 7.1 病根一：能不能跳，取决于玩家站在哪

第一版的起跳判据只有三个条件：

```
玩家高出 40px   ·   水平 240px 内   ·   冷却好了
```

**既没有上限，也不看落点。** 于是两种白跳同时存在：

| 情况 | 第一版的行为 | 玩家看到的 |
|---|---|---|
| 玩家在上面**两层**（206px） | 照样蹲下起跳，跳高只有 123px，顶到板底掉回来 | "它跳了，但上不来" |
| 玩家在水平 240px 外 | 照样起跳，滞空只能横移 107px，落点在半空 | "它跳了，但落空" |

同一只虫、同一块台面：你站左边它上得来、站右边它上不来 —— **而玩家推不出这个规则。**
这不是难度，是"没有规则"。

**修法：起跳前预演整条抛物线（`pounceLands`）。**
逐帧复刻 `stepBody` 的两条判据（单向平台 `prevY <= p.y + 2 && y >= p.y`、木桩实心），
算出真实落点；**只有落点比起点高 ≥ 60px 才允许蹲。**

改完之后玩家能自己算的规则只剩一条：**它只在真的能落到更高那层时才蹲。**
于是每一次蹲身都兑现 —— 预告重新可信。上不去的时候它不装样子，就在下面跟着。

### 7.2 病根二：穿板那两帧读作"嵌在木头里"

单向平台允许从板底穿上来（**玩家自己就是这么跳的**），板厚 20、虫高 28，
所以穿过去的那一两帧必然是"半截身子在板上、半截在板下"。
而敌人统一画在所有地形**之后**，于是读作穿模 bug。

**修法：画到板后面（`platOverFoe`）+ 板顶留一道跟着它走的暗影。**

但只做遮挡还不够 —— 出图实测虫会被板**整只吃掉**（只剩 4px 黄边 + 一个悬空的箭头），
读作"虫凭空消失"，比嵌在木头里更糟。所以板顶那道暗影是必需品：
它是"下面有东西顶着"的唯一线索，也是它出来的预告，和蹲身、滞空是同一套语言。

### 7.3 走错的那条路（记下来，别再走）

我一开始想的是**根治**：禁止穿模，让虫"绕到板的外侧再跳"。几何上算得通
（从地面升到台面高度 0.175s、横移 37px，站在台外 37px 处起跳就全程不穿板）。
结果三连崩：

1. **判定顺序**：先判穿模再判落地，而落地那一帧的 y 还没被 `stepBody` 纠正
   （脚 467 落在板 462..482 内部）→ 所有"正常落台"被判成穿模 →
   **27 屏 38 块台面当场变成不可达**。
2. **板沿震荡**：改对顺序后，虫绕到板外，`platAbove` 变空、朝向立刻被"朝玩家"覆盖回去，
   走回板下又触发绕行 —— 13px 来回摆动，**7 屏里 6 屏永远上不来**。
   加 `f.detour` 锁方向 + 出板瞬间强制起跳能解决，但已经是在给一个错的方向打补丁。
3. **桩**：第 13 屏桩立在板中间，虫无论朝哪边跳都被桩挡，原地抖。

**结论：为了躲两帧穿模，把机制搞死，不值。** 单向平台穿板不是 bug，是同一条语法 ——
玩家和敌人用同一条规则才叫一致。穿模用遮挡解决，那才是标准画法（Mario / Celeste 一直这么干）。

### 7.5 一个没修的已知行为

**虫在木桩正下方时上不来**（第 13 屏实测起跳 0 次）：桩是实心墙，
从桩底下往上顶必然被挡，这是地形在起作用，不是 bug ——
但它会小幅度来回徘徊（13px 级），看起来像"在下面等"。
我判断可以接受：桩只有 1-3 根、覆盖 24px 宽，**"桩底下是安全区"本身是地形给出的信息**。
如果后面觉得这个徘徊不好看，再给它加"绕开桩"的找路 —— 那时候要用
`f.detour` 那套锁方向的写法（§7.3 第 2 条）。
