# Legion · 雾巢：让深巢真的"往下摸"

> 2026-10-27 · 起因是用户两句话：
> 「现在这个关卡的怪物都一样啊」
> 「这个关卡 我感觉可以做一个下探的关卡 有迷雾啥的 探索性的 你发挥下想象 创造力」
>
> 本文是**已落地**的设计记录（代码在 `client/prototype/grove.html`），
> 不是提案。没做的部分在 §6 里单独列出来，不混在"已完成"里。

---

## 1. 病根：不是"缺一层雾"，是两件事同时不成立

| 症状 | 真实原因 |
|---|---|
| 怪物都一样 | 池子是**全局**的，`["bug","bug","spider"]` + 按深度依次加壳/蛾/脉虫。浅层（1–4）抽来抽去就是"两只 bug"，石壳要到第 5 层才出现 —— 而多数人第 2~4 层就下了判断 |
| 没有探索感 | 一进场整屏全亮（只有一圈以玩家为圆心的暗罩）。**暗罩只管"离你多远"，不管"你去过哪"** —— 所以每次转头那片黑都还是那片黑，形状一模一样，不会让人产生"那边我还没看过"的念头 |

这两条其实是同一个病的两面：**每一层抽同一个池子，而且一进场就全亮。**
所以雾不是装饰，它是把这两条缝起来的东西：

- 看不见的地方，你连对面站的是什么都不知道（只看得见两点眼睛）
- 照亮它需要动作：走过去（随身灯），或者把球推过去（球就是火）
- 每层的巢室类型不同 → 池子本来就不同 → 照亮之后看到的也不一样

## 2. 雾：三种地方，不是两种

`drawNestDark` 那一层是以玩家为圆心的**一个圆**，它做不出"探索"。
雾要成立必须有**记忆**，于是光照场拆成两份：

| 字段 | 含义 | 生命周期 |
|---|---|---|
| `lit` | 这一帧被照到多少（0..1） | 每帧清零重算 |
| `seen` | 这一层到现在照到过多少 | **只增不减，层内不清零** |

三档明度由此成立，而这三档就是"探索"能被读出来的全部：

| 地方 | 画出来的样子 | 不透明度（浅层 / 中层 / 深层） |
|---|---|---|
| 看得清（`lit` 高） | 正常 | 0 |
| 走过记得（`seen` 高、`lit` 低） | 看得见轮廓，明显比脚下暗 | 0.44 / 0.52 / 0.60 |
| 没去过（两个都 0） | 接近全黑，只剩光点 | 0.94 / 0.96 / 0.97 |

**深度这条轴上，真正变的是"记忆"和"灯"，不是"未探"。**
未探三档 0.94→0.97 几乎一样（那一档已经是"黑"了，再黑没地儿去）；
记忆 0.44→0.60 是"走过的地方你还记得多少"，灯 240→175 是"你能提前看多远"。

### 2.1 三类光源

| 光源 | 半径（浅 / 中 / 深） | 为什么要它 |
|---|---|---|
| 随身灯 | 240 / 200 / 175 | 基本盘。带 ±3% 呼吸 —— 完全恒定的光圈读作"贴在屏幕上的蒙版" |
| **球** | 258 / 238 / 222 | **球就是火把**。推一颗出去照亮一条路，代价是那颗球（和装在里面的兽）滚远了 |
| 菌光囊（已炸开） | 168 | 探索的回报：这个角落这一层剩下的时间永远亮着 |
| 裂缝 | 90 | 压得很低 —— 只给"雾里有个暖色的地方"，不能亮到从远处就看清整条缝 |
| 巢蛾 / BOSS | 88 / 118 | 蛾本来就是"用光打"的怪，在雾里先亮起来等于自己报位置 |

### 2.2 怎么画的（性能与观感）

不是逐格填方块（1160 个 `fillRect` 每帧在变，方块边缘会把岩洞读成马赛克），
而是**栅格化 + 放大**：

1. 16px 一格（40×32 = 1280 格），每格算一个 alpha 写进一张位图
2. 位图放大 16 倍铺到井上 —— 双线性插值顺手把边缘糊成了雾的过渡
3. 每格 alpha 再乘一个**每层固定**的噪声（0.86~1.00，只减不加），给出雾的团块感
4. 三层很淡的椭圆亮雾横着飘（速度相位各不同）—— 静止的雾读作"画面蒙了块脏玻璃"

一次 `drawImage`，一帧不到 0.1ms。

### 2.3 雾里的怪：只给一双眼睛

三条路都试过，只有第三条成立：

| 做法 | 结果 |
|---|---|
| 干脆不画 | 那只怪像凭空冒出来一样扑你 = 偷袭 |
| 画剪影 | 剪影就是答案，雾立刻失去意义 |
| **只给眼睛** | 既说"那儿有东西"，又不说"是什么" |

眼睛**统一青白**（不是用怪的 `c1` 上色）：雾里连毛色都看不见，
"颜色是线索"这件事在这里不成立 —— 一旦按种族上色，玩家第二次就学会看颜色了。
会眨眼（每 3 秒左右闭一次）：一对恒亮的点在暗底上读作两只发光蘑菇。

## 3. 菌光囊：雾里的目的地

雾如果只收成本不给东西，玩家会沿灯能照到的地方走最短路线，雾就退化成一个滤镜。
菌光囊是雾里的**目的地**：一团在暗处发着微光的囊，走过去（或把球推过去）就炸开。

| 项 | 值 | 依据 |
|---|---|---|
| 每层数量 | 2~3（巢室决定） | 一个囊等于没有选择，"还有别的地方没去"才是探索 |
| 触发 | **走上去**或球撞 | 本作没有交互键（只有跳/推/攻），新增一个键就是新增一条教学；走上去是**已经存在的动作** |
| 回报 | 永久点亮（168）+ 孢子收成 +2 | "永久"是重点：截图拍不出永久性，所以冒烟里专门钉了一条（人走远了那里还亮） |
| 位置 | 至少 1 个在地面，其余在 446/336 台 | 全在台上的话，每层的囊都在同一个视平线上，重复感立刻回来 |
| 离裂缝净距 | ≥ 50（`NEST_FOG.POD_CHASM`） | 缝自己会发光，贴上去等于摆在亮处，失去"发现" |

## 4. 巢室生态：让"这层住谁"变成一个可见的选择

每层抽一个巢室，它决定**怪物池**、**名字**（HUD 与开场大字）、**囊数量**。

| 巢室 | 池子 | 囊 | 出场 |
|---|---|---|---|
| 蛛巢 | bug + 盲蛛 | 2 | 1 层 |
| 石室 | bug + 石壳 | 2 | 1 层 |
| 卵房 | bug + 盲蛛 | 3 | 1 层 |
| 菌圃 | bug + 巢蛾 | 3 | 4 层（蛾要 4 层才开） |
| 地脉 | bug + 地脉虫 + 石壳 | 2 | 8 层（脉虫要 8 层才开） |

三条规则，每条都对应一种"不这么做就复发"：

1. **只从"这一层真的有料"的巢室里抽**（池子去重后 ≥2 种）。
   不筛的话第 1 层抽到"菌圃"而蛾要 4 层才开，那一层就叫着菌圃、里面全是毛虫 ——
   名字和内容对不上，比不做巢室更糟。
2. **解锁提前到 1/4/8**（原 5/9/14）。石壳只要一条规则（只会往下滚），
   是四只新怪里最好懂的；解锁太晚是"怪物都一样"的另一半原因。
3. **同一波里前 N 只必须互不相同**（`uniqN`）。只靠"轮转"不够：
   池子是 `["bug","shell","bug"]` 时两次抽到 bug 仍然可能。
   修正**不额外抽随机数** —— 只是把已经抽到的那一只换成池里没用过的，
   所以后面的目标/镜像不会漂移。

## 5. 实测

| 检查 | 结果 |
|---|---|
| `tools/nest-check.js`（60 层 × 10 种子，C1~C8 + 雾巢 5 条新断言） | **9289 项全过** |
| `tools/nest-play.js`（第二套机器人，**已钉死随机种子**） | 14/18 = 78%（旧代码同种子上限 89%） |
| `tools/grove-smoke.js` | 1422 项全过（新增 20 项雾巢断言） |
| `tools/grove-runtime-check.js` | 39 项全绿 |
| `tools/_nest-hash.js` | 地形 60 层哈希**一字不差**；波次哈希变了（巢室就是来改它的） |

**关于 78% 这个数字，要说清楚三件事：**

1. **机器人原来不可复现。** `S.rng` 默认是 `Math.random`，同一个工具连跑两次
   通关层数差 1~2 层（实测 16/18 与 14/18 都出现过，代码没变）。一个 ±2 层的
   指标测不出"少通了一层"这种回归 —— 所以这一轮把 `nest-play` 的种子按
   (层, 角色) 钉死了。**以后的通关率才第一次可以横向比。**
2. 用同一组种子跑改动前的代码：89%。**差的这 2 层都发生在"只剩 1 只送不走"**：
   11 层是地脉虫（每 4 秒才探头 2 秒，机器人不会等窗口），31 层剩 5/6。
   这是**怪更难**，不是地形有死路（`nest-check` 的 C1~C8 一条没红）。
3. 设计文档给的窗口是 **40%~90%**，78% 在窗内。

新增的 5 条 nest-check 断言，对应"玩起来才会发现、发现时已经晚了"的事：
巢室名丢失（HUD 显示 undefined）、一层只有一种怪、囊摆到缝口/出生点/悬空、
整层只有一个囊。

## 6. 四条踩过的坑（比设计本身更值得留）

### 6.1 独立随机流：在 `R()` 上多抽一次，60 层地形整体漂移

雾 / 巢室 / 菌光囊全部走 `nestRand(seed ^ 0x9E3779B1)`。
设计文档早就记过这个坑（改配色时少消耗一次随机数 → 机器人通关率 15/18 → 10/18），
这次一开始就把 `RF` 独立出来，并用 `tools/_nest-hash.js` 做守门人：
**地形哈希必须一字不差**，波次哈希允许变。

### 6.2 镜像漏了裂缝 —— 一条从 10-26 就存在的漏

`nestMirror` 只翻台/坑/坡/营地/出生点/敌人。裂缝是 10-26 才加进来的，
加的时候没回来补那一行。后果不是"缝位置难看"，而是**坐标系分裂**：
镜像层里营地翻了、出生点翻了、敌人翻了，只有缝还在原来的 x 上。
雾巢的囊要按"离缝多远"摆，一撞就露：`nest-check` 直接报"贴缝 380"。

修法是把 `L.chasms` 也翻一次。镜像对**所有相对距离都是等距变换**，
所以 C7c/C7e/C8 一条都不会变 —— 这也是"补这一行是安全的"的唯一依据。

### 6.3 同一个数字写在两处，就会在边界上红

生成器判"囊离缝 44"，`nest-check` 判"50"，于是每一层都在边界上红（482 条），
而地形本身是对的。改成两边都读 `NEST_FOG.POD_CHASM`。
**魔数出现在两个文件里，就等于有两个真相。**

### 6.4 第一版雾太淡：0.62 的 alpha 只是"变暗了一点"

第一版未探 0.62 / 记忆 0.26。量化之后：走过的地方和没走过的在像素上
只差 25 级亮度（20~58），而人眼在暗底上要 ~40 级才读得出"这是两个不同的地方"。
第二版拉到 0.94/0.44 才成立。

同一个问题还有第二处：底光（`drawNestGlow`）原来画在雾**之后**，
整条屏宽的地缝光把雾从下面照亮，没去过的地面也在发亮 —— 雾只剩上半屏成立。
挪到雾之前，让真正穿透雾的只有菌光囊（它才是那个该被看见的诱饵）。

## 7. 没做的（明确列出来，不混进"已完成"）

| 项 | 为什么先不做 |
|---|---|
| 雾的边界做出撕裂感 | 现在是"位图放大 + 噪声"糊出来的柔和边界，读作雾但不够"野"。要真做需要给掩码加一层域扭曲（domain warp），成本在心里没底 |
| 裂缝吞球 / 吞人 | 需要跨层状态搬运，`pawpack.nest` 现在只存深度（沿用 10-26 的结论） |
| 走到底部的裂缝 = 下潜（而不是清场自动下一层） | 要新增一个 phase，回归面比雾大；这一轮先保住"雾 + 巢室"两条 |
| 巢室的场景道具（蛛网 / 卵堆 / 晶簇） | 名字和怪已经不同了，道具是"再加强一档"，不是必需品 |
| 探明度 HUD | 雾自己清掉的过程就是进度条，加数字反而分心 |
