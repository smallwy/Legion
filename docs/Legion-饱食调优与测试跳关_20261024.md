# 饱食调优 + 测试跳关（2026-10-24）

> 两件事：① 把「喂饱了反而软」这个反符号扳正，让「继续 / 收工」第一次成为真选择；
> ② 加一个测试期随时能用的跳关面板，不用再「验第 23 屏先把前 22 屏打一遍」。

## 一、调优：三个数值，一个符号

### 1.1 改了什么

| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| 1 | `bellyPower()` | `[0.92, 1.12, 1.00]`（全饿/半饿/满饱）**非单调** | **`[0.86, 0.95, 1.00]`** 单调递减 |
| 2 | 每屏掉饱食 `BELLY_PER_CLEAR` | `16` | **`20`** |
| 3 | 结算卡「继续」副标题 | 只报倍率 | 加三态：力气不变 / 降一档 / 见底 |
| 4 | 结算卡「收工」副标题 | `+N 果` | `+N 果 · 吃完回满` |
| 5 | 底部提示行 | `E 收工回家` | `E 收工（回满力气）` |

### 1.2 为什么必须改（改前的真实轨迹）

`belly` 每屏 −16，档位线 `≥70 满饱 / 30-70 半饿 / <30 全饿`：

| 过屏 | belly | 档 | 火力 |
|---|---|---|---|
| 0（出门） | 100 | 满饱 | 1.00 |
| 1 | 84 | 满饱 | 1.00 |
| 2 | 68 | 半饿 | **1.12 ← 最强** |
| 3–4 | 52 / 36 | 半饿 | 1.12 |
| 5–6 | 20 / 4 | 全饿 | 0.92 |

三个后果，都实测过：

1. **非单调**：平 → 升 → 降。玩家没法从这条线上读出「我该回家了吗」，而它每 77 秒（一屏 par 均值）就弹一次 —— **是全游戏最频繁的那个决策**。
2. **「喂饱了反而软」**：出门满饱 = 最弱档，打两屏才最强。而喂饭是计划书里 0:20 的第一个交互动作 —— 这个动作在数值上等于惩罚。
3. **账算下来永远「继续」**：代价 −18%（1.12→0.92），收益 +25%（1.60→2.00 倍率）。于是「收工」从来没被选过，那个每屏弹一次的对话框退化成**确认框**。

「战斗内目标感不强」的精确病灶就是第 3 条。

### 1.3 改完的轨迹

| 过屏 | belly | 档 | 火力 |
|---|---|---|---|
| 0 | 100 | 满饱 | 1.00 |
| 1 | 80 | 满饱 | 1.00 |
| 2–3 | 60 / 40 | 半饿 | 0.95 |
| 4+ | 20 / 0 | 全饿 | **0.86**，**冲刺没了** |

一趟自然收到 4-5 屏（≈6 分钟）：短到能重开，长到有弧线。

**贪的甜头全部交给连锁倍率**（1+0.15n），**代价全部交给力气**。两个机制各管一件事，不再互相抵消。

### 1.4 两条不能碰的红线（试过，被打回）

| 尝试 | 结果 |
|---|---|
| 满饱 `dashT 0.16 → 0.21`（冲得远 31%） | ALL9 里第 8 / 15 / 18 屏机器人**当场崩**（240s 超时） |
| 满饱 `dashCd × 0.72`（冲得更勤） | 第 1 / 4 / 15 屏崩，**红的从 3 条变 5 条** |

原因：**冲刺是关卡几何的隐式输入**。27 屏的平台间距、竖井宽度、营地落点是围绕「0.16 秒 × dashPow」这组数调的，动任何一项都等于偷偷改地图。

所以冲刺**只做一件事：全饿收走**（本来就是）。想加强满饱的手感只能在推球力和表现上做。

同理 **`满饱 = 1.00` 不能动**：27 屏全部按「满饱推出去多远」（PUSH_BASE=620）调过，给满饱任何惩罚都等于把所有关卡悄悄调紧 —— 实测第 1 屏机器人会直接清不完。

### 1.5 一个自己写错又抓回来的 bug

结算卡副标题第一版只写了**两态**：

```js
const loseTxt = tNext < tNow ? "力气降一档" : "力气见底";   // ❌
```

满饱时（100 → 80，两边都还是满饱档）会写成 **「力气见底」**，意思完全相反 ——
玩家会以为打完这屏就废了。

改成三态并抽成 `nextBellyHint()` 单函数，冒烟直接验**真身**（不是抄一份副本再验）：

```js
eq(P.nextBellyHint(100), "力气不变", ...);   // 100→80 都还满饱
eq(P.nextBellyHint(85),  "力气降一档", ...); // 85→65 掉进半饿
eq(P.nextBellyHint(45),  "力气见底", ...);   // 45→25 掉进全饿
eq(P.nextBellyHint(10),  "力气不变", ...);   // 已经全饿，别吓人
```

## 二、测试跳关：三种方式

### 2.1 F2 面板（最常用）

**任何时候按 F2**（play / 结算 / 挑一屏 / 门口都能开）。

```
┌─ 测试跳关 ── 27 屏全开 · 无视解锁与存档进度 ─┐
│  苔原    1 2 3 4 5 6 7 8 9                    │
│  枯木坡 10 11 12 13 14 15 16 17 18            │
│  泥沼   19 20 21 22 23 24 25 26 27            │
└───────────────────────────────────────────────┘
```

| 操作 | 效果 |
|---|---|
| 方向键 | 移动光标（3×9 网格，不绕圈） |
| 回车 / 空格 | 直接开打光标那一屏 |
| 鼠标点格子 | 同上 |
| F2 / ESC | 关掉面板，**回到打开前的阶段**（在战斗里打开就回战斗，不是回门口） |

格子上的信息：**屏号 + 关卡名 + 右上角评级**（打过的才有）。当前屏金框，悬停绿框。

### 2.2 `[` / `]` 连扫（手测最快）

在战斗里按 `]` 直接进下一屏，按 `[` 回上一屏。**不用回面板**，适合一屏一屏连着看。

只在 play 阶段生效 —— 结算界面回车已经是「进下一关」，再挂一对键会让人分不清哪个是正常推进。

### 2.3 URL 参数（自动化用）

```
grove.html?from=home&hero=3&stage=22     # 第 23 屏，带第 4 只（长耳兔）
```

`stage` 是**从 0 数**，`hero` 是 0-5。这个入口改动前就有，只是原先只能在启动时用。

### 2.4 它不会污染存档

- **不推进 `progress`**：`beginRun` 里有一行 `progress = max(progress, stage)`，跳关前后会还原 —— 否则按两下 `]` 就把存档写到第 20 屏，下次从主界面进来直接掉那儿，看起来像存档坏了。
- **不写盘**：`beginRun` 自己不调 `saveProgress`。
- **不发奖励、不算一趟的关数、不动倍率**。

冒烟有 13 条断言守着这三条（§27b）：27 格几何全在画布内、中心点命中自己、两两不重叠、progress=0 也能跳第 23 屏、progress 不被写、面板进出回到正确阶段。
