# Q萌桌面伴侣市场 · 可落地性深度调研

> 调研日期：2026-10-14
> 调研对象：「Q萌生物 × 桌面伴侣 × 轻自动化」这一方向
> 调研目的：不看"这个方向好不好玩"，只看"一个人 + 轻美术 + 有限预算，能不能真的做出来、发出去、活着"

---

## 0. 先给结论（如果你只看一段）

**可落地性：技术 ★★★★★ / 成本 ★★★★★ / 市场 ★★☆☆☆**

- **做得出来吗？** 能。这是目前所有候选方向里**技术门槛最低的一个**——Godot 官方文档已把"桌面透明 + 鼠标穿透 + 置顶"这条路写成了完整配方，甚至有人把它当作**人生第一个 Godot 项目**就做完了。
- **花得起吗？** 花得起。美术 2 千–2 万，Steam 上架 $100，4–6 周流程。**这是全市场最便宜的入场券之一。**
- **卖得掉吗？** **这是唯一的真问题，而且答案不乐观。** 这个赛道有一个极其罕见的特征：**好评率极高、销量极低**。大量作品 90%+ 好评却只有几十条评测（≈几十到几百份销量），同时赛道里已经躺着 **60 款近乎同名同玩法的竞品**，并且上方压着一个**免费开源的多年积累项目**。

一句话：**这是一个"容易做、容易死"的市场。做出来不是难点，被看见才是。**

## 1. 技术可落地性：★★★★★（已解决，不是风险）

### 1.1 Godot 官方已给出完整配方

桌面伴侣的技术难点只有三个：**窗口要透明、要能置顶、鼠标点击要能"穿过"它点到下面的窗口**。这三件事在 Godot 里全部是**项目设置里的开关**，不需要写底层代码。

Godot 官方文档 "Creating applications"（`docs.godotengine.org`）明确列出了这条路径所需的全部设置：

| 需求 | 对应设置项 |
|---|---|
| 去掉标题栏/边框 | `display/window/size/borderless` |
| 允许逐像素透明 | `display/window/per_pixel_transparency/allowed` |
| 窗口背景透明 | `display/window/size/transparent` |
| 视口透明（不要灰底） | `rendering/viewport/transparent_background` |
| 永远在最上层 | `display/window/size/always_on_top` |
| 不抢焦点（点它不影响你正在打字的窗口） | `display/window/size/no_focus` |
| 鼠标点击穿透 | `mouse_passthrough` |
| 只让可点击区域穿透、其余穿透 | `mouse_passthrough_polygon` |
| 不被截图/录屏抓取（Win/macOS） | `exclude_from_capture` |

**这些不是"玩家发现的偏方"，是官方文档正式记载的用途。** 这一点非常重要：意味着你不需要逆向、不需要 hack、不会有"某天更新后全废了"的风险。

### 1.2 已有大量"单人从零做完"的先例

- **Godot 4 桌宠教程**：DigiKey 等平台发布了完整的分步教程（"Desktop Pet in Godot 4"），从建项目到透明窗口到动画，属于"跟着做就能出东西"的成熟度。
- **BelPet**（Spotify 桌面宠物）：开发者自述这是**自己的第一个 Godot 项目**，用 C# 完成。**"第一个 Godot 项目"能做到这个程度，是对新手门槛最直接的量化。**
- **《Godot 4 桌宠开发避坑指南》**（CSDN）：中文社区已有成体系的踩坑文档，三大坑明确写出——**① 透明失效 ② 动画状态机 ③ 跨机器兼容**。

### 1.3 三个已知坑（这才是真正的技术风险）

技术不是"能不能做"，而是"在别人的电脑上会不会坏"。官方与社区明确记录的三个坑：

| 坑 | 现象 | 规避 |
|---|---|---|
| **独占全屏覆盖** | 用户在玩全屏游戏时，桌面伴侣**被游戏盖住或闪烁** | 无解，属于系统层限制；在产品说明里写清"建议窗口化/无边框游玩"即可 |
| **混合显卡（NVIDIA Optimus）** | Windows 笔记本上**透明失效**（出现黑底/白底方块） | 改用 **Compatibility 渲染器**（不要用 Forward+），这是社区反复验证的解法 |
| **Linux X11 未开合成器** | 桌面透明直接失败 | 说明里注明需要合成器；或首发只标 Windows 支持 |

**结论：技术风险已经从"未知"降级为"已知且可绕过"。** 这是本方向相对其他所有候选方向的**最大优势**——你可以把全部精力放在玩法上，而不是和引擎搏斗。

> 渲染器选择（要记住）：**Compatibility > Forward+**。透明、跨 GPU 兼容性都更稳。代价是画面效果上限略低——而 Q 萌扁平风根本用不到 Forward+ 的高端渲染。

## 2. 成本与流程可落地性：★★★★★（最便宜的入场券之一）

### 2.1 开发成本

| 项目 | 成本 | 备注 |
|---|---|---|
| 引擎 | **0** | Godot，MIT 协议，商用免费 |
| 像素美术工具 | **0–140 元** | Aseprite $19.99 买断；开源版可自行编译免费获得（Steam 版 98.9% 好评 / 27,095 评测 / 约 65 万份，是行业标准） |
| 桌面伴侣美术 | **2,000–20,000 元** | 按上一份《美术成本分析》口径：1 个主体 × 3 个动作 |
| Steam 上架费 | **$100/游戏** | 卖到 $1,000 收入后返还 |
| 音乐/音效 | 0–1,000 元 | 免费素材库足够，Q 萌风格对音效要求极低 |

### 2.2 Steam Direct 上架流程与时间线（硬约束）

| 环节 | 要求 |
|---|---|
| 上架费 | **$100/款**，收入满 $1,000 后**返还** |
| 平台抽成 | **30%**（标准档） |
| 商店页审核 | 最短 **4–6 周**（这是硬流程，不能压缩） |
| 强制等待期 | 提交后**必须等满 30 天**才能发售 |
| Coming Soon 页 | **发售前至少 2 周**必须上线（愿望单累积的起跑线） |
| AI 内容披露 | **强制**（SteamDB 会显示 "AI Content Type" 字段，用 AI 生成美术/音频必须如实申报） |

**最小时间线（从今天算起）**：
```
Day 0        开始开发
              ↓ 4–8 周（4 周原型 + 迭代）
Day ~60      项目成型，开 Coming Soon 页 → 开始攒愿望单
              ↓ 至少 14 天（不能少）
Day ~75      可发售；但强烈建议先跑一次新品节（Next Fest）
              ↓
Day ~90–120  正式发售（EA 或 1.0）
```

**4 个月内可以完整走完一次"从零到上架"。** 这是本方向在成本维度最实际的优势——**试错周期短**。如果失败，你损失的是一季度，不是两年。

### 2.3 变现结构

- **本体定价：¥22–33**（对标 Ropuka's Idle Island、Tiny Pasture、小微怪等）
- **DLC 造型包**：Bongo Cat 靠卖造型（松鼠/机甲/摔角手）持续变现，这是本赛道**验证过的唯一稳定二次收入**
- **绝对禁区**：不要做"游戏内物品换真钱"（TBH 的教训：被骂成"不带电费的加密货币矿机"、"第二份工作换几分钱"，且服务端崩溃直接删玩家背包。**单人扛不住 7×24 服务器 + 经济平衡 + 反工作室**）

## 3. 竞品现状：★★☆☆☆（这是最危险的部分）

### 3.1 好消息：这个赛道已经"被 Steam 官方承认"了

**"Desktop Companion" 已成为 Steam 官方可搜索标签**（由 ComicLeaks 报道的标签系统更新确认）。这意味着：

- **利好**：有稳定的搜索流量入口，Steam 算法会把它当成一个独立品类分发，而不是打散在 "Casual" 里。
- **利空**：**官方给标签 = 官方告诉你这里已经很挤了。** 一个新标签被建立，通常是因为同类产品已经多到不建立标签就没法归类。

### 3.3 坏消息：60 款竞品已经在等你，且大部分"无声死亡"

一份第三方统计列出了 **59–60 款以上同类作品**，且**几乎全部标注 "No user reviews"**（即评测数为 0）：

```
Desktop Taxi

Corner Miner
Backpack Cat（免费）
Sia Desktop Pet（Q 版 AI VTuber 桌宠）
Desktop Claw Master
Character House -Desktop Companion-
桌面伴侣时光旅人（50% 好评，仅 2 条评测）
...
```

**请注意最后一行的残酷性：50% 好评。** 在这个"好评率普遍 90%+"的赛道里出现 50%，说明**连"做得让人基本满意"都没做到**——它们不是被市场淘汰的，是**根本没做完/没做对就发上去了**。

**结论：这个市场的死亡方式不是差评，是"零评测"。** 你的直接竞争者里，大多数连一个真实玩家都没留下。

### 3.4 🚨 最致命的一条：一个免费开源项目占住了"免费"这一档

**VPet-Simulator**：免费、开源、已有**数百个动画**、积累了**多年的创意工坊内容**。

这条信息对定价策略是毁灭性的：

- 你想做"Q 萌宠物在桌面上动来动去"——**它免费，而且动得比你的多。**
- 你想靠创意工坊做长尾——**它已经积累了几年。**
- 你想靠"免费引流 + DLC 变现"（Bongo Cat / TBH 同款打法）——**免费的坑位被一个开源项目长期占据。**

**这意味着：你不能再卖"桌宠"本身，只能卖"桌宠在做什么"。** 具体来说——**必须把玩法从"它好看/它会动"推到"它和你的电脑有关系"**（这也正是前几份报告反复收敛到的那个切口）。

### 3.5 真正的爆款反例：Character House -Desktop Companion-

这是唯一一个"打穿了"的样本，必须单独拆：

| 指标 | 数值 |
|---|---|
| 预估销量 | **148,430 份** |
| 当前在线玩家 | **26,622** |
| 历史峰值并发 | **29,686** |
| 好评率 | 97.7%（258 条评测） |
| 30 天畅销榜排名 | **#120** |
| 定价 | **免费** |

它的愿望单关键词非常值得抄：`wpm`（打字速度）、`keystrokes`（按键数）、`cute`、`customizable`、`tracker`、`ocs`（原创角色）。
**——"你的打字数据驱动桌面角色"是它打穿的核心。**

同时它的差评关键词只有两个字，但极其致命：**`keylogger`（键盘记录器）**。

> ⚠️ **这是本方向最大的产品感知风险，必须提前设计应对**：
> 一旦你的产品"检测键盘/读取你在做什么"，一部分玩家会立刻联想到恶意软件。
>
> **规避原则：**
> 1. **只统计，不记录**：只显示"今日按键 12,340 次""专注 47 分钟"，**绝不保存任何按键内容**；
> 2. **默认关闭 + 明示开关**：行为检测功能**默认关闭**，用户主动打开，并在首次开启时用一句话说清"只记数量，不记内容"；
> 3. **本地处理**：明确写"全部数据只存在你本机，不上传"；
> 4. **商店页主动解释**：把这句话写进商店页描述，而不是藏在隐私条款里。

## 4. 真实销量的冷水：两个单人先例的实际数字

前面几份报告反复出现"好评极高但卖不动"的现象，这次直接把**真实数字**摆出来（第三方估算，PureGameStats / Gamalytic）：

| 产品 | 预估销量 | 好评率/评测数 | 峰值并发 | 备注 |
|---|---|---|---|---|
| **Deskpet**（单人 / Matheus Bello） | **62 份** | 100% / 4 条 | **2 人** | EA 2026-02-07，$2.99，有 Overlay 模式（透明+点击穿透） |
| **DeskPet**（另一款同名） | **15 份** | — / 1 条 | — | 总收入约 $28 |
| **Desktop Gremlins**（单人 / ShuGhost） | 无法统计 | **0 条评测** | — | EA 2026-08-06，NZ$2.87 |

**Desktop Gremlins 值得单独看，因为它是"功能做得很全但还是没人"的教科书案例：**

它有的功能：
- 对指定程序做出反应（Steam、Discord、VS Code、Photoshop）
- 对音乐做出反应
- 4–5 种进化形态（史莱姆 → 暗黑女巫）
- **Chaos Mode**（摇晃窗口、旋转浏览器、重排桌面图标、闪烁任务栏）
- **Steam 创意工坊造型包**
- **Twitch 频道点数联动**
- **Steam 联机**

它没有的：**Steam 评测 0 条，且新闻流从头到尾没有发过一条。**

成就数据反推：解锁比例恰好是 1/9 的整数倍，推测**只有约 9 个账号上报过数据**。

> **这个案例的教训是全篇最重要的一句话：**
> **功能清单不是市场。** 一个单人开发者把能加的功能全加了，结果连 10 个人都没进来。
> 问题不在产品，在**发行**——商店页没人看过，没有愿望单蓄水，没有新品节曝光，没有首周更新节奏。**在 Steam 上，"发上去"不等于"被看见"。**

**对比一下：Character House 免费、148,430 份；Desktop Gremlins 功能更花、$1.7、0 评测。** 差距不在功能多少，在于**Character House 给出了一个"必须现在就装"的理由（你的打字数据），而 Gremlins 只给了"我很可爱"。**

## 5. 可落地性总评：分维度打分

| 维度 | 评分 | 理由 |
|---|---|---|
| **技术实现** | ★★★★★ | Godot 官方有完整配方；已有"第一个 Godot 项目"就做成的先例；三个坑都是已知可绕过 |
| **开发成本** | ★★★★★ | 美术 2 千–2 万；引擎/工具免费；上架 $100 可返还 |
| **周期可控** | ★★★★★ | 4 个月可完整跑完"开发→上架→发售" |
| **单人可行性** | ★★★★★ | 无联网、无平衡、无服务器（**前提：不做交易/不做联机**） |
| **差异化空间** | ★★☆☆☆ | 60 款竞品 + 免费开源 VPet + 免费爆款 Character House |
| **市场天花板** | ★★☆☆☆ | 头部 1.6 万评测，但中位数是"0 条评测" |
| **被看见的难度** | ★☆☆☆☆ | **最大风险**。Desktop Gremlins 功能拉满 = 9 个用户 |

**综合：这是一门"手艺上很容易、商业上很难"的生意。**

用一句话概括可落地性：**你能做出来，但你大概率卖不掉——除非你解决了"为什么是现在、为什么是你"。**

## 6. 如果你还是要做：可落地的执行方案

### 6.1 唯一可行的差异化切口（必须三选一，不能都不选）

| 切口 | 说明 | 对标验证 |
|---|---|---|
| **A. 行为挂钩**（首推） | 它吃的是**你在电脑上做的事**——打字、编译、专注时长、下载量 | Character House（打字→148K 份）、Bongo Cat（打字→19.4 万峰值）、鸟语森林（专注→金币） |
| **B. 成长即镜像** | 它的形态**反映你的工作方式**——写代码多→工程师形态；摸鱼多→圆滚滚 | 艾果（跨玩家配种）、波波萌宠（基因组合） |
| **C. 荒诞仪式感** | 用**荒诞的互动**代替教程，让玩家截图传播 | Spiritstead（把鸡举到篝火上烤三秒召唤幽灵） |

**明确不推荐的切口**："就是很可爱的桌宠"——这个位置被 VPet-Simulator（免费+开源+多年工坊）占死了。

### 6.2 五层配方（沿用前几份报告的收敛结论）

```
第 1 层  外层形态：桌面伴侣（透明置顶、底部/角落）
第 2 层  钩子：真实工作行为 = 它的食物（行为挂钩）
第 3 层  内核：养成仪式感（喂食→反馈→进化）
第 4 层  差异化：它吃什么 = 你在电脑上做什么
第 5 层  变现：本体 ¥22–33 + DLC 造型包
```

### 6.3 4 周原型（只做这 4 件事，做完再决定要不要继续）

1. Q 萌小生物在屏幕底部弹跳 / 闲逛 / 发呆
2. **打字时它有反应**（这是核心钩子的最小验证）
3. 饿了变蔫、喂饱精神（**只做"变慢"，绝不做"倒退/掉信任度"**）
4. 长大一点点，多一个小配件

### 6.4 三个新自检问题（回答不了就别做）

1. 「**我会不会在写代码时顺手把它打开放角落，而且不想关？**」
   —— 只有"好玩"但不"想一直开着" = 你在做普通游戏，不是桌面伴侣。
2. 「**我会不会想截图发给朋友？**」
   —— 传播是唯一免费的流量，不能截图的产品在 Steam 上等于隐身。
3. 「**如果它突然想要我没有的东西，我会不会觉得烦？**」
   —— 会烦 = 需求系统设计错了（对照 12 小时差评的焦虑链条：随机需求 + 资源不可控 → 担心它饿 → 信任度下降 → 焦虑 → 不放松）。

### 6.5 发行才是决胜局（桌面伴侣最常见的死因）

Desktop Gremlins 的失败不在产品，在发行。**必须在开发阶段就并行做这些：**

| 动作 | 时机 | 说明 |
|---|---|---|
| 开 Coming Soon 页 | 发售前 **≥2 周**（越早越好，建议项目一成型就开） | 愿望单是唯一的蓄水渠道 |
| **参加 Steam 新品节（Next Fest）** | 发售前 | 本赛道最大的免费曝光位，**必做** |
| 社交传播种子 | 开发全程 | 每做一个新动作就录 10 秒 GIF，发 X / B 站 / 小红书。**Q 萌是本赛道唯一免费的流量，别浪费** |
| **首周更新节奏** | 发售当周 | 2026 年 Steam 算法最重要杠杆之一：发售首周的更新频率直接决定推荐曝光 |
| 时长控制 | — | 对标 Ropuka's Idle Island / Tiny Pasture 的"轻量感"。**不要试图做 50 小时内容**（单人做不完，且桌面伴侣的用户本来就不想要长内容） |

---

## 7. 最终建议

### 建议做，但要换一个目标函数

**不要把它当成"我的第一款独立游戏"，要当成"我用最低成本验证一次 Steam 发行全流程的练习"。**

理由：
- 技术成本、美术成本、周期成本都是全部候选方向里**最低的**（★★★★★）；
- 失败代价极小——4 个月 + 2 千元美术，换来的是**完整的"上架→愿望单→新品节→发售→首周更新"实操经验**；
- 而这个经验恰恰是 Desktop Gremlins 那类"产品做对了但发行没做"的开发者最缺的东西。

**如果一定要定一个成功标准，建议不是"卖 10 万份"，而是：**
- 愿望单破 1,000（说明商店页和题材能吸引人）
- 首月评测 > 30 条、好评 > 90%（说明产品立住了）
- 有人在评论里说"我上班一直开着"（说明桌面伴侣属性成立）

**达到这三条，就值得投入做第二款。达不到，你只花了 4 个月，而这 4 个月的发行经验会跟着你一辈子。**

### 什么情况下应该放弃这个方向

1. **你不愿意做发行**——如果你的计划是"做完发上去就好"，那这个方向对你**必死**（Desktop Gremlins 证明功能全满也救不了）。
2. **你想靠它一次翻身**——赛道的销量分布是断崖式的，中位数是 0 条评测。想要确定性收入，前几份报告里的**轻度肉鸽割草**（土豆兄弟一人 + Godot 卖 1000 万份）天花板更高。
3. **你打算做联机或交易**——单人在这个赛道里唯一的安全区是**纯单机、纯本地、无服务器**。
