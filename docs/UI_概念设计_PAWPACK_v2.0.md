## 0. 为什么整版推翻

v1 交付后被判了四条：**不够可爱 / 主界面太简易 / 六只同质化 / 战斗 UI 简易且缺关卡差异**。

其中前三条不是细节问题，是**三个系统性错误的叠加**。必须同时改，只改一个会被另外两个抵消：

| # | 错在哪 | v1 | v2 | 为什么 |
|---|---|---|---|---|
| 1 | **明度** | 黄昏紫 `#3A3560→#6E5A94→#B87F9A` | 白天粉蓝 `#7FCDEF→#E9FAFF` + 奶油黄草地 | 低明度 + 冷紫是**情绪/抒情**的语言（独立游戏海报那一套）。可爱风的第一条是高明度（L > 80%），第二条是暖 |
| 2 | **比例** | 头径占身高 0.44，眼占脸 1/6 | 头占 **0.52–0.60**，眼占脸宽 **1/3** | 0.44 头身比读作"Q 版小人"。眼占 1/6 时六只全是"有五官的团子"，不是角色 |
| 3 | **描边** | 统一冷紫近黑 `#3A2B44` | 每只用**自己主色的深暖调**（猫 `#8B5030` / 兔 `#B06A8C` / 狐 `#A04E2E` / 牛 `#5E7398`） | 冷色近黑压在粉彩上会让画面"变硬"，那是绘本感不是可爱感 |

第四条「主界面太简易」的根因是**画面是插画不是界面**（见 §4）；「同质化」的根因是**只换配件不改体型 + 没有稀有度**（见 §3）。

## 1. 设计语言：「棉花糖」

### 1.1 参考对象与取舍

| 参考 | 抄什么 | 不抄什么 | 为什么不抄 |
|---|---|---|---|
| **蛋仔派对** | 厚底按钮（底部一条实色"厚度"）、顶部月牙高光、胶囊化 | 满屏红点 / 活动入口 / 七日签到 | 买断单机没有运营位；塞满活动入口会被 Steam 玩家直接判"手游味" |
| **星之卡比 探索发现** | 粉彩天空、深描边贴纸感、圆润剪影 | 3D 体积、软阴影 | 2D 平涂做体积必然脏 |
| **Ooblets** | 高饱和角色 + 粗描边、明亮草地 | 写实质感、纹理细节 | 美术预算是"一个人能画完" |
| **动物森友会** | 奶油面板、大留白、**家和过日子的痕迹** | 完全无描边 | 无描边在 1280×720 缩略会糊 |
| **宝可梦 / 抽卡类** | **稀有度梯度**（普通→传说）、星级、专属特征 | 抽卡动画、概率公示 | 我们没有内购，稀有度只做"叙事稀缺"，不做抽取 |
| **雪人兄弟** | 单屏一关、即时飘字反馈 | 街机像素风 | 已定矢量 Q 版（见 §3） |

**一句话定位**：卡比的"软" + 蛋仔的"厚" + 动森的"过日子"，做成**贴纸质感的棉花糖世界**。

### 1.2 三条形状铁律（v2 修订）

1. **一切皆有描边，但描边不是黑色**：用主体色的深暖调，粗细 = 尺寸 × 0.026（≥ 2.2px）。  
   —— v1 的"统一近黑描边"是错的。描边要**融进角色**，不是"给角色套线框"。
2. **投影必须是硬投影**：同色偏移 `y+5~9`，`rgba(107,74,66,.16~.22)`，永不用 `shadowBlur`。  
   —— 模糊阴影是写实信号；卡通靠实色错位压层次。
3. **尖角一律圆化**：耳朵、角、屋顶、尾巴尖、花瓣——全部走二次/三次曲线。  
   —— **尖 = 硬 = 不可爱**。这是一条没有例外的规则，屋顶用半圆拱不用三角。

### 1.3 渐变的唯一合法用途

**只有天空**（家园、高塔、深井井口）允许线性渐变。  
角色、平台、面板、按钮**禁止渐变**，只用 2–3 个纯色阶做明暗。按钮的"高光"是**一块实色月牙**，不是渐变。

## 3. 宠物立绘（`concept2-0-立绘谱.png`）

### 3.1 形体规格

| 项 | 规定 | v1（错） |
|---|---|---|
| 头径 `hd` | 总高 × **0.52–0.60** | 0.44–0.47 |
| 身体宽 `bw` | 总高 × **0.50–0.90** | 0.46–0.72 |
| 身体高 `bh` | 总高 × **0.38–0.46** | 0.44–0.52 |
| 身体形状 | **蛋形**（下宽上窄），不是正椭圆 | 正椭圆 → 读成"球" |
| 描边 | 总高 × 0.026，用**自身主色的深暖调** | 统一近黑冷紫 |
| 表情 | 4 套：常态 / 饿 / 半饿 / 饱。**只换眼、嘴、腮红，不换骨架** | 同 |

### 3.2 脸型不能共用一个圆

观众**记脸不记配件**。六只共用同一个头圆，配件再多也分不开。所以头形是函数：

```js
headPath(g, cx, cy, rx, ry, chin)   // chin ∈ [0, 0.6]
// chin 越大 → 下巴越收（狐 0.56 = 倒三角；仓鼠 0.00 = 方脸）
// rx / ry 由 hrx / hry 乘 headR 得到（仓鼠 hrx 1.14 = 最宽的脸；兔 hry 1.02 = 最长的脸）
```

### 3.3 大眼睛三要素（缺一件就是"死鱼眼"）

```js
rw = R * 0.88,  rh = R * 1.16        // ① 竖椭圆。横椭圆像青蛙，正圆像纽扣
// ② 主高光(左上, rw*0.40×rh*0.30) + 副高光(右下, rw*0.20) —— 双高光才有湿润
// ③ 下缘淡蓝反光 rgba(198,240,255,.50) @ (cy+rh*0.64, rw*0.48×rh*0.17)
//     ← 这条最容易被漏掉，但它是"水汪汪"的真正来源
```

> 反光 alpha 不要超过 .55。v2 调试时用过 .62，整只眼发蓝紫，像外星人。
>
> ⚠️ **例外一个都不许有**：v2 里狐「星屑」原本画成两道闭眼弧线（想表达"笑里有话"），
> 结果它是六只里唯一没有眼白、唯一不遵守三要素的——**传说位反而最不吸引人**，
> 和"极致想得到"直接矛盾。现在六只的常态一律是 `bigEye()`，弧线笑眼只留给满饱态。

### 3.4 六只全参数（`kit2.js` PALS，实现以代码为准）

| 宠物 | bw | bh | hd | hrx | hry | chin | 材质差异 | 稀有度 |
|---|---|---|---|---|---|---|---|---|
| 砂糖 · 尖耳猫 | 0.56 | 0.40 | 0.56 | 1.00 | 0.94 | 0.18 | 头顶呆毛 + 竖瞳 | ★ 普通 |
| 年糕 · 短尾犬 | 0.68 | 0.38 | 0.55 | 1.04 | 0.90 | 0.36 | 卷尾（身后）+ 露舌 | ★ 普通 |
| 团子 · 胖仓鼠 | **0.90** | 0.46 | 0.52 | **1.14** | 0.86 | **0.00** | 颊袋 + 两颗门牙 + 背部短纹 | ★★ 少见 |
| 雪团 · 长耳兔 | **0.50** | 0.46 | 0.54 | 0.93 | **1.02** | 0.20 | 一耳微折 + 大后脚 | ★★ 少见 |
| 豆奶 · 老实牛 | 0.82 | 0.40 | **0.58** | 1.06 | 0.90 | 0.30 | 月牙角 + 额头深斑 + 鼻梁白 | ★★★ 稀有 |
| 星屑 · 影狐 | 0.54 | 0.38 | 0.56 | 1.00 | 0.92 | **0.56** | **巨纺锤尾 + 白尾尖 + 星尘** | ★★★★ 传说 |

**「极致想得到」是怎么做出来的**：星屑是唯一的传说位——体型最瘦、下巴最尖、尾巴比它身子还大、还带星尘粒子。它不是"狐耳猫"；它是**一眼就该被单独记住的那只**。六只平均 = 六只都不想要。

> ⚠️ **稀缺特征必须在成品图里真的看得见**。v2 第一版谱上每格 `clip` 半宽只有 96px，
> 而狐的巨尾要甩到 `cx±137` —— **"尾巴比身子还大"这个传说位的唯一理由被裁掉了**，
> 图上只剩一小截尾巴和一颗星尘。修法：狐在谱上镜像（尾巴甩向右侧、右边没有邻格），
> 单独把这一格的 clip 向右放宽到 280。同理，剪影行也必须跟着镜像——否则同一张图上
> 主图和剪影的尾巴方向相反，读成"两只不同的宠物"。

### 3.4b 体积光影（v2.1 新增，回答"有没有立体感"）

v2 第一版是**纯平涂 + 一条描边**，六只在缩略图上读成贴纸。加了体积之后才站得住。

**规则：右下背光、左上受光，全场统一一种光。**

| 层 | 做法 | 参数 |
|---|---|---|
| 暗带 | 沿轮廓内侧一条带（`edgeBand`），只裁右下 | 厚度 = 半径 × 14%，`dn(主色, 0.26)` |
| 亮带 | 同上，只裁左上 | 厚度 = 半径 × 5.5%，`ln(主色, 0.30)` |
| rim | 左上轮廓最外一圈 | 厚度 ≈ 描边宽 × 0.9，`rgba(255,255,255,.38)` |
| 额头高光 | 一块横向月牙 | 宽 0.30 HRX × 高 0.15 HRY，白 .26 |
| 头身 AO | 头压在身体上的接触阴影 | 椭圆 `HRX×0.92 / HRY×0.20`，`rgba(74,44,24,.17)` |

**走过的三条弯路（都别再踩）**：

1. **用"偏移的大椭圆"当暗部** → 分界弧线切在脸中间，读成"戴了个面具"/"脸上一道脏痕"。
2. **加大对比** → 更脏、更明显。方向错了，加多少都是错。
3. **暗带 24% + 亮带 21%** → 中间只剩 55% 主色，整只读成"气球"。

正解是**环形带**：裁出「外轮廓 − 内缩同形」之间那一圈，再用一个方向圆裁掉其余三面。
这样暗部永远贴着轮廓走，不会进到脸中心。实现见 `kit2.js` 的 `edgeBand()`。

> **脸的规则和其他部位不同**：脸是视觉中心，暗部只能贴在右下**边缘带**，
> 而且**不要**给脸加 form 的亮带（会读成"脸上贴了个浅色圆片"）。体积感交给
> 额头月牙高光 + 头身 AO。

### 3.5 剪影检验（入库前必过）

把六只涂成纯色并排看：**每只能在一秒内认出来，才算过。**

脚本已自动化：`silhouette()` 读像素、非透明处统一染色。肉眼看立绘永远觉得"挺不一样"，**涂黑一排才知道根本分不开**——v1 的仓鼠和犬在剪影里几乎一模一样，就是这么发现的。

### 3.6 四套表情的状态语义

| 表情 | 触发 | 视觉 | 玩法耦合 |
|---|---|---|---|
| 常态 | 满饱 | 圆眼 + 双高光 + ω 嘴 | 基础 |
| 半饿 | 30–70（第 3 关起） | **星星眼 + 张嘴笑 + 腮红 + 脚下金环** | 火力最强 **×1.5** |
| 全饿 | < 30（第 6 关起） | 上眼睑压低 + 波浪嘴 + 汗滴 + 瘪肚纹 | **冲刺锁（K）**，倍率 ×0.6 |
| 饱 | ≥ 70 | 眯眼 ^ ^ + 满足弧嘴 + 腮红 | 回家 / 吃果后 |

## 4. 家园主界面（`concept2-1-家园.png`）

### 4.0 v2.1 重构：从"一个出口"到"全部功能"

v2 第一版只有「出门」一个入口，其余全靠床和食盆暗示 —— 这是"不够"的真正原因。
主界面要**统筹所有功能并给未来规划留位**，所以按计划书的系统清单逐个落地：

| 功能 | 阶段 | 承载方式 | 位置 |
|---|---|---|---|
| 选宠（六只性格） | P0 | 宠物本体（可点） | 前排 y 596–646 |
| 出门 | P0 | 底部主按钮 | (968, 654) 262×58 |
| 灶台 · 喂饭（饱食度） | P0 | **场景建筑** + 铜牌 | (44, 372) |
| 工作台 · 做道具（6 种） | P1 | **场景建筑** + 铜牌 | (186, 372) |
| 产地选择（3 产地 + 锁） | P1 | **路牌**，箭头朝左指出画外 | (792, 380) |
| 图鉴（六只 × 稀有度） | P2 | 底部次按钮 `4/6` | (704, 660) |
| 背包（食物/材料/道具） | P1 | 底部次按钮 `12` | (816, 660) |
| 今日目标（四条） | P0 | 左上卡片 | (24, 104) 344×118 |
| 设置 / 存档 | P0 | 右上齿轮 | (1236, 38) |

**为什么入口做成建筑而不是悬浮图标**：这个游戏卖的是"过日子"，入口一旦变成
悬浮图标就退回成了菜单页。动森也是建筑即入口。建筑头顶统一挂一块小铜牌，
玩家看到牌子就知道"这儿能点" —— 这是全套资产的识别语言。

**为什么必须有"今日目标"**：六只再可爱，玩家打开游戏也不知道第一步干嘛。
卡片给了一条主线（喂饱 2 只 · 带一只出门）+ 四条可勾选的小目标。

### 4.1 为什么 v1 被判"太简易"

v1 是**一张插画**：六只站在草地上，六个头像 + 三个按钮。好看，但**看不出要干什么**。

> 「不是有个宠物家园的感觉吗，应该有一个玩法或者养成才对」

可爱不是靠装饰堆出来的。主界面要让玩家在**3 秒内自己读出循环**，所以同屏必须存在这四样，缺一个就退回"插画"：

| # | 要素 | 回答的问题 | v2 实现 |
|---|---|---|---|
| 1 | **需求气泡** | 我现在该做什么 | 4 个头顶气泡：睡觉 / 吃 / 亲近 / 玩（5 种图标：heart·food·sleep·play·fish） |
| 2 | **一个正在被互动的瞬间** | 这是可以点的 | 年糕追球 + 「摸摸」气泡 + 手指光标 + 三颗飘心 |
| 3 | **今日互动 4/6** | 还差几只（短目标） | 六个圆点，四个实心，旁边写「还差 2 只」 |
| 4 | **亲密度 3/5** | 长期图什么（长目标） | 五颗心 + 「再摸 12 次升级」 |

**短目标和长目标必须同时在画面上。** 只有短目标 = 每日任务式的手游味；只有长目标 = 玩家不知道该做什么。

### 4.2 空间分配纪律

### 4.4 三条改版时不能丢的意图

1. **视线路径是 屋顶猫 → 中间追球的狗 → 底部出门按钮**。宠物的"动作密度"决定视线落点，所以年糕（追球）和砂糖（爬高）必须是画面里最闹的两只。
2. **每个宠物处于不同状态**，不允许六只排排站。睡觉 / 吃 / 追 / 跳 / 看 / 趴——**状态差异本身就是"这是个活着的家"**。
3. **HUD 必须是一条**。分散贴在草地上会被读成"贴纸"，且会和宠物的脚打架（v1 就踩了这个：前景草把六只的脚全挡了）。

## 5. 战斗内三关空间对照

### 5.1 为什么出三关而不是一关

v1 只画了一关，所以**"不同关卡差异性"在图上根本不存在**。差异不能靠换配色——玩家会觉得"还是同一关"。差异必须来自**空间结构 + 专属动词**：

| 关 | 名字 | 结构 | 专属动词 | 专属背景语言 | 难度信号 |
|---|---|---|---|---|---|
| 第 1 关 | 苔原入口 | **横向**：三级平台 + 缓坡 + 木桥 + 长球道 | **推** | 木平台 + 草簇 + 木桩支柱 | 满饱 ×1.0 / 3 心 |
| 第 5 关 | 深井 | **纵向**：交错圆石台，上下 2 层 | **落** | 井口光柱 + 荧光苔 + 水滴 + 侧石壁 | 半饿 ×1.5 / 2 心 |
| 第 8 关 | 双塔 | **阶梯**：五层木楼板 + 齿轮 + 绳索，中间真空 | **绕** | 脚底云海 + 背景双塔剪影 | 全饿 ×0.6 / 1 心 + 冲刺锁 |

**同一套 HUD 复用三关**——这才看得出是同一款游戏，而不是三个 demo。

### 5.2 HUD 三级分层（判定标准：缩到 480px 宽还一眼读得出的才算一级）

| 层级 | 内容 | 表现手法 | 玩家多久看一次 |
|---|---|---|---|
| **一级** | 血量、肚子、目标进度 | 奶油纸实体卡 + 4px 描边 + 硬投影 dy5 | 每 2–3 秒 |
| **二级** | 关卡进度、道具槽 | 半透明深色胶囊 / 小一档实体卡 | 每 10 秒 |
| **三级** | 操作提示、快捷键 | 无底、低对比 | 开局看一眼 |

> **为什么"肚子"是一级**：它决定"再推一关还是收工回家"，是全游戏最重要的一次决策。放成小字等于把这个决策藏起来。

### 5.4 三关场景结构（`bgMeadow` / `bgWell` / `bgTower`）

**草甸（横向）**
- 草线 y=452，平台 `woodPlat(46,426,268)` 等，抬高木台**必须有木柱**（(860,1160) 两根）——没柱子会读成"贴纸"
- 平台底 426 vs 草线 452，差 26px。差值 < 10px 会读成"悬空的线"（v1 踩过）

**深井（纵向）**
- 井口光：`ellipse(640,10,330,120)` 暖光 + 3 道向下扩散的光柱（alpha .04–.06）
- 两侧石壁各 74px，砖缝斜线间距 62
- 交错圆石台，缺口**竖直对齐**——这是"落"能成立的前提
- 落点涟漪：两个同心扁椭圆（18 / 30）

**高塔（阶梯）**
- **云必须在脚底**（(300,560)(900,610)(120,660)(1150,520)）——这是"很高"的唯一证据
- 五层楼板：`(40,508,300) (250,404,250) (480,310,260) (740,386,240) (950,286,290)`
- 齿轮**必须咬在楼板边**（(452,336)(748,412)），悬空会读成装饰
- 绳索从 y=130 起——**不能穿过顶部 HUD**（v1 踩过）
- 背景双塔剪影 (150,1120) alpha .20/.26，制造"双塔"

### 5.4b 平台拼接规范（v2.1 新增，"斜的没和横向接好"的根治）

**平台不是摆在一起的板子，是一根连续的梁。** 四条硬规矩：

| # | 规矩 | 不这么做会怎样 |
|---|---|---|
| 1 | **厚度统一 `PLAT_T = 26`** | 坡 22 / 桥 16 / 台 26 → 三条底面基线，接缝处必然错台 |
| 2 | **坡两端压进平台内 30px，先画坡、后画台** | 点对点对齐时，平台 8px 圆角会露出豁口，读成"平台被斜着砍了一刀" |
| 3 | **接缝画 4px 木端面封平** | 同高两条水平线相接处留 8px 小凹口 |
| 4 | **连接不同高度的两块台，桥必须是斜的** | v2 第一版"木桥"水平放在 (666,330)，右端却要接 y=386 → **悬空 56px** |

草甸关实测坐标：

```
坡 1  slope(284, 426 → 452, 330)   坡脚埋进平台 A（A 右端 314）
平台 A woodPlat(46, 426, 268)
平台 B woodPlat(452, 330, 214)
坡 2  slope(640, 330 → 800, 386)   坡顶埋进平台 B（B 右端 666）
平台 C woodPlat(800, 386, 420)
```

坡度实测 30° 与 22.7°，都在"一眼看得出能走"的范围（≤ 30°）。

> 试过但**不成立**的两个方案：① 接缝加 34×30 铁箍 —— 4 个铁箍读成"一排糖块"；
> ② 坡上画竖向木纹 —— 贝塞尔取点方向算错会让木纹"扎"出坡面，而且坡只有 190px 长，
> 抵不上风险。材质连续感靠"统一厚度 + 同色侧面 + 同款顶面亮带"就够了。

### 5.5 两条不能妥协的规矩

1. **血量用心形，不用方块条。** 方块读"能量"，心读"它会死"。这是情绪差别，不是审美差别。
2. **飘字必须避开敌人和平台。** 放中正 (640,196) 时正好压在敌人头顶、副标被平台切断，两层都读不清。现在放右上净区。

### 6.3 设计要点

- **遮罩 0.86**。0.80 时 HUD 从卡片周围透出来，和卡片里是同一组信息，互相打架。  
  但**不能压到全黑**——背景要认出"我刚刚在这儿"（脚本先画草甸关，再盖 `rgba(36,28,44,.86)`）。
- **评级是奖章不是数字**：三层同心圆 + 沿下半弧排的月桂叶（按切线旋转）。竖排一排叶子会变成"两根虫"。
- **两个出口必须都能选**：继续深入（黄，有倍率有风险）/ 收工回家（奶油，落袋回血）。只有一个"下一步"的结算等于没做选择。
- **倍率提示要写在按钮旁边**，不能只写在说明里。玩家在结算面板停留 2 秒，看不完三行小字。
- **背景装饰必须整体移出面板覆盖区**（面板 x 300–980）。压在边缘会被读成"穿帮漏出来"。

## 7. 实现约定（交给 Cocos 的部分）

### 7.1 切图规则

| 元素 | 切图方式 | 说明 |
|---|---|---|
| 面板 / 卡片 | **九宫格**，边距 = 圆角 + 描边宽（约 44px） | 拉伸时圆角和描边不能变形 |
| 按钮 | **一张**常态图 + 代码位移 | 按下 = 整体 `y+5`、厚度 `9→3`。不要切两态 |
| HUD 角色头像 | 正圆遮罩 + 同一张立绘 | 不单独切头像 |
| 道具图标 | 单图 58×58，透明底 | 三个图标统一描边 2.6px |
| 飘字 | **不切图**，`Label` + outline | 主标 outline 8–9px，副标 4px |
| 需求气泡 | 九宫格（r19） | 五个图标各自单图 26×26 |

### 7.2 像素密度

- 设计基准 **1280×720**，目标 1920×1080 → **1.5×** 出图后按 1× 使用，避免放大糊。
- 出 4K 按 3× 出图；**不要**把 1.5× 直接拉伸。

### 7.3 立绘的两种尺寸纪律

| 场景 | 高度 | 眼睛半径 `eyeR` | 用途 |
|---|---|---|---|
| 家园 / 立绘谱 | 116–178 | `headR × 0.29` | 主体，看细节 |
| 战斗内 | 116–120 | 同上（换算） | 小，看剪影 |
| HUD 头像圆 | 由 `r×2.1` 反推 | — | 只用脸 |

> 立绘**只有一份代码**（`drawPal(g, key, footX, footY, h, mood, opt)`）。家园、战斗、头像全调它，改一处三处同步变。这是"立绘和游戏里是同一只"的唯一保证。

| 概念图元素 | 原型现状 | 改动量 |

| `drawPal()` | `drawPet()`，40px，头身比 1:1.6，浅色描边 | **重写形体**（头/身体/眼），配件逻辑可留 |
| 家园四件套 | 无 | 新增（气泡 / 互动 / 今日 / 亲密度） |

## 8. 与《美术风格指引_PAWPACK.md》的冲突及处置
