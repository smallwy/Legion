# PAWPACK 主界面规格 v1.0

> **状态**：2026-10-21 首版。基准图 `client/shots/home-layout@v1.png`（1280×720）。
> **本文取代** `UI_概念设计_PAWPACK_v2.0.md` §4（家园主界面）与 §4.0（九入口功能表）。
> **已确认**：横屏 1280×720 / Steam / Casal→Puzzle→Action / 建筑即入口 / 无内购。
> **未确认项**：见 §9，需你拍板后才放量。

---

## 1. 这张图要解决什么

v2.1 的批评是「家园还是不够，你需要统筹考虑所有的功能」。到 v3.2 为止，功能已经比 v2 多了三项（派遣、推关进度、吧唧收集），同时砍掉了一项（今日目标）。**主界面必须按最新的功能盘重画，不是给 v2 的图打补丁。**

一句话原则：**这是"家"，不是"菜单页"。每个入口都得长在场景里。**

---

## 2. 全功能盘：三层归属

| 层 | 内容 | 承载 | 为什么放这层 |
|---|---|---|---|
| **顶部 HUD**（常驻） | 食物 · 材料 · 吧唧 · 图鉴 4/6 · 背包 · 设置 | 6 个胶囊，y=20..84 | 每次决策都要看，且不属于任何一个场景地点 |
| **场景一级入口** | 灶台（喂饭）/ 工作台（做道具）/ 派遣板（五只看家）/ 路牌（出门）/ 小屋（家本体） | 5 栋建筑 + 头顶铜牌 | **建筑即入口**。入口做成悬浮图标就退回成菜单页 |
| **场景角色层** | 六只宠物 · 食盆 · 窝 · 玩具球 | 实体 | 位置即性格；状态用环境表达（空碗 = 该喂饭） |
| **弹窗二级** | 出门三步（选产地→选宠→带道具）/ 喂饭 / 做道具 / 派遣 / 图鉴 / 背包 / 设置 | 半屏或全屏面板 | 一次只做一件事 |

### 2.1 明确砍掉的三样

| 砍掉 | 理由 |
|---|---|
| **今日目标** | 与"不做手游日常"冲突。`宠物+趣味性玩法融合设计手册` §253 记《桌宠大乱斗》被批的原话就是"养宠物，还有战斗、建造、抽卡、图鉴和任务" |
| **底部功能栏** | Steam 横屏不该有手游底栏。所有入口已由建筑承载，再加一条底栏就是双份入口 |
| **宠物需求气泡** | 试过，泡在建筑之间没有落脚空间（被灶台、工作台、栅栏三面夹）。改用**空碗**这种环境信号，不占画面 |

### 2.2 相对 v2 的变化

| 项 | v2 | v1.0 | 原因 |
|---|---|---|---|
| 入口数 | 九入口（含今日目标） | **8 个**（5 建筑 + 3 HUD 次要） | 砍今日目标 |
| 新增入口 | — | **派遣板** | CR-024 系统 C：派五只看家采材料 |
| 新增 HUD | — | 吧唧 / 图鉴进度 | 收集层要常驻 |
| 底部栏 | 有（图鉴/背包/出门） | **删除** | 手游味 |
| 六只的位置 | 一排散在门口 | **三层纵深 + 位置即性格** | "散在门口"读不出性格 |

## 4. 六只：位置即性格

| 宠物 | ★ | cx | footY | 高度 | 占屏高 | 位置依据（性格） |
|---|---|---|---|---|---|---|
| 团子 仓鼠 | ★★ | 150 | 620 | 126 | 17.5% | **灶台前**：贪吃，守在锅边 |
| 豆奶 牛 | ★★★ | 332 | 596 | 118 | 16.4% | **工作台前**：怕热，找个能趴下的地方 |
| 雪团 兔 | ★★ | 520 | 604 | 106 | 14.7% | **屋门口**：兔子只敢在洞口附近 |
| 砂糖 猫 | ★ | 600 | 300 | 88 | 12.2% | **屋顶**：猫必须站最高的地方 |
| 年糕 狗 | ★ | 900 | 610 | 128 | 17.8% | **路牌旁**：狗永远在门口等 |
| 星屑 狐 | ★★★★ | 1178 | 402 | 78 | 10.8% | **栅栏最右**：狐不轻易靠近 |

### 4.1 三条硬规则

1. **位置即性格**：不靠文字说明，靠站位。玩家看一眼就知道"那只守着锅的一定很馋"。
2. **距离即亲密度**：前景 106–128 / 中景 88 / 远景 78。越靠后越神秘 —— 星屑是 ★★★★，它就该在画面最远的地方。
3. **站在它在乎的东西旁边**：灶台 / 工作台 / 门口 / 路牌。不是随机撒开。

### 4.2 高度依据

v3.2 §9 定的是「宠物 120→180，占屏高 16.7%」。这里 126/720 = **17.5%**，略高 0.8 个点 —— 因为主界面没有战斗 HUD 抢空间，可以比战斗内大一点。**战斗内仍守 16.7%**，两个场景不要混用。

## 5. 点击区

| 类型 | 规则 | 实例 |
|---|---|---|
| 宠物 | 视觉高度 × 1.15，**下限 88×88** | 团子 126 → 145×145；星屑 78 → **88×88**（触到下限） |
| 建筑铜牌 | 牌面外扩 12，**下限 44×44** | "派遣" 56×26 → 80×50 |
| HUD 胶囊 | 已 ≥52 高，宽度够 | 全部达标 |

> Steam 鼠标最小 44×44；**若将来上触屏或手机，全部按 88×88 复核**。星屑是唯一一只刚好卡在下限的，它是风险点。

## 7. 交互与状态

| 交互 | 表现 | 依据 |
|---|---|---|
| 摸宠物 | 六只各自反应（v3.2 §11.1）；连续摸递进到翻肚 | 已定 |

| 空碗 | 满/空两态。**空 = 该喂饭**，是环境信号不是按钮 | 新定 |

## 8. 引擎落地要点

| 项 | 规格 |
|---|---|
| 分辨率 | 1280×720 → 1920×1080 **全 ×1.5** |
| 适配策略 | **高度优先**：Unity `Canvas Scaler` Match=**1**；UE `DPI Scale` 以短边为基准；Godot `stretch_mode=canvas_items / aspect=expand`；Cocos `fitHeight` |
| HUD 胶囊 | **九宫格**，边界 左26 上26 右26 下26（圆角 26）。宽度要随本地化变长，不能定做 |
| 建筑铜牌 | **九宫格**，边界 左13 上8 右13 下8。两个字和三个字都靠它 |
| 宠物 | 单张立绘 + 锚点 **(0.5, 1.0)**（脚底中心）。已实测六只立绘底部留白仅 6px，可用 |
| 图层顺序 | 天空 → 云 → 远山 → 草地 → 树/栅栏 → 小屋 → 花圃 → 后排名建筑 → 宠（按 footY 升序）→ 铜牌 → HUD |
| 图集分组 | `home-bg`（背景一次打包）/ `home-props`（5 栋建筑 + 家具）/ `pets`（六只立绘 + 状态）/ `hud`（胶囊 + 图标） |

## 10. 已知待打磨（不阻塞确认）

1. AI 立绘的描边比矢量场景细（约 2.5px vs 4.5px），远看像两套皮。**混合管线的固有代价**，需要统一描边宽度或给立绘加外描边。
2. 豆奶挡了工作台下半，只露出锯子和锤子。可接受（有铜牌指引），但如果要动，把它挪到 380。
3. 右侧 1150..1280 偏空，只有星屑和一棵裁一半的树。**"空"不等于"要加东西"**（v2.1 教训），先留着。
4. 花圃（686..770）夹在小屋和路牌之间，两个字的宽度，读起来像"花坛"不像"花圃"。可以删。
