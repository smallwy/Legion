## 0. 为什么这四张图是代码画的，不是 AI 生成的

| | AI 出图 | 代码精绘（本方案） |
|---|---|---|
| 中文文字 | 必然糊成笔画团 | 准确 |
| 尺寸 | 不可量，只能"看着差不多" | 每个元素都有确定坐标，可直接抄进 Cocos |
| 改版 | 重抽，全套漂移 | 改一个 token，四张图同步变 |
| 立绘与游戏内一致性 | 两张皮 | 同一份 `drawHip()`，立绘和游戏里是同一只 |

**结论**：AI 适合出"氛围和风格参考"，不适合出"UI 规格图"。这张桌子上的活儿，代码比模型准。

> ⚠️ 另有一条硬约束：Steam 的 AI 内容披露政策下，AI 生成的**成品**素材要打标签、销量均值约 1/3。用代码画的矢量资产不算 AI 生成，这条风险直接归零。

## 1. 设计语言：「糖果纸」

### 1.1 参考对象与取舍

同类型（Q 版卡通关卡制、单屏、轻操作）里，UI 做得最成熟的几个，逐个说清**抄什么、不抄什么**：

| 参考 | 抄什么 | 不抄什么 | 为什么不抄 |
|---|---|---|---|
| **蛋仔派对** | 厚底按钮（底部一条实色"厚度"）、糖果色、夸张圆角 | 满屏红点 / 活动入口 / 七日签到 | 我们是买断单机，没有运营位；塞满活动入口会被 Steam 玩家直接判"手游味" |
| **星之卡比 探索发现** | 粉彩天空、深描边贴纸感、圆润的角色剪影 | 3D 体积、软阴影 | 2D 平涂做体积必然脏 |
| **Ooblets** | 高饱和角色 + 粗描边、明亮的草地 | 写实质感、纹理细节 | 我们的美术预算是"一个人能画完" |
| **动物森友会** | 奶油纸面板、大留白、低信息密度 | 完全无描边 | 无描边在 1280×720 下缩略会糊 |
| **雪人兄弟** | 单屏一关、即时飘字反馈 | 街机像素风 | 已定矢量 Q 版（见 §6） |
| **Cult of the Lamb** | 粗黑描边 + 高饱和的"邪萌"反差 | 黑暗宗教调性 | 我们是治愈向 |

**一句话定位**：把卡比的"软"和蛋仔的"厚"合起来，做成**贴纸质感**——所有东西都像从一张彩色卡纸上剪下来、贴上去的。

### 1.2 三条形状铁律

1. **一切皆有深色描边**：`#3A2B44`，1280×720 基准下 **4px**（角色按尺寸等比，见 §5）  
   —— 描边是"贴纸感"的全部来源。去掉描边就变成扁平矢量插画，缩略图立刻糊。
2. **投影必须是硬投影**：同色偏移 `y+6~9`，不用 `shadowBlur`  
   —— 模糊阴影是写实信号；卡通靠**实色错位**压层次。
3. **按钮必须有厚度**：底部一条比面色深 2 阶的实色带，厚度 7–8px；按下时整体下移、厚度变 3px  
   —— 这是唯一能让玩家"感觉到按下去了"的零成本手段。

### 1.3 渐变的唯一合法用途

**只有天空**（主界面黄昏、战斗晴空）允许线性渐变。  
理由：大气必须有纵深，纯色天空会读成"没画完"。其余一切——角色、平台、面板、按钮——**禁止渐变**，只用 2–3 个纯色阶做明暗。

### 2.2 圆角

| 元素 | 半径 |
|---|---|
| 大面板 / 结算卡 | 32–34 |
| HUD 卡片 | 24–26 |
| 小卡片 / 道具槽 | 16 |
| 按钮 | `h × 0.42`（恒为胶囊） |
| 头像窗 | 正圆 |

### 2.3 字号（1280×720 基准）

| 层级 | 字号 | 字重 | 用途 |
|---|---|---|---|
| 标题 | 44–46 | 700 | LOGO |
| 面板主数 | 26–27 | 700 | 果子数、最终金额 |
| 评级 | 84 | 700 | S/A/B |
| 正文 | 16–20 | 400/700 | 名字、按钮标签 |
| 辅助 | 12–14 | 400 | 说明、单位 |
| **最小** | **11** | 400 | 仅限角标；**正文不得低于 12** |

> **字号铁律（沿用你的长期偏好）**：正文 ≥ 12px，且必须做「标准 / 大 / 特大」三档切换。  
> 实现方式：不是三套布局，是**一个 `uiScale` 系数**乘到所有字号和间距上，锚点跟着走。

### 3.3 三条设计意图（改版时别丢）

1. **视线路径是 家 → 谁 → 走**。小屋在最左当锚，六只在中间当主角，按钮在右下当出口。任何新元素塞进来都不能切断这条线。
2. **前排一只 + 后排五只，是"一只能出门"的空间表达**。不要改成六个等大并排——那等于放弃"选"这件事。
3. **小路是唯一的叙事元素**。没有它，画面就是"六个立绘摆在绿板上"。路必须从屋门口出发、向右出画。

## 4. 战斗内 UI（`concept-2-战斗UI.png`）

### 4.1 为什么必须重做

现行 HUD 的问题**不是不好看，是信息平铺**：头像 / 名字 / 血量全挤在一个深色圆角块里，字号 10–11px，谁都不比谁重要。玩家在打斗中扫一眼，抓不到"我还剩几条命"。

### 4.2 三级信息分层（这是重排的核心）

| 层级 | 内容 | 表现手法 | 玩家多久看一次 |
|---|---|---|---|
| **一级** | 血量、肚子、目标进度 | 奶油纸实体卡 + 5px 描边 + 硬投影 | 每 2–3 秒 |
| **二级** | 关卡进度、道具槽 | 半透明深色胶囊 / 小尺寸卡片 | 每 10 秒 |
| **三级** | 操作提示、快捷键 | 无底色、低对比白字 | 开局看一眼 |

**判定标准**：把图缩到 480px 宽，还能一眼读出的那几块，就是一级。

### 4.3 组件坐标

| 组件 | 位置 / 尺寸 | 内部 |
|---|---|---|
| 角色卡 | (22, 18)，286×104，r26 | 头像圆 cx56 cy56 r36；名字 (104,32) 20px；副标 (104,56) 11px；三颗心 (116/142/168, 82) r10 |
| 关卡进度 | (458, 16)，364×48，胶囊 | 文字居中 (x+96)；8 个点从 x+200 起，间距 19 |
| 目标卡 | (980, 18)，278×116 | 标题 (18,26)；主数右对齐 (w-18,27) 21px；进度条 (18,46) 242×12；收成行 y+84 |
| 肚子条 | (22, 636)，286×62，r31 | 碗图标 (34,36)；条 (70,34) 150×14；倍率右对齐 |
| 道具槽 ×3 | (1062/1132/1202, 636)，60×60，r16 | 图标居中；快捷键角标右上 14×14 |
| 飘字 | (700, 176)，44px | 主字描边 9px + 副标描边 4px |

### 4.4 两条不能妥协的规矩

1. **血量用心形，不用方块条。** 方块读"能量"，心读"它会死"。这是情绪差别，不是审美差别。
2. **飘字必须避开敌人和平台。** 第一版放在正中 (640,196)，正好压在敌人头顶、副标被平台切断，两层都读不清。现在放右上净区。

```
│ ─────────────────────────────────────────────────────── │
│  这一趟走了 3 关                                          │
│  攒下 128 果 × 1.30 =  166      [再推一关 → ×1.45]      │
│  ┌──────────────┐  ┌──────────────┐                     │
│  │   继续深入    │  │   收工回家    │                     │
│  └──────────────┘  └──────────────┘                     │
└──────────────────────────────────────────────────────────┘
```

### 5.2 设计要点

- **遮罩 0.88**，不是 0.80。0.80 时 HUD 会从卡片周围透出来，和卡片里是同一组信息，互相打架。
- **评级是奖章不是数字**：三层同心圆 + 沿下半弧排的月桂叶（按切线旋转）。竖着排一排叶子会变成"两根虫"。
- **两个出口必须都能选**：继续深入（橙，有倍率有风险）/ 收工回家（白，落袋回血）。只有一个"下一步"的结算等于没做选择。
- **倍率提示要写在按钮旁边**，不能只写在说明里。玩家在结算面板停留 2 秒，看不完三行小字。

## 6. 宠物立绘（`concept-0-立绘谱.png`）

### 6.1 旧版问题

现行 `grove.html` 的 `drawPet()` 在 40px 上是够用的，但有两个硬伤：

1. 六只只有"换主色 + 换耳朵"的差别，**缩成剪影几乎一样**——违背"剪影可辨"铁律
2. 头身比接近 1:1.6，读起来是"Q 版小人"，不是"Q 版动物"

### 6.2 新版规格

| 项 | 规定 |
|---|---|
| 头身比 | **1 : 1.1**（大头短身） |
| 头径 | 总高 × 0.44–0.47（按体型微调） |
| 身体 | 椭圆，宽 0.46–0.72、高 0.44–0.52 总高 |
| 描边 | 总高 × 0.024（≥ 2.2px） |
| 眼睛 | 头径 × 0.175 半径，占脸约 1/3 |
| 表情 | 4 套：常态 / 饿 / 半饿 / 饱。**只换眼、嘴、腮红，不换骨架** |

### 6.3 体型表（剪影能分开的真正原因）

**只换配件 = 六只涂黑后全是同一个"雪人"**（第一版就是这么翻车的）。差异必须来自体型：

| 宠物 | bw | bh | hd | 剪影特征 |
|---|---|---|---|---|
| 尖耳猫 | 0.48 | 0.48 | 0.44 | 瘦高 + 上扬长尾 |
| 短尾犬 | 0.58 | 0.44 | 0.46 | 中等偏方 + 贴头垂耳 |
| 胖仓鼠 | **0.72** | 0.52 | 0.42 | 最宽最矮，最圆 |
| 长耳兔 | **0.46** | **0.50** | 0.43 | 最瘦最高 + 超长立耳 |
| 老实牛 | 0.66 | 0.45 | **0.47** | 最宽 + 头最大 + 弯角 |
| 影狐 | 0.48 | 0.46 | 0.43 | 瘦 + 大蓬尾（超出身体轮廓） |

### 6.4 剪影检验（入库前必过）

把六只全部涂成纯色，并排看：**每只能在一秒内认出来，才算过。**

脚本里已实现自动化：`silhouette()` 读像素、非透明处统一染色。这是唯一能客观验的办法——肉眼看立绘永远觉得"挺不一样"，涂黑一排才知道根本分不开。

### 6.5 四套表情的状态语义

| 表情 | 触发 | 视觉 |
|---|---|---|
| 常态 | 满饱 | 圆眼 + 高光 + ω 嘴 |
| 饿 | 全饿（<30，第 6 关起） | 上眼睑压低 + 波浪嘴 + 汗滴 + 瘪肚纹。**右侧收走冲刺（K）** |
| 半饿 | 30–70（第 3 关起） | **星星眼 + 张嘴笑 + 腮红 + 脚下金环**。火力最强 ×1.5 |
| 饱 | ≥70 | 眯眼 ^ ^ + 满足弧嘴 + 腮红 |

## 7. 实现约定（交给 Cocos 的部分）

### 7.1 切图规则

| 元素 | 切图方式 | 说明 |
|---|---|---|
| 面板 / 卡片 | **九宫格**，边距 = 圆角 + 描边宽（约 40px） | 拉伸时圆角和描边不能变形 |
| 按钮 | **两态**：常态 / 按下（下移 + 厚度变薄），或九宫格 + 代码位移 | 推荐后者：只切一张，位移用代码 |
| 角色卡头像 | 正圆遮罩 + 一张立绘 | 头像不必单独切，用同一张立绘裁圆 |
| 道具图标 | 单图 60×60，透明底 | 三个图标统一描边 2.6px |
| 飘字 | **不切图**，直接文本 + 描边 | `Label` 的 outline 组件 |

### 7.2 像素密度

- 设计基准 **1280×720**，目标平台 1920×1080 → **1.5×** 出图后按 1× 使用，避免放大糊。
- 若要出 4K，按 3× 出图；**不要**把 1.5× 的图直接拉伸。

### 7.3 与 `grove.html` 原型的对应

| 概念图元素 | 原型现状 | 改动量 |
|---|---|---|
| 立绘 `drawHip()` | `drawPet()`，40px，头身比 1:1.6 | 重写形体部分，脸/配件逻辑可留 |
| 角色卡 | 深色圆角块 + 10px 字 | 重写 |
| 目标卡 | 纯文字列表 | 重写 |
| 肚子条 | 已有（结算面板里） | 移到战斗中，改样式 |
| 道具槽 | 无 | 新增 |
| 结算面板 | 已有，深色卡 | 改配色 + 加奖章 + 加第二按钮 |

## 8. 与《美术风格指引_PAWPACK.md》的冲突及处置

**这份文档和旧指引在"画风"上是不一致的，必须说清楚：**

| 项 | 旧指引（`美术风格指引_PAWPACK.md` §1） | 现行实现 / 本文 | 处置 |
|---|---|---|---|
| 风格 | 像素 art，16–32px 工作分辨率 | 矢量 Q 版，任意尺寸等比 | **以本文为准**，旧指引 §1/§1.5 需要改 |
| 缩放 | 整数倍，Point 过滤 | 连续缩放，Linear | 同上 |
| 颜色数 | ≤ 24 色 | 不限，但每只 ≤ 4 个纯色阶 | 放宽 |
| 描边 | 1px | 总高 × 0.024（40px 时 ≈1px，158px 时 ≈3.8px） | 统一为"按尺寸等比" |
| 渐变 | 全面禁止 | 天空允许 | 加一条例外 |

**为什么会漂**：原型从像素占位转向矢量绘制（因为要画斜坡、要任意缩放、要一屏多平台），但指引没跟着改。这不是谁的错误，是文档没跟上实现。  
**建议**：旧指引 §1–§1.5 整体改写为"矢量 Q 版"标准，保留 §2 配色板、§4 状态纪律、§5.5 摄像头、§9 校验清单（去掉像素相关项）。
