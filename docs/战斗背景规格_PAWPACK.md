# 战斗背景规格 · 推球（PAWPACK）

> 版本 v1.3 / 2026-10-22（v1.1 背景分层 → v1.2 Q 版坑洞 → v1.3 删装置 + 火焰动画）
> 适用范围：`prototype/grove.html` 的 `drawForest()` / `drawTree()` / `drawRamp()` / `drawPlat()`
> 生成物：`assets/scripts/grove/GroveRuntime.ts`（改源后必跑 `tools/extract_grove_runtime.py`）

---

## 0. 一句话

战斗背景从「一张天 + 一块地 + 一排等距小树」改成**五个景深层**：
远雾林 → 老树干 → 起伏草脊 → 中间草地 → 前景灌木。
深度靠**遮挡**建立，不靠透视——这是「空间感要有，但不要太多」的落点。

## 1. 问题定性（改之前长什么样）

用户原话三条，对应三个可诊断的病：

| 原话 | 诊断 | 病根 |
|---|---|---|
| 「背景感觉像贴上去的」 | 缺遮挡关系 | 地面用 `fillRect(0,300,W,...)` 画，**一条横贯全屏的绝对水平线**；所有元素完整可见，谁也不挡谁 |
| 「斜坡太堵」 | 单件视觉体量过大 | 494 长 × 33 厚的实心斜板，等于 13000px² 的实色横在屏幕中间，把背景挡完了 |
| 「比较粗大了点」 | 截面过厚 | 平台视觉厚 33px = 屏高 5.5%，参考图圆木直径只有 4% |

另有一条**隐藏病因**：两棵近景树的受光面都固定偏左（`x - r*0.24`），
但太阳在 (700, 74)。左边那棵等于把高光画在了背光面 ——
**两个物件的受光方向互相矛盾，眼睛会判定它们是两张独立的贴纸。**

## 2. 五层结构

设计分辨率 960×600。层号从远到近。

| 层 | 内容 | 基线 / 参数 | 色与雾 | 遮挡关系 |
|---|---|---|---|---|
| L0 | 天空渐变 | y 0 → 340，三档色标 | `sky1 → sky2` | 被 L1 压 |
| L0.5 | 远山三道 | 296 / 310 / 324，振幅 104 / 72 / 46 | 混天 0.20 / 0.48 / 0.72 | 互压 |
| L0.6 | 暖雾带 | y 284 → 352 | `horizon` 0.94 → 0 | **盖住山脚** |
| L1 | 草脊（起伏） | `300 + 13·sin(x/323) + 6.5·sin(x/139)`，振幅 ±19.5 | `grassLight → grass2 → grass → grassDark` 四档 | **压住山脚** |
| L1.5 | 草面纹理 | 90 撮，尺寸 2~6.5，alpha 0.10~0.23 | `grassDark` | 在草脊之上 |
| L2 | 远排树 | 15 棵，sc 0.25~0.38 × **2.0**，深度 0.12~0.24 | 往 `horizon` 混 42%~48% | 互压 |
| L2.5 | 中景树 | 15 棵，sc 0.40~0.78 × **2.0**，深度 0.28~0.82 | `treeFar ↔ treeNear` 按 depth 插值 + 每棵 ±0.30 色相偏移 | **互压** |
| L3 | 树脚雾 | y 296 → 322，alpha 0.14 | `horizon` | 压在树根上 |
| L4 | 两侧近景树 | 左 x=6 / 右 x=W−8，sc 1.9 | 实色 + 3.4px 描边 | **压住一切** |
| L5 | 前景灌木 | 6 丛，x = 0.065/0.185/0.305/0.695/0.815/0.935 | `shrub` 剪影 | 压住玩法元素边缘 |

**中段 0.30~0.70 刻意留空**：那是推球通道和玩法目标（火坑 / 营地）所在，
前景被吃掉之后玩家会找不到该往哪儿推。

## 3. 关键数字与依据

### 3.1 草脊振幅 ±19.5，周期 2027 / 873

- **为什么不能是直线**：任何贯穿整幅画面的水平直线，眼睛都读作「两块图拼在这里」。
  这一条是「像贴上去」的最大单一来源。
- **为什么是 20 不是 60**：脊线最高 280.5，而最上层平台在 248、坡底在 350。
  越界就开始和玩法元素打架。上限由碰撞几何反推，不是审美选择。
- **为什么两个正弦**：单个正弦在 960 宽里会左右各留一段同形，读作「复制粘贴的波浪」。
  两个周期不成整数比（2027 / 873 ≈ 2.32）之后，画面内看不到重复。

### 3.2 中景树 60×sc 树干 / 27×sc 树冠 / ×2.0 总缩放（第二轮是 1.5，第三轮放大）

| 参数 | 值 | 依据 |
|---|---|---|
| 树干长 | 60×sc | 40 时树干 37 高、树冠 62 宽，比例 1.2 → 读作「灌木」或「棒棒糖」 |
| 树冠半径 | 27×sc | 31 时树冠过大，15 棵连起来是一道**绿篱** |
| 树干宽 | 16×sc | 只拉长不加宽，才有「细高」而不是「柱子变长了」 |
| 总缩放 | 2.0（第三轮从 1.5 调大） | 最高的树 111→178px，冠顶到 y=132 —— 卡在 HUD（90）之下、最上层平台（248）之上 |

**深度表达的三条，缺一不可**：

1. **尺寸**：sc 0.40 ~ 0.78（2 倍差）
2. **颜色**：`hexMix(treeFar, treeNear, depth)` 再往 `horizon` 混 `(1−depth)·0.55`
   —— 只做「往雾里混」会让最近的那棵也只比最远那棵实一点，十五棵同一个淡橄榄色
3. **遮挡**：相邻两棵重叠 20%~40%。**这是唯一可靠的深度线索**，
   尺寸和颜色只是辅助

**基线位移只给 `depth × 12`**（不是 30）：
给 30 时树干会整根落到草脊以下，十五根立在草地前面、间距又均匀，读作「一排栅栏」。
树必须扎在脊线上，深度靠尺寸和颜色，不靠把树往下挪。

基线**夹紧到 334**：350 那层平台从 350 起，树根扎进去就开始读作「战斗发生在树上」。

### 3.3 树脚雾只有 26px 高、alpha 0.14

第一版写成 48px 高、alpha 0.30（照搬概念图里「远树下半截看不见」的观感），
结果树干被拦腰切了一刀。

**因为空气透视是按距离累积的，不是按高度。**
同一棵树的上半截和下半截离镜头一样远，下半截没有理由更雾。
这层只负责「地面和树根之间没有硬边界」，不负责纵深。

### 3.4 厚度：平台 27 / 栈道 21

| 件 | 旧 | 新 | 依据 |
|---|---|---|---|
| 平台视觉厚 `PLAT_TK` | 33 | **27** | 33 = 屏高 5.5%，参考图圆木 4%。27 = 4.5%；再下到 24 会读成「一块板」（3 层挤不进 8px），再上到 30 就回到「粗大」 |
| 栈道面 `RAMP_TK` | 33 | **21** | 494 长 × 27 = 13000px² 实色，是「堵」的直接来源。21 = −22% 体量 |
| 接头渐变 | — | 前 **18% 行程** | 不做渐变，台面与坡下缘差 6px，接缝处出现台阶缺口 |
| 短支腿 | — | 4 处，7×18 | 给出「浮在地面之上」的唯一证据 |
| 支腿间距 | — | 坡长的 0.26 / 0.46 / 0.66 / 0.84 | — |

**短支腿不落地**：最长那关坡顶离地 206px，落地就是战场中间竖一排栅栏，
球道被切成格子（可读性事故）。只出 18px，读作「架起来的」就够。

**平台 27 = 3 × 9**：每层 9px 刚好够一条层缝（3.4）+ 一个年轮（5.6），
`LAYER_SHIFT` 的错缝语义不变。

### 3.5 光源统一

太阳固定在 (700, 74)。所有受光面按 `sign(700 − x)` 决定朝向：

- x < 700 → 高光在右侧
- x > 700 → 高光在左侧

树冠受光团偏移 `r × 0.24`（中景）/ `r × 0.18`（远景，不带描边）。

## 4. Q 版化：坑 / 门 / 边界（2026-10-22 第二轮）

用户原话：
> 「我需要的是 Q 版风格，现在给到的空间感，里面的元素像是贴上去的，没有感觉。
> 火坑就像是个贴图，贴上去的，看起来很假……右下角的营地去掉吧，
> 场景左下角和右下角，只有球撞过去都会消失，不会弹，右下角搞一个比较形象的门出口。」

三条诉求拆成三条可执行的修法，全部落在**结构**上，不靠调色。

### 4.1 坑洞：三层厚度（`drawPit` / `qflame`）

旧实现 = 一个梯形填色 + 两侧两条斜线 + 七根 22px 细火苗。

| 缺什么 | 后果 | 补法 | 数值 |
|---|---|---|---|
| 没有描边 | 同屏平台/木桩/角色都是 2.6~3.2px 描边，唯独坑没有 → 被并进背景 | 外轮廓描 `COL.outline` 2.8px，**只描左斜/底/右斜，不描坑口横线** | 坑口描了会读作"洞口被板压住" |
| 没有断面 | 地面被切了个洞，边缘是零厚的线 | 断面土层（受光）+ 深腔（背光） | `CUT = 8`，不超过地面块厚 44 的 1/5 |
| 内部只有一种暗色 | 读不出"往下陷"，只读出深色形状 | 后壁受光带 | 14px 高，rgba(152,118,84,.62)→0 |
| 坑沿是平的 | 读作"地面上的一块色"，不是挖出来的 | 隆起土堆（三圆并集） | 12×5.5 / 8.5×5.5 / 5.5×3.5 |

几何：`INSET = 14`（坑口每侧比坑底宽 14，总宽 100 → 底宽 72，斜边约 30°）、`BOT = y + 32`（坑底离地面 32，下方还剩 12px 土，剖面不算挖穿）。

**Q 版火焰 `qflame(cx, by, h, w, ph)`**：一团胖水滴 + 只描外焰 + 两层内焰（同形缩到 0.60 / 0.30）。三团错落 `28 / 25 / 44` 高。
- 旧版 7 根细火苗实体只有 5px 宽，缩到手机不足 3px，读作"一排橙色竖线"。
- **内焰不能描边**：一团火的内部出现黑线，读作"火裂开了"。

三种坑（火 / 水 / 泥）共用同一套底盘，只换腔内内容。

### 4.2 出口：**v4 全部删掉**（这一节的上一版是三根圆筒、再上一版是拱门）

> 用户第三轮：「右下角那个圆筒出口太突兀了，直接出掉吧」
> 用户第三轮：「左侧有个也不需要」（指左端那根封口树干）

**结论：这一屏不需要任何"出口装置"。** 前两版一共做过三种（编筐 → 拱门 → 朝左空心圆木），
每一版都在解决上一版的问题，但**方向一直是错的**：它们都在"往画面里加一个东西"。

加东西的代价是隐性的：这一屏已经有平台、坡、坑洞、木桩、角色五种物件。
任何新加的"装置"都必须画得足够大才读得出是什么，一旦大了，它就是画面里
体量最大的单体，眼睛第一眼落在它上面 —— 这就是"突兀"的机制，跟画得好不好无关。

**v4 的做法**：

| 项 | v3 | v4 |
|---|---|---|
| 右端 | 横放空心圆木（rx27 / ry42，长到画面外） | **无**。地面铺出画外，球滚出屏幕即落袋 |
| 左端 | 通高封口树干（下缘 496） | **无**。地面铺出画外，球滚出屏幕即判出场 |
| 地面块绘制范围 | `26 ~ 934`（逻辑墙） | **`-20 ~ 980`**（画面外） |

关键一条是最后一行：**逻辑墙不是地面的边缘**。`WALL_L=26 / WALL_R=934` 是球的碰撞范围，
上一版直接把它当地面块的收口位置，两端就露出"地面到此为止"的断头，
于是必须再画一个封口物去遮 —— 要遮的东西本来就不该存在。

地面铺到 `-20 ~ 980` 之后：
- 球滚到画面外才消失（左端判据从 `b.x + b.r < WALL_L - 2` 改成 `b.x + b.r < -4`）
- "滚出屏幕"是 2D 里最不需要解释的一种出界，玩家不需要任何装置来交代
- 右端落袋仍然靠 `CAMP` 区间（852~934）判定，落袋瞬间有金字 + 金色碎片 + 宝箱掉落

### 4.3 两端：地面层开口、上层反弹（v3 定的规则，v4 不再改）

> 用户第二轮：「左下角和右下角球直接滚出去，上层是可以反弹的。」

这条规则本身是对的，v4 只改了"怎么画"，没改"怎么判"。

| 层 | 行为 | 判据 |
|---|---|---|
| 地面（球心 556） | 两端**开口**。左滚出去 = 判出场；右滚进来 = 落袋结算 | `b.y >= GROUND_Y - 24` |
| 上层（462 / 350 / 248） | 实墙，撞上去**反弹** | `b.y < GROUND_Y - 24` |

判据用球的 y：球心压在台面上，地面 556、最低一层浮空台 462，差 94，取 24 的余量。

**上层撞墙的视觉载体**是平台自身的端头（浮空台从 `WALL_L` 开始、带圆角年轮），
不需要额外画墙 —— 球在 462 层撞左墙时，左边缘落在 26，正好压在平台的端面上。

**预瞄线必须同步**（`predictBall`）：地面层往左画到"出界"（标记 `out`），
不再画一条"会弹回来"的线。线上画着会弹、实际滚出去，是这套系统里最不能骗人的一处。

### 4.4 火焰动画：四件事叠加，缺一样都不像在烧（v4）

> 用户第三轮：「地下那团火或者其他元素能动起来吗，能成像真的一样」

先说清楚能力边界：**canvas 2D 平涂做不到写实级火焰**（没有后处理、没有粒子系统、
没有热浪扭曲）。能做到的上限是"一眼看得出在烧"，靠的是四件事叠加，
每件事都对应一个可指认的"不像"：

| # | 做法 | 不做会怎样 |
|---|---|---|
| ① | **三层各自独立相位**（外焰 0 / 中焰 +1.9 / 焰心 +3.7） | 三层共用相位 = 等比缩放，读作"一个气球在呼吸" |
| ② | **亮度要闪**（`heat`，13.7Hz + 23.1Hz 叠加，插值在三档橙之间） | 固定色值 = 无论形状怎么抖，都是"一个在变形的橙色物体" |
| ③ | **焰舌分离**（两小团从焰尖脱出去、飘一段淡掉） | 火不是一个会伸缩的色块，它一直在往上掉渣 |
| ④ | **火光溢出**（`lighter` 加色叠三圈扁椭圆，照到坑沿和草地） | 不照亮周围任何东西的光源，眼睛必然判定是贴上去的 |

补充三条实现细节：

- **窜火用 `max(0,sin)^6`**，不是正弦：六次方让函数绝大部分时间贴着 0，
  只在峰值附近冲上去 —— 三两次里窜一次 20%。普通正弦是匀速升降，像弹簧在拉。
  窜高时 `W` 同步除以 `sqrt(surge)`（面积守恒的直觉），只拉高不变细就是气球。
- **光晕必须是扁椭圆**（ry/rx ≈ 0.58）：① 火在平地上的光斑本来就横向铺开；
  ② 圆形半径 200 会一路照到 350 那层浮空台**上面**去 —— 平台不透明，穿过去就露馅。
- **衰减曲线要"平"**：0~55% 半径几乎不掉、85% 之后才收口。用标准三段式（0/0.5/1 线性）时，
  半径 110 处实际 alpha 只剩 4%，采样差 5 个色阶，人眼完全无感。

火焰几何（画布 960×600，坑宽 100，`BOT = y + 32`）：

| 项 | 值 | 依据 |
|---|---|---|
| 主火 | h 42 / w 30，`ph 0.8` | 屏高的 7%，Q 版靠轮廓识别，太小就退回"一排橙色竖线" |
| 左火 / 右火 | 26×19 / 23×17，`ph 0.0 / 1.9` | 错落才不像三根蜡烛；间距 `±0.30w`，太挤会糊成一团 |
| 轮廓比例 | 底宽 ≈ 高 × 0.65，中段外鼓 | 尖顶瘦身是写实火焰；Q 版必须是**胖水滴**，重心压在下半 |
| 描边 | 2.2px，**只描外焰** | 内焰也描 = 火内部出现两条黑线，读作"火裂开了" |
| 火星 | 8 颗，带短拖尾 | 单颗圆点静帧上就是个点；拖尾让同一帧里有方向和速度 |

同一套语言已经用在另外两种坑上（`drawPit` 的 `water` / `mud` 分支）：
水坑三圈外扩涟漪，泥坑四颗冒泡（带描边的大圆，细碎气泡会碎成噪点）。
弹簧菇（`drawBouncer`，`S.t * 4.4` 的 squash）和传送门本来就是动的。
### 4.5 背景层：明度骨架 + 中景植被（v3）

> 用户第三轮：「这个场景还是达不到我想要的那种感觉……空间感一定要设计的合理，
> 不要一根木头很突兀的感觉。」（附一张参考图：暖奶白天空、分层圆冠林、粗木平台、深色前景丛）

问题不是"细节不够"，是**明度骨架**：改之前整张图从上到下几乎同一个明度，
于是读作"一块绿纸"，所有物件都像贴在上面。

| 项 | 改前 | 改后 | 依据 |
|---|---|---|---|
| 树冠 | 单个 blob（读作棒棒糖） | **五瓣并集**（主瓣 + 左上 + 右上 + 左下 + 右下，最低一瓣压住树干顶） | 有"压住树干"这层关系，树冠才是挂在树上，不是插在杆上 |
| 树色 | 全部从 `treeNear` 出发，只差明度 | 每棵按 `hash(x)` 取 ±0.30 色相偏移（暖偏金 / 冷偏青） | 一片林子是三种树混着长；同色一排读作"复制粘贴" |
| 树高 | `TREE_SCALE = 1.5`（最高 167px） | `2.0`（最高 178px，冠顶到 132） | 参考图里中景树占屏高一半；背景的体量感来自比例，不来自细节 |
| 中景树干 | 无 | 3 根（246 / 704 / 916，宽 40 / 26 / 34） | 不等距、不等粗 —— 等距等粗就是"一排柱子" |
| 中景灌木 | 无（草脊到地面之间 250px 是空的） | 9 丛，`ch = 50×scale`，7 瓣并集 | 参考图里这一段至少叠三档灌木，眼睛一路有东西落脚才有纵深 |
| 灌木色 | — | `hexMix(hexMix(treeNear, shrub, 0.34), horizon, 0.12)` | 必须**明摆着比草地暗一档**（约 25% 明度），只暗 5% 就成"草地里的虚影" |
| 舞台压暗 | 无 | 392 → 600 的线性渐变，alpha 0 → 0.22 | 参考图最暗的地方在下缘。起点 392 在最低一层台（462）上方 70px，不影响层级判断 |
| 草地细节 | 90 撮细草 | 再加 26 块苔斑 / 22 片落叶 / 7 颗石子 / 3 簇蘑菇 | 一整片草地里找不到一块干净平面 |

**一个必须记住的 canvas 坑**：`blobPath()` 内部有 `beginPath()`，
所以"多瓣并集"必须给它加一个 `cont` 参数（后续瓣不新开路径），
否则画了 5 个圆只有最后一个被填充 —— 画面上看起来完全像"颜色调淡了"。
同一套 API 下 `stroke()` 描的是**每条子路径的整圈轮廓**，所以并集图形
**不能描边**（内部弧线会露出来，读作一团线）。灌木因此改为不描边，
靠明度分层次；只有近景树是单瓣 + 整圈描边。

### 4.6 浮空台：从"一块板"到"两根圆木"（v3）

> 用户第三轮：「不要一根木头很突兀的感觉。」

旧实现是「一块 27px 圆角板 + 三条水平层缝」。层缝只能把一块板切成三块板，
永远切不出圆木 —— 圆木的证据是**每根都有自己的一条受光弧和一条背光弧**，
叠在一起时中缝读作"上木的背光压着下木的受光"，必然是一条暗线紧挨着一条亮线。

| 项 | 值 | 依据 |
|---|---|---|
| 圆木根数 | 2 | 27 / 2 = 13.5，端头圆能画到 r≈7；分三根只剩 9px，端头圆退化成小点 |
| 端头年轮 | rx 5.6 / ry 8.2 | 故意比木身略鼓 —— 鼓出来才看得出"这是被锯断的断面" |
| 树皮 | 短横纹，长 22~48 | 竖缝在 27px 高的横木上读作"一截一截的木板" |
| 段缝 | 每 168px 一道 | 一道竖线单独画读作裂纹，必须"左暗右亮"成对出现 |
| 树结 | 每 190px | 没有结的木头读作"一截木色的条" |

厚度仍是 27（屏高 4.5%，参考图圆木直径约 4%）。
### 4.7 撞墙反弹：三处修正

用户描述的现象是「球撞过去都会消失，不会弹」。成因是三条叠加：

| 问题 | 数值 | 修法 |
|---|---|---|
| 低速反弹后几乎不动 | ×0.62 衰减，低速撞击只剩 3~8px/s | 最小反弹速度 `MIN_BOUNCE = 120` |
| 看不见的撞击也在计数 | `wallHits >= 3` 不看速度，墙角蹭两下就散 | 只有 `impact > 200` 才计数 |
| 反弹没有任何反馈 | 无木屑、无震屏 | 6 颗木屑 + `S.shake = 5` |

完整的假象链条是：撞过去 → 速度衰减到几乎为零 → 屏幕上不动 → air 漏光 → `burstBall`。
中间每一步都"合理"，合起来就是玩家看到的"撞过去就没了"。

### 4.8 树的地面投影

**这是"元素像贴上去的"最直接的成因**：十五棵中景树 + 十五棵远景树，一棵影子都没有。
平台、坡、角色、球都有影子，唯独树没有 —— 全屏最大的面积没有落影。

- 宽度 `42 × sc`（树冠宽约 54 × sc，收到 0.78 倍；再宽像水洼）
- 高度 `5 × sc + 2`，压在 `baseY + 1.5`
- alpha `0.09 + D × 0.15` —— 远处更淡更扁。和"颜色往雾里混"是空气透视的两半，必须同步。

### 4.9 前景丛结构性避开坑

前景是"压在镜头前面的东西"：它盖住什么，什么就真的看不见。

原来的做法是"丛集中在两侧、中段留空"，那只管住了画面正中。
第 1 关火坑在 500~600，和 0.695 那丛（中心 667、半径 78）刚好重叠 ——
**整个坑的下半截被草吃掉**，场上只剩三簇火苗尖。

改成按当前关卡的 `PITS` / `CAMP` 实时构图：任何一丛的**底座团**（±0.45r）
和某个坑（两边各留 40px）或门口（两边各留 60px）重叠，整丛跳过。
少一丛灌木不影响画面；盖掉一个火坑等于这一关没法玩。

## 5. 未达标项（如实记录）

### 5.1 第三轮之后仍然没解决的

| 项 | 现状 | 差在哪 |
|---|---|---|
| 树的形态 | 五瓣并集 + 色相抖动 | 仍是"一坨团块 + 一根直杆"，没有参考图那种**分层横向团块 + 明暗面**（受光面/背光面各自一块） |
| 草地 | 三档渐变 + 苔斑 + 落叶 + 石子 | 有细节了，但仍偏"平涂"，没有参考图的笔触感和明暗斑块 |
| 平台支撑 | 全部悬空 | 参考图的平台是**叠木结构 + 立柱**。我们的不能加立柱：立柱会横穿球道，玩家会误判成障碍。这一条是**玩法约束**，不是没做 |
| 天空光源 | 有渐变 + 光束，无明确光斑 | 参考图右上有明确逆光光斑；现在是上黄下白 |
| 上角垂叶 | 未做 | 参考图左上/右上各有叶枝伸入形成画框；HUD 卡片正好占这两个角，需先确认 HUD 避让 |
| 栈道（`drawRamp`） | 薄板 + 短支腿 | 参考图里是**分段圆木拱桥**；改成拱形会改动碰撞面，属于玩法改动，需单独一轮 |
| 火焰的"写实感" | 形状抖动 + 亮度闪烁 + 焰舌 + 光晕 | 这是 canvas 2D 的上限。再往上要**热浪扭曲**（需要逐像素后处理）和**真粒子系统**，两者都超出 canvas 绘制；Cocos 侧可以用 `ParticleSystem2D` 重做火焰，但那要先把火坑从整体绘制里拆成一个独立节点 |

### 5.2 关于"要不要改成重新立绘"

用户提过「你如果不好做，可以选择重新立绘」。这里把两条路的代价写清楚，
下一次决策不用重新讨论：

| 路线 | 做法 | 代价 | 风险 |
|---|---|---|---|
| A 继续代码绘制（当前） | 每轮改 `grove.html` 里的 `drawXxx` | 一套画法自动适配 8 个主题（只换色），改一处全关生效 | 上限就是"矢量平涂"，做到头也到不了参考图的笔触质感 |
| B 生成背景底板 + 道具精灵 | 生成 1 张无平台的场景底板 + 平台/门/坑各一套透明底精灵 | 8 个主题 × 1 张底板；切图 / 图集 / 加载 / 运行时替换都要动 | 生成的图与代码绘制的元素**光照和透视必须对齐**，否则"贴纸感"会更重 |

判断依据：现在的问题已经不是"分层不对"，是**质感**。分层、遮挡、明度骨架
都已经建起来了（§4.4）；再往 A 路走是边际递减，往 B 路走才有质变。
真要走 B，必须先定**生成图的透视与光源参数**（相机俯角、光源方位、地面线位置），
再让代码绘制的元素去对齐它 —— 反过来做必然对不上。

### 5.3 已解决
