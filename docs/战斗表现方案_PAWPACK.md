# 战斗表现方案 PAWPACK · 基于当前像素绘画级别

> 版本 v1.0 · 2026-10-20 · 对应《立项计划书》§2.2 / §2.7、《美术风格指引》§3 / §4
> 本文回答一个问题：**在「单帧静态 32px、9–11 色、零动画帧」的美术条件下，战斗该怎么演。**

---

## 一、先盘清事实：美术现在能给什么

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 静态单帧精灵 | ✅ 4 张（32×32，9–11 色） | 宠物 + 步行虫/飞虫/甲虫 |
| 动画帧（待机/走/攻击/受击/死亡） | ❌ 零帧 | 美术指引 §3 预算 ≤15 帧/只，一帧都还没画 |
| 特效素材（粒子/爆炸/拖尾） | ❌ 无 | 全靠 `Graphics` 画几何图形 |
| 角色设计感 | ⚠️ 弱 | 程序化占位，基本图元拼装 |

**结论：任何"靠一帧帧画出来的动作"在当前阶段都不可行。** 战斗表现必须建立在**零素材成本**的手段上。

---

## 二、核心结论：走「读图式战斗」，不走「演出式战斗」

### 两条路线的区别

| | 演出式战斗（需帧动画） | **读图式战斗（本作路线）** |
|---|---|---|
| 传达伤害意图 | 敌人挥爪的第 3 帧 | **地面红圈 + 圈内进度填充** |
| 传达施法意图 | 读条动画 | **半径渐涨的橙圈** |
| 打击感来源 | 命中帧的画面冲击 | **顿帧 + 白闪 + 击退 + 飘字** |
| 玩家要学什么 | 记住每种怪的动作前摇 | **学会一套几何符号**（圈=范围、菱形=弹道、线=方向） |
| 美术成本 | 每怪 15+ 帧 | **0 帧** |
| 扩展新怪 | 每只都要画 | **换个色/换个形状参数** |

### 为什么这条路在当前美术级别下是「对的」而不是「将就的」

1. **静态剪影的可辨认度 > 动画的可辨认度**。混战中 28 个东西在动，玩家反而看不清动作；高对比的静止剪影 + 明确的范围圈，读起来更快。
2. **36px 的角色画不出来动作细节**。32px 高度里画"抬手蓄力"，只能画出 2–3 个色块的位移，信息量还不如一个圆环。
3. **和《美术指引》§4 的纪律一致**：状态全靠特效层，不画新帧。这条本来就是为了"一个人撑住 6 宠同屏"。

> ⚠️ **这不是说永远不做帧动画**。宠物施法链路 6 帧（§3 预算）仍然值得做，因为那是**玩家持续盯着的焦点**。但**敌人**的帧动画优先级应该排在很后面——玩家不需要看清敌人怎么挥爪，只需要知道"它要打哪里、什么时候打"。

## 三、三条像素风硬约束（当前实现有违反）

这三条是"用静态像素图做动效"的物理限制，不遵守就会出现"糊/抖"的观感，和之前降采样糊掉是同一类问题。

### 约束 1：禁止非整数缩放

32px 贴图 × 1.3 = 41.6px。Point 采样下，像素块大小会在 1px 和 2px 之间不均匀跳变，观感是"像素颗粒在抖"。

**当前违规**：
- `EnemyManager.update()`：受击脉冲 `s *= 1 + 0.3 * hitPunch` → 最大 1.3 倍
- `PetSquad.update()`：施法 `s *= 1.28`、前摇 `1.18`、后摇 `1.28`

**修法**：
- 受击反馈**不用缩放**，改「2px 位移抖动 + 白闪」（受击最高频，最刺眼）
- 呼吸/前摇保留小幅缩放，但**压到 ≤1.12**（视觉差异小，颗粒不均不明显）
- 施法瞬间的 1.28 倍 → 改「2px 后坐力位移 + 白光爆闪」

### 约束 2：禁止精灵旋转

旋转后的像素边缘会产生锯齿和亚像素混色，和 Point 采样打架。**朝向变化只能用 `scaleX = -1` 镜像**。

**当前状态**：✅ 敌人和宠物都没有旋转（`EnemyManager` 只设 position/scale）。**保持这个约束**。

### 约束 3：所有动效位移对齐整像素

摄像机跟随、击退、浮动都要落到整数像素，否则整张图在采样时会"呼吸"。

**当前状态**：⚠️ 相机 `followLerp` 平滑、击退速度积分都是浮点。实践中影响很小（引擎会内部处理），但**屏幕震动（新增时）必须只用整数值**。

## 四、表现分级方案（全部标注美术成本）

### P0 · 现在就该有，0 帧，只改代码

| # | 表现 | 手段 | 落点 | 备注 |
|---|---|---|---|---|
| 1 | **敌人受击白闪** | 独立 Graphics 层画白色剪影，两档衰减 | `EntityRenderer.drawHitFlash()` | ✅ **已修**（原实现贴着图就不闪） |
| 2 | **命中顿帧（hitstop）** | 命中瞬间全局 `timeScale = 0.05`，持续 2–3 帧 | `GameBootstrap.update` 里拦 `dt` | 打击感的第一来源，成本几乎为零 |
| 3 | **死亡爆散** | 4–6 个菱形碎片向外飞散 + 缩小消失 | `EntityRenderer` 新增碎片池 | 替代"死亡帧"，比缩小消失爽得多 |
| 4 | **伤害飘字** | 命中位置冒出数字，0.4s 上浮消失 | `EntityRenderer` + Label 池 | 让玩家知道"打中了、打多少" |
| 5 | **前摇圈进度填充** | 圈内扇形/圆形从 0 填到满 | `EntityRenderer.drawTelegraphs` | **现有圈只画轮廓，玩家不知道还剩多久** |
| 6 | **玩家受击反馈** | 屏幕红闪 + 整像素震屏（±3px） | 新增 `ScreenFx` | HP 只有 6，每次受伤都要"有感觉" |

| # | 表现 | 手段 |
|---|---|---|
| 7 | **宠物施法三段视觉语言** | 前摇=金环收缩到宠物身；施法=白光爆闪+后坐力；后摇=整体变暗+缩小 |
| 8 | **弹道拖尾** | 每颗子弹留 2–3 个渐隐残影（纯几何） |
| 9 | **半饿金环**（CR-004 招牌） | 宠物身上套金环 + 5% 缩放脉冲（已有 `powerMultiplier` 挂钩点） |
| 10 | **怪窝激活演出** | 激活瞬间一圈冲击波扩散 + 地面闪光 |

## 五、几何符号语言（统一视觉语法，必须先定死）

这是"读图式战斗"的地基。玩家学会一次，终身受用。

| 几何 | 含义 | 颜色 | 状态 |
|---|---|---|---|
| 实心圆环（渐变填充） | **伤害将要发生** ← 最危险 | 红 `#FF5252` | 已有轮廓，**缺填充** |
| 半径渐涨的圆环 | **敌方正在读条施法** | 橙 `#FFB454` | ✅ 已有 |
| 收缩的金环 | **己方宠物正在蓄力** | 金 `#FFD700` | ⚠️ 现有是固定半径圆，应改收缩 |
| 菱形 | 弹道 / 拾取物 | 米黄 `#FFE9A8` / 绿 `#6BCB77` | ✅ 已有 |
| 细线段 | 位移方向 / 冲刺轨迹 | 白 / 同施法者 | 未使用 |
| 菱形碎片群 | 死亡 / 击碎 | 本体主色 | 新增 |

**铁律**：**红 = 会伤到你，橙 = 对方在准备，金 = 你在蓄力，绿 = 可拾取**。四种颜色承担全部"危险等级"信息，不依赖任何动画。

> 这条同时解决了 32px 精灵在混战中"看不清是什么"的问题——玩家根本不需要看清怪长什么样，只需要看清地上那个圈是什么颜色。

## 六、当前发现的 bug（已修 / 待修）

### ✅ 已修 1：背景草地盖住了所有实体（致命，跑起来直接看不到怪）

`GameBootstrap.buildWorld()` 的节点创建顺序是
`玩家 → 敌人池 → 宠物 → 背景 → 特效层`，而 2D 绘制优先级 = `children` 遍历序
（`Batcher2D.walk()` 源码已核实）。**背景是一整块 2400×1350 的实心草地，排在敌人之后
`addChild`，于是把玩家、敌人、宠物全部盖住**——直接跑看到的就是一片空地。

`z` 值救不了：`setPosition` 的 z 不参与 2D 排序。之前误以为靠 z 分层是安全的。

**修法**：`BackgroundRenderer` 构造时 `node.setSiblingIndex(0)` 强制置底。

### ✅ 已修 2：有贴图后，敌人受击白闪完全消失

`EntityRenderer.drawEnemyBodies()` 的白闪循环判据是 `needProcBody(e)`，而
`needProcBody()` = `e.active && !e.hasSprite` —— **精灵一旦加载成功就返回 false，白闪整段被跳过**。
后果：敌人挨打只剩 30% 缩放脉冲，而缩放在 Point 采样下还会让像素颗粒抖动。

**修法**：白闪独立成 `drawHitFlash()`，判据只看 `hitPunch`，与有没有贴图无关；
半径取贴图显示宽度的 0.72（略小于本体），让贴图自带的 1px 墨色描边露在白闪外侧——
观感是「整只怪闪白但轮廓仍在」而不是「变成一个白多边形」。两档（强闪/余晖）各一次 `fill`，
仍合并进同一 mesh，不影响 DrawCall。

### ⚠️ 待修：施法/前摇的缩放倍率超标

`PetSquad` 的 `1.28`、`1.18`、`1.28`，以及 `EnemyManager` 受击的 `1.3`，
在 Point 采样下会产生像素颗粒抖动（见 §三约束 1）。属于手感调参，需看过实机效果再定，
建议收敛到 ≤1.12，或改用整像素位移。

## 七、同屏密度上限（这是美术决定的硬约束）

按当前参数推算：

| 项 | 值 |
|---|---|
| 相机视野 | 960 × 540（`CAMERA.viewHeight = 540`，16:9） |
| 敌人显示尺寸 | 64 × 64 |
| 视野内最多并排 | 15 只（横向） |
| 当前 `BATTLE.maxAlive` | **28** |
| 28 只占屏面积比 | **≈ 22%**（纯包围盒），实际视觉重叠更严重 |

**判断**：28 只在 64px 尺寸下会开始"糊成一片"。三种颜色（绿/红/蓝）还能区分，但**玩家会分不清哪个是残血、哪个刚刷出来**。

**建议**：
- Day 1–2 保持 28（性能验证用），**Day 3 手感调优时降到 16–18**
- 用「**少而清晰**」替代「多而华丽」：18 只怪 + 明确的攻击圈，比 28 只怪糊成一片更有压迫感
- 如果要保持 28，就必须依赖 §五 的颜色语法，让"红圈"成为唯一需要看清的东西

## 九、建议的落地顺序

1. **修白闪 bug**（§六）—— 不修的话，现在这版贴着图玩，打击感是零
2. **P0 的 1/2/5**（白闪 + 顿帧 + 前摇圈填充）—— 这三个做完，战斗手感会有质变，且全部 0 美术成本

4. **Day 2 的 3 宠 + 半饿金环**（P1-9），这是 CR-004 的招牌
