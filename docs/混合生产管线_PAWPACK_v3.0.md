# 混合生产管线 · PAWPACK v3.0

> 版本：v3.2 ｜ 2026-10-21（v3.2 补 §10 六只全量立绘与姿态差异规范 + §11 宠物行为系统）
> 触发：用户反馈「感觉达不到吸引玩家的级别 / 我需要商业化的游戏UI界面 / 最好有动感 / 现在就像贴上去的」
> 上一版：`docs/UI_概念设计_PAWPACK_v2.0.md`（v2 全矢量方案，仍然有效，作为**规格**的依据）

---

## 0 · 结论先行

**「像贴上去的」不是参数没调好，是生产方式的天花板。** 矢量精绘能做到「尺寸精确、可切九宫格、可换文字、多分辨率」，但它的质感上限就是**精致的扁平插画**——没有景深、没有环境光污染、没有材质。继续调参数只会得到「更精致的贴纸」。

**解法是分工，不是二选一：**

| 层 | 生产方式 | 为什么不能换 |
|---|---|---|
| 背景插画 | **AI 出图** | 景深 / 体积光 / 环境光污染 / 材质笔触，矢量做不出来 |
| 角色立绘 | **AI 出图（透明底，单只）** | 动态姿势 / 副运动 / 衣褶毛发，矢量要画几千个路径还不一定对 |
| UI 控件 | **矢量精绘** | 必须能切九宫格、换文字、出 4 态、多分辨率。AI 出图的尺寸不可控、文字必糊、边界不可测 |
| 动感 | **引擎实现** | 静态图永远只能「暗示」动，不能「有」动 |

一句话：**AI 给质感和氛围，矢量给精度和可维护性，引擎给动感。**

## 1 · 「像贴上去的」的六个技术成因

逐条可验证。任何一条不解决，画面就还是平的。

| # | 成因 | 症状 | 解法 |
|---|---|---|---|
| 1 | **只有一个深度层** | 天空、山、草地、房子、角色、UI 全部「齐平」，没有前景 | 必须有 **前景层**：大尺寸、虚化、出画的草叶/花瓣压住画面下缘 |
| 2 | **没有环境光污染** | 角色是纯色块，草地上不该这么干净 | 草地上的角色腹部要吃绿色反弹光；天空下的顶部要吃冷蓝。**任何物体都不该只有自身固有色** |
| 3 | **光照方向不统一** | 每只宠物各打各的光 | 全场**单一主光**（左上暖光），所有投影朝右下，包括 UI 控件 |
| 4 | **没有接触阴影分层** | 只有一层淡椭圆 | 三层：紧贴地面的深色硬阴影（AO）+ 中层软阴影 + 大范围方向投影 |
| 5 | **主体与背景没有分离手段** | 角色边缘和背景糊在一起 | **边缘光（rim light）**：主体轮廓朝光侧一道亮边，让主体「跳」出来。v2 的 rim alpha 只有 .38，几乎看不见 |
| 6 | **没有动作** | 六个站姿，像立牌 | 动作线（C 形）+ 重心偏移 + 副运动（毛发/尾巴滞后）+ 地面交互（扬尘/残影） |

**前五条是「画面组织」，第六条是「动」。** 后一条单独在 §5 展开——因为它是唯一**画不出来**的。

## 2 · 三层分工与坐标系

### 2.1 为什么角色层必须单独出

这是本轮最重要的发现，用一次失败验证出来的：

> 第一版我把「需求气泡 + 三颗飘心 + 手指光标」按 AI 背景里的兔子位置摆好（估的 x 20–115, y 185–275）。渲染出来一看：**兔子实际在 y > 330**（缩略图里我误把 display 坐标当成了原图坐标），只露出两只耳朵，身体正好被底部 HUD 吃掉。气泡落在空草地上，手指悬在路牌旁边，读成一个白色胶囊——**比原来的贴纸感更糟**。

**规则：AI 出整张场景 = 角色坐标随机 = 所有「贴着角色的 UI」必然落空。**

因此：

```
图层栈（从下到上）
├─ L0  背景插画      AI 出，1024 宽起，不含任何角色
├─ L1  中景道具      AI 出（可含），或矢量
├─ L2  角色          单只 AI 出（透明底），坐标由我按栅格定
├─ L3  角色附属 UI   需求气泡 / 飘心 / 手指 / 伤害数字 —— 锚在 L2 坐标上
├─ L4  HUD          矢量，绝对安全区
└─ L5  前景层        虚化草叶/花瓣，压 L0–L4 全部
```

**只有 L2 的坐标是我定的，L3 才敢贴上去。**

### 2.2 安全区约定（1280×720 基准）

| 区域 | 坐标 | 规则 |
|---|---|---|
| 顶部信息带 | y 0–76 | 只放横条类控件（标题 / 今日目标 / 设置） |
| 左/右竖边 | x 0–20 / x 1260–1280 | 留白 |
| 底部 HUD 带 | y 604–720 | 只放 HUD。**背景插画在此区域内不得有重要内容** |
| 主内容区 | y 76–604，x 20–1260 | 场景 + 角色。角色脚底必须 ≤ 604 |

> 出背景图时必须把这四个数值写进提示词：`keep the bottom 1/6 empty grass with no important objects`。

## 3 · AI 背景出图规范

### 3.1 提示词骨架（变量槽位）

```
{风格锚点} 2D mobile game {场景类型} background illustration,
{时段与色调},
{远景}, {中景}, {近景},
{前景层描述},
单主光 {方向} + {色温},
STRONG DEPTH LAYERING: distant {低对比/去饱和}, middle ground {清晰/高饱和},
FOREGROUND out-of-focus {大尺寸物体} framing the bottom corners,
clear empty space reserved: top {x} and bottom {y},
ABSOLUTELY NO text, no letters, no numbers, no user interface, no buttons, no icons, no watermark
```

### 3.2 三条硬约束

1. **不含角色。** 角色一旦进背景，L3 的锚点就废了。要角色就单出。
2. **底部 1/6 必须是空草地。** 不写这句，AI 一定把前景花堆到画面最下沿，HUD 压上去就是两层抢。
3. **构图重心偏上或偏侧。** 居中构图会被 HUD 切成上下两半。

### 3.3 已验证

| 图 | 文件 | 结论 |
|---|---|---|
| 家园背景（含角色，反面教材） | `client/shots/_ai-bench/2D_mobile_game_home_screen_bac_*.png` | 景深 / 光照 / 氛围全部达标，但**角色不可用**，且偏黄昏（与「高明度白天」纪律冲突） |

## 4 · AI 立绘出图规范

### 4.1 必须写进提示词的设计规格

把 v2 的角色设计翻译成 AI 能懂的视觉描述，**数值不能省**：

| 项 | 值 | 提示词写法 |
|---|---|---|
| 头身比 | 头占身高 **54–60%** | `huge head about 56% of total height` |
| 眼睛 | 占脸宽 **1/3** | `enormous round eyes about one third of face width` |
| 眼睛三要素 | 竖椭圆 + 双高光 + 下缘淡蓝反光 | `two catchlights per eye plus pale blue rim reflection at lower edge` |
| 描边 | 厚，每只自身主色的深暖调 | `thick warm dark-brown outline` |
| 明暗 | 三阶硬边，禁渐变 | `three-tone hard-edged cel shading only no airbrush` |
| 主光 | 左上 | `single warm key light from upper left` |
| 边缘光 | 左上轮廓 | `crisp bright rim light along the upper-left silhouette` |
| 接地 | 脚下硬阴影 | `carved contact shadow under the feet` |

### 4.2 已验证

| 图 | 文件 | 结论 |
|---|---|---|
| 砂糖·奔跑立绘 | `_ai-bench/2D_game_character_sprite__chib_*.png` | **质感与动感全面超过矢量版**：C 形动作线、前爪伸出、后腿蹬地、尾巴甩、围巾飘、速度线、扬尘、脚下硬阴影 |

**但同时暴露四个偏差**（必须迭代修正，不能直接用）：

1. 头占身高只有约 **45%**（规格 56%）→ 读成「小猫咪」不是「Q 版大头」
2. 额头多出深色斑纹（v2 规格是纯奶油 + 橘耳）
3. 眼睛不够大，没有下缘淡蓝反光
4. 四足奔跑的腿部结构偏写实，不是蛋形身体的 Q 版结构

→ **迭代方式**：image-to-image，把这张作 `image1`，提示词只写修正项 + `input_fidelity` 调高。比重新文生图省话也稳。

### 4.3 六只的一致性怎么保证

AI 最不可靠的就是「同一套角色画六只」。三条办法，按可靠性排序：

1. **同一段风格锚点逐字复用**（必须做）
2. **image-to-image 传递风格**：第一只定稿后，作 `image1` 出后续五只，`input_fidelity` 0.6–0.75
3. **最后统一后处理**：六只一起过一遍描边加粗 + 三阶色阶量化，把 AI 的细微笔触差异压平

> 现实预期：**AI 出的六只，一致性大概到 70%。** 剩下的 30% 必须靠人工精修或矢量重绘补。所以六只正式立绘仍然建议「AI 出底 + 矢量修规格」，不是纯 AI。

## 5 · 动感：静态图给不了，必须进引擎

**用户说「最好有动感」，这是本轮最该讲清楚的一件事：概念图是静态的，它永远只能「暗示」动，不能「有」动。** 真正的动感在引擎里，由动画参数决定。

我做的是**给引擎的动画规格**（不写运行时代码，这是引擎专家的活）。

### 5.1 待机层（角色活着的最低成本）

| 元素 | 参数 | 时长 / 缓动 |
|---|---|---|
| 宠物呼吸 | `scaleY` 1.00 → 1.02 → 1.00 | 2000ms，`easeInOutSine`，六只各错开 300ms 相位 |
| 耳朵抖动 | 随机 `rotate` ±6°，间隔 4–7s | 180ms，`back.out(2)` |
| 眨眼 | 眼睑 `scaleY` 1 → 0.05 → 1 | 120ms，每 3–6s 随机 |
| 尾巴摆动 | `rotate` ±10° | 1400ms，`easeInOutSine` |

**关键：六只的相位必须错开。** 同步呼吸 = 六个机器，错开才是「一窝活的」。

### 5.2 交互反馈层（点击的手感）

| 元素 | 参数 | 时长 / 缓动 |
|---|---|---|
| 按钮按下 | `scale` 0.94 | 120ms `easeOut` |
| 按钮回弹 | `scale` 1.04 → 1.00 | 100ms `back.out(3)` |
| 卡片弹入 | `scale` 0.86 → 1.00 + `alpha` 0→1 | 220ms `back.out(2)` |
| 数值增加 | 旧数字上滑 18px 淡出 / 新数字自 -18px 滑入 | 240ms `easeOutCubic` |
| 飘心 | `scale` 0.6→1.0（80ms）→ 上飘 60px + `alpha` 1→0（820ms） | 总 900ms |
| 需求气泡 | `scale` 0→1.15→1.00（260ms `back.out`），之后每 2800ms 上下浮动 3px | — |

### 5.3 视差层（「贴纸感」的终极解法）

**视差是让 UI 与场景产生空间关系的唯一手段。** 手指在屏幕上滑动时：

| 层 | 位移系数 | 说明 |
|---|---|---|
| L5 前景草叶 | **1.15×** | 比背景快，产生「穿过」的错觉 |
| L4 HUD | **0×** | 完全固定 |
| L3 角色附属 | 跟随 L2 | — |
| L2 角色 | **1.00×** | 基准 |
| L0 背景 | **0.86×** | 比角色慢，产生纵深 |

位移幅度：横向 ±12px 封顶。超过会晕。

### 5.4 转场

| 场景 | 动作 | 时长 |
|---|---|---|
| 家园 → 战斗 | 镜头向小屋门口推近 `scale` 1.0→1.35 + 白闪 `alpha` 0→0.6→0 | 420ms + 180ms |
| 战斗 → 结算 | 画面轻微上推 40px + 半透明遮罩 `alpha` 0→0.55 | 300ms |
| 结算数据行 | 逐行淡入，间隔 90ms | 每行 200ms |

## 6 · 矢量 UI 吃环境光的四条规则

把 v2 的纯色控件直接贴到 AI 插画上，**会比原来更「贴」**——因为插画层次丰富、控件层次为零，对比之下控件就是一张纸片。

| # | 规则 | 具体参数 |
|---|---|---|
| 1 | **透** | 控件底色 `alpha ≤ 0.92`，让插画的暖色透上来。**不要用 `#FFFFFF` 纯白** |
| 2 | **投影方向统一** | 全部朝右下（主光在左上），`rgba(74,44,24,.24)`，偏移 `+2,+6` |
| 3 | **顶部内侧高光** | 上沿 2.4px 暖白 `rgba(255,255,255,.55)`，读成「被光打到的厚度」 |
| 4 | **渐变雾代替实心条** | 底部 HUD 用 `alpha 0 → .80` 的渐变，像空气。实心条压在草地上是最典型的「贴」 |

### 6.1 已验证

`client/shots/concept3-1-家园-AI混合.png` —— AI 背景 + 矢量 HUD，融合度合格。
**试错一次**：第一版底部雾用了 148px 高、`.94` 实心，把整个前景花层压成一片米色，景深白做了。收到 116px / `.80` 才对。

| 事项 | 单位成本 | 备注 |
|---|---|---|
| AI 出图（单张，high） | 5–10 credits | 出图即计费，不看结果好坏 |

| 六只 + 三关背景 | 约 **50–70 次出图** | 这是完整一轮的量 |

**生产节奏建议：**

```
第 1 步  定 1 只立绘到「商业化达标」        ← 现在卡在这

```

**不要在第 1 步没定稿前批量出图。** 角色风格一旦定错，六只全部返工。

## 9 · 角色与环境比例规范

> 起因：用户第 5 条「注意宠物在战斗中的比例要符合大小」。
> 诊断结果：**宠物的绝对尺寸是对的，错的是它的三个配套值。**

### 9.1 双基准对照表（Steam 横屏）

**设计基准 = 1920×1080**（Steam 绝对主流）。现有的 1280×720 图按 ×1.5 换算即可，因为全部是矢量 + 高分辨率贴图，缩放无损。

| 项目 | 1280×720 | 1920×1080 | 推导依据 |
|---|---|---|---|
| 战斗·宠物高 | **120** | **180** | 占屏高 16.7%。见 §9.2 依据 1 |
| 家园·宠物高 | 160–180 | 240–270 | 家园是"看角色"的场景，比战斗大 1.4 倍 |
| 图鉴格·宠物高 | 96 | 144 | 占格子 80%，四周留 10% 内边距 |
| HUD 头像·宠物高 | 40 | 60 | 战斗尺寸的 1/3 |
| 场景远景·宠物高 | 128 | 192 | 用作视差背景里的"远处的宠物" |
| **平台厚度** | **18** | **27** | 宠物的 1/6.7。见 §9.2 依据 2 |
| 杂兵（史莱姆） | 46 | 69 | 宠物的 1/2.6 |
| 精英怪 | 75 | 113 | 宠物的 1/1.6 |
| BOSS | 300–360 | 450–540 | 宠物的 2.5–3 倍 |
| 弹道物品（雪球） | 28 | 42 | 宠物的 1/4.3 |

### 9.2 四条推导依据（每个数字都要能回答"为什么"）

**依据 1 · 可辨识下限**
把立绘缩到各档尺寸实测（见 `client/shots/_ai-bench/_size-test.png`）：
- 240 / 180 / 128 / 96 px：双高光 + 下缘淡蓝反光全部可读
- 60 px：仍能认出耳朵/眼睛/尾巴，但高光糊成一点
→ **战斗尺寸不能低于 96（1280 基准）**，取了 120 留 25% 余量。

**依据 2 · 平台的视觉重量不该超过角色**
原平台厚 26，宠物 120 → 比值 **4.6 : 1**，读成"厚水泥板"，角色的脚像踩在桩子上。
商业平台跳跃的参考比值是 **6–8 : 1**（平台是"可以踩的地面"，不是障碍物）。
取 18 → **6.7 : 1**。

**依据 3 · 跳跃空间**
单次跳跃高度应为 **1.5–2 个身位**。宠物 120 → 需要 180–240px 的垂直空间。
本次修完，A 台顶 510 到 B 台顶 414 = 96px（0.8 身位）——**草甸关是用坡走上去的，不需要跳，可以接受**。
但**后续做跳跃关（高塔）时，平台垂直间距必须 ≥ 180px（1080 基准 270px）**。

**依据 4 · 敌人阶梯**
杂兵必须明显小于主角，否则玩家分不清"我是谁"。1/2.6 是实测舒服的比值；
BOSS 要到 2.5–3 倍，才读得出"这是另一个量级"。

### 9.3 本次修掉的三个比例 bug

| # | bug | 症状 | 修法 |
|---|---|---|---|
| 1 | 平台厚 26（4.6:1） | 读成"厚水泥板"，角色站上去像踩桩子 | 26 → **18**（6.7:1） |
| 2 | 地平线 452，下方 268px（**37% 屏**）全是空草地 | 游戏区被压成 y300–452 的一条缝，宠物占 79%，跳不起来 | 地平线下移 84 → **536**，整条路同步下移 |

云改成**三层**（上层 α.94 / 中层 α.50–.62 / 贴地平线 α.34），空气透视才成立。

### 9.4 Steam 多分辨率适配

| 项 | 值 |
|---|---|
| 设计分辨率 | 1920×1080 |
| 主适配 | 16:9 |
| 需兼容 | 16:10（1920×1200）、21:9（2560×1080） |
| 适配策略 | **高度优先**（`fitHeight` / Unity Match=1）：UI 永远是 1080 逻辑高，左右多出的部分由场景延伸填充 |
| 安全区 | 左右各留 **64px**（1080 基准）给 21:9 与窗口化边框 |
| 上下安全区 | 顶部 76px / 底部 116px 只放 HUD，不放场景关键内容 |

> **为什么高度优先**：Steam 玩家显示器比例杂（16:9 / 16:10 / 21:9 / 超宽）。
> 宽度驱动的适配会在 16:10 上把上下切掉，导致 HUD 被裁。
> 高度驱动只会让左右多出场景，永远不裁关键信息。

## 10 · 六只全量立绘：姿态差异化

### 10.1 第一轮就踩的坑：姿态模板本身就是同质化的来源

拿砂糖当锚点出年糕，第一版技术上完全合格，但一眼看过去**它和砂糖是同一只**。原因不是配色、不是画风，是：

> 六只都用「正面站正 + 一只爪抬起 + 领巾 + 头顶呆毛」，这就是**姿态模板**。
> 玩家看到的不是六个角色，是六次同一个角色的换色。

这和 v2 矢量版被判"同质化"是同一个病，只是换了个层面复发。**同质化不是靠加配件解决的，是靠打破模板解决的。**

### 10.2 定规：画风统一，姿态不统一

商业做法（宝可梦、动森）都是这样：**共用画风锁，各用姿态语言**。姿态的差异本身就在说明它是什么角色、它会什么技能。

| 宠物 | 姿态语言 | 说明的技能 | 取景 |
|---|---|---|---|
| 砂糖 | 站立，一只爪抬起打招呼 | 基准站姿（溜溜球） | 正面 |
| 年糕 | 坐姿前倾，尾巴卷成螺旋 + 摇尾残影 | 在门口等你 / 音波 | 正面 |
| 团子 | 蹲坐，口含整颗果、颊袋鼓成两个球 | 滚地雷 | 正面，最宽 |
| 雪团 | 腾空蹬展，大后脚，一耳折 | 三连跳 | 正面，最瘦 |
| 豆奶 | 趴卧，半眯眼，尾巴甩苍蝇 | 冲撞 / 最懒 | 正面，最扁 |
| 星屑 | 站立，巨尾甩向一侧，周围星尘 | 影分身 / 传说 | 正面，头最大 |

**必须守的一条**：六只**都朝正面**。侧身看似更有动感，但图鉴格、HUD 头像、对话立绘全都是正面取景，一只侧身就要另出一套正面图 —— 成本翻倍。

> 星屑第一版就是侧身回望，结果它是六只里**唯一头小眼小的**（侧脸的三分之四会压缩眼部面积），
> 传说位反而最不吸引人。改回正面 + 巨尾从身后甩出，头和眼睛才画得够大。**这个坑矢量版也踩过一次。**

### 10.3 验收记录（六只全部达标）

|---|---|---|---|---|

| `tuan-zi-ham@v1.png` | 927×1163 | ~56% | 极宽球形 / 双颊袋 / 无尾 | ✓ |

**归一化方式**：统一**高度**归一化、不统一宽度。六只的"身高"在游戏里没有意义（都是宠物），
差异应该体现在**胖瘦**上 —— 仓鼠变宽、雪团变窄，体型梯度才是真的。
若统一宽度，六只会被拉成一样宽的方块，体型差异全被抹平。

### 10.4 ⚠️ 品红键控的两个硬坑

**坑 1：`background:"transparent"` 参数不可用。**
第一次要求透明底，AI 把"透明"**画成了灰白棋盘格底纹**，进引擎就是一块布。
必须走「纯品红 `#FF00FF` 出图 → 程序键控」。

**坑 2：AI 不保证真的输出纯品红，阈值不能写死。**

六只里有四只实际渲染成 `rgb(215,50,142)` 的**暗品红**（score = min(r,b)−g = 92），
而固定阈值 `LO=24 / HI=150` 会把 92 判成"半透明过渡带"，映射出 alpha ≈ 0.54 ——
整张背景留一层淡紫，包围盒撑满全图 1024×1536，**看起来像被加了一圈边框，实际是背景没键掉**。

修法：**阈值由实测背景色反推**。`sampleBg()` 取四边一圈像素中位数作基准，再令

```
LO = score0 × 0.50
HI = score0 × 0.78
```

系数依据：背景 score0=92 → LO=46 / HI=72，而粉彩角色的粉色内耳 score≈28 安全留在 LO 以下；
纯品红 score0=255 → LO=128 / HI=199，同样成立。若 score0 < 60 说明底色被洗掉，**直接报错，不猜**。

## 11 · 宠物行为系统

> 起因：用户第 3 条「这些动物在场的话，有自己的特色，比如能自己动，具有一定的动效，摸的时候也有动作反应」。
> 交付图：`client/shots/concept4-动效分解.png`；实现：`client/concept/concept4-motion.js`。

### 11.1 核心判断：性格差异不是长相，是"同一个输入的不同反应"

同一根手指摸下去，六只必须给出六种不同回应。这才是"有性格"。
如果六只都是「轻轻跳一下 + 冒一颗心」，那它们就是同一个宠物换了皮。

| 宠物 | 性格设定 | 被摸的反应 | 变换参数（引擎可执行） |
|---|---|---|---|
| 砂糖 | 别扭，先装不在乎 | 先愣 100ms，再歪头贴向手 | `rot +7.4°` / `scaleY 0.97` / `scaleX 1.03` |
| 年糕 | 你不摸它它就凑过来 | 头往上顶，尾巴转速 ×3 | `dy −7px` / `scaleY 1.05` / 摇尾弧×4 |
| 团子 | 被摸就整只倒过去 | 颊袋抖一下，整个人倒向手 | `rot +11.5°` / `scaleX 1.06` / `scaleY 0.94` |
| 雪团 | 一点就炸的那种活泼 | 耳朵先弹，整只跳起来转半圈 | `dy −30px` / `rot −3.4°` / 影子缩至 0.67 |
| 豆奶 | 懒得理你，但尾巴诚实 | 睁一只眼看你，然后继续睡 | `rot +1.1°` / 几乎不动 / `Zzz` 缩小 / 尾摆 2 次 |
| 星屑 | 每次反应都不一样（传说位） | 眯眼笑，星尘炸开一圈，分身一起蹭 | `rot −4.6°` / `dy −4px` / 星尘爆发 10 颗 |

**反例要记下来**：豆奶"几乎不动"是**故意的**。六只里必须有一只反应很小 ——
全都在跳的话，玩家会累，而且"懒"这个性格就没了。**差异化包含"更少的动作"。**

### 11.2 三层动画栈（必须分三层，否则会打架）

| 层 | 触发 | 内容 | 参数 | 打断规则 |
|---|---|---|---|---|
| **L1 呼吸** | 常驻 | `scaleY 0.985↔1.015` + 头部上下 1.5px | 周期 **2800ms**，六只相位错开 **300ms** | **永不打断** |
| **L2 自主行为** | 随机 | 位移 / 旋转 / 挤压拉伸 / 残影 | 间隔 **6000–14000ms**（泊松分布） | 被 L3 覆盖 |
| **L3 响应** | 玩家点击 | 上表的六种反应 | 预判 **90ms** → 反应 **320ms** → 回落 **280ms** | 最高优先级 |

**为什么 L1 必须独立且不可打断**：呼吸是"活着"的最低信号。任何动作（包括摸的反应）都不能把
呼吸关掉再打开 —— 会读成"卡了一下"。正确做法是**三层叠加变换**，不是状态机切换。

**为什么相位必须错开 300ms**：六只同步呼吸 = 六个机器。这一条比任何单只的精修都重要。

### 11.3 自主行为：每只三个专属动作

| 宠物 | 动作 A | 动作 B | 动作 C（带位移） |
|---|---|---|---|
| 砂糖 | 追自己尾巴原地转一圈 `2600ms` | 舔爪抹脸 `1800ms` | 跳上房顶 `3000ms` |
| 年糕 | 原地转两圈再坐下 `2200ms` | 竖耳听声音 `1200ms` | 追球跑过院子 `3200ms` |
| 团子 | 往嘴里塞东西、颊袋鼓起 `1600ms` | 滚一圈 `2000ms` | 蹭食盆 `1400ms` |
| 雪团 | 跺后脚 `800ms` | 耳朵转方向 `1000ms` | 三连跳横穿院子 `2100ms` |
| 豆奶 | 甩尾赶苍蝇（常驻循环） | 打哈欠→趴下 `2400ms` | 慢慢挪到有阳光的地方 `4000ms` |
| 星屑 | 尾巴扫过带星尘 `1600ms` | 原地消失/出现在别处 `1400ms` | 绕着院子飘一圈 `3400ms` |

### 11.4 ⚠️ 单帧立绘做不到「真走路」，必须选路线

这是本轮最重要的技术约束，不写清楚会在实现阶段返工：

- **单帧静态立绘能做到**：位移、整体倾斜摇摆、挤压拉伸、残影、透明度
- **单帧立绘做不到**：真实走路循环（腿交替）。腿不动却在平移 = **滑步**，比不动还糟

两条路线：

| 路线 | 做法 | 成本 | 风险 |
|---|---|---|---|
| ① 出行走帧 | 每只再出 2–4 帧行走姿态 | **+12–24 张图**，且帧间一致性 AI 只有约 70% | 高 |
| ② **蹦跳式移动**（推荐） | 跳跃位移 + squash/stretch + 落地挤压，完全不画腿 | **0 张额外图** | 无 |

**选 ②**。理由：① Q 版风格里蹦跳比走路更贴（仓鼠是滚的、兔子是跳的、猫是轻盈跳的）；
② squash/stretch 程序就能做，一帧图够；③ 省下的 12–24 张图预算应该花在**战斗背景**上，那才是玩家看得最久的东西。

移动实现规格：
```
起跳   squash: scaleY 0.88 / scaleX 1.10        80ms  ease-out
腾空   translate 抛物线，最高点 dy −38px        320ms  linear（水平）/ ease-out（垂直）
落地   squash: scaleY 1.12 / scaleX 0.92        90ms  ease-in
回弹   scale → 1.0                              140ms  back.out(2.4)
落地扬尘  6 个小圆向外扩散 + 淡出                260ms
```

### 11.5 连续摸的递进（让玩家愿意反复摸）

每次摸的反应都一样 = 第三次就不想摸了。反应必须**随亲密度递进**：

| 累计摸的次数 | 反应 | 目的 |
|---|---|---|
| 第 1 次 | 表中对应的基础反应 | 给出反馈，证明"能点" |
| 第 3 次 | 基础反应 + 主动凑向手指 | 让玩家觉得"它喜欢我" |
| 第 5 次 | 翻肚子（特殊姿态，需单独一帧）或绕圈 | 给一个**只在这个时刻出现**的稀有反应 |
| 每日上限 | 30 次后进入"困了"状态，反应减弱 | 防止刷亲密度，也是叙事（它累了） |

> 第 5 次的"翻肚子"是唯一需要**额外出一帧图**的地方，六只共 6 张。
> 这一帧建议做成**单独资源**（`<name>-belly@v1.png`），不进图集，只在亲密时刻加载。

### 11.6 点击区与判定的工程约定

| 项 | 值 | 依据 |
|---|---|---|
| 触摸判定区 | 包围盒外扩 **12px** | 视觉轮廓不等于容易点到，尤其雪团很窄 |
| 最小点击区 | **88×88**（1080 基准 132×132） | 触屏下限；Steam 鼠标可放宽到 64×64 |
| 判定优先级 | 立绘本体 > 需求气泡 > 场景建筑 | 宠物在建筑前面时必须优先选中宠物 |
| 长按 | 200ms 后进入"持续摸"，反应循环但间隔加大到 900ms | 防连点刷爆动画 |
| 反馈延迟上限 | **100ms** 内必须有第一帧变化 | 超过就会被感知为"没反应" |

### 11.7 工程实现的两条纪律

1. **不许用序列帧做这些动作**。上面的全部是**程序变换**（位移/旋转/缩放/透明度），
   序列帧会把 6 只 × 十余个动作变成几百张图，图集装不下、内存吃不消，改一个参数要重出图。
2. **变换必须绕脚底中点**（`anchorY = 1.0`），不能绕图片中心。绕中心旋转读成"飘在空中"，
   绕脚底才读成"站着的身体在倾"。六个立绘已统一 `anchorX 0.500 / anchorY 1.000`。

## 12 · 背景与角色的分层铁律（主界面 v2 才立住的一条）

### 12.1 一句话

> **AI 背景里不能有任何角色。角色必须单独出透明底，由程序按锚点合成。**

### 12.2 为什么（已经踩过一次，代价是整版返工）

concept3-1 那版让 AI 直接出了"有六只宠物的家园"。结果：

- 按缩略图估兔子在 `y 185–275`，实际 `y > 330`，**差 140px**
- 于是挂在兔子头上的需求气泡落在空草地上，手指悬在路牌旁边，读成一个白色胶囊
- **比原来要修的"贴纸感"更糟**

结论：**角色锚定的 UI，前提是角色坐标可控。** AI 出整张场景 = 坐标随机 = 所有贴着角色的 UI 都会落空。

### 12.3 三层职责（不可混）

| 层 | 谁产出 | 绝不能做的事 |
|---|---|---|
| L0 背景 | AI | 不能含任何角色（连蝴蝶、鸟、虫子都不行——它们会成为"角色锚定 UI"的干扰源） |
| L1 角色 | AI（透明底） | 不能画进背景 |
| L2 控件 | 矢量 | 不能画插画 |

### 12.4 背景出图的 prompt 结构（已跑通，一张就过）

1. **先锁画风**："Keep this EXACT storybook style, palette, lighting, camera angle"
2. **逐个点名移除**："no cat on the roof, no rabbit, no hamster, no puppy, no ox, no fox, no butterfly, no birds"
3. **交代地面怎么补**："where they stood, show only clean empty grass / dirt path / wooden decking, with a soft contact shadow left on the ground only"
4. **逐个点名保留**：房子、烟囱、路牌、工作台、炉子、垫子、栅栏、花圃
5. **收尾强约束**："COMPLETELY EMPTY environment with zero living creatures, no text, no UI, no watermark"

### 12.5 坐标必须用颜色分割量，不能读栅格图

肉眼读栅格参考图换算，**误差 40–70px**，徽标会悬在草地上。

正确做法（`client/concept/_probe2.js`）：

1. 按色相筛出目标物（黑锅=低亮度 / 木门=中棕 / 屋顶=红 / 垫子=粉）
2. **加 ROI 限制**在合理区域（否则整张图的暖色草地会污染匹配）
3. 取**列峰 x + 行峰 y**，连续块取**连通域重心**

实测结果：大黑锅重心 `(650,360)`、木门列峰 `x=475`、工作台盒 `[140,260]-[399,429]`、路牌 `x=223`。这套方法对战斗场景同样适用。

### 12.6 绘制顺序（两个会立刻翻车的顺序错误）

| 错 | 症状 | 正 |
|---|---|---|
| 氛围雾画在角色**之后** | 直接把宠物下半身刷白，读成"腿被雾吃了" | 雾在角色之前 |
| 底部 Dock 顶 > 宠物 footY | 脚被 Dock 切掉 | `footY ≤ dockTop − 18` |

### 12.7 静态图不画指针

试了三种画法，全部失败：

- 竖直压在头顶 → 读成"头上插了根棍子"（和呆毛/耳朵重叠）
- 斜压脸颊 → 读成"脖子上挂了个白胶囊"
- 加点击波纹 → 波纹能看见，手指还是读成异物

根因：**矢量手指和 AI 立绘不是同一套光照与笔触**，放在一起就是异物。静态图只负责证明"有反馈"（反应泡 + 飘心 + 柔光），"正在被摸"这个动作交给 `home-demo.html` 的真动画。

## 13 · 敌人立绘：四只全量，与「从背景里跳出来」的三条修正

### 13.1 一句话

> 敌人立绘缺的从来不是「画得好不好」，是**它不在任何一层里** ——
> 管线只定义了「背景 / 宠物立绘 / 矢量 UI」三层，敌人一直挂在最旧的
> 三档色代码图形上。补上这一层之后，同一个位置上的画风差从「三个数量级」
> 降到「同一套」。

### 13.2 第一版为什么不合格：只做了抠底 + 装框

按 `prep_pets.py` 的老流程走（采四角背景色 → 涂水印 → 抠底 → 去紫边 → 裁边 → 装框），
技术上一张不错。放进游戏里立刻看出问题：**四只敌人读不出来**。

原因不是画得差，是 AI 水彩的天然属性与游戏底图相冲：

| 问题 | 量出来的数 | 后果 |
|---|---|---|
| 边缘渐隐、无墨线 | 立绘边缘 alpha 是 20%→80% 的长过渡带 | 铺在草地上「化」进去，像贴纸没贴牢 |
| 整体彩度偏低 | 乌鸦 mean (149,128,123)，R/G/B 差不到 26 | 在饱和草地上是一块灰斑 |
| 主体明度贴近草地 | bug lum 165 vs 草地 lum 152，只差 13 | 色相又都是绿，剪影消失 |

对照组是旧的三档色代码图形：`c1` 明度 178、纯色块、外加 `COL.outline` 深描边 —— 所以它
在 34px 下**比 AI 立绘更好读**。这就是「细节多了反而看不清」的经典陷阱：
**可读性不是细节密度，是明度差 + 剪影边界。**

### 13.3 三条修正（都在 `prep_foes.py` 里，不换图不重出）

**① 补墨线（`outline()`）**

按 alpha 外扩画一圈 `#3A2B44` —— 与全场景 `COL.outline` 同色，敌人墨线必须和
UI、场景木台、宠物描边是同一支笔。

- 不用 `MaxFilter`：它是方形掩膜，半径一大就出直角，虫子的圆肚子会变成圆角矩形。
- 用「高斯模糊 σ=0.62×ow → 阈值 110 → 再模糊 0.30×ow」等效圆形膨胀，外缘留 1px 抗锯齿
  （否则缩到 28px 会闪）。
- **线宽按体高定，不按贴图尺寸**：`ow = clamp(vh × 0.065, 1.5, 2.6)` 显示像素。
  小虫子相对更细、大野猪相对更粗，视觉线宽才齐。
  系数 0.065 的参照：宠物立绘自带的画内描边折合显示约 2.4px / 73 ≈ 0.033；
  敌人要额外承担「从背景分离」的职责，取近 2 倍。

**② 提彩度（`vivid()`，走 HSV 的 S 通道）**

`ImageEnhance.Color` 是**乘法**，S=0.12 的灰紫乘 1.45 还是 0.17，等于没动。
改成逐像素 HSV：`S' = pow(S, 0.80) × 1.45`（clamp 255）。

- gamma < 1 → 中间饱和顶得多、高饱和保住，避免整体过艳变塑料。
- **明度（V）一律不碰**：明暗结构是画里的东西，动了就假。
- 亮度只微抬 1.06。压暗是错的方向（第一版试过 bright=0.97，越压越融）。

修正后四只的明度差（前景 alpha>200 像素平均，基准草地 lum 152）：

| 敌人 | 修正前 Δlum | 修正后 Δlum |
|---|---|---|
| 刺毛虫 | +13 | **+19** |
| 乌 鸦 | −16 | **−19** |
| 小野猪 | −24 | **−28** |
| 幼 虫 | +37 | **+50** |

**③ 视觉尺寸上移到数据层（`FOES[].vw/vh`）**

第一版把视觉尺寸写死在 `prep_foes.py` 里，绘制侧却用 `ih = f.h`（碰撞高）反算 ——
结果 `vw` **完全无效**，`vh` 只在恰好等于碰撞高时才对得上。

定规：**`w/h` 是碰撞盒，`vw/vh` 是画多大**，两套值都放在 `grove.html` 的 `FOES` 里，
与 `prep_foes.py` 的 `FOES` 表逐字一致。

| 敌人 | 碰撞 w×h | 视觉 vw×vh | 溢出 | 理由 |
|---|---|---|---|---|
| 刺毛虫 | 34×28 | 44×28 | 宽 29% | 横着爬的虫，碰撞得窄才摸得准，画窄了看不出是条虫 |
| 乌 鸦 | 36×32 | 42×34 | 宽 17% | 飞行单位，翅膀要有展幅 |
| 小野猪 | 56×40 | 76×54 | 宽 36% | 唯一会冲锋的小怪，视觉必须有压迫感（否则读成第四只宠物） |
| 幼 虫 | 26×22 | 30×24 | 宽 15% | 最小单位，少溢一点保判定清晰 |

⚠️ **溢出的代价写在明处**：视觉比碰撞宽的敌人，球从边缘擦过时不命中，玩家会觉得「打空了」。
36% 是这批的上限，再大就要重新评估手感（`grove-smoke` 367 项**测不出这个** —— 它测的是数值，
手感只能靠实机试）。

**贴图底边必须贴 `f.y`**：局部坐标 y 向下为正，底边要落在世界 `f.y` 上，所以
`yTop = bh/2 - ih`，不是 `-ih/2`。写成 `-ih/2` 会让视觉更高的敌人往地里陷
`(ih-bh)/2` 像素 —— 野猪会陷 7px，脚看不见。

**④ 连带的：包裹层也要按视觉尺寸**

包裹层是这个游戏**唯一的血条**。它原来用 `bw/bh` 算椭圆半径，贴图化以后
环会切进身体里 —— 出图上野猪的血条比它自己小一圈，像穿了件小一号的衣服。
改成用 `vw/vh` 算半径、中心用 `f.y - vh/2`（贴图底边贴地，所以视觉体中心不是 `cy`）。

### 13.5 「可爱冲突」是怎么落在画上的

四只敌人的表情是**这张图上唯一承担敌我区分的东西**：

- 刺毛虫：怒目 + 下撇的嘴 + 腮红 —— 生气但不可怕
- 乌 鸦：压眉 + 尖喙 —— 有攻击性
- 小野猪：獠牙 + 瞪眼 —— 冲锋者的凶
- 幼 虫：无辜大眼 —— 它甚至不是敌人（是 BOSS 的产物，爬到 BOSS 那就被吃掉）

**不是靠「画得更凶」来区分敌我，是靠表情。** 体型、笔触、光照、头身比全部与宠物同源 ——
玩家认得出「这是同一个世界的生物」，但一眼知道谁在生气。
