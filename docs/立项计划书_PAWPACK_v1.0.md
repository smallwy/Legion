## 1. 项目定位与一句话卖点

### 1.1 一句话定位

> **带一只 Q萌宠物出门，把怪物糊成球推着撞；家里另外五只在等你回来。宠物不是子弹，是会饿、会闹、会记仇、会争宠的活物。**

> ⚠️ **v1.0 原句（作废）**：「带 6 只 Q萌宠物并肩作战，一边打怪一边把它们养大」——"并肩"在单屏推球里做不到，也读不清（见 CR-024 §1）。

### 1.2 品类与定位（**关键，不可动摇**）

| 项           | 设定                                  | 理由                                    |
| ----------- | ----------------------------------- | ------------------------------------- |
| **主标签**     | **Casual → Puzzle → Action**（cozy 只作氛围标签，不作主标签）   | cozy 玩家要的是"真·低压"，而推球要预判落点，本质是动作解谜；挂 cozy 卖硬关卡 = 差评（CR-024 §7.2） |
| 绝不能主打   | ❌ "又一款子弹天堂" / ❌ "cozy 模拟经营"                         | Action Roguelike 成功率仅 3.5%，低于均值；模拟经营赛道已卷，且一人做双玩法必崩 |
| **核心结构**    | **Hub-and-Spoke 资源网**（家园=中心，多玩法=辐条） | 玩家目标="让家变好"，不是"过第 N 关"                |
| **差异点（唯一）** | **宠物 = 有状态、有关系、有记忆的活物**             | 几百款割草游戏无一做"单位关系"系统                    |

### 1.3 玩法公式

```
【家园 Hub】喂饭（定火力）/ 做道具（改规则）/ 派五只看家（采材料）
      ↓ 选产地 + 选 1 只宠物 + 带 2 件道具
【产地】单屏推球：糊 → 滚 → 推；一屏一屏往里走
      ↓ 每屏结算：继续深入 / 就地收工 / 撤回
【反哺】食物 → 火力↑ / 材料 → 下一趟能走更深
      ↑___________________________________|
        双线闭环，非推图；无失败，只有"这趟少拿点"
```

### 1.4 三条设计红线（违反即纠偏）

1. **不做卡关式线性推进** — 长主线用"**产地 + 深度层**"实现，**不用关号**；走不下去就地收工，明天再来（cozy 玩家被卡关会退款）
2. **不做失败惩罚** — 只有"收获少一点"，没有"游戏结束"；被打 3 次 = 强制收工，丢的是这一趟背的收成，不是进度
3. **不做大地图** — 家园**一屏**，产地 **3 个 × 8 屏 + 1 个 BOSS 屏**，绝不做开放世界

### 2.2 主玩法（产地推进）战斗状态机

> **v2.0 定稿（CR-024，2026-10-20）**：主玩法从"20 波怪潮割草"整体替换为"雪人式单屏推球"。以下状态机是**唯一有效**的。

```
  [家园备货]  选产地 / 选 1 只宠物 / 带 2 件道具
        │
        ▼
  ┌──────────────── 单屏 · 30~60 秒 ────────────────┐
  │  糊：攻击不扣血，只加 1 层苔；满 3 层变球        │
  │  滚：球撞到未满层的敌人 → 卷进球里，变大变慢     │
  │  推：走向球就推走；落点决定收成倍率              │
  │  收：主目标达成（清场 / 收成达标 / 限球 / 护送）  │
  └───────────────┬────────────────────────────────┘
                  ▼
     结算评级 S / A / B（主目标 + 0~2 个奖励目标）
                  ▼
     继续深入 → 下一关（**倍率 +0.15、肚子 -16**）
     就地收工 → 结算 = 这一趟攒下的 × 倍率，回家吃饱
                  ▼
     回到门口：收成入池 → 喂饭 / 做道具
```

**四条硬规则（不可协商）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **没有命数、没有超时。** 被打 3 次 = 强制收工，不是死亡 | 红线②：惩罚只"慢下来"，不"倒退" |
| 2 | **每屏 1 个主目标 + 2 个可选奖励目标**，主目标达成即可前进 | 主目标不卡关，奖励目标给 mastery（S 评级） |
| 3 | **战斗内只有 1 个身体。** 玩家本人就是那只宠物，无 AI 跟随、无编队 | 宠物犯蠢的风险归零；单屏可读 |
| 4 | **球是限时资产。** 停住 4.2 秒开始缩小，被敌人碰到会破 | 防止"攒 3 只再推"变成唯一最优解 |

> **怪物 AI 模型（CR-008，用户明确）**：本作主玩法的敌人**不是"从屏幕外涌来追击玩家"**，而是**玩家移动到某个地点后，该地点成批生成一群怪物**（像踩进怪窝）。这群怪物有**独立 AI**：
> - **可移动**：在自己的活动范围内游走/调整站位，不必然追玩家；
> - **攻击半径**（如 60px）：玩家或宠物**进入半径内**才发动攻击；
> - **施法半径**（如 140px）：进入半径即可**施法**（有前摇，给玩家反应窗口），造成范围/远程伤害；
> - **可施法**：远程怪会读条放技能，不是只会平 A。
>
> 这把战斗从"被怪潮推着走"改成"你主动走过去清一窝"——玩家的主动性（走位选择打哪窝、何时进场）成为核心乐趣，也更符合"百炼英雄式移动捕杀"。
>
> **CR-014 补充**：一窝清完**不再重刷**。原实现留了 `respawnDelay: 18` 冷却重刷，把"踩一窝"实际做成了刷怪场；现改为清完即永久 `cleared`。**清完全部 4 窝 → BOSS 登场 → 击杀通关**，倒计时不再是结束条件。

> 详见 §8.1 CR-015 与 `docs/方向抉择_最初vs现在_PAWPACK.md`。

> **战斗模型明确（CR-007 + CR-009 + CR-014）**：本作主玩法为 **2D 俯视微倾视角**；敌方为 **怪物（含昆虫/野兽/元素怪等可移动单位）**（非静止炮塔），在场景中自由移动；玩家 **WASD 控制主角走位**，**3 名英雄列队跟随主角身后、自动施法捕杀**——对齐《百炼英雄》的**移动中捕杀猎物**手感：你带着一支小队在场上游走，所到之处自动清场。这把"爽快割草"与"cozy 养宠"用同一套走位操作咬合。

> ⚠️ **CR-014 修订说明（这条是纠错，务必看）**：原文此处写的是「宠物**环绕**中心点自动施法捕杀——即"百炼英雄式"」，**这个类比从一开始就是错的**。

> **宠物施法状态机（CR-009，新增）**：宠物自动施法不是一个"瞬间发射"的黑盒，而是有完整可读状态的动画链路——
> 1. **前摇（Telegraph，约 0.25s / 2-3 帧）**：宠物抬手/蓄力，身上出现微量光芒或嘴巴张开，让玩家"看到它要打谁"；
> 2. **施法（Cast，约 0.1s / 1-2 帧）**：发射弹道、喷吐、或释放范围法阵；
> 3. **后摇（Recovery，约 0.3s / 3-4 帧）**：动作回位、喘口气，期间不能再次施法，玩家可借此判断"这波火力空窗期有多长"。
> 总攻速（前摇+施法+后摇）≈ 首版 2.2 次/秒，不同宠物通过"规则变体"改变的是三阶段分配（如大耳兔前摇长但射程远；老实牛无后摇但移动惩罚大），不是单纯加数值。

### 2.3 核心创新系统（v2.0 重写：三个系统全部保留，但换了挂载点）

> **v2.0 原则**：三个系统一个都不删，但**全部只保留"能被一句话说清 + 能被玩家看见"的部分**。
> 战斗里只有 1 个身体 → 系统 A 变成"选解法"，系统 C 搬到家园。**这叫搬家，不叫降级。**

#### 系统 A：宠物「解法变体」（P0，决定重玩性）

> ⚠️ **命名统一（v2.0）**：以已跑通的原型 `client/prototype/grove.html` 为准。
> v1.0 的旧名（贪吃鼠 / 大耳兔 / 影子狐 / 圆滚猪）**作废**，代码与文档一律用下表。

| 宠物 | 弹道形状 | 一条规则变体 | 一句话解法 |
|---|---|---|---|
| **尖耳猫** | 扇形三发 | 覆盖宽，射程最短 | 撒网 |
| **短尾犬** | 宽波穿透 | 贴脸最狠，一下糊两格宽 | 堵路 |
| **胖仓鼠** | 高速穿透 | 射得最远，可穿后排 | 穿糖葫芦 |
| **长耳兔** | 抛物线 + 落点爆炸 | **能越障**（木桩、高台） | 隔山打牛 |
| **老实牛** | 超宽贴身判定 | 站着就是墙，移速最慢 | 当墙用 |
| **影狐** | 高速刃 | 最快，单体 | 快刀 |

**关键约束：六只里没有"最强"，只有"这张图最合适"。** 用**地形克制**做平衡，不做数值平衡（每张图至少让 2 只可用、至少 1 只明显吃亏）。

#### 系统 B：「半饿最强」（P0，双线咬合的钥匙）

数值不变，但**语义升级**：火力倍率不再只是"打得多快"，而是"**糊满 3 层要几发**"。

| 状态 | 火力 | 糊满 3 层需要 | 玩家感受 |
|---|---|---|---|
| 满饱（≥70） | ×1.0 | 3 发 | 稳，但造球慢，容易被围 |
| **半饿（30~70）** | **×1.5** | **2 发** | **造球快，连锁起得早 —— 最强** |
| 全饿（<30） | ×0.6 | 5 发 | 危险，几乎造不出球 |

> 于是"喂多少"从**数值选择**变成**打法选择**：这趟打快攻还是稳推。

> 同类搭班 +20% / 异类 -15% / 抢食 / 嫉妒 / 护主 / 羁绊。
>
> **砍的理由不是它不好，是它护的不是 B 路线的城。** 咩咩启示录真正的护城河是
> 「教徒有名字、会老、会死、会叛教」（**情感层**），不是「这样摆效率高 15%」（**策略层**）。
> B 路线卖的是"六只会饿会闹的小动物"，那是情感层。
>
> 而且它是全案里**成本最高、玩家最看不见**的一环（要界面、心情图标、计算、图鉴）。
> 同样两周，投在"六只在门口的反应"上，市场回报高一个数量级。

**只保留一条，因为它同时也是性格**：

| 规则 | 玩家看见的 | 成本 |
|---|---|---|
| **连续 3 趟只带同一只 → 其余五只心情↓** | 门口那五只表情变丧、自荐台词变短；出过门的那只肚子更圆 | 一个计数器 + 复用已有的饿饱表现（`bellyTier` / `MOODS`） |

**不做**：搭班加成、采集点、效率数字、图鉴、心情图标系统、多宠同场。
**推迟到 1.1**：如果 P0 的胶囊图 A/B（CR-029 §7）证明性格层成立、且社区主动问"能不能让它们一起做事"，再回来考虑。

> **这条的写法很关键：心情不是数值，是表情。**
> 玩家不该去算"我该轮换谁"，而是某天回家发现狗不摇尾巴了 —— 那才是情感层。
> 一旦挂上数字和图标，它立刻退回策略层，和砍掉的那六条没有区别。

### 2.5 ★ 贯穿游戏全流程的设计主线（三条并行线）

> 任何功能如果挂不上这三条线中的任一条，**就不做**。这是设计的脊椎。

- **线 1 首次体验（绿，0-10 分钟）**：进家园 → 领养第 1 只 → 出门 → **推出第一颗球，撞死一排** → 带吃的回家 → 看到家里还空着 5 个位置。目标：让他不关掉。
- **线 2 日常循环（琥珀，每天 15-30 分钟，闭环）**：出门推进 → 收成/材料 → 回家喂饭、做道具 → 下一趟走更深（或今天就到这儿）。虚线回流：**"我还能再贪一屏吗"**是一趟的张力，"这周能走到底吗"是这一周的目标。
- **线 3 长期回访（紫，数周）**：解锁产地深层 → 六只宠物各自找到"最合适的那张图" → 每只用它最顺的那张图走一趟到底。目标：让他还回来。

**★ 红线框（设计禁区）**：① 不做**卡关式**线性推进 ② 不做失败惩罚（只"收获少点"）③ 不做大地图（家园一屏 + 3 产地 × 8 屏）。
**★ 游戏名即传播钩子**：**《吧唧军团 / Munch Legion》**——"吧唧"=啃食拟声（绑定喂养+半饿线），"军团"=**家里六只，一只出门五只看家**（不是同屏六只）。名字把"cozy+战斗"矛盾摆平，是记忆点第一环（详见第 8 章 CR-005）。

### 2.7 数值骨架（v2.0 雪人化，替换 v1.0 割草口径）

| 项 | v2.0 数值 | 说明 |
| --- | --- | --- |
| 玩家 HP | **3** | v1.0 的 6 血是按 20 波持续压力定的；单屏没有持续压力 |
| 无敌帧 | 0.9s | 防连击秒杀 |
| 玩家移速 | 190 px/s | 沿用原型 |
| 包裹层数 | **3 层**（满即变球） | 核心：屏幕不需要血条 |
| 球初始半径 | 22 px，每卷一只 +2.8 px（上限 +16） | `grove.html` 实测 |
| 球阻尼 | **0**（地面无摩擦），唯一衰减是撞墙 ×0.62 | 用户明确要求"雪球不做减速"。副作用是球比玩家快、追不上 —— 决策必须提前，预瞄线从辅助变成必需品（CR-024 §8.7.5） |
| 推球初速 | **620 px/s 起，助跑最多 ×1.95（1180）** | 用户要求"站得越远推球，推力越大"。只算**当前方向**上的连续位移（来回横跳不攒），跑满 380px 到顶。退开再冲 = 有代价的好习惯：退的那两秒敌人也在往你身上走（CR-026 §8.12.4） |

| **场景件** | 平台 / 火坑 / 泥坑 / 木桩 / 营地 / **水塘** / **斜坡** / **弹簧菇** / **传送洞** | 后四种是第三轮新增。水塘只吞"砸进去"的球（滚过去不沉），斜坡能把球推上上一层，弹簧菇弹起 228px，传送洞保持水平速度换位 |

| **↓ 下穿** | 站在台上按 ↓，**只放过脚下那一块**平台，落到**下一层**就停；松开再按才继续往下。`p.dropPlat` 锁住目标、`p.dropLock` 防连按；脚下一个上浮小箭头提示 | 平台是单向的（能跳上去），所以必须有一条下来。上一版是"窗口内所有平台都不算落脚点"，按住 ↓ 会一路穿到地面 —— 玩家要的是**下一层**，不是跳楼。`b.skyDrop` 另留一条路给 BOSS 天降（中途所有非地面平台都不接）。0.26 秒 ≈ 一层（CR-024 §8.10.2 / §8.11.3） |
| **波次** | 场上 **≤1 只**就刷下一波（不是清完）；**BOSS 波之前必须清空**（不能夹击）；间隔 1.1s（BOSS 1.6s）；波内最短 3.5s | "清完才刷"的代价是收尾那 20 秒没有决策，只有赶路 —— 而推球游戏最不该有的就是赶路。BOSS 波例外：BOSS 加残兵是夹击，那时玩家想的就不是"这球怎么推"了（CR-024 §8.10.3） |
| **BOSS** | **不做第二套规则**：`cm = 4 + lv`（第 1 关 5 层，第 8 关 10 层封顶），糊满变球、推进坑，和小怪同一套代码。独有五条：① 慢速追击 `40 + lv*7` ② 每 6.5s 砸地放**两道贴地冲击波**（跳起来能躲）③ 球撞它会被**弹回来**（可以连推同一颗）④ **繁殖**：每 7.5s 产卵，两侧各钻一只幼虫，幼虫不打玩家、往 BOSS 爬，被吃掉 → BOSS **补 1 层壳**（硬上限 3 层、共 5 对）⑤ **范围散射**：每 5.5s 朝玩家喷 **5 发扇形粘液弹**（初速 380 / 重力 150，被地形挡住）。三动作**节拍错开、一帧只开一个**（砸地 6.5 / 散射 5.5 / 产卵 7.5）。抗性 **0.5s/层**。球 r=44，火坑收成 ×14 / 营地 +12 | 冲击波是为了逼玩家离地，否则 BOSS 战就是"站在脚边一路糊"的木桩战。抗性第一版写 0.28s（照着音波喇叭 0.30s 一发配的），实测 **2 秒就被糊成球** —— 连发武器一梭子三四层。改完深井（lv3·7 层）实测约 15 秒。繁殖的"精巧"在**闭环**而不在加技能：产卵 → 归巢 → 被吃 → 补壳，玩家要么现在拦虫、要么等会儿多糊三层；而幼虫本身也能被糊成球推进火坑（+2 收成），所以"拦"是有收益的。三个坑：① 幼虫出生点必须在 `±(半宽+56)` 外，BOSS 半宽 54、吃得着的范围 66，原来从 ±50 钻出来一出生就落在嘴里，"繁殖"退化成"免费回血"；② 散射弹的落地判定只能判"从上方落到台面"，用包围盒的话 BOSS 胸口正好和头顶那块板同高，五发一出口就被吃掉；③ 弹道要平，330+300 会 1 秒砸进土里。⚠️ 代价：第 4 关 BOSS 战 64s → **112s**、第 5 关 35s → 59s，因为 BOSS 实际层数从 `cm` 变成 `cm + 3`（CR-024 §8.10.7 / §8.11.5） |

| 评价倍率 | S ×1.5 ／ A ×1.2 ／ B ×1.0 | **不卡进度**，只影响带回量。原来还有一条「中途收工 ×0.8」，随「收工拿满倍率」作废 —— 收工本来就已经放弃倍率，再罚一次就是两道罚 |

## 5. 技术方案（Cocos + Go）

### 5.1 前端：Cocos Creator 3.8+

| 项         | 方案                              | 理由                            |
| --------- | ------------------------------- | ----------------------------- |
| **引擎**    | Cocos Creator 3.8+（TypeScript）  | 用户指定；2D 性能足够；可导出 Web/微信小游戏/原生 |
| **渲染**    | 2D 合批（Auto Atlas）               | 2D 性能关键，同图集自动合批               |
| **对象池**   | 内置 `NodePool`                   | 子弹/敌人/特效**必须**用池（割草高频生成销毁）    |
| **碰撞**    | 简化碰撞体（圆形）+ 碰撞分组                 | 子弹只与敌人检测，敌人之间不检测              |
| **GC 控制** | 避免 in `update()` new 对象；复用 Vec3 | JS GC 是"全停顿"，频繁 GC 会周期性卡顿     |
| **UI**    | 少用 Label 实时更新、少用 Mask           | 小游戏低端机上 Mask 性能差              |

**性能目标**：同屏 200 敌人 + 60 子弹，60 FPS；DrawCall < 30。

### 5.2 后端：Go

| 项        | 方案                             | 说明                            |
| -------- | ------------------------------ | ----------------------------- |
| **语言**   | Go                             | 用户指定；goroutine 高并发、低延迟、单二进制部署 |
| **框架**   | **优先评估 Nakama**（开源 Go 游戏后端）    | 自带账号/存档/排行榜/成就，省数月开发          |
| **自研备选** | Go + Gin + PostgreSQL          | 若 Nakama 过重，自研最小 API          |
| **数据库**  | PostgreSQL（账号/存档） + Redis（排行榜） | Redis 有序集合排行榜 O(log N)        |
| **部署**   | 单二进制（TrontCloud 模式）            | 无 Docker 依赖，部署简单              |

> ⚠️ **重要判断**：**第一版不需要后端**。双线养成是纯单机玩法。后端只在需要"云存档 + 排行榜 + 社群对比"时才做。**M5 之前不要碰后端**，否则会拖死排期。

## 9. 市场对齐与纠偏机制（**强制记录区**）

> **本机制的存在意义**：防止"越做越偏"而不自知。**每次版本完成后必须对照本章执行。**

### 9.1 纠偏触发器（满足任一即必须执行）

| 触发器           | 判定条件                    |
| ------------- | ----------------------- |
| **T1 里程碑完成**  | 每个 M 里程碑结束时             |
| **T2 排期偏差**   | 实际进度落后计划 > 30%          |
| **T3 玩法偏离**   | 做出来的东西"感觉不对"（用户直觉是有效信号） |
| **T4 市场变化**   | 同类竞品出现重大变化（爆款/翻车）       |
| **T5 用户提问质疑** | 用户再次问"这真的可行吗"类问题        |

### 9.2 纠偏检查单（每次必答这 6 问）

1. **做出来的东西，和立项时的"一句话定位"还一致吗？**
2. **玩家脑中的行为链是"我在凑一个组合"还是"我在打怪"？**（深度自检）
3. **有没有违反三条设计红线**（线性关卡／失败惩罚／大地图）？
4. **当前版本的"记忆点"是什么？**（能不能一句话说清、能不能截图传播）
5. **相比 Miners Moos & Miracles 的五条评测，我们多了什么？**
6. **预期锚定还成立吗？**（是否在不知不觉中锚定了 850 万份）

### 9.3 偏差判定与处置

| 偏差类型                | 处置                        |
| ------------------- | ------------------------- |
| **方向性偏差**（偏离定位）     | **立即停止当前开发**，回到第 1 章重新对齐  |
| **范围膨胀**（想做太多）      | 砍掉副玩法，只保主玩法（**这是最常见的死法**） |

| **排期滞后**            | 砍内容而非砍质量；延长周期而非赶工         |
