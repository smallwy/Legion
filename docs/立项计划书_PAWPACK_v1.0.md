## 1. 项目定位与一句话卖点

### 1.1 一句话定位

> **带 6 只 Q萌宠物并肩作战，一边打怪一边把它们养大；宠物不是子弹，是会饿、会闹、会记仇、会护主的活物。**

### 1.2 品类与定位（**关键，不可动摇**）

| 项           | 设定                                  | 理由                                    |
| ----------- | ----------------------------------- | ------------------------------------- |
| **主标签**     | **Cozy → Pet → Action Roguelike**   | cozy 标签成功率 11%（Steam 均值 4.2% 的 2.6 倍） |
| **绝不能主打**   | ❌ "又一款子弹天堂"                         | Action Roguelike 成功率仅 3.5%，低于均值       |
| **核心结构**    | **Hub-and-Spoke 资源网**（家园=中心，多玩法=辐条） | 玩家目标="让家变好"，不是"过第 N 关"                |
| **差异点（唯一）** | **宠物 = 有状态、有关系、有记忆的活物**             | 几百款割草游戏无一做"单位关系"系统                    |

### 1.3 玩法公式

```
【家园 Hub】养宠物（喂/撸/洗）
      ↓ 宠物饿了
【主玩法】远征找食（玩家只走位，多宠自动施法捕杀怪物猎物：含昆虫、野兽、元素怪等）
      ↓ 带回食物/材料
【反哺】喂食 → 宠物变强/羁绊↑ → 下次远征收获↑
      ↑___________________|
        （双线闭环，非推图）
```

### 1.4 三条设计红线（违反即纠偏）

1. **不做线性关卡线** — 用"家园成长解锁新场景"代替（cozy 玩家被卡关会退款）
2. **不做失败惩罚** — 只有"收获少一点"，没有"游戏结束"（惩罚只"慢下来"不"倒退"）
3. **不做大地图** — 家园**一屏**，战斗场景 3-4 张，绝不做开放世界

> **怪物 AI 模型（CR-008，用户明确）**：本作主玩法的敌人**不是"从屏幕外涌来追击玩家"**，而是**玩家移动到某个地点后，该地点成批生成一群怪物**（像踩进怪窝）。这群怪物有**独立 AI**：
> - **可移动**：在自己的活动范围内游走/调整站位，不必然追玩家；
> - **攻击半径**（如 60px）：玩家或宠物**进入半径内**才发动攻击；
> - **施法半径**（如 140px）：进入半径即可**施法**（有前摇，给玩家反应窗口），造成范围/远程伤害；
> - **可施法**：远程怪会读条放技能，不是只会平 A。
>
> 这把战斗从"被怪潮推着走"改成"你主动走过去清一窝"——玩家的主动性（走位选择打哪窝、何时进场）成为核心乐趣，也更符合"百炼英雄式移动捕杀"。
>
> **CR-014 补充**：一窝清完**不再重刷**。原实现留了 `respawnDelay: 18` 冷却重刷，把"踩一窝"实际做成了刷怪场；现改为清完即永久 `cleared`。**清完全部 4 窝 → BOSS 登场 → 击杀通关**，倒计时不再是结束条件。

> ⚠️ **CR-015 推翻了 CR-008 的刷怪模型与 CR-014 的清窝推进（2026-10-20，用户已拍板）**：
> 「清窝推进」把一局压到 **57 秒 / 每窝 5.2 秒**，而本作的全部系统（饱食度衰减、升级三选一、喂食决策）都需要**连续压力**才有展开空间 —— 5 秒打完一窝，饱食度只掉 2.5 点，玩家永远感受不到"饿"。
> 现改回 **20 波怪潮**（第 19 波清完 BOSS 登场 = 第 20 波），一局约 5~6 分钟。
> **保留 CR-008 的真遗产**：半径制攻击/施法（这让走位有意义），只是把"守在窝边等你来"改为"从屏幕外涌来主动追"（`EnemyManager.spawn(..., hunter=true)`）。
> **同时恢复 CR-001 之前的「战斗中喂食」**（推翻 CR-010 的"战斗内冻结"）：饱食度 0.5/秒衰减，半饿 ×1.5 / 满饱 ×1.0 / 全饿 ×0.6。
> 详见 §8.1 CR-015 与 `docs/方向抉择_最初vs现在_PAWPACK.md`。

> **战斗模型明确（CR-007 + CR-009 + CR-014）**：本作主玩法为 **2D 俯视微倾视角**；敌方为 **怪物（含昆虫/野兽/元素怪等可移动单位）**（非静止炮塔），在场景中自由移动；玩家 **WASD 控制主角走位**，**3 名英雄列队跟随主角身后、自动施法捕杀**——对齐《百炼英雄》的**移动中捕杀猎物**手感：你带着一支小队在场上游走，所到之处自动清场。这把"爽快割草"与"cozy 养宠"用同一套走位操作咬合。
>
> ⚠️ **CR-014 修订说明（这条是纠错，务必看）**：原文此处写的是「宠物**环绕**中心点自动施法捕杀——即"百炼英雄式"」，**这个类比从一开始就是错的**。
> 核实《百炼英雄》真实形态：搜狐品类分析将其归为**「佣兵团like」**（对标《轰隆隆佣兵团》），并明确指出**"割草感并不显著"**；实际玩法是 **4–5 名英雄（坦克/输出/辅助）列队跟随主角**、摇杆拖动整队走位、自动普攻 + 技能长 CD 手动放、打场景布点怪群 + 固定 BOSS。
> **"围绕主角转圈"是幸存者like（Vampire Survivors）的形态，不是百炼英雄的形态。** 已按真实形态改为**列队跟随**（`HERO_SLOTS` 定义前/左后/右后/正后槽位）。
>
> 📌 **术语统一**：本文档与代码里出现的「**英雄**」= **上阵的宠物**（`HERO` 常量即原 `PET`）。
> 世界观上它们始终是宠物（吧唧军团 = 养宠），"英雄"只是借用百炼英雄的**队伍编成**概念来描述战斗队形。
> 代码中保留 `HERO` 命名是为了与「家园里未被带上阵的宠物」区分；对外文案一律用「宠物」。
> **宠物施法状态机（CR-009，新增）**：宠物自动施法不是一个"瞬间发射"的黑盒，而是有完整可读状态的动画链路——
> 1. **前摇（Telegraph，约 0.25s / 2-3 帧）**：宠物抬手/蓄力，身上出现微量光芒或嘴巴张开，让玩家"看到它要打谁"；
> 2. **施法（Cast，约 0.1s / 1-2 帧）**：发射弹道、喷吐、或释放范围法阵；
> 3. **后摇（Recovery，约 0.3s / 3-4 帧）**：动作回位、喘口气，期间不能再次施法，玩家可借此判断"这波火力空窗期有多长"。
> 总攻速（前摇+施法+后摇）≈ 首版 2.2 次/秒，不同宠物通过"规则变体"改变的是三阶段分配（如大耳兔前摇长但射程远；老实牛无后摇但移动惩罚大），不是单纯加数值。

### 2.3 核心创新系统（第 7 轮分析确定的三个 P0/P1）

#### 系统 A：宠物「规则变体」（P0，决定重玩性）

| 宠物         | 规则变体（**改规则，不是加数值**）             |
| ---------- | ------------------------------- |
| 🐭 **贪吃鼠** | 可带 3 个食物槽（其他 1 个），攻速 -20%       |
| 🐰 **大耳兔** | 攻击距离 +80%，血量 -50%               |
| 🐱 **尖耳猫** | 攻击弹射到最近另一敌人，伤害 -30%             |
| 🐮 **老实牛** | 免疫击退、极硬，**完全不能移动**（靠玩家走位带它）     |
| 🦊 **影子狐** | 死亡后复活一次，但全局限 1 次                |
| 🐷 **圆滚猪** | 每吃一份食物**永久** +2% 全属性（开局最弱，后期最强） |

#### 系统 B：「半饿最强」（P0，双线咬合的钥匙）

```
满饱 → 火力 ×1.0   （安全，但平庸）
半饿 → 火力 ×1.5   （强，但宠物会"闹"，可能脱离队形）
全饿 → 火力 ×0.6   （危险，且缓慢掉血）
```

> **设计意图**：养成线让你能喂饱（安全），战斗线诱惑你保持半饿（强）。**两线的张力由这一条建立。**

#### 系统 C：宠物「关系网」（P1，护城河）

| 关系       | 触发          | 效果          |
| -------- | ----------- | ----------- |
| **同类相邻** | 同族宠物距离 < 阈值 | 攻击 +20%     |
| **异类相邻** | 异族宠物距离 < 阈值 | 攻速 -15%（分心） |
| **抢食**   | 两只都饿时靠近食物   | 离得近的先吃      |
| **嫉妒**   | 只撸一只宠物      | 其他宠物心情下降    |
| **护主**   | 玩家被击中       | 最近的宠物冲锋过去   |
| **羁绊**   | 共同出战 N 次    | 解锁永久加成      |

### 2.5 ★ 贯穿游戏全流程的设计主线（三条并行线）

> 任何功能如果挂不上这三条线中的任一条，**就不做**。这是设计的脊椎。

- **线 1 首次体验（绿，0-10 分钟）**：进家园 → 领养第 1 只宠物 → 首次远征 → 带战利品回家。目标：让他不关掉。
- **线 2 日常循环（琥珀，每天 15-30 分钟，闭环）**：出门找食 → 收获食物/材料 → 回家喂养/升级 → 宠物变强 → 下次出门更远。虚线回流：养成驱动下一次出门。
- **线 3 长期回访（紫，数周）**：解锁新地点 → 关系网成型 → 家园外观变化。目标：让他还回来。

**★ 红线框（设计禁区）**：① 不做线性关卡线 ② 不做失败惩罚（只"收获少点"）③ 不做大地图（家园一屏+战斗 3-4 张）。
**★ 游戏名即传播钩子**：**《吧唧军团 / Munch Legion》**——"吧唧"=啃食拟声（绑定喂养+半饿线），"军团"=最多 6 只并肩（绑定战斗线）。名字把"cozy+战斗"矛盾摆平，是记忆点第一环（详见第 8 章 CR-005）。

### 2.6 ★ 首日体验逐分钟流程（0-10 分钟）

| 时间 | 玩家动作 | 系统反馈 | 情绪目标 |
| --- | --- | --- | --- |
| 0:00 | 进家园，看到 1 只圆滚滚宠物 | 宠物蹦跳、BGM 轻快 | 安心、"可爱" |
| 0:30 ⚠️流失点 | 系统提示"带它去找吃的" | 高亮远征入口 | 好奇（此处最易关掉） |
| 1:00 | 点远征，进入战斗场景 | WASD 移动中心点，宠物自动开火 | 惊喜、"会自己打" |
| 2:00 | 敌人变多，宠物清场 | 经验珠吸入、火力上升 | 爽 |
| 3:00 | 撤离，带回食物 | 食物入池动画 | 满足 |
| 4:00 | 回家喂食宠物 | 宠物吃食、金环特效（半饿） | 亲密 |

## 5. 技术方案（Cocos + Go）

### 5.1 前端：Cocos Creator 3.8+

| 项         | 方案                              | 理由                            |
| --------- | ------------------------------- | ----------------------------- |
| **引擎**    | Cocos Creator 3.8+（TypeScript）  | 用户指定；2D 性能足够；可导出 Web/微信小游戏/原生 |
| **渲染**    | 2D 合批（Auto Atlas）               | 2D 性能关键，同图集自动合批               |
| **对象池**   | 内置 `NodePool`                   | 子弹/敌人/特效**必须**用池（割草高频生成销毁）    |
| **碰撞**    | 简化碰撞体（圆形）+ 碰撞分组                 | 子弹只与敌人检测，敌人之间不检测              |
| **GC 控制** | 避免 in `update()` new 对象；复用 Vec3 | JS GC 是"全停顿"，频繁 GC 会周期性卡顿     |
| **UI**    | 少用 Label 实时更新、少用 Mask           | 小游戏低端机上 Mask 性能差              |

**性能目标**：同屏 200 敌人 + 60 子弹，60 FPS；DrawCall < 30。

### 5.2 后端：Go

| 项        | 方案                             | 说明                            |
| -------- | ------------------------------ | ----------------------------- |
| **语言**   | Go                             | 用户指定；goroutine 高并发、低延迟、单二进制部署 |
| **框架**   | **优先评估 Nakama**（开源 Go 游戏后端）    | 自带账号/存档/排行榜/成就，省数月开发          |
| **自研备选** | Go + Gin + PostgreSQL          | 若 Nakama 过重，自研最小 API          |
| **数据库**  | PostgreSQL（账号/存档） + Redis（排行榜） | Redis 有序集合排行榜 O(log N)        |
| **部署**   | 单二进制（TrontCloud 模式）            | 无 Docker 依赖，部署简单              |

> ⚠️ **重要判断**：**第一版不需要后端**。双线养成是纯单机玩法。后端只在需要"云存档 + 排行榜 + 社群对比"时才做。**M5 之前不要碰后端**，否则会拖死排期。

### 5.3 客户端安全

- 客户端**不内置 API Key**（会被反编译）
- 采用三层认证：PublicAuth / SessionAuth / APIKeyAuth

| 1 | **"cozy + 战斗"可能两头不讨好**  | 想放松的玩家嫌怪潮烦；想爽的玩家嫌养成慢。**这是最大的结构性风险，必须在 Demo 阶段验证。**                   |
| 2 | **宠物关系系统可能"看起来好，玩起来烦"** | 玩家可能不想管宠物嫉妒。**P2 的冲突系统建议慎加。**                                        |
| 3 | **一个人做完的可能性**           | 12 周排期是**理想值**。实际一个人做这类游戏通常需要 **6-12 个月**。请把 12 周理解为"有 Demo"，不是"发布"。 |
| 4 | **AI 标签会压销量**           | 如果成品素材大量用 AI，销量可能打 3 折。**这是可以避免的，别偷懒。**                              |
| 5 | **"多玩法"是最容易崩的地方**       | MM\&M 就是反例。**宁可 1 个深玩法，不要 6 个浅玩法。**                                  |
| 6 | **市场数据多为第三方估算**         | ±30% 误差。所有预期都要打折扣看。                                                  |
| 7 | **没有发行商的情况**            | 独立发行需要你自己做营销。**Hozy 的成功一半是营销，不是游戏。**                                 |
