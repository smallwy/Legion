# 美术风格指引 · 吧唧军团（Munch Legion）Art Bible

> **本文档是美术的「唯一事实来源」。** 无论立绘、地图、UI、特效，凡是产出物，必须先对照本文档 + 文末「风格校验清单」过关，才能入库。
> 目的：让**你自己**、**外包画师**、**AI 出图工具**每一次做图，都能"感知到这是吧唧军团"，而不是各画各的。
> 配套：计划书第 2.4–2.6 节（时间轴/设计主线/首日流程）+ 第 6 章（美术预算）。

---

## 0. 一句话风格定位

**「像素 Q 萌、一眼可辨、状态靠滤镜不靠新素材」** —— 用最低成本画出"又可爱又能打"的反差萌。

- 关键词（给 AI / 给画师都用的**风格锚**）：`pixel art`, `chibi`, `16-32px`, `rounded`, `high saturation`, `readable silhouette`, `cozy but lively`, `juicy feedback`。
- **反例关键词（禁止）**：`realistic`, `anime cel-shading`, `dark gritty`, `detailed shading`, `photoreal`。

---

## 1. 视觉三铁律（不可妥协）

| 铁律 | 规定 | 为什么 |
| --- | --- | --- |
| **像素尺寸** | 角色 16–32px 工作分辨率，**整数倍放大**（×3 / ×4 显示），严禁亚像素/模糊缩放 | 保持像素颗粒感，缩略图也清晰 |
| **剪影可辨** | 6 只宠物在 32px 下， silhouette 必须一眼区分（圆/尖耳/长耳/犄角/尾巴） | Steam 商店页只有 2-3 秒，靠剪影认角色 |
| **状态可视** | 饱食/半饿/全饿 **用颜色光环+滤镜表达，不画新动作帧**（仅约束"状态变化"；家园"交互动画"见 §3.5，合法不禁止） | 省 80% 动画成本（详见 §4） |

## 3. 立绘规范（角色 / 宠物）

- **头身比**：Q 萌 **1:1 ~ 1:1.2**（大头短身），眼睛占脸 1/3，高光点不可省。
- **表情系统**：每只宠物至少 4 态 —— `常态 / 饿（流口水+瘪嘴）/ 半饿兴奋（金环+星星眼）/ 吃饱满足（眯眼）`。表情用**眉毛+嘴形+光环**组合，**不新增骨骼动画**。
- ** Outline**：1px 深色描边（`#2D2438` 或角色暗部），保证缩略图不糊。
- **动作帧预算**（战斗首版）：待机 2 帧（呼吸）、走 4 帧、**施法链路 6 帧**（前摇 2 帧 + 施法 1 帧 + 后摇 3 帧）、吃 3 帧。**总计 ≤ 15 帧/只**。多余动作一律用"滤镜/粒子"代替。
  - **施法链路必须拆三段**（CR-009）：前摇（蓄力/抬手，让玩家预判）、施法（发射瞬间）、后摇（回位喘气，制造"空窗期可读性"）。不能做成"抬手即发射"的瞬发。
- **换色即新宠**：骨架复用，仅换主色 + 1 个特征（耳形/角），**3 骨架 × 2 配色 = 玩家感知 6 只**，成本仅 3 只。

### 3.5 家园交互帧预算（用户明确：家园宠物要「具象化、可互动」）

> 家园里的宠物**不是战斗单位的缩小版**，而是有存在感、能被玩家逗弄的活物。因此家园需要一组**独立于战斗**的交互帧，且显示尺寸可比战斗时更大（建议家园视图工作分辨率取到 32px 上限，显示 ×4–×6，比战斗中 6 宠同屏时更醒目）。

| 交互动作 | 帧数 | 说明 |
| --- | --- | --- |
| 待机呼吸 | 2 | 与战斗待机可共用 |
| **蹭光标 / 被抚摸** | 3 | 头向光标方向歪、眯眼享受（**「具象化可互动」的核心卖点帧**） |
| 开心扭动 | 3 | 拿到食物/被撸后原地小转圈 |
| 睡觉 | 2 | 家园闲置时趴下闭眼（Zzz 粒子） |
| 跟随光标走动 | 4 | 玩家点击/拖动时小碎步跟随 |
| 吃食 | 3 | 与战斗吃帧共用 |

- **家园宠物帧预算 ≈ 17 帧/只**（不含战斗 11 帧）；首版可仅做「蹭光标 + 开心 + 吃食」3 组验证手感，其余先占位。
- ⚠️ **状态铁律（§1）只约束「状态变化」（半饿/饿/饱），不禁止「交互动画」**。抚摸/睡觉/扭动是合法的新帧，该画就画——它们正是"可互动"的卖点，与"状态靠滤镜省帧"不矛盾（状态是战斗爽点，交互是家园情感点）。

## 4. 状态/特效纪律（省成本的核心）

> 这是整份指引里**最值钱的一条**：战斗里所有"状态变化"都不靠新素材，靠**滤镜 + 光环 + 粒子**。

| 要表达的状态 | 错误做法 | 正确做法（低成本） |
| --- | --- | --- |
| 半饿最强 | 画一套金甲新立绘 | 套 `#FFD700` 光环 shader + 5% 缩放脉冲 |
| 全饿危险 | 画瘦骨嶙峋帧 | 红色描边 + 整体 3px 抖动 |
| 升级/喂食 | 新动画 | 橙色粒子爆发 + 数字飘字 |
| 关系网触发 | 新互动动画 | 相邻宠物间画一道虚线 + 小箭头图标 |
| 宠物开心 | 新舞蹈帧 | 头顶冒爱心粒子（2 帧） |

**结论**：立绘素材只负责"长相"，状态全交给"特效层"。这让你一个人也能撑住 6 宠同屏的反馈密度。

## 5. 环境 / 地图规范

- **家园**：一屏（约 320×180 逻辑像素，×4 = 1280×720），中心是窝，四周 3 个资源点。无计时、无怪物。**宠物在此以「具象化可互动」形态呈现（见 §3.5），是玩家情感投入的主场景。**
- **战斗场景（远征）**：共 **4 张**，每张一个主色调 + 1 个独特机制（如：森林=食物×1.5、雪原=移速-、火山=怪物加速、夜市=特殊资源）。**禁止只换皮**。
- **Tile 规格**：32×32 tile，Auto Atlas 合批；买现成 tileset 优先，自绘仅补缺失件。

### 5.5 摄像头规范（战斗 · 用户明确"在合适的摄像头下施法"）

> 摄像头是「可读性」的命脉（§1 剪影可辨）。定错 zoom/角度，6 宠 + 弹幕会糊成一团，第一时间流失玩家。

| 项 | 规定 |
| --- | --- |
| 视角 | **俯视微倾（约 70–80° 顶视，轻等距感）**，不纯侧视、不第一人称 |
| 跟随 | 相机锁定**玩家中心点**，中心点移动相机跟随（见计划书 Day1「相机跟随」） |
| 缩放 | 固定 zoom，保证同时可见：中心点 + 6 宠环绕 + 半径内弹幕/敌人；建议屏内可见约 1.5 个屏幕直径的战场 |
| 施法表现 | 宠物**自动施法**（玩家不手动瞄准），施法链路必须拆三段（CR-009）：<br>① **前摇 2 帧**（蓄力/抬手/嘴巴张开，身上微量光芒）<br>② **施法 1 帧**（发射弹道/喷吐/法阵）<br>③ **后摇 3 帧**（动作回位/喘气）<br>弹道与受击用 VFX 粒子表达，**不算新立绘帧**；6 宠同屏的"壮观感"来自数量 + 金环，而非单个宠物特写 |
| 禁项 | 禁止镜头剧烈抖动、禁止随机旋转、禁止缩放漂移 |

### 5.6 战斗敌人（怪物 · 成批生成 · 有攻击/施法半径）

> 敌方单位设定（CR-007 + **CR-008 修正** + **CR-009 放宽**）：**怪物（含昆虫/野兽/元素怪等小型可移动单位）**，不是静止炮塔。关键修正——敌人**不是从屏幕外涌来追击玩家**，而是**玩家移动到某个地点后，该地点成批生成一群怪物**（像踩进怪窝）。这群怪物有**独立 AI**：可移动、可施法、各有**攻击半径**与**施法半径**。

| 项 | 规定 |
| --- | --- |
| 敌人类型（首版 3 种） | **步行虫**（近战，进入攻击半径平 A）、**飞虫**（远程，进入施法半径读条喷吐）、**甲虫**（厚血近战坦克，半饿倍率才啃得动）——**首版用昆虫造型验证，后续可换成野兽幼崽/元素史莱姆/蘑菇怪等**，只要剪影与宠物形成"可爱 vs 野生"反差即可 |
| 形态 | 小、圆润带甲壳，剪影与宠物区分（宠物圆软、敌人尖硬带腿/翅），仍有 Q 萌底色但明显"野生感" |
| 生成 | **抵达地点后成批刷新**（如 12 只/窝），不主动跨屏追玩家；玩家走进某窝的触发范围才激活该窝 |
| 移动 | 在自身活动范围内游走/调站位，**不必然追玩家**；离开活动范围边缘则返回 |
| **攻击半径** | 玩家/宠物进入半径（如 60px）才发动近战攻击（首版步行虫/甲虫） |
| **施法半径** | 进入更大半径（如 140px）即可**施法**（飞虫喷吐等），施法有**前摇读条**给玩家反应窗口，造成远程/范围伤害 |
| 反馈 | 受击 = 白闪 2 帧 + 击退；施法前摇 = 身体发光/蓄力色；死亡 = 缩小消失 + 经验珠弹出（juicy） |
| 配色 | 敌人主色用偏冷/浊的对比色（如 `#6B8E23` 橄榄绿、`#C0392B` 暗红、`#34495E` 甲灰），与主色板里的暖色宠物形成"可爱 vs 野生"反差 |

## 6. UI 规范

- 风格：**圆角矩形 + 厚描边 + 像素图标**，按钮有"按下" 2 帧反馈。
- 图标：**每个功能一个像素图标**（喂食=碗、远征=脚印、关系=链、半饿=钟），图标库统一在 `ui-icons.png` 合图。
- 字体：像素字体（如 `Silkscreen` / `Zpix` 中文像素），标题可稍大但正文 ≥ 12px。
- 布局：信息密度低，留白多，避免"手游塞满"感——cozy 玩家要的是清爽。

## 7. AI 出图「风格锚定包」（给 AI 工具用）

> 每次让 AI 出概念图/UI 稿，把下面这段**原样粘贴**作为正向约束，再加你的具体对象。这样每次出图都锁在同一套风格里，不会出现"这图不像我们游戏"。

**正向（必带）**：
```
pixel art, chibi style, 16-32px working resolution, integer-scaled, thick 1px dark outline,
rounded shapes, high saturation, readable silhouette, cozy cute creature but lively,
juicy feedback, flat colors no gradients, palette: cream #F4E4C1 / wood #8B5A2B /
pig-pink #FFB6C1 / cat-orange #FF9F68 / fox-purple #B47CE0 / gold-halo #FFD700 / deep-ui #2D2438
```

**负向（必带）**：
```
no realistic, no anime cel-shading, no photoreal, no detailed shading, no blur,
no subpixel, no gritty dark, no text watermark, no extra limbs
```

**对象占位**：`[一只圆滚猪宠物，金色半饿光环，星星眼，像素风]` → 替换 `[...]` 即可。

> ⚠️ **Steam AI 政策（计划书第 6 章）**：AI 出的**概念图/占位/UI 草稿**属"幕后工具"豁免披露；但**成品商店素材若用 AI 生成必须披露**，且披露游戏销量约为均值 1/3。**所以：AI 只用于"定风格/出参考"，成品立绘/地图以买/外包为主。**

## 9. 风格校验清单（每个资源入库前必过）

- [ ] 工作分辨率 16–32px，整数倍放大，无模糊
- [ ] 在 64×64 缩略图下，剪影/主色仍能一眼认出是什么
- [ ] 用了 §2 的 Hex 配色，无自创颜色
- [ ] 状态变化（半饿/饿/饱）用光环/滤镜表达，未画新动作帧
- [ ] 家园宠物具备「具象化可互动」交互帧（蹭光标/被抚摸至少 3 帧，见 §3.5）
- [ ] 战斗宠物施法动画拆三段：前摇 ≥2 帧 + 施法 ≥1 帧 + 后摇 ≥3 帧（CR-009）
- [ ] 敌人造型与宠物形成"可爱 vs 野生"反差，不限制具体物种
- [ ] 战斗摄像头符合 §5.5（俯视微倾/跟随中心点/固定 zoom/无抖动）
- [ ] 有 1px 深色描边，缩略图不糊
- [ ] UI 正文 ≥ 12px，有三档字号切换
- [ ] 与 `ref-*.png` 锚点图"同一种游戏感"（主观但必须对齐）
- [ ] AI 出的图仅作参考/草稿，成品非 AI 生成（或已按计划书披露）

## 11. 原型期「具象占位美术」（CR-007 · 关键放行）

> 你明确要求"刚开始做也希望看到形象的美术在战斗场景中"。为此，**原型期（W1-3）放行使用 AI 生成的风格锚定占位精灵**——它们看起来就是最终方向（Q 萌宠物 + 怪物敌人，首版以昆虫造型占位），而非抽象方块，用以尽早验证手感与视觉。

1. 仅用于**内部试玩 / 录屏**，绝不上 Steam 商店页、不进任何对外宣传素材；
2. 全部带"AI 占位"标记，仓库内单独放 `assets/placeholder/`，与正式 `assets/final/` 物理隔离；

**结论**：这把"想早看到形象美术"和"不破 ¥7,900 预算 / 不踩 AI 标签"同时满足。手感与视觉一旦验证，再花第一笔钱买正式素材。
